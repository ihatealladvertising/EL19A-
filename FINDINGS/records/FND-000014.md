## Target-side observations

### Structural pair and call mechanics

- \`sub_22FAC\` accepts R4=value pointer, R5=UWORD axis pointer, R6=UWORD query; it performs the 32-point UWORD axis search and interpolation.
- At \`0x648D8\`, \`sub_648A6\` supplies values \`0x10F8A\`, axis \`0x0F712\`, query selected from \`FFFF1066\` / \`FFFF1064\` by ROM \`0x87C8.bit7\` plus UWORD addend \`FFFF10A0\`. Raw UWORD result is staged at \`FFFF10E2\`; later normalization stages include \`FFFF170C\` and derived byte \`FFFF170A\`.
- At \`0x68A46\`, the reverse-direction path supplies values \`0x0F712\`, axis \`0x10F8A\`, query \`FFFF33EA\`. The result is normalized/clamped into \`FFFF1580\`.
- At \`0x37398\`, a separate caller queries values \`0x0F712\`, axis \`0x10F8A\` with \`4 × UWORD[FFFF9916+0x98]\`; its output is adjusted/clamped and staged at \`FFFF993C/FFFF993E\`. This is a distinct state path.
- Additional reader contexts are catalogued at \`0x69622\` and \`0x767DE\`; they do not supply a proven physical identity.

### Forward-query operand provenance

- **\`FFFF1066\`:** WO65089's \`sub_68D94\` trace records a UWORD write at \`0x68F5E\` under GBR=\`FFFF1054\`, effective address \`FFFF1054+0x12 = FFFF1066\`. The value follows a preceding piecewise lookup using \`0x10EEA/0x1100A\` or \`0x10F2A/0x1104A\`, followed by further arithmetic/scaling. This is a computed software state/result, not a direct sensor read.
- **\`FFFF1064\`:** \`INDEX/catalog_179_consumer_summary.tsv\` attributes a \`sub_22FAC\` reader at \`0x69622\` in \`sub_69496\` to \`0x0F712\` and records a UWORD taint/store at \`FFFF1064\` (\`0x69630\`). The crosswalk also records \`FFFF1064\` consumed as a query by \`sub_648A6\` at \`0x648BA\`. The immediate query producer at \`0x69622\` is not fully reconstructed in the cited WO closeouts; treat this as partial/index-derived lineage.
- **\`FFFF10A0\`:** UWORD addend in the forward query at \`sub_648A6\`. WO65098's bounded search did not identify a direct writer. No physical identity or source is established.
- ROM \`0x87C8.bit7\` selects the two RAM operands. No D/N, MAF, RPM or other mode meaning is assigned to this bit.

### Capture-derived reverse-query boundary

- \`FFFF33EA\` is reached through separate F3D6 lookup/state logic whose query is derived from a counter-difference/reciprocal chain beginning with UDWORD \`FFFF14E0\`.
- \`sub_257AC\` reads \`FFFF14E0\` and previous sample \`FFFF8650\`, computes a corrected unsigned delta, shifts right five and stores \`FFFF85E4\`. The actual producer of \`FFFF14E0\` is not identified.
- Both \`INT_ATU02_ICI0A\` and \`INT_ATU12_IMI1AE\` call the shared \`sub_2088C\) path that executes \`sub_257AC\`; neither is proven to supply the sample.
- The known ATU02 ICR0A capture is stored at \`FFFF1A64\`, not \`FFFF14E0\`. ATU12/IMI1E has a channel-1 hardware-pin candidate (\`TIO1E = PD4/TIO1E\`), but no target-side PFC/pin route or sample transfer to \`FFFF14E0\` is proven.

## Conclusion

The only safe current name is **bidirectional 32-point UWORD transfer/lookup pair**. The ROM proves geometry, helper mechanics and several independent software callers. It does not prove that the pair is a MAF/airflow conversion, engine-load table, RPM conversion or fuel quantity path. The “MAF/Flow” catalogue description remains a discovery hypothesis, not a validated target physical identity. No unit, physical sensor, actual input pin, or actuator endpoint is assigned.
