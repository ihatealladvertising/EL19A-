# FND-000019 — `0x0F01C` is a 16-point coolant-temperature curve; `0x0F02C` is a separate 4-entry bin floor table

**Status:** CURRENT
**Semantic layer:** input identity (advanced: coolant temperature) and output identity (advanced: two clamped byte publications, no actuator sink)
**Evidence grade:** reader/helper and ROM-callsite anchored (Reader-Verified for geometry, query and publication)
**Confidence:** HIGH for extent, geometry, query, gates, floors and publication cells; MEDIUM for the bin's physical domain; UNRESOLVED for the meaning of the published cells

## Scope

Bounded conclusion for the ROM region `0x0F01C`–`0x0F02F` as read by `sub_48D2E` (`0x048D2E`–`0x04913C`) at call PC `0x048E60`, reached under WO66049. It completes the query/geometry question left open by WO65291 and extends `FND-000017`'s grid statement without contradicting it. No physical name, unit or engineering conversion is promoted.

## Observations

1. **Two references only.** The whole `0x0F01C` region has exactly two code references: `mov.l off_48FE8,r4` at `0x048E5A` (helper call at `0x048E60`, `r6 = sub_22E10` from `off_48FEC`) and `mov.l off_48FFC,r5` at `0x048EFE`. WO65291's "call context `0x48FE8`" is the pool address, not the call PC.
2. **One shared query for both curves.** `0x048E58`/`0x048E64` load `r7 = 0xFFFF84B4`; `mov.b @(4,r7),r0` at `0x048E5C` and again `0x048E6A` reads `U8[FFFF84B8]`; the `jsr` delay slots `0x048E62`/`0x048E6E` `extu.b r0,r5` supply it to both calls. No arithmetic, shift or intermediate cell. `FFFF84B8` is the rescaled AN27 NTC coolant-temperature image (`FND-000018` §4). No RPM operand exists in the routine.
3. **Grid.** Identical to `FND-000018` §2: `table[idx] + (table[idx+1]-table[idx])*(q&15)/16` with `idx = q>>4`; `q >= 0xF0` returns `table[15]`.
4. **Gates.** `sub_48D2E` installs GBR = `0xFFFF859C` (`word_48D94`, `ldc` at `0x048D42`). The lookups run only when all of: `UBYTE[FFFF3518]` (`FFFF34C1+0x57`) bit5 clear (`0x048E16`), `UBYTE[FFFF3519]` (`+0x58`) bit6 clear (`0x048E24`), `FFFF3518` bit6 clear (`0x048E2E`), `FFFF3519` bit3 clear (`0x048E38`), `UBYTE[FFFFA6FF]` == 0 (`0x048E44`), `UBYTE[FFFF8617]` (`@(0x7B,gbr)`) bit5 clear (`0x048E50`). Any failure branches to `loc_48F60`, which never queries either table.
5. **Offset.** If `UBYTE[FFFF362E].bit2` is set (`0x048E7C`), `UBYTE[0x8565] = 0x18` is added to both results and to the `r11` accumulator with `cmp/gt 0xFF` saturation (`0x048E80`–`0x048ED2`).
6. **Bin selector.** `0x048ED4`–`0x048EFC` counts how many of the three ROM thresholds `UBYTE[0x0E21A..0x0E21C]` = `06 08 0C` (6, 8, 12) are `<= UBYTE[FFFF84D4+0x10]` = `FFFF84E4`, capped at 3 → bin 0–3. The same three-threshold selector is recorded in `FND-000016`/`REC-000020` for `0x0E21A`; here it indexes the `0x0F02C` table rather than the `0x0ED9C`/`0x0F2AE`/`0x107CC` arrays.
7. **Floors.** `r5 = UBYTE[0x0F02C + bin]` at `0x048F04`; `r13 = max(F01C_result, r5)` (`cmp/ge` at `0x048F08`) and `r12 = max(EE68_result, r5)` (`0x048F14`). A second floor `UBYTE[0x8B9D] = 0x04` is applied at `0x048F48`–`0x048F5A`.
8. **Publication.** With `r10 = 0xFFFF1054` (`off_48FD8`), `mov.b r13,@(0x3ED,r10)` at `0x048F8C` writes **`UBYTE[FFFF1441]`** and `mov.b r12,@(0x330,r10)` at `0x048F90` writes **`UBYTE[FFFF1384]`**. The clamped values leave the routine only as these two bytes.
9. **Caller.** `sub_48D2E` is invoked from `loc_47C0A` in `loc_47B54` (`0x047C0A`, `off_47CD0`), the `0x0218F8`-dispatched routine that also calls `sub_488BA` at `0x047BDA` (WO66048).

## Conclusion

`0x0F01C` is a **16-point UBYTE curve on the coolant-temperature query** whose result is combined with a companion `0xEE68` curve and then **floored by a 4-entry bin-indexed table at `0x0F02C`** before being published to `FFFF1441` and `FFFF1384`. The `0x0F02C` table is a distinct calibration object, not a continuation of the curve: it is indexed by a computed 0–3 bin derived from `0x0E21A` thresholds against `FFFF84E4`, so it has no physical axis and must not be presented as a curve.

The prior "32-byte, 16×1 or 2×16, values 0x00–0x81 rising" reading is a window artefact spanning three separate objects; the curve itself is strictly non-increasing and the rising range belongs to the unrelated ramp at `0x0F031`.
