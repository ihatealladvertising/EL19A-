# FND-000018 — `0xED64`/`0xEDA0` share one coolant-temperature query and publish only a plausibility verdict

**Status:** CURRENT
**Semantic layer:** input identity (advanced: coolant temperature) and output identity (advanced: no actuator sink; status bit + enum-state input)
**Evidence grade:** reader/helper and ROM-callsite anchored (Reader-Verified for geometry and query; target-side instruction proof for the verdict path)
**Confidence:** HIGH for geometry, query cell, helper contract, verdict tree and output channels; MEDIUM for the physical nature of the compared cell `FFFF85A9`; UNRESOLVED for physical units and for the downstream meaning of the verdict

## Scope

Bounded conclusion for the paired 16-point curves at ROM `0x0ED64` and `0x0EDA0` in `sub_488BA` (`0x0488BA`–`0x048C1C`), reached under WO66048. This record completes the axis/query-domain question left open by `FND-000017` (implicit grid recorded, physical domain unresolved) and closes the fuel-cut-family question left open by WO65291. It promotes no physical name, no engineering unit and no °C mapping.

## Observations

1. **Single reader, single pointer.** The only ROM reference to `0xEDA0` is the pool word `off_48B6C` at `0x048B6C` (`00 00 ED A0`), loaded by `mov.l off_48B6C,r4` at `0x048942` and consumed by `jsr @r14` at `0x048948` (`r14 = sub_22E10` from `off_48B64`). No `FF FF ED A0` absolute literal exists. `0xED64` is loaded identically at `0x048930` and called at `0x04893A`.
2. **GBR discipline.** `sub_488BA` installs its own GBR = `0xFFFF859C` (`word_488EE`, `ldc r0,gbr` at `0x0488CE`, restored at `0x048C0A`). Every `@(h'NN,gbr)` in the routine is `FFFF859C+NN`. `r8 = 0xFFFF34C1` (`off_48B68` at `0x048938`) carries the routine's only `FFFF34C1`-relative access.
3. **Helper contract.** `sub_22E10`: `r4` = table base, `r5` = `extu.b` query byte, result in `r0`. Query `>= 0xF0` returns `table[15]` (`rts` delay slot `mov.b @(h'F,r4),r0` at `0x022E20`). Otherwise `loc_2350C` shifts the query right four times into `idx = r5>>4` with the low nibble `frac` rotated into `r3` (`swap.w` → `frac<<12`), selects the byte path at `loc_23532`, and `sub_231C8` computes `value = table[idx] + (table[idx+1]-table[idx]) * (q & 15) / 16` via `mul.l` high word, with a dedicated `hi < lo` branch (`0x0231CC`–`0x0231E2`). Effective grid: `q` 0–239 interpolates the 15 segments `0,16,…,224`; `q >= 240` returns `table[15]`.
4. **One shared query.** `0x048934` `mov.b @(4,r7),r0` with `r7 = 0xFFFF84B4` (`word_48A6E`) reads `U8[FFFF84B8]`; its `jsr` delay slot `0x04893C extu.b r0,r5` supplies the `0xED64` query. `0x048946` repeats the identical load and delay slot `0x04894A` supplies the `0xEDA0` query. No arithmetic, shift or staging between the load and either helper call. There is **no second axis**, and no RPM operand anywhere in the routine.
5. **Query identity.** `FFFF84B8` = `U8[FFFF84B4+0x04]` is the rescaled AN27 NTC coolant-temperature image already recorded in `CALIBRATIONS/discovered_tables_catalog.csv` rows `0x0F406`, `0x0DE5E` and `0x10FEA`, in WO65739 §"The `+0x04` field is already established as the rescaled AN27 ECT image (WO65239)", and is written by the lineariser `sub_2245C` (`U8[FFFF84BB..84C1] → U8[FFFF84B4..84BA]`).
6. **Post-lookup conditioning.** `UBYTE[FFFF362E].bit2` set → both results get `+UBYTE[0x8565] = +0x18` with `cmp/gt 0xFF` saturation (`0x048960`–`0x04899C`). `UBYTE[FFFF361D].bit0` clear → both results are floored at `UBYTE[0x86A7] = 0x00`, which is degenerate and changes nothing (`0x04899E`–`0x0489BE`).
7. **Threshold, not publication.** The only comparison operand is `UBYTE[FFFF85A9]` (`FFFF859C+0xD`), tested as `UBYTE[FFFF85A9] > threshold` with `cmp/gt`. `0xED64`'s result (`r12`) is the strict threshold, tested at `0x0489E4`, `0x048A3E`, `0x048AB8`, `0x048ACE`, `0x048B2E`, `0x048B44`, `0x048BCE`; `0xEDA0`'s result (stack `var_28`) is the soft threshold, tested at `0x048A1C`, `0x048A5E`, `0x048A9E`, `0x048BB6`, `0x048BE8`. Different branches select one or the other; they are never applied together as a bracket.
8. **Arming.** Every verdict path requires `r13 = UBYTE[FFFF860B] & 0x08` non-zero (`and #8` at `0x04895E`); `r13 == 0` always exits with return 0. `UBYTE[FFFF860F].bit3`, `UBYTE[FFFF8600].bit1`, `UBYTE[0x8CD3].bit7`, `UBYTE[0x87C8].bit7`, `UBYTE[FFFF84CA]==2`, `UBYTE[FFFF1D7C].bit6`, `UBYTE[FFFF208C]==0` and `UBYTE[FFFF8531] >= 4` select the branch.
9. **Outputs.** Terminal block `0x048BF4`–`0x048C04`: the verdict flag (0 at `0x0488D8`, 1 at `0x048BD8`) sets or clears **bit6 of `UBYTE[FFFF34D2]`** (`FFFF34C1+0x11`, `byte_FFFF34D2`, `.res.b 1`) before `mov.b r10,@(r0,r8)` at `0x048C04`. Strict failure (V1, `loc_48BD2`) returns 1 **and** sets bit6; soft failure (V2, `loc_48BF0`) returns 1 with bit6 clear; default returns 0 with bit6 clear. Neither curve value leaves the routine.
10. **Consumer.** Sole external caller is `bsr sub_488BA` at `0x047BDA` in the alternate entry `loc_47B54` of the `0x047B54` routine, pointer-table entry `0x0218F8` (GBR `0xFFFF34B0`). A non-zero return with `UBYTE[FFFF11F3] == 0` calls `sub_48C1E` at `0x047BF0`, whose 16-bit result is stored to `UWORD[FFFFB644]` (`0x047BF8`) and mirrored to `U16[FFFF11F0]` via `UBYTE[FFFF1054+0x19C]`/`0x19D` (`0x047BFA`–`0x047C08`). The return is then passed as `r4` to `sub_491BC` at `0x047C2C`, the producer of the `FFFF11F3` 0–4 state, matching WO64892's recorded input contract.
11. **Current consumers of the status bit.** `byte_FFFF34D2` has exactly three absolute readers: `0x0A151E`, `0x0A31EE` (`FFFF34B3+0x1F`) and `0x0A3BAE` (`FFFF34C1+0x11`). Bit6's own consumers were not traced; WO65913 already uses one of these sites as an early-exit gate.

## Conclusion

`0x0ED64` and `0x0EDA0` are a **paired coolant-temperature-keyed threshold pair**: two 16-point UBYTE curves on the same single query (`FFFF84B8`, rescaled AN27 NTC coolant temperature), each used as a single-sided comparison against `UBYTE[FFFF85A9]`, with the outcome published as `UBYTE[FFFF34D2].bit6` and a 0/1 return that drives the `FFFF11F3` enum state machine and gates a `sub_48C1E` 16-bit publication.

They are **not** warm-up or idle-speed control tables, and they are **not** RPM-scheduled: no RPM value is read anywhere on the path. The provisional XML names `Fuel Cut Bosch [S] (ED64)` / `Fuel Cut JECS [S] (EDA0)` and their `Rpm_x25` scaling are contradicted by the proven query source, not merely unsupported.
