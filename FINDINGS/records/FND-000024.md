# FND-000024 — `0x0D856` and `0x0C2D6` are 8×8 UWORD BE maps with dedicated 8-entry UWORD axes, and a matcher "companion" is a sibling lookup, not an axis

**Status:** CURRENT
**Semantic layer:** input identity and function identity are **not** advanced; this record establishes structure (address, extent, storage, geometry, axes, reader, query cells, destination) for two previously uncatalogued objects.
**Evidence grade:** Reader-Verified (byte-exact ROM extent, complete helper contract derived from the shared interpolation core, all four arguments resolved per callsite)
**Confidence:** HIGH for extent/storage/geometry/axes/reader/arguments; LOW for donor symbol identity; UNRESOLVED for physical function and units

## Scope

Bounded structural characterisation of two reported 8×8 UWORD map candidates, reached under WO70009:

- `0x0D856` — reported candidate `mTEHOSMAP`
- `0x0C2D6` — reported candidate `mMPAMBFAC`

It also retires a reusable evidence error: a donor-matcher "companion caller reference" is a **sibling lookup in the same enclosing function**, not an axis of the candidate.

## Observations

1. **Both objects are read by `sub_22CF8` (`0x22CF8`–`0x22D26`).** Its contract is fixed partly by its own body and partly by the core it tail-jumps into:

   - `0x22CFE` `mov r5,r0` + `0x22D00` `mov r7,r5` + `0x22D04` `jsr sub_2340C` with delay slot `0x22D06` `mov #h'E,r4`: the **first** search runs over the axis passed in `r5`, with the UWORD query in `r7`.
   - `0x22D0C` `mov r6,r0` + `0x22D0E` `mov.l @(h'10+arg_0,r15),r5` + `0x22D12` `jsr sub_2340C` with `0x22D14` `mov #h'E,r4`: the **second** search runs over the axis passed in `r6`, with the query taken from the caller's stack argument.
   - `0x22D24` `jmp loc_232D0` with delay slot `0x22D26` `mov #8,r5`.

2. **`r4 = 0xE` proves an 8-entry UWORD axis.** `sub_2340C` (`0x2340C`) uses `r4` as a **byte** offset: `mov.w @(r0,r4),r1`, `add #-2,r4` per step, `cmp/pz`. Starting at `0xE` = element 7 and stepping by 2 therefore scans an **8-element UWORD** vector. (Contrast `sub_233CC`, start `0xF`, step 1 → 16-element UBYTE.)

3. **`loc_232D0` is the UWORD 2D core and fixes the geometry.** `0x232D6` `mulu r5,r0` with `r5 = 8` multiplies the row byte offset (`2*rowIndex`) by 8 → `16*rowIndex`; `0x232D8` `add r2,r4` adds the column byte offset (`2*colIndex`); `0x232DE` `shll r5` makes the row stride `16` bytes; `0x232EC`/`0x232EE` and `0x232FC`/`0x232FE` read the four bilinear cell words with `mov.w @r4` / `mov.w @(2,r4)` / `mov.w @r5` / `mov.w @(2,r5)`, then call `sub_231C8` (endpoint interpolation, `MUL.L` high word, no rounding).

   Therefore: **rows = axis-A length = 8, columns = 8, element = UWORD big-endian, extent = 8×8 = 64 elements = 128 bytes**, row-major with a 16-byte row stride.

4. **The reported "128 elements / 256 bytes" is excluded by the ROM layout, not merely by arithmetic.**
   - `0x0D856 + 128 = 0x0D8D6`, which is the first byte of the already Verified 16×16 UWORD BE table `0x0D8D6`–`0x0DAD5` (`sub_22AFC` @ `0x5C28E`). The 512-byte table `0x0D656`–`0x0D855` (`sub_22D30` @ `0x66E3C`) ends at `0x0D855`. The only free gap is exactly 128 bytes and its all-`0x8000` fill stops precisely at `0x0D8D5`, where `0x0D8D6` begins `7E E3 7F B8 …`.
   - For `0x0C2D6`: the 16×16 table `0x0C0D6`–`0x0C2D5` ends at `0x0C2D5`; the `0x1000` fill runs `0x0C2D6`–`0x0C355`; `0x0C356`–`0x0C3D5` is a further 128 zero bytes; the next object is `0x0C3D6` (8×8 UWORD BE, `sub_22CF8` @ `0x6F6DC`). Only the first 128 bytes are addressable by an 8-row × 8-column reader.

5. **Object A — `0x0D856`.** Extent `0x0D856`–`0x0D8D5`; all 64 elements `0x8000` (1 unique value). Single listing reference `0x6B1D0` `mov.l off_6B3C0,r4`; pool word ROM `0x6B3C0` = `0x0000D856`. Enclosing function `sub_6B160` (`0x6B160`, `rts` `0x6B234`), gated on `UBYTE[0x8B52].bit5` (`0x6B16E`–`0x6B174`). Arguments: `r4 = 0x0D856`; `r5 = 0x104BC` (`0x6B1CC` r6 = `0x104AC`, `0x6B1D2` r5 = r6, `0x6B1D6` `add #h'10,r5`); `r6 = 0x104AC`; `r7 = U16[FFFF1054+0x3E6] = U16[FFFF143A]`; stack arg `= U16[FFFF1054+0x384] = U16[FFFF13D8]` (`0x6B1CE` read, `0x6B1D4` `mov.w r0,@(h'1C+var_1A,r15)`).

6. **Object B — `0x0C2D6`.** Extent `0x0C2D6`–`0x0C355`; all 64 elements `0x1000`. Single listing reference `0x6FC76` `mov.l off_6FD78,r4`; pool word ROM `0x6FD78` = `0x0000C2D6`. Enclosing function `sub_6FCFE` (`0x6FCFE`; body `loc_6FBF6`, `0x6FBF6`–`0x6FCFC`; called by `jsr @r2` at `0x6ED04`), gated on `UBYTE[0x8405].bit0` (`0x6FC04`–`0x6FC0A`). Arguments: `r4 = 0x0C2D6`; `r5 = 0xFDF0`; `r6 = 0xFE00` (`0x6FC74` `mov r5,r6`, `0x6FC78` `add #h'10,r6`); `r7 = U16[0x0A324+0x14] = U16[0x0A338] = 0x0000` (`0x6FC6A` literal `0xA324`, `0x6FC80` `mov.w @(h'14,r7),r0`); stack arg `= U16[FFFF13D8]` (`0x6FC7A`, `0x6FC7E`).

7. **Axes (all four are adjacent UWORD vectors, matching the `add #h'10` idiom).**

   | Object | Axis | Address | Values |
   |---|---|---|---|
   | `0x0D856` | rows (`r5`) | `0x104BC`–`0x104CB` | `856, 1024, 1505, 2314, 3635, 4096, 5120, 6144` |
   | `0x0D856` | columns (`r6`) | `0x104AC`–`0x104BB` | `640, 768, 832, 896, 928, 960, 1024, 1152` |
   | `0x0C2D6` | rows (`r5`) | `0xFDF0`–`0xFDFF` | `7936, 15872, 23808, 31744, 39680, 47616, 55552, 63488` (step `0x1F00`) |
   | `0x0C2D6` | columns (`r6`) | `0xFE00`–`0xFE0F` | `2048, 1792, 1536, 1280, 1024, 768, 512, 256` (**descending**) |

   `0x104AC` is preceded by a 4-entry UBYTE vector at `0x104A4` (`CC DD EE FF`) belonging to a different reader; `0xFE10` begins an unrelated ascending vector (`0000 1FE0 3FC0 5FA0 …`), so `0xFE00` ends at `0xFE0F`.

8. **`0x0C2D6`'s stock row query is a constant zero.** `0xA324` is a ROM literal used as a pointer; `0x0A324`–`0x0A343` is 32 zero bytes, so `U16[0x0A338] = 0x0000`. `sub_2340C` then falls through all eight entries and returns `r4 = 0`, `r5 = 0` (`loc_2343C` → `mov #0,r4`; `locret_23444` `mov #0,r5`). In this stock ROM the surface is therefore read as **row 0 only** and degenerates to its first row.

9. **The two maps share their column query.** `U16[FFFF13D8]` is the column query for both objects, and it is an internal RAM word (`FFFF1054 + 0x384`), as is `0x0D856`'s row query `U16[FFFF143A]` (`FFFF1054 + 0x3E6`).

10. **Destinations.** `0x0D856`: result clamped to `0xA000` (`0x6B1E2`/`0x6B1E8`/`0x6B1EE`) and stored at `word_6B2BC = 0x5E4` → `U16[FFFF1638]`, then blended with a `0x0CD56`-derived quantity (`mul.l r14,r2`, `xtrct`), saturated at `0x7FFF` and `0xFFFF8000`, and stored at `word_6B2C0 = 0x5F8` → `U16[FFFF164C]`. `0x0C2D6`: stored at `word_6FD10 = 0x788` on base `0xFFFF2150` → `U16[FFFF28D8]`, then a `0x10D7A`/`0x1005E` curve result at `0x8EC`, a `>>8>>2>>2` product at `0x688`, a `0x68A` product through `sub_22434`, then `0x7FFF`/`0xFFFF8000` saturation with the intermediate at `word_6FD0C = 0x68A` → `U16[FFFF27DA]` and the final write at `0x6FCEC` → `U16[FFFF3470]` (`0xFFFF3454 + 0x1C`).

11. **The reported "companion caller references" are sibling lookups, not axes.** In `sub_6B160`: `0x1100A` (32×1 UWORD curve, axis `0x10EEA`, `sub_22FAC` @ `0x6B19E`) and `0x0CD56` (16×16 UWORD, axes `0x0E2C9`/`0x0FEC0`, `sub_22D68` @ `0x6B1B0`). In `sub_6FCFE`'s body: `0x10954` (16×1 UWORD curve, axis `0xF912`, `sub_22F80` @ `0x6FC18`, alternate branch) and `0x0CD56` again (`0x6FC34`/`0x6FC40`, other branch), plus `0x10D7A`/`0x1005E` (`0x6FC98`). None has 8 entries as an axis would; `0x0CD56`'s 16×16 geometry cannot index an 8-row grid; and `0x0CD56` appears in **both** functions (and at `0x66146`, `0x69160`, `0x69174`, `0x6919E`, `0x6967C`, `0x6B6D6`, `0x6CC9E`, `0x6FBD0`), so it cannot discriminate a one-to-one pairing.

## Conclusion

`0x0D856` and `0x0C2D6` are two independent, code-verified **8×8 UWORD big-endian** lookup maps of **128 bytes each**, read by the same helper `sub_22CF8`, each with its own pair of 8-entry UWORD breakpoint vectors:

| Object | Extent | Extent bytes | Payload | Row axis | Column axis |
|---|---|---|---|---|---|
| `0x0D856` | `0x0D856`–`0x0D8D5` | 128 | all `0x8000` | `0x104BC` | `0x104AC` |
| `0x0C2D6` | `0x0C2D6`–`0x0C355` | 128 | all `0x1000` | `0xFDF0` | `0xFE00` (descending) |

Both stock payloads are constant, so neither object varies in this ROM.

**Reusable method rule:** a donor-matcher "companion caller reference" is evidence that the same enclosing function performs another lookup; it is **not** evidence of an axis, of a shared grid, or of a one-to-one symbol assignment. Axes must be identified from the helper's own argument registers (`r5`/`r6` pair with `+0x10` separation here) and their length from the helper's start-offset immediate (`0xE` = 8 UWORD entries for `sub_22CF8`; `0xF` = 16 UBYTE entries for `sub_22DA8`/`sub_233CC`).
