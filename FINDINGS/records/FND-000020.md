# FND-000020 — The `0x08AF6E` block is routine-private read-modify-write scratch, not a published diagnostic frame

**Status:** CURRENT
**Semantic layer:** structure (status-network endpoint), negative result at block scope
**Evidence grade:** Reader-Verified (frame boundary, every copy and write-back PC, both callee argument sets)
**Confidence:** HIGH that `sub_8AD7C` publishes nothing; MEDIUM-BROAD is explicitly **not** claimed about other writers of the same cells

## Scope

Bounded conclusion for the stack block written around `0x08AF3A`–`0x08AF96` inside `sub_8AD7C` (`0x08AD7C`–`0x08B3F4`), reached under WO66051. It answers the endpoint question left open by WO65922 (the `FFFF284E` memo's only outward product is `FFFF357A.bit2`, snapshotted here) and extends WO65877/WO65910/WO65922's "internal state, empty consumer set" from single bits to a 14-byte block. It makes no calibration claim.

## Observations

1. **The block is the routine's own frame.** `0x08AD92`/`0x08AD94` `mov.w word_8AEDA,r3 ; h'FFFFFF7C` + `add r3,r15` allocates −0x84 bytes; `0x08B3DC`–`0x08B3E0` `add #h'FFFFFF84,r15` releases it immediately before `ldc.l @r15+`, `lds.l @r15+,pr`, the register pops and `rts` at `0x08B3F2`. Every slot used (`0x34`, `0x38`, `0x44`, `0x48`, `0x4C`, `0x50`–`0x70`, `0x74`, `0x78`, `0x7C`, `0x80`) is below `0x84`.
2. **No frame pointer is ever formed.** The routine contains no `mov r15,rN`, so the block cannot be passed as an argument, copied as a unit or referenced by an address held in a register. It is reachable only through immediate `@(imm,r15)` displacements.
3. **The routine makes exactly two calls**, and neither takes the frame. `0x08AEB8` `bsr sub_8B3FE` has no r15-derived argument; `0x08B2F8` `bsr sub_8B87E` carries `mov #0xE,r4` in its delay slot and `sub_8B87E` is a leaf query — `r0 = UBYTE[FFFFA074 + r4*3 + 2]`, `tst #8`, return 0/1.
4. **Fourteen status bytes are read and then written back to the same cells.** Reads at `0x08AF3A`–`0x08AF8E`; write-backs at `0x08B16E`–`0x08B2F6`, one per source displacement:

5. **The block is mixed, not a status snapshot.** Slot `0x4C` holds a 16-bit word formed as `UBYTE[0x8635] << 8` (`0x08AF22`–`0x08AF38`) and is consumed by two `cmp/hs` comparisons (`0x08AFA6`, `0x08B068`); slots `0x44`/`0x48` are branch flags (`0x08AF2C`, `0x08AF32`, `0x08AFBC`, `0x08B006`); slots `0x74`/`0x78` are saturated accumulator words built from `UWORD[FFFF2150+0x8AE]`, `+0x8AC` and `UBYTE[FFFF2150+0x200]` (`0x08B04A`–`0x08B128`, `0x08B192`–`0x08B1B4`).
6. **No publication path.** No `sub_33E18` ring append or `sub_32790` wrapper call appears in the routine (WO65907's contracts are not engaged); no serial, message-buffer, lamp or MMIO address is written. The only outward effects are the 14 in-place byte stores, the `FFFF2150` counters, and `UBYTE[FFFF1E89] = 0x1E` on the `loc_8AFC2`/`loc_8B02C` path.

## Conclusion

The `0x08AF6E` block is **routine-private scratch used for an in-place read-modify-write of 14 status bytes**. It is not a diagnostic frame, not a queue payload and not a preserved structure: the values are computed in a −0x84 stack allocation and written back to the cells they came from, and the allocation is abandoned at `rts`.

Consequently the gathering of status bytes into one block is **not** evidence of an external publication path, and WO66051's discriminator question is answered negatively at block scope: the `FFFF34C1` status network's updates here terminate in firmware logic.

## What is not claimed

- **Not** that no other routine writes or publishes these 14 cells. 348 pool words reference `FFFF34C1`, so a block-wide xref was out of scope; this record covers only `sub_8AD7C`.
- **Not** any physical meaning for the 14 cells, the `0x8635` header byte, the `FFFF2150+0x8AE`/`+0x8AC`/`+0x200` counters, or `FFFF1E89`.
- **Not** that `sub_8B3FE`'s return (captured to `r13` at `0x08AEBC` and to slot `0x34`) has no other significance; it was identified only as not frame-derived.
