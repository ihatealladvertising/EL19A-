# FND-000010 — `unk_FFFF2150` limit band is firmware-initialised RAM, not calibration

**Status:** CURRENT
**Semantic layer:** input identity (origin of the `FFFF1640` clamp bounds); physical identity unresolved and not promoted.

## Addresses and geometry

- RAM struct base `FFFF2150` (`unk_FFFF2150`), limit band fields `A1C`–`A54`, i.e. `FFFF2B6C`–`FFFF2BA4`.
- Clamp edges used by the `FFFF1640` owner: `FFFF2B6E` (`A1E`), `FFFF2B72` (`A22`), `FFFF2B7C` (`A2C`) — as established in WO65499.
- Storage: 16-bit words inside the band; `FFFF2B6C`–`FFFF2BA4` appear in the pinned listing only as `UNDEFINED .res.b` lines, so no ROM image bytes exist for them.
- Writers (all indexed, base `FFFF2150` proven statically from literal-pool words):
  - `0x29C10`–`0x29CBC` — base `r1` from `off_29DEC` (`h'FFFF2150`) at `0x29C10`; writes `A20`,`A22`←`r13` and `A1C`,`A1E`←`r14` at `0x29C88`–`0x29C96`, plus `A44`,`A46`,`A54` and fifteen wider fields (`0x334`, `0x5E8`, `0x688`, `0x788`, `0x796`, `0x7A8`, `0x7AA`, `0x85C`, `0x8A8`, `0x8EC`, `0x922`, `0x924`, `0x92C`, `0xB3A`, `0xB3E`); `r14 := 0x7FFF` at `0x29C44`.
  - `0x6D4A0`–`0x6D4B0` — base `r6` from `off_6D6BC`, whose ROM bytes at `0x6D6BC` are `FF FF 21 50`; the bound publisher: `mov.w @(h'A52,r6),r2` / `cmp/gt r2,r4` / `bt` / `mov r4,r2` / `mov r2,r4` at `0x6D496`–`0x6D49E` raises `r4` to at least `U16[FFFF2BA2]`, then commits `A1E←r13` (`0x6D4A4`), `A22←r4` (`0x6D4A8`), `A1C←r14` (`0x6D4AC`), `A20←r7` (`0x6D4B0`), and returns at `0x6D4B8`.
  - `sub_67D0C` — base `r4` from `off_67D88` (`h'FFFF2150`) at `0x67D0E`; `mov.w @r6,r2` with `r6 = 0x90CC` at `0x67D10`, then sixteen stores of `r2` at `A3C`,`A3E`,`A3A`,`A5E`,`A48`,`A5A`,`A56`,`A4A`,`A4C`,`A4E`,`A50`,`A2E`,`A40`,`A42`,`A52`,`A58` (`0x67D12`–`0x67D60`). ROM bytes at `0x90CC` are `7F FF` = `0x7FFF`. One `jsr` reference resolves to `sub_67D0C`.

## Observation

Every band offset is materialised as a 16-bit literal-pool word loaded into `r0` and used as an index — `mov.w word_29D18,r0 ; h'A1C` then `mov.w r14,@(r0,r1)`. That is why a fixed-displacement census finds no writer: no `@(h'A1C,rN)` store exists anywhere in the ROM.

A ROM→RAM block copy is excluded by two independent facts. First, the ROM contains **no post-increment store of any width**: all 51 `@rN+` operands in the 509,428-line listing are loads or `mac` operands (`0xAB368`–`0xAB41A`). Second, the only whole-block copier, `copy_longwords_by_size` at `0x21F3C`, has exactly one call site, `0x20EF0`, with destination `FFFF84D4`, source `FFFF8534`, length `0x60` (WO65496); its body is a jump-table Duff's device (`0x21F44` `mov.l @(r0,r3),r3`, `jmp @r3`, table at `0x21F98`) whose stores are fixed displacements from the caller's destination base with a maximum of `@(h'3C,r1)`. No ROM literal anywhere encodes an address in `FFFF2B6C`–`FFFF2BA4`.

The band is therefore initialised by explicit firmware code: a `0x7FFF` no-limit default stamped by `sub_67D0C`, and register-computed bounds published by `0x6D4A0` (with `FFFF2BA2` as a lower bound in the `max()`). `0x7FFF` is the same positive-full-scale sentinel that the `FFFF1640` clamp saturates to.

## Conclusion

The `FFFF2150` limit band — including the `FFFF1640` clamp edges — is **writable RAM state initialised by firmware**, with a `0x7FFF` no-limit default and a computed bound publisher. It is **not** calibration-mirrored and must not receive a calibration definition, supply address, scaling or name. `FFFF1640` and its band remain opaque.

## Confidence and evidence grade

- **Confidence:** writer existence, base ownership and the `0x7FFF` default **HIGH** (each base statically proven from a pool word whose ROM bytes were verified). Reachability of clusters 1 and 2 from reset **LOW/OPEN** — no `jsr` edge from the boot path was traced and both are unlabeled code. Writer-set completeness **MEDIUM**: the screen covered indexed stores within 40 lines of a `FFFF2150` pool load (2,392 candidates), and the band's own offsets appear in only these routines, but a writer that inherits `FFFF2150` in a register without a pool load would be missed.
- **Evidence grade:** pinned-listing decode plus byte-exact ROM reads (`VERSA f501.bin`, MD5 `46991697c502052752a2cabcb84c9e27`). No donor transfer, no live test, no XML/A2L/workbook change.
