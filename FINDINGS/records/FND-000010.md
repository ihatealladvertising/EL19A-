# FND-000010 — `unk_FFFF2150` limit band is firmware-initialised RAM, not calibration

**Status:** CURRENT  
**Semantic layer:** input identity (origin of the `FFFF1640` clamp bounds); physical identity unresolved and not promoted.

## Addresses and geometry

- RAM struct base `FFFF2150` (`unk_FFFF2150`), primary limit band fields `A1C`–`A54`, i.e. `FFFF2B6C`–`FFFF2BA4`.
- Clamp edges used by the `FFFF1640` owner: `FFFF2B6E` (`A1E`), `FFFF2B72` (`A22`), `FFFF2B7C` (`A2C`) — as established in WO65499.
- Storage: 16-bit words inside the band. `FFFF2B6C`–`FFFF2BA4` appear in the pinned listing only as `UNDEFINED .res.b` lines, so no ROM image bytes exist for those RAM fields.
- Writers (all indexed, base `FFFF2150` proven statically from literal-pool words):
  - `0x29C10`–`0x29CBC` — base `r1` from `off_29DEC` (`h'FFFF2150`) at `0x29C10`; writes `A20`, `A22` from `r13` and `A1C`, `A1E` from `r14` at `0x29C88`–`0x29C96`), plus `A44`, `A46`, `A54` and fifteen wider fields (`0x334`, `0x5E8`, `0x688`, `0x788`, `0x796`, `0x7A8`, `0x7AA`, `0x85C`, `0x8A8`, `0x8EC`, `0x922`, `0x924`, `0x92C`, `0xB3A`, `0xB3E`); `r14 := 0x7FFF` at `0x29C44`.
  - `sub_6D274` (`0x6D274`–`0x6D4BA`) — publisher at `0x6D4A0`–`0x6D4B0`,  base `r6` from `off_6D6BC`, whose ROM bytes at `0x6D6BC` are `FF FF 21 50`. It commits `A1E←r13`, `A22←r4`, `A1C←r14`, `A20←r7`. The `0x6D496`–`0x6D49E` operation is a **signed minimum selection**, not a maximum; see WO65808 and REC-000011 for the branch-specific sources.
  - `sub_67D0C` — base `r4` from `off_67D88` (`h'FFFF2150`) at `0x67D0E`; initializes sixteen fields at `A3C`, `A3E`, `A3A`, `A5E`, `A48`, `A5A`, `A56`, `A4A`, `A4C`, `A4E`, `A50`, `A2E`, `A40`, `A42`, `A52`, `A58`. Fourteen receive `0x7FFF` from ROM word `U16[0x90CC]`; the exceptions are `A52` (`FFFF2BA2`) and `A58` (`FFFF2BA8`), which receive `0x8000` from the immediate `0x80` shifted left by eight at `0x67D54`–`0x67D5A`. The RTS delay slot stores `0x8000` to A58 at `0x67D60`. One `jsr` reference resolves to `sub_67D0C`.

## Observation

Every band offset is materialised as a 16-bit literal-pool word loaded into `r0` and used as an index — e.g. `mov.w word_29D18,r0 ; h'A1C` then `mov.w r14,@(r0,r1)`. That is why a fixed-displacement census finds no writer: no `@(h'A1C,rN)` store exists anywhere in the ROM.

A ROM→RAM block copy to this band is excluded by two independent observations. First, the ROM contains **no post-increment store of any width**: all 51 `@rN+` operands in the 509,428-line listing are loads or `mac` operands (`0xAB368`–`0xAB41A`). Second, the only whole-block copier has one call site, `0x20EF0`, with destination `FFFF84D4`, source `FFFF8534`, and length `0x60` (WO65496 / WO65739); it does not target `FFFF2150`. The earlier stated `+0x3C` maximum for that helper is corrected: the length-`0x60` call selects the generic helper path and writes through destination offset `+0x5C` (REC-000012). No ROM literal anywhere encodes an address in `FFFF2B6C`–`FFFF2BA4`.

The band is initialised by explicit firmware code. `sub_67D0C` stamps `0x7FFF` into fourteen fields and `0x8000` into A52/A58. The publisher `sub_6D274` commits branch-selected RAM state and constants; on the traced path its A22 value uses a signed minimum involving A52. These values remain firmware state, not calibration data.

## Publisher source observations

WO65808 bounded the register-source trace in `sub_6D274`:

- ROM bytes `U8[0x8405] = 0x0C` and `U8[0x8B0E] = 0x02` select the A2E state-selection path for this ROM. The remaining selector is `U8[FFFF3628+0x0C].bit6`; its semantic name is unresolved.
- `r13 → A1E`: `U16[FFFF2B7E]` (A2E), selected at `0x6D444` or `0x6D490`.
- `r4 → A22`: signed minimum. With selector bit 6 set, `min(U16[FFFF2BA2], U16[FFFF2BB2])`; with bit 6 clear, the earlier `r4` value is min-selected against `U16[FFFF2BA2]`.
- `r14 → A1C`: with bit 6 clear, `U16[FFFF990E]` or zero according to the 0x50 status mask; with bit 6 set, `U16[FFFF2BB2]`.
- `r7 → A20`: with bit 6 clear, constant `0x8000`; with bit 6 set, `U16[FFFF2BB2]`.
- `FFFF2BA2` is written by `sub_67D0C` as `0x8000`; it is not read-only. A global writer census for A52 was not performed, so runtime persistence of that initializer value is not asserted.

The source fields `FFFF2B7E`, `FFFF2BB2`, `FFFF990E`, and the earlier `r4` input are not established as physical measurements. Their further producers were outside WO65808's one-level boundary.

## Conclusion

The `FFFF2150` limit band — including the `FFFF1640` clamp edges — is **writable RAM state initialised and updated by firmware**. It is **not** calibration-mirrored and must not receive a calibration definition, supply address, scaling or physical name. The initialization is not uniform: fourteen listed fields receive `0x7FFF`, while A52 and A58 receive `0x8000`; the bound publisher uses a signed minimum, not a maximum. `FFFF1640` and its band remain opaque.

## Confidence and evidence grade

- **Confidence:** existence and base ownership of the three indexed-store clusters **HIGH**; A52/A58 initializer values and signed-minimum decode **HIGH**; physical interpretation of the source fields **NOT ESTABLISHED**. Reachability of clusters 1–2 from reset remains **OPEN**. Writer-set completeness remains **MEDIUM** because a writer inheriting `FFFF2150` in a register without a nearby pool load could escape the bounded screen.
- **Evidence grade:** pinned-listing decode plus byte-exact ROM reads (`VERSA f501.bin`, MD5 `46991697c502052752a2cabcb84c9e27`). No donor transfer, live test, or XML/A2L/workbook change.
