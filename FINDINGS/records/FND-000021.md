# FND-000021 — `0x0FEE0` is a 64-entry UWORD lookup, not a 32-entry curve

**Status:** CURRENT  
**Semantic layer:** structural geometry (extent, element width and helper access); query-domain and physical identity unresolved  
**Evidence grade:** target helper/caller instruction trace recorded in pinned-ROM work order; corroborated by current scanner source's clamp-derived point-count logic  
**Confidence:** HIGH for the 64-entry minimum extent and UWORD access; MEDIUM for the complete 64×1 fixed-grid interpretation; UNRESOLVED for exact displayed query breakpoints, complete payload and physical function

## Scope

Correct the geometry of the EL19A ROM object at `0x0FEE0`. The prior 32-point description misread the helper's immediate `0x7E` as decimal 62 rather than hexadecimal 126. The helper's saturated branch therefore reads element 63, not element 31.

This finding reuses the target-side instruction bytes and caller reconstruction recorded in `CONTROL/WO65132.md` §§3–4, with the current scanner source's Pattern A clamp-count logic as an implementation-level cross-check. No fresh ROM rehash or scanner rerun was performed for this finding.

## Object and reader facts

| Field | Current conclusion |
|---|---|
| ROM base | `0x0FEE0` |
| Element type | UWORD, big-endian |
| Lookup form | 2D implicit/fixed-grid helper; 1×64 curve representation |
| Minimum element count | 64 UWORD entries (index 0–63) |
| Required byte extent | `0x0FEE0–0x0FF5F` inclusive (128 bytes) |
| Terminal element | UWORD at `0x0FF5E–0x0FF5F` |
| Caller | `0x369EA` invokes `sub_22E98` with R4 = `0x0FEE0` |
| Query source | UWORD[`FFFF184C`], zero-extended and multiplied by 16 before the helper |
| Helper threshold | UWORD `0x3F00` at `0x22EAC` |
| Physical meaning / conversion | Not established |

## Discriminating instruction evidence

The target helper sequence recorded in WO65132 is:

| PC | Bytes | Instruction | Consequence |
|---|---|---|---|
| `0x22E98` | `90 08` | `mov.w word_22EAC,r0` | loads threshold `0x3F00` |
| `0x22E9A` | `65 5D` | `extu.w r5,r5` | zero-extends query |
| `0x22E9C` | `35 02` | `cmp/hs r0,r5` | selects saturated path at/above threshold |
| `0x22E9E` | `89 02` | `bt loc_22EA6` | takes saturated path |
| `0x22EA6` | `74 7E` | `add #0x7E,r4` | advances R4 by hexadecimal `0x7E` = 126 bytes |
| `0x22EA8` | `00 0B` | `rts` | return |
| `0x22EAA` | `60 41` | `mov.w @r4,r0` | delay-slot UWORD read at the adjusted address |

At the call site, `0x369DE` loads R4 = `0x0FEE0`; `0x369E0` reads UWORD[`FFFF184C`]; `0x369E2` zero-extends it; `0x369E6` and `0x369E8` each execute `shll2 r5`, producing the ×16 query transform; and `0x369EA` calls `sub_22E98`.

The arithmetic is decisive:

- `0x7E` hexadecimal = 126 decimal bytes.
- 126 bytes / 2 bytes per UWORD = 63 byte-offset elements.
- Adding the zero-based index gives 64 entries.
- `0x0FEE0 + 0x7E = 0x0FF5E`; the UWORD read consumes bytes through `0x0FF5F`.

The committed `tools/sh7058_cross_rom_scanner.py` encodes the same count rule in Pattern A: for the `add #imm,r4; rts; mov.w/mov.b @r4,r0` return pattern, it derives point count as `clamp_bytes // element_width + 1`. A UWORD clamp of `0x7E` therefore gives 64. This is source-code corroboration, not a fresh scanner execution.

## Corrections and unresolved details

1. The 32 UWORD values listed in WO65132 §3.1 cover only `0x0FEE0–0x0FF1F`, the first 64 bytes. They are a partial payload, not the complete lookup.
2. The full second half `0x0FF20–0x0FF5F`, the claimed zero padding beginning at `0x0FF60`, and all 64 values have not been independently read or hashed in this work.
3. The threshold and saturated terminal read prove the 64-entry minimum extent. The exact interpolation grid inside `sub_234FC` was not transcribed in WO65132. The newer scanner documentation reports eight shift/rotate pairs and a 256-count helper-domain grid, but no raw scanner output or fresh helper-body trace was available here. Exact displayed breakpoints remain pending verification.
4. The existing `fixed_0_2048_63488` catalogue axis is not validated by the instruction evidence reviewed here. Do not present it as established.
5. The existing V6 donor candidate `mTATVO` is declared as a 32-point UWORD curve in WO65140/WO65133. Its former “dimensions exact” rationale is invalid against a target lookup requiring 64 points. No physical `mTATVO` identity or conversion is supported; the score must be reconsidered without the dimension-match contribution.
6. No target output conversion, unit or physical function is established.
