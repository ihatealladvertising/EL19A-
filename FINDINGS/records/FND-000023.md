# FND-000023 — `FFFFB644`/`FFFF11F0` have one reader each and terminate in an internal state byte

**Status:** CURRENT
**Semantic layer:** output identity (the status network's only 16-bit value publication does not leave the firmware)
**Evidence grade:** Reader-Verified (exhaustive access census with per-routine base resolution, both consumer bodies read)
**Confidence:** HIGH for the census and both consumer chains; MEDIUM for the physical meaning of the compared quantity; UNRESOLVED for what `UBYTE[FFFF1104] = 3` selects

## Scope

Bounded conclusion for the two cells written by `loc_47B54` at `0x047BF8`/`0x047BFA`–`0x047C08`, reached under WO70005: `UWORD[FFFFB644]` and `U16[FFFF11F0]` (`FFFF1054+0x19C`/`0x19D`). It closes the endpoint WO66048 deliberately stopped at. No calibration object is characterised.

## Observations

1. **`UWORD[FFFFB644]` has three listing hits and one reader.** Write: `0x047BF4` `mov.w word_47C8E,r6` → `0x047BF8` `mov.w r0,@r6`. Read: `0x047C1E` `mov.w word_47C8E,r6` → `mov.w @r6,r2` → `extu.w r2,r6` → `jsr @r3 (sub_491BC)` at `0x047C2C`. Third hit is the RAM definition. No pool literal, `gbr`-relative or displacement access reaches the cell elsewhere.
2. **`FFFF11F0` is written once and read once.** Write `0x047BFA`–`0x047C08`: `mov #0x67,r0` + `shll2` → `0x19C`, `mov.b r2,@(r0,r5)`; then `word_47C90 = 0x19D`, `mov.b r2,@(r0,r5)`, with `r5 = 0xFFFF1054`. Read `0x059DB6`/`0x059DBC` in `sub_599AE`: same `0x67<<2` idiom and `word_59DD8 = 0x19D`, with `r14 = 0xFFFF1054` from `off_59ECC` (`0x059D18`, `0x059D38`, `0x059D66`).
3. **Byte order.** `mov.w r0,@r6` is big-endian, so `mov.b @r6` (`0x047BFC`) copies the **high** byte to `FFFF11F0` and `mov.b @(1,r6)` (`0x047C02`) the **low** byte to `FFFF11F1`; `U16[FFFF11F0]` therefore equals `UWORD[FFFFB644]`.
4. **Every other `0x19C`/`0x19D` access resolves elsewhere** under `FND-000012`: `0x034276`/`0x034286`/`0x0342F6` with `gbr = 0xFFFF8534` → `FFFF86D0`; `0x0628EE` in `sub_5FA70` with `gbr = 0xFFFF8E54` → `FFFF8FF0`; `0x0BD390`/`0x0BD42E` with `gbr = 0xFFFF2D0C` → `FFFF2EA8`; `0x0B0F50`, `0x0B1738`, `0x0B17B6`, `0x0B1800`, `0x0B18D8` with `r12 = 0xFFFF2F00` → `FFFF309D`; `0x08EFAC` `r13`-relative; `0x022E5C`, `0x06AABC`, `0x0B6ABC` = `dword_BE64+0x19C` = `0xC19C`.
5. **The reader sums the two bytes and clamps against a ROM byte.** `sub_599AE` `0x059DB6`–`0x059DEE`: `r2 = exts.w(extu.b(U8[FFFF11F0]))`, `r7 = exts.w(extu.b(U8[FFFF11F1]))`, `r4 = extu.b(U8[0x869A+0x0F]) = U8[0x86A9] = 0x32` (50), `r2 = r2 + r5`, and `r6 = max(0, hi + lo - 50)` stored as `UWORD[FFFF20E0+0x06]` (`mov.w r0,@(6,r5)` at `0x059DEE`). The high and low bytes are **added**, not reassembled into the word.
6. **Second hop, same routine.** `0x059E10`–`0x059E1E`: `r0 = UWORD[FFFF20E0+0x06]`, `tst r0,r0`, `bf` to `loc_59E20`; when the value is **zero**, `mov #3,r2` is stored through `r0 = 0xB0`, `r14 = 0xFFFF1054` → **`UBYTE[FFFF1104] = 3`**.
7. **No named output.** Neither consumer contains a `sub_33E18`/`sub_32790` append, an MMIO store, a lamp drive or a message-buffer copy. `sub_491BC` stashes its `r6` argument to its own stack (`0x0491D0` `mov.w r0,@(0x28+var_26,r15)`, `0x0491E0` `mov.l r6,@r15`).

## Conclusion

Both publications of the coolant-threshold chain terminate internally. `UWORD[FFFFB644]` is consumed once as a scalar argument; `U16[FFFF11F0]` is consumed once as a summed quantity tested against ROM byte `0x86A9`, producing `UWORD[FFFF20E0+0x06]` and then the internal state byte `UBYTE[FFFF1104]`.

The status network's only 16-bit value publication is therefore **not** a route to an external reader. With `FND-000020` (the `0x08AF6E` block is private read-modify-write scratch), both located endpoints of the `FFFF34xx`/`FFFF35xx` status network resolve to internal state.

**Identity layer advanced:** output identity, partially — the value is a threshold-comparison input that sets an internal state byte, not a published measurement or command.

## Uncovered ROM data reference (not a promoted object)

`U8[0x86A9] = 0x32` (50) is used as the arithmetic limit. It sits in the byte run `0x869A`: `19 19 00 0A 01 0A 19 14 01 05 07 0F 0F 00 00 32 32 0A`. This region has no matrix row, no catalogue entry and no XML object. Its extent and boundaries are **not** established here, and neighbouring bytes are used by other code (`0x8635` is `sub_8AD7C`'s header byte), so it must not be treated as a single table on this evidence.

## What is not claimed

- **Not** the physical meaning of `hi + lo`, of the sum-versus-50 comparison, of `UWORD[FFFF20E0+0x06]`, or of `UBYTE[FFFF1104] = 3`.
- **Not** that `FFFF20E0` is characterised: only offset `+0x06` is at issue here; other code writes `+0x18` and `+0x1C` of the same base.
- **Not** any reading of `sub_491BC`'s use of its `r6` argument beyond the stack stash.
- **Not** an extent for the `0x869A` byte run.

## No-repeat boundary

Do not re-open the question of whether this value publication reaches an external reader — it does not.
