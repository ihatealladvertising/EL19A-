# REC-000024 — `0x0FEE0` clamp is 126 bytes, requiring 64 UWORD entries

**Status:** CURRENT (additive correction; historical WO and Release 1 artifacts retained unedited)  
**Affected object:** EL19A ROM `0x0FEE0`, current Release 1 row 195  
**Supporting finding:** `FND-000021`  
**Source reports:** WO65132 §§3–4, WO65140 and WO65133  
**Confidence:** HIGH for the terminal UWORD address and required 64-entry extent; exact interpolation grid and complete payload remain unresolved

## Old interpretation

WO65132 called `0x0FEE0` a 32×1 UWORD BE curve spanning `0x0FEE0–0x0FF1F` (64 bytes). It described the helper's `add #0x7E,r4` as “last element offset (62 bytes)” and consequently called the terminal read the “last 32nd entry.” WO65140 reused that 32-point target geometry; WO65133 awarded the V6 `mTATVO` donor row a “dims exact” rationale for another 32-point UWORD curve.

Release 1 XML row 195 remains `sizey="32"`; scope matrix row 195 lists a 64-byte extent; the catalogue lists 32×1 and `fixed_0_2048_63488`.

## Corrected interpretation

`0x7E` is a hexadecimal instruction immediate, equal to 126 decimal. The helper executes `add #0x7E,r4` at `0x22EA6`, then executes `mov.w @r4,r0` in the RTS delay slot at `0x22EAA`. With R4 = `0x0FEE0`, the terminal word is read at `0x0FF5E–0x0FF5F`, which is element index 63. The helper therefore requires 64 UWORD BE entries and a 128-byte extent, `0x0FEE0–0x0FF5F`.

The caller at `0x369EA` supplies base `0x0FEE0` and a UWORD query from `FFFF184C` transformed by ×16. The helper compares it with `0x3F00` and returns the terminal word on the saturated path. The earlier report's decimal reading of the immediate truncated the object by half.

## Consequences

1. The XML's 32-cell object cannot represent the helper's terminal element; a future corrected raw/provisional representation needs 64 cells.
2. The scope matrix and catalogue extents must eventually cover 128 bytes. Neither was edited under WO70006's change restrictions.
3. The first 32 values transcribed by WO65132 are only the first half of the lookup. The second half and claimed `0x0FF60` padding boundary have not been independently verified here.
4. The fixed-axis label `fixed_0_2048_63488` is not established by the reviewed target instructions. The scanner documentation reports a 256-count helper grid, but without complete raw run output and a direct re-trace of `sub_234FC`, exact displayed breakpoints remain open.
5. The 32-point V6 `mTATVO` donor no longer has a target-side dimension match. WO65133's “dims exact” score reason is superseded; the total score should be recomputed separately. No donor physical name or unit is promoted.
6. Historical reports and XML remain unedited. Any XML, matrix or catalogue edit requires separate owner/integrator authorization.

## Evidence boundary

The correction uses the instruction bytes, caller sequence and pinned input identity recorded in WO65132, plus the clamp-derived count formula visible in current scanner source. This session did not re-read the binary, verify all 64 ROM words or execute the scanner. Therefore the 64-entry minimum extent is corrected, while full payload and exact interpolation grid remain open.
