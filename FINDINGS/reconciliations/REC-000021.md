# REC-000021 — Linked shared storage between 0x0CD56 and 0x0FEC0

**Status:** CURRENT  
**Affected objects:** UWORD BE 16×16 surface at `0x0CD56`; UWORD BE 16-point curve at `0x0FEC0`; their reciprocal axis/data relationship.  
**Source evidence:** WO65060, WO65110, WO65133, WO65293; FND-000017; REC-000019.

## Prior presentation / risk

The Release 1 successor correctly represented both reader-backed objects and their ROM pointers, but presented them as ordinary independent tables. That hid a consequential shared-storage relationship from the RomRaider user. This is not an erroneous duplicate address and is not a reason to remove either object; both are read by target lookup paths.

## Corrected interpretation

1. `0x0CD56` is a 16×16 UWORD BE surface. Its X axis is the 16-byte UBYTE vector at `0x0E2C9`; its Y axis is the 16-word UWORD BE vector at `0x0FEC0` (FND-000017; WO65293; WO65060).
2. `0x0FEC0` is independently reader-backed as a 16×1 UWORD BE curve through `sub_22F80` at `0x69166`. Its 16-point query axis is row 0 of the `0x0CD56` surface (WO65110; WO65133; WO65060).
3. The relationship is reciprocal: values at `0x0FEC0` are the surface's Y breakpoints, while row 0 at `0x0CD56` is the curve's query axis. WO65293 additionally records a self-re-entry path in which the `0x0CD56`-derived `FFFF1D72` value is used in the related lookup chain.

## Disposition

- Preserve both objects in the definition. Do not delete `0x0FEC0` as a duplicate or flatten the `0x0CD56` surface.
- Mark both RomRaider labels as `[P] [LINKED]` and add XML comments describing the shared-storage relationship.
- Treat the pair as coupled for editing: changing `0x0FEC0` changes the Y breakpoints of `0x0CD56`; changing row 0 of `0x0CD56` changes the query axis of the `0x0FEC0` curve.
- No read-only/locked property is asserted. The user should inspect both objects together before changing either.
- Functional identity, physical query units and data conversions remain provisional; the linked-storage relationship itself is high-confidence.

## Confidence

**High:** addresses, storage widths, dimensions, reader/helper identities and cross-use of the arrays.  
**Unresolved:** physical units, operating domain and whether any particular edit strategy is preferable for the coupled pair.

## Source anchors

- **WO65060:** `0x0FEC0` varying 16×1 UWORD BE via `sub_22F80`.
- **WO65110:** `0x0FEC0` call at `0x69166`, query `FFFF1D72`.
- **WO65133:** `0x0FEC0` 16×1 UWORD BE, Y axis `0x0CD56`, `sub_22F80 @ 0x69166`.
- **WO65293:** `0x0CD56` 16×16 UWORD BE, axes `0x0E2C9`/`0x0FEC0`; row-wise/self-re-entry behavior around `0x69150–0x69186`.
