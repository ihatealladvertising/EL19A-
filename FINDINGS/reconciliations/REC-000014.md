# REC-000014 — 0x848A/0x848B object-type correction: RAM cell vs ROM constant

**Status:** CURRENT  
**Affected addresses/objects:** `0x848A`, `0x848B`, `FFFF848A`, `0x0000848B`, `FFFF12EA` (donor context only).

## Old interpretation

`FND-000004`/`REC-000004` treat `0x848A`/`0x848B` as paired UBYTE scalars with a user-verified donor `mDDSHPTD`/`mDDSHPTN` mapping, both read as QDSPT rate parameters in `sub_403D8`, with the E678 branch selecting `0x848A` and the E688 branch selecting `0x848B`, stored at `FFFF1054+0x296 = FFFF12EA`. The donor D/N (Drive/Neutral) distinction is retained as a working assignment.

## Corrected/current interpretation

`CONTROL/WO65847.md` resolves each object independently:

- **`0x848A` = RAM cell `FFFF848A`**: read as `mov.w word_XXXX, rX ; h'FFFF848A` in at least 4 routines (`0x020E16`, `0x03615A`, `0x036184`, `0x036AB4`, `0x036B06`), raw value `0x43`, used in QDSPT-related calculations.
- **`0x848B` = ROM constant `0x0000848B`**: read via `mov.l off_40614, r6 ; h'848B` at `0x0404D4`, then `mov.b @r6, r2` at `0x0404DE` reads ROM byte `0x0000848B` (raw value `0x43`, a coincidence with `0x848A`'s RAM value).
- **`FFFF848B`** (the RAM cell mirror) exists as `.res.b 1` but is **never referenced** in code.

The two objects are **not the same kind**: one is a RAM cell read repeatedly in QDSPT routines, the other is a ROM constant read once in a different code path. The donor D/N distinction is unsupported because the two "candidates" are different object types accessed through different mechanisms, and they are not consumed by the same calculation or by different paths in the same routine.

## Reason and discriminating evidence

- `CONTROL/WO65847.md` §Trace result: per-site access patterns show `0x848A` read 5+ times as GBR-relative/register-indirect RAM; `0x848B` read once as ROM literal-pool dereference.
- `CONTROL/WO65847.md` §Verdict: D/N UNSUPPORTED — 0x848A and 0x848B are different object types (RAM vs ROM).
- `CONTROL/WO65817.md` §Candidate classification 2 (superseded in part): paired rate scalars in QDSPT calculation, donor name not supported; now refined to object-type distinction.

## Confidence

Target read mechanics HIGH; object-type distinction HIGH; D/N functional interpretation UNRESOLVED/unsupported; consumer units LOW.
