# REC-000015 — 0x8550/mDSHCUT: FFFF1DB4.bit5 attribution contradicted

**Status:** CURRENT  
**Affected addresses/objects:** `0x8550`, `FFFF1DB4`, `FFFF1018`, `FFFF84BA`.

## Old interpretation

`CONTROL/WO65817.md` §Candidate classification 1 attributes `0x8550` (ROM byte `0x0A`, read by `sub_403D8 @ 0x4043A`) as a dashpot cut/enable threshold with hysteresis: `r5 = (FFFF1DB4.bit5 ? UBYTE[FFFF84BA] : UBYTE[FFFF84BA] + 3)`, compare `cmp/hs r2,r5`, result stored to `FFFF1DB4 @ 0x4044A`, with `FFFF1DB4.bit5` gating the dashpot target path into `UWORD[FFFF1018]` @ `0x40548–0x4054E`. `FFFF1DB4.bit5` is classified as an internal state flag consistent with dashpot cut/enable but not proven.

## Corrected/current interpretation

`CONTROL/WO65865.md` performs whole-image per-site GBR resolution and concludes `FFFF1DB4` has **no reader and no writer** in this image. The address appears only as its `.res.b 1` declaration; no pool literal encodes `FF FF 1D B4`, and no `@(h'34,gbr)` site executes with GBR = `FFFF1D80`. Therefore `FFFF1DB4.bit5` cannot be written by `sub_403D8 @ 0x4044A` nor gate any dashpot target path. WO65817's GBR assumption (shared with its earlier WO65841 error) was incorrect: a fixed line window crossed an `rts`, and no per-site base was verified.

The `0x8550` facts that survive: ROM byte `0x0A` at `0x8550`, zero-extended into R5 by `sub_403D8 @ 0x4043A`, used in a hysteresis-adjusted threshold compare against `UBYTE[FFFF84BA]` (with `+3` offset when the now-invalid bit5 condition is false), result stored to an internal UWORD destination that is **not** `FFFF1DB4`. `UWORD[FFFF1018]` is reached at `0x40548–0x4054E` but the bit-5 gating path through `FFFF1DB4` is invalidated.

## Reason and discriminating evidence

- `CONTROL/WO65865.md` §Verdict: `FFFF1DB4` NO READER / NO WRITER; bit-level question moot; no calibration interpretation attaches.
- `CONTROL/WO65865.md` §Reconciliation of WO65841: same GBR-assumption error pattern (six `@(h'34,gbr)` sites assumed `FFFF1D80` base; actually resolve to six different cells); WO65817 inherits the same error pattern for `FFFF1DB4`.
- `CONTROL/WO65817.md` §Candidate classification 1 (superseded on the `FFFF1DB4` attribution only): `0x8550` ROM byte, reader, hysteresis compare, and `FFFF1018` consumer remain as reported; only the `FFFF1DB4.bit5` write/gate attribution is withdrawn.

## Confidence

`0x8550` ROM read and threshold compare: MEDIUM (reader verified, arithmetic traced). `FFFF1DB4.bit5` dashpot gate: REJECTED (no reader/writer exists). `FFFF1018` internal UWORD consumer: LOW (no named actuator endpoint). Physical identity of `0x8550` as mDSHCUT: UNRESOLVED; donor name not promoted.
