# Structural Function & A2L RAM/Table Matcher (`tools/a2l_structural_matcher.py`)

Pure Python 3 (standard library only) structural matcher linking **EL19A** (`EVIDENCE/VERSA f501.bin`) caller subroutines to the two compiled **ROM + A2L** pairs in `EVIDENCE/`:

- **V6 (`SH705822N`):** `EVIDENCE/side project/64810223F121200000.hex` + `EVIDENCE/side project/64811000p2_m.a2l`
  - `36` auto-discovered lookup helpers, `306` unique tables (**298 / 306** exact A2L `CHARACTERISTIC`/`AXIS_PTS` hits), **`12,917`** addressed `MEASUREMENT` RAM symbols.
- **Juke MR16DDT (`SH705828N`):** `EVIDENCE/Nissan Juke 1.6-dig-T S19 (9APCTDEM06)/9APCTDEM06.s19` + `RFCC_2XHK19BDF1.a2l`
  - `37` auto-discovered lookup helpers, `585` unique tables (**575 / 585** exact A2L `CHARACTERISTIC`/`AXIS_PTS` hits), **`9,100`** addressed `MEASUREMENT` RAM symbols.

> **Evidence Policy:** Every match produced by this script is a **high-precision structural hypothesis / lead only** (not target-side semantic proof on EL19A). A2L names, units, and scalings must not be promoted into EL19A definitions without target-side reader/query/consumer verification.

## Usage

Run from repository root:

```bash
python3 tools/a2l_structural_matcher.py

```

## How It Works

1. Parses both `.hex`/`.s19` flat images and Shift-JIS A2L files (`CHARACTERISTIC`, `AXIS_PTS`, `MEASUREMENT`).
2. Runs `discover_helpers` + `extract_calls` (from `tools/sh7058_cross_rom_scanner.py`) on `EL19A`, `V6_HEX`, and `Juke_S19`.
3. Segments caller functions at `sts.l pr,@-r15` (`0x4F22`) prologues (`217` caller functions in EL19A, `223` in V6, `403` in Juke) and extracts per-function structural fingerprints:
* ordered lookup-helper signature sequence `(kind, dim1, dim2, elem_type)`
* non-trivial table/axis payloads (`>2` distinct bytes)
* ROM scalar pool constants (`< 0x20000`), immediate constants, function length, and referenced `0xFFFFxxxx` RAM cells (mapped to A2L `MEASUREMENT` names in V6/Juke).


4. Scores EL19A functions against V6 and Juke functions matching the same helper-signature bag, highlighting:
* **Dual V6 + Juke Consensus Functions** (`45` functions where *both* `SH705822N` V6 and `SH705828N` Juke independently land on the same A2L symbol root), and
* **Single-Source / Rare Structural Leads** (`25` additional functions containing tables absent from Release 1 XML).

def load_s19(path: Path) -> bytes:
buf = bytearray([0xFF] * 0x100000)
for line in path.read_text(errors="ignore").splitlines():
if len(line) >= 4 and line[0] == "S" and line[1] in ("1", "2", "3"):
alen = {"1": 4, "2": 6, "3": 8}[line[1]]
cnt = int(line[2:4], 16)
addr = int(line[4 : 4 + alen], 16)
data = bytes.fromhex(line[4 + alen : 2 + cnt * 2])
if addr + len(data) <= len(buf):
buf[addr : addr + len(data)] = data
return bytes(buf)

def load_hex(path: Path) -> bytes:
buf = bytearray([0xFF] * 0x100000)
upper = 0
for line in path.read_text(errors="ignore").splitlines():
if not line.startswith(":"):
continue
cnt = int(line[1:3], 16)
addr = int(line[3:7], 16)
rt = int(line[7:9], 16)
data = bytes.fromhex(line[9 : 9 + 2 * cnt])
if rt == 0 and upper + addr + len(data) <= len(buf):
buf[upper + addr : upper + addr + len(data)] = data
elif rt == 4:
upper = int.from_bytes(data, "big") << 16
elif rt == 2:
upper = int.from_bytes(data, "big") << 4
return bytes(buf)

def parse_a2l(path: Path) -> Tuple[Dict[int, Tuple[str, str, str]], Dict[int, Tuple[str, str]]]:
txt = path.read_bytes().decode("cp932", errors="replace")
syms: Dict[int, Tuple[str, str, str]] = {}
for kind in ("CHARACTERISTIC", "AXIS_PTS"):
for blk in txt.split(f"/begin {kind} ")[1:]:
end = blk.find(f"/end {kind}")
body = (blk[:end] if end != -1 else blk).lstrip()
hm = re.match(r"(\S+)\s+"([^"]*)"", body)
am = re.search(r"\b0x([0-9A-Fa-f]+)\b", body)
if hm and am:
syms[int(am.group(1), 16)] = (hm.group(1), hm.group(2), kind)
meas: Dict[int, Tuple[str, str]] = {}
for blk in txt.split("/begin MEASUREMENT ")[1:]:
end = blk.find("/end MEASUREMENT")
body = (blk[:end] if end != -1 else blk).lstrip()
hm = re.match(r"(\S+)\s+"([^"]*)"", body)
am = re.search(r"ECU_ADDRESS\s+0x([0-9A-Fa-f]+)", body)
if hm and am:
meas[int(am.group(1), 16)] = (hm.group(1), hm.group(2))
return syms, meas

def norm_sym(name: str) -> str:
"""Normalize minor variant suffixes (e.g. mTQH0ST_S vs mTTQH0ST) for consensus comparison."""
s = re.sub(r"(_S|_2|#\d+)$", "", name or "")
if s.startswith("mTT"):
s = "mT" + s[3:]
return s

def score_pair(el_pr: dict, cand: dict) -> Tuple[int, dict]:
    exact_order = el_pr["sig"] == cand["sig"]
    n_pay = 0
    for eb, cb in zip(el_pr["payloads"], cand["payloads"]):
        if eb is not None and eb == cb:
            n_pay += 1
    if not n_pay:
        el_set = {b for b in el_pr["payloads"] if b is not None}
        c_set = {b for b in cand["payloads"] if b is not None}
        n_pay = len(el_set & c_set)
    cal_ov = len(el_pr["cal_vals"] & cand["cal_vals"])
    imm_ov = len(el_pr["imms"] & cand["imms"])
    len_diff = abs(el_pr["len"] - cand["len"])
    score = (20 * n_pay) + (5 if exact_order else 0) + (3 * cal_ov) + imm_ov - (len_diff // 128)
    return score, {"n_pay": n_pay, "exact_order": exact_order, "cal_ov": cal_ov, "imm_ov": imm_ov, "len_diff": len_diff}

### Theoretical Gaps in the Current A2L Integration

Right now, `parse_a2l_rich` in `nissan_sh705x_workbench.py` and `parse_a2l` in `a2l_structural_matcher.py` extract basic entries from `CHARACTERISTIC`, `AXIS_PTS`, `MEASUREMENT`, and `COMPU_METHOD` blocks using lightweight string splits and regular expressions. Incorporating the full A2L symbol tables addresses four structural limitations:

* **Missing Map-to-Axis & Layout Graph:** `CHARACTERISTIC` blocks often reference `AXIS_DESCR` (`AXIS_PTS_REF`, `CURVE_AXIS_REF`, input quantity `MEASUREMENT`, breakpoints, and conversion) and `RECORD_LAYOUT` definitions rather than embedding every detail in one flat line. * **Incomplete Conversion & Math Semantics:** Parsing full `COMPU_METHOD`, `COMPU_TAB`, `COMPU_VTAB`, and formula/rational coefficients gives richer context for candidate evaluation (e.g., whether a donor symbol is a raw counter, bitfield/state enum, temperature, or ratio), while keeping units/formulas tagged strictly as *donor metadata* rather than target-ROM truth.


* **Unused Subsystem & Strategy Grouping:** Full A2L parsing of `FUNCTION` and `GROUP` blocks (plus `SUB_FUNCTION` / `DEF_CHARACTERISTIC` / `IN_MEASUREMENT` / `OUT_MEASUREMENT`) clusters related symbols into functional neighborhoods. That helps score multi-table subroutines (such as dual V6/Juke consensus functions) as coherent subsystem leads rather than isolated name hits.


* **Full-Symbol Coverage & Provenance:** Parsing all symbols in both A2L files—not only those directly hitting a scanned ROM address—lets you inspect unmapped or relocated symbols, attach A2L file hashes/versions to run manifests, and explicitly mark unresolved links instead of dropping them silently.

### 1. Key A2L Sections to Parse

To move beyond flat symbol/address lookups in `64811000p2_m.a2l` (`SH705822N` V6) and `RFCC_2XHK19BDF1.a2l` (`SH705828N` Juke), the parser should walk `/begin <KEYWORD> ... /end <KEYWORD>` blocks cleanly while retaining raw/unresolved attributes when syntax varies:

* **`CHARACTERISTIC` & `AXIS_PTS`:** Symbol name, long identifier/description, characteristic type (`CURVE`, `MAP`, `VALUE`, `ASCII`, `VAL_BLK`, etc.), ROM address (`ECU_ADDRESS`), `RECORD_LAYOUT` reference, `CONVERSION` (`COMPU_METHOD`) reference, and nested `AXIS_DESCR` blocks (axis attribute/type, input `MEASUREMENT` quantity, `AXIS_PTS_REF`, `CURVE_AXIS_REF`, `FIX_AXIS_PAR` / `FIX_AXIS_PAR_DIST`, breakpoint count, and conversion).
* **`MEASUREMENT`:** Symbol name, description, data type (`UBYTE`, `SBYTE`, `UWORD`, `SWORD`, `ULONG`, `SLONG`, `FLOAT32_IEEE`, etc.), conversion reference, `ECU_ADDRESS` (typically `0xFFFFxxxx` RAM cells or ROM/constant addresses), `BIT_MASK` / `READ_WRITE` / `ECU_ADDRESS_EXTENSION` if present, and limits/resolution metadata.
* **`COMPU_METHOD`, `COMPU_TAB`, & `COMPU_VTAB`:** Conversion type (`IDENTICAL`, `LINEAR`, `RAT_FUNC`, `TAB_INTP`, `TAB_NOINTP`, `TAB_VERB`, `FORM`), physical unit string, `COEFFS` / `COEFFS_LINEAR` / `FORMULA` / `FORMAT` strings, and discrete table/enum mappings so you can distinguish raw counts, scaled physical quantities, and state/bitfield enums.
* **`RECORD_LAYOUT`:** Element layout and axis/data ordering rules (`FNC_VALUES`, `AXIS_PTS_X`, `AXIS_PTS_Y`, `NO_AXIS_PTS_X`, `NO_AXIS_PTS_Y`, index ordering, and byte/word widths) so table extents and dimensions have an explicit donor layout reference alongside target-ROM reader geometry.
* **`FUNCTION` & `GROUP`:** Strategy/subsystem blocks (`SUB_FUNCTION`, `DEF_CHARACTERISTIC`, `REF_CHARACTERISTIC`, `IN_MEASUREMENT`, `OUT_MEASUREMENT`, `SUB_GROUP`, `ROOT`) to group co-occurring maps and RAM signals into functional neighborhoods during candidate ranking.
