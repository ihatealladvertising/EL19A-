Per-call static-flow adapter:
  - tools/reader_trace_static_flow_adapter.py serializes raw build_static_indices.full_rom_analysis().cat_calls into deterministic JSON, preserving each table EA, reader PC, function/helper, query-origin tokens and destination stores.
  - Export pins the decoded ROM SHA-256, exact Stage-16 listing-member SHA-256 and listing path. The emitted JSON is itself SHA-256-pinned by the graph evidence record.
  - Graph enrichment selects only the exact target EA + call PC + helper EA. A table with multiple readers does not cause query/result data to be spread across calls.
  - Query RAM origins and taint-proven R0 stores are represented as derived edges. Near-call stores remain heuristic and create unresolved boundaries; they are not linked as lookup-result value flow.
  - Pipeline suppresses per-address aggregate query/result fields when exact per-call input is supplied. Calls without per-call input remain backward-compatible.
  - Listing identity can populate graph coverage, but independent_redecode_performed remains false. No opcode decode or semantic promotion is claimed.

Existing composed pipeline:
  tools/reader_trace_pipeline.py combines byte-concordant ROM read rows, conservative per-address summary evidence, optional exact per-call static flow, exact-image helper profile attachment and graph validation.
  Unknown helper EAs remain unprofiled. Aggregate downstream RAM reads remain read-site observations only; they do not prove value causality.

Geometry:
  - 1D UBYTE implicit-uniform lookup; q >= 0xF0 terminal path retained with the 224/240 wording conflict unresolved.
  - 32-point explicit UWORD axis/value curve, query construction, helper chain, result staging and conditional post-call normalization.
  - 4x4 UBYTE map with distinct, strictly increasing 4-point axis vectors and one unsigned UBYTE query used for both axis searches.
  - 0x0AFF2 path distinguishes R0-to-R2 delay-slot transfer, first multiplication consumer, UWORD product sink FFFF115A and separate inline element staging FFFF14E4.
  - All graph edges retain evidence basis explicitly; report-derived edges are not represented as fresh instruction observations.

Evidence and production boundary:
  The 0x0F10E and 0x10F8A cases remain extracted from prior closed reports, not independent instruction re-decodes. The 0x0AFF2 graph cites the exact Stage-16 listing SHA recorded by WO70033, but its graph remains structured report extraction.
  The new per-call adapter was tested against synthetic full_rom_analysis-shaped records; no production per-call static-flow document was generated or attached to a target graph in this implementation stage.
  The new source-listing identity contract carries the pinned listing hash but does not itself decode instructions. Physical meanings, donor semantics, query-transform details and downstream value causality remain unpromoted.

Limit:
  The implementation now has a graph contract, byte-concordant indexer adapter, exact per-call static-flow adapter/exporter, exact-image helper-profile attachment and composed pipeline. It is not yet a generalized instruction-level semantic reader tracer, whole-ROM CFG/interprocedural engine, or proof of physical calibration meaning.
