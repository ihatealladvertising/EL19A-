## Required extraction

For each included screenshot, record only what is legible and visibly supported:

1. Filename and image SHA (from repository inventory), plus a stable screenshot/item identifier.
2. RomRaider table/window title and visible table name.
3. Any displayed ROM address, definition name, category/tree path, parent/child relationship or selected node.
4. Table dimensionality and displayed row/column counts.
5. X/Y axis labels, units, visible axis values and orientation as displayed; distinguish axis labels from table values.
6. Scalar values, displayed units, precision and surrounding label/context.
7. Any visible scaling/conversion, if explicitly displayed.
8. Confidence per extracted field: clear, partial/ambiguous, or unreadable. Preserve literal spelling and formatting; do not silently normalize.

Separate direct visual observations from interpretations. If the same table appears in multiple screenshots, retain separate source observations and then link them as a likely duplicate only when title/address/content support it.

## Catalogue cross-reference

For each visible table/address candidate:

- Match against `CALIBRATIONS/discovered_tables_catalog.csv` by exact address first, then by title/name only as a secondary candidate.
- Record catalogue address, extent, dimensions, storage type, reader/helper and axis addresses only when an exact row exists.
- Classify as exact address match, name-only candidate, shape/value-pattern candidate, or no match.
- Do not force a match based only on similar table shape, values, or donor terminology.
- Preserve screenshot address vs ROM address vs XML address as separate fields where they differ.

For visible scalar items, search only the existing scalar/candidate inventory and relevant reports for exact address/name/value evidence. If no address is visible, leave address unresolved; do not guess one.
