## Objective

For ignition and fueling tables visible in the non-Rev-Hang screenshot set, determine whether the displayed RomRaider axes are correctly identified as **RPM on Y and load on X**, or whether that convention is contradicted by the actual EL19A reader/query construction. Resolve axis orientation, raw query units and displayed scaling only for screenshot-linked candidates.

The requested RPM/Y and load/X convention is a working hypothesis to test, not a rule to impose on every map.

## Evidence to reuse — do not re-derive

- WO65261's source-addressable screenshot extraction and exact catalogue joins.
- WO65109's ignition/knock fragment reader audit and any exact axis/query findings it established.
- `CALIBRATIONS/discovered_tables_catalog.csv` and the existing reader-pattern/helper indexes.
- Existing per-table reader reports for any exact matched ignition/fueling candidates. Cite their PCs and report anchors; do not repeat their helper census.

## Mandatory falsifiable hypothesis record

- **Identity layer advanced:** input identity and function identity; axis/unit interpretation.
- **Hypothesis:** for the screenshot-linked ignition and fueling maps in scope, the displayed Y axis represents engine RPM and the displayed X axis represents engine load, with any raw-to-display conversion explainable from target-side query construction.
- **Evidence:** exact screenshot/item IDs and literal displayed axes from WO65261; exact ROM table addresses, dimensions, axis storage and reader callsites from the catalogue; WO65109's ignition findings. Keep screenshot, target-ROM and donor/XML evidence in separate source classes.
- **Prediction:** the reader's query arguments and axis-search order resolve to RPM on Y and load on X, and the transformations convert the runtime source values into the displayed axis units; otherwise the convention is rejected or limited to a subset.
- **Cheap discriminator:** start with exact screenshot-to-catalogue matches; inspect the single known reader/callsite and query producer for each highest-priority ignition/fueling candidate; compare actual first/second axis argument order and runtime source cells with displayed labels.
- **Falsifier:** the query producers show the axes reversed, one axis is a raw index/other state rather than load or RPM, or no conversion supports the displayed units.
- **Information gain:** distinguish genuine engine-speed/load maps from tables merely displayed with plausible RPM/load labels; prevent a global axis convention from being copied into XML without evidence.
- **Result:** supported, weakened, rejected or unresolved. No axis identity is promoted from screenshot appearance alone.

## Scope

1. Select only screenshot-linked ignition and fueling candidates with exact or strongly supported catalogue matches. Rank by screenshot clarity, reader evidence and likely calibration importance.
2. For each selected table, record table base/extent, dimensions, storage width/signedness, reader/helper, callsite PC, axis addresses and actual query argument order.
3. Trace each query argument to its nearest runtime source cell(s). Record width, signedness, scaling, offsets, clamps, branch conditions and any selector affecting the query.
4. Determine which axis is RPM, which is load, and whether the reader's row/column convention matches the RomRaider display. State explicitly whether RPM is X or Y for each table; do not assume one global orientation.
5. Compare target-side raw values and conversions with the screenshot's displayed axis ticks/units. Quantify any supported conversion; do not infer scale from approximate visual spacing.
6. Reconcile exact overlaps with WO65109. If its findings already resolve a candidate, cite and reuse them rather than tracing again.
7. If a candidate is not an ignition/fueling map or the screenshot/catalogue match is weak, mark it out of scope with reason rather than force a classification.
