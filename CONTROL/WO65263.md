## 5. FFFF99A8 consumer resolution — NEGATIVE

### 5.1 Index rows that name FFFF99A8 are misaddressed

WO65118 lines 18446–18448 name `ffff99a8` for three word reads:

| PC | Function | Instruction | Index base | Index address | Recomputed address |
|---|---|---|---|---|---|
| `0x9882A` | `sub_9881E` | `mov.w @((dword_9904 - h'9860),gbr),r0` (bytes `C5 52`) | `FFFF9860` | `FFFF99A8` | **`FFFF9904`** |
| `0x988A6` | `sub_9881E` | `mov.w @(h'A4,gbr),r0` (bytes `C5 52`) | `FFFF9860` | `FFFF99A8` | **`FFFF9904`** |
| `0x99F50` | `sub_99F30` | `mov.w @((dword_9904 - h'9860),gbr),r0` | `FFFF9860` | `FFFF99A8` | **`FFFF9904`** |

Derivation: `sub_9881E` sets GBR=`FFFF9860` at `0x98826–0x98828` and contains no further GBR write before `0x988A6`. The SH-4 `mov.w @(disp:8,GBR),R0` encoding scales the encoded displacement by two: raw `0x52` → byte displacement `0xA4`, matching both the symbol expression `0x9904−0x9860` and the annotation `h'A4`. Effective address = `FFFF9860 + 0xA4 = FFFF9904`. The index address column equals `FFFF9860 + 2×0xA4 = FFFF99A8`, i.e. the width factor was applied a second time.

### 5.2 Independent confirmation of the scaling artifact

WO65118 line 21617: `ffffb500 ffffb5c0 00032F24 sub_327FE read w gbr_disp mov.w @(h'8C,gbr),r0 base=ffffb4a8`. Listing line 67723 shows bytes `C5 46` → byte displacement `0x8C`; true address `FFFFB4A8 + 0x8C = FFFFB534`; index address `FFFFB5C0 = FFFFB4A8 + 2×0x8C`. Two independent word rows show the same 2× inflation. Byte-width rows are unaffected (e.g. `0x38D0C`, base `FFFF9916`, displacement `0x8F` → index `FFFF99A5`, correct).

The correction is recorded here for these rows only; a full index audit is out of scope and no index file was edited.
