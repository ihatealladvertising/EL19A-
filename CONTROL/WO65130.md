## Decision question — ANSWERED

The two `0x0E9AC` callsites are **separate consumers of the same curve and helper**, not one proven monitor feature. They are co-resident under top-level `sub_70620` only at the structural call-graph level; no direct instruction-level edge between their intermediate branches was proven, and no runtime cadence is established.

Caller 1 (`sub_55F66 @ 0x56006`) ends by storing a 32-bit boolean to **`FFFF8A54`**: `1` when `UWORD[FFFF2BB8] > 100 × U8(sub_22F28 result)`, else `0`. Caller 2 (`sub_7D006 @ 0x7D07A`) copies the same result byte to **`FFFF1287`** and **`FFFF1E8A`**; `FFFF1E8A` is tested at `0x7D04E–0x7D052` and gates whether the lookup runs. The two destinations are a mirror copy at the write site, not address aliases.

Two pinned-lead corrections are required:

1. `FFFF1054 + 0x233 = FFFF1287`, **not `FFFF12A7`**. `FFFF12A7` has no read or write in the bounded evidence.
2. Caller 2’s stores are indexed by `r0 = r13`; the sole proven caller sets `r4 = 0` and therefore `r13 = 0`, reducing the effective addresses to `FFFF1287` and `FFFF1E8A` for that path. They are not unconditional absolute stores absent that proof.

No physical-unit or diagnostic-function identity is established. The curve output is not proven to be a percent, temperature, or any other physical quantity.

## 3. Caller 1 — `sub_55F66`, call at `0x56006`

### 3.1 Containment and query producer

`sub_55F66` spans `0x55F66–0x5611A`. Its sole listed caller is `sub_55518 @ 0x557CC` (`B3 CB bsr sub_55F66`, delay slot `mov r0,r5`).

The query is not a direct byte load; it is a longword load followed by low-byte zero-extension:

| PC | Instruction | Effect |
|---|---|---|
| `0x5554A` | `mov.l off_5564C,r2 ; FFFF33E6` | caller loads literal pointer |
| `0x55552` | `mov.l r2,@r15` | stores it as `arg_0` at caller `[SP+0]` |
| `0x55F88` | `bf/s loc_55F96` | branch; delay slot executes on both paths |
| `0x55F8A` (delay) | `mov.l @(h'2C+arg_0,r15),r9` | callee frame is `0x2C`, so `r9 = LONGWORD[FFFF33E6]` |
| `0x55FFC` | `extu.b r9,r9` | low byte, zero-extended |
| `0x56000` | `mov r9,r6` | query register |

No intervening write to `r9` exists between `0x55F8A` and `0x55FFC`. The producer of `FFFF33E6` itself is outside this bounded trace; the combined resolver shows several unrelated word accesses to that address (for example a write at `0x58DF0`), but none proven to feed this call.

### 3.2 GBR proof

| PC | Instruction | Effect |

### 3.3 Lookup, multiply, compare, and first action

| PC | Instruction | Effect |
|---|---|---|
| `0x55FFA` | `mov.l off_5605C,r4 ; E9AC` | data pointer |
| `0x55FFE` | `mov.l off_56060,r5 ; F51E` | axis pointer |
| `0x56002` | `mov.l off_56064,r2 ; 22F28` | helper pointer |
| `0x56004` (delay) | `mov #1,r8` | loop constant, not a helper input |
| `0x56006` | `jsr @r2` | lookup call |
| `0x56008` (delay) | `mov #2,r12` | loop bound |
| `0x5600A` | `extu.b r0,r2` | result as UBYTE |
| `0x5600E` | `mov #0x64,r6` | multiplier 100 |
| `0x56010` | `mulu r2,r6` | unsigned multiply |
| `0x56018` | `sts macl,r7` | product |
| `0x56082` | `extu.w r7,r7` | low 16 bits |
| `0x56080` | `mov.l off_562A0,r3 ; FFFF2150` | threshold base |
| `0x56084` | `mov.w word_561AC,r0 ; h'A68` | already-scaled byte offset |
| `0x56086` | `mov.w @(r0,r3),r5` | `UWORD[FFFF2BB8]` |
| `0x56088` | `extu.w r5,r5` | zero-extended |

Both compare operands are non-negative and at most 16-bit, so the signed `cmp/gt` is effectively an unsigned comparison over `0..65535`. `255 × 100 = 25,500`, so the `extu.w` truncation loses no product bits. Flag polarity: **1** means `UWORD[FFFF2BB8] > 100 × result`; **0** means threshold ≤ product. There is no conditional branch on this compare; `T` is consumed directly by `movt`.

The lookup sits inside the loop `0x5601E–0x5607C`. That loop is gated by the **old** `GBR+0x14` value read at `0x5600C` and tested at `0x5601E–0x56020`, plus `GBR+0x1C`. The current lookup result is not used inside the loop; `r7` is consumed only at `0x5608A`. Thus the first concrete state action controlled by this lookup is the `0x5608E` boolean store.

Additional gate: `0x55FEE` requires `byte[FFFF8A70].bit7` set for the lookup path; otherwise the routine stores `bit7 | 0x80` to `FFFF8A70` and skips the lookup. No direct reader of `FFFF8A54` was found in the bounded resolver/listing search. A separate resolver-confirmed writer initializes the same EA via a different base: `sub_56AAA @ 0x56B12` writes longword `0` using `GBR = FFFF8A38`, displacement `0x1C` → `FFFF8A54`.

### 4.3 Mirror classification and first consequence

The same `r6` byte is copied to two distinct addresses separated by `0xC03`, from different base pools. This is **mirrored state at the write site**, not an address alias. The fields behave independently afterward:

- `FFFF1287`: no reader or test found in the bounded search. Stop at the `0x7D088` write.
- `FFFF1E8A`: read and tested at `0x7D04E–0x7D052`; also written with `0xFF` by `sub_748B8 @ 0x748C8` using `GBR = FFFF1E7C`.

`FFFF1E8A` gate behavior:

| PC | Instruction | Meaning |
|---|---|---|
| `0x7D04A` | `mov.l off_7D1F0,r2 ; FFFF1E7C` | base |
| `0x7D04C` | `add #h'E,r2` | `FFFF1E8A` |
| `0x7D04E` | `mov.b @(r0,r2),r6` | read mirrored byte |
| `0x7D050` | `tst r6,r6` | zero test |
| `0x7D052` | `bf loc_7D092` | nonzero → skip lookup |
| `0x7D054`/`0x7D056` | `bra loc_7D092` / delay `mov #1,r14` | zero → set secondary-path flag |

Within one invocation, the lookup/mirror-write path has `r14 = 0`, while the secondary block at `0x7D092` requires `r14 = 1`; they are mutually exclusive. The lookup path itself requires the gates at `0x7D02C–0x7D048` (`FFFF99F0.bit6`, `FFFF99F4.bit1`, and nonzero `FFFF36BD`) and the `FFFF1E8A` test. The secondary block has further gates and eventually calls `sub_7D30E`; its result is tested by `sub_7CFB4 @ 0x7CFD8` and can lead to `sub_7D124 @ 0x7CFDC`. Those deeper actions are outside this bounded stop.
