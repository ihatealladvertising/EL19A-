## Questions to test

1. **Variable/stage correspondence:** Search donor A2Ls for forum identifiers and close variants, including `vLADVTRM`, `vADVTRMAP`, `wvHTARTDR`, `vADVTRM`, `vMBTCAL`, `vCATDAN`, `vADVJAR`, `vVTCADV`, `vTADVMnm`, `bvBETA`, `vTQRET`, `vADVHOS`, `vDLTADV`, `avSCKRET`, `vADVBL`, `vADVADJ`, `vADV`, `vFADV`, and `mCRSET`. Record exact descriptions, addresses, types, conversions, ECU provenance and whether each symbol actually exists. Search synonyms only where the A2L provides a defensible lead.
2. **EL19A target-side chain:** For any plausible matches, identify corresponding RAM cells, producers, consumers, arithmetic, guards and first meaningful ignition-angle/output stage in the target listing. Keep variable-name resemblance separate from proven dataflow.
3. **128 flag hypothesis:** Test whether the forum's claimed knock flag value/bit 128 is present in a relevant raw map/result path and whether firmware explicitly masks, tests or subtracts it. Include exact instruction sites and data width/signedness. Do not infer a flag merely because a byte can equal 128.
4. **−64 conversion hypothesis:** Test whether a target-side `-64` (or equivalent bias) is applied to a candidate ignition value before/at a degree-valued stage. Distinguish literal arithmetic from a display/A2L conversion. Reconcile with WO65287's finding that no raw-to-degree conversion was established in its bounded path; do not silently supersede it.
5. **Calculation-stage structure:** Test only stages for which there are concrete symbols or target-side dataflow leads: MBT/base timing, trims, IAT retard, catalyst/quietness/VTC corrections, knock/torque retard selection, acceleration/re-acceleration corrections, limits/Consult adjustment, and final/OBD timing. A stage may be classified absent/unresolved within the bounded search.

- Search exact forum symbol names and reasonable naming variants in available A2Ls first; record negative searches and source provenance.
- Trace only concrete matches/leads in EL19A. Bound each target-side trace to the first meaningful ignition-related consumer or an explicit unresolved boundary.
- Check the existing ignition candidates (including 0x9B2E, 0x9C2E, 0x9DAE and other already-ranked ignition-family objects) only where a verified reader/consumer path connects them. Do not presume these are timing degrees or knock windows.

- Do not transfer donor semantics to EL19A. Similar names, same FID, or structurally similar tables are leads, not proof.
