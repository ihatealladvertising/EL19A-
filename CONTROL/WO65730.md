## Questions to test

1. **Variable/stage correspondence:** Search donor A2Ls for forum identifiers and close variants, including `vLADVTRM`, `vADVTRMAP`, `wvHTARTDR`, `vADVTRM`, `vMBTCAL`, `vCATDAN`, `vADVJAR`, `vVTCADV`, `vTADVMnm`, `bvBETA`, `vTQRET`, `vADVHOS`, `vDLTADV`, `avSCKRET`, `vADVBL`, `vADVADJ`, `vADV`, `vFADV`, and `mCRSET`. Record exact descriptions, addresses, types, conversions, ECU provenance and whether each symbol actually exists. Search synonyms only where the A2L provides a defensible lead.
2. **EL19A target-side chain:** For any plausible matches, identify corresponding RAM cells, producers, consumers, arithmetic, guards and first meaningful ignition-angle/output stage in the target listing. Keep variable-name resemblance separate from proven dataflow.
3. **128 flag hypothesis:** Test whether the forum's claimed knock flag value/bit 128 is present in a relevant raw map/result path and whether firmware explicitly masks, tests or subtracts it. Include exact instruction sites and data width/signedness. Do not infer a flag merely because a byte can equal 128.
4. **−64 conversion hypothesis:** Test whether a target-side `-64` (or equivalent bias) is applied to a candidate ignition value before/at a degree-valued stage. Distinguish literal arithmetic from a display/A2L conversion. Reconcile with WO65287's finding that no raw-to-degree conversion was established in its bounded path; do not silently supersede it.
5. **Calculation-stage structure:** Test only stages for which there are concrete symbols or target-side dataflow leads: MBT/base timing, trims, IAT retard, catalyst/quietness/VTC corrections, knock/torque retard selection, acceleration/re-acceleration corrections, limits/Consult adjustment, and final/OBD timing. A stage may be classified absent/unresolved within the bounded search.

6. **Explicit MBT-relative trim model:** Test the forum's stated sequence as separate, falsifiable operations rather than treating −64 as a generic conversion:
   - vLADVTRM raw value → & 0x7F reference value (vADVTRMAP);
   - subtract high-IAT retard (wvHTARTDR) to form vADVTRM;
   - add that trim to calculated MBT (vMBTCAL);
   - subtract catalyst-heating (vCATDAN) and jar-sound (vADVJAR) compensation, add VTC compensation (vVTCADV), then apply the reported −64 bias to form vTADVMnm.
   Record operand widths, signedness, operation order, saturation/limiting and units at each proven step. Distinguish an A2L display conversion from executed target arithmetic. Do not collapse this into the existing 9B2E family without a concrete link.
7. **Downstream timing stages:** Where named symbols or target dataflow provide a bounded lead, test the reported max(bvBETA, vTQRET) selection (vADVHOS), acceleration/re-acceleration arbitration (vDLTADV + vADVHOS versus avSCKRET → vADVBL), limiter/rate checks and CONSULT adjustment (vADVADJ → vADV), and reference-tooth offset (mCRSET → vFADV). Treat the forum's stated +50°/−7° limits and commonly 110° reference offset as donor/forum claims only; never import those constants into EL19A absent target proof.
8. **Separate idle/deceleration branch (GOV/GOV3/GOVL):** The user supplied an additional lead that GOV, GOV3, GOVL and coolant/gear-based mTAVCD1 adders feed GOVIDL through a path said to bypass MBT and the trim-map chain, with an 8-point RPM axis 0, 400, 800, 1200, 1600, 2000, 2400, 2800. This claim is not present in the current repository forum-text extract (which contains the broad ignition pipeline discussion but no GOV/GOVIDL/mTAVCD1 passage); preserve its provenance as user-supplied supplemental evidence until the underlying posts/A2L are located. Search exact names in available A2Ls first. Trace only concrete EL19A symbol/RAM/caller leads to determine whether a distinct idle/decel timing branch exists and whether it bypasses MBT/trimming. Do not assume the 8-point axis, RPM units, table roles, or tuning advice apply to EL19A. If no concrete lead exists, report unresolved and stop rather than broad-scanning.
