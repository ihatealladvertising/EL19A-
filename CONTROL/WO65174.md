## Objective

Reverse-anchor a small set of sensor-specific P-code monitors from their already-indexed DTC writer callsites to the monitor conditions, RAM inputs, and—where directly established—the first raw/filtered acquisition source. The aim is to attach a physical subsystem anchor to EL19A RAM/threshold evidence, not to infer calibration semantics from a P-code description alone.

## Required work

For each selected slot/callsite:

1. Verify the slot index, P-code, RAM status-slot address and writer helper/site against the pinned crosswalk. Keep multiple writer sites and the duplicate P0122 slots distinct.
2. Starting from the exact callsite, inspect the writer helper's argument setup and then trace backward no more than one or two enclosing monitor functions. Identify the branch/condition that reaches the writer and the value(s) tested.
3. Recover the relevant input RAM address(es), load width/signedness, masks, arithmetic/compare order and any immediate or ROM threshold values. Preserve raw constants and scaling operations; do not assign engineering units unless a separate conversion is explicit.
4. Where the source is a known OBD Mode $01 PID or already-established acquisition chain, cite the exact address/path and prior WO. Otherwise stop at the first unresolved producer or dynamic boundary.
5. Distinguish a monitor input from a DTC result/status slot, a diagnostic response field, a latched state, and a generic scheduler/counter variable. Do not label every compared byte as a sensor measurement.
6. Summarize the strongest sensor/subsystem anchors and rank candidate thresholds or calibration objects only when the monitor code directly reads them.

## Deliverable and acceptance

Commit a single bounded report in this assigned `CONTROL/WO65174.md` file. Include a per-slot evidence matrix with:
- DTC slot/P-code and all scoped writer PCs;
- monitor function and exact writer call path;
- input RAM address, access width, signedness/bit mask and raw compare/arithmetic condition;
- threshold source (immediate, ROM scalar/table, RAM field, or unresolved);
- known PID/acquisition linkage, if proven;
- stop boundary and confidence separated into code mechanics, subsystem anchor and physical meaning.

Acceptance requires decisive claims to be checked against the pinned listing bytes and existing structural indexes. A function or constant name from an annotation is a lead, not proof. Any slot whose callsite is missing or disagrees with the index must be recorded as a discrepancy, not silently substituted.
