## Objective

Freeze the object-by-object scope for **Conservative Release 1** using the already selected full-definition XML baseline, V58 engineering workbook and current Findings system. Decide which existing baseline objects can be included as established, included as raw/provisional, or excluded. The purpose is to enable construction and validation of a successor XML—not to continue broad ROM discovery.

## Falsifiable release hypothesis

- **Hypothesis:** The selected full-definition baseline contains a useful Release 1 subset that can be represented accurately using existing structural, reader, axis and Findings evidence, without requiring complete physical identity for every object.
- **Identity layer:** Release/build disposition. Advance input/function/output identity only where existing evidence already supports it or a very small, concrete discriminator is essential to a Release 1 decision.
- **Evidence:** The selected baseline is `CALIBRATIONS/EL19A_best_guess_provisional_full_definition.xml`; the current engineering workbook is V58; the Findings index is at revision FND-000014 plus REC-000016. Earlier tiers in `EL19A_WO65325_provisional_tiered_v1.xml` are comparison history, not an automatic replacement baseline.
- **Prediction:** A meaningful subset can be assigned a defensible release disposition using existing evidence. Unsupported names/conversions/axes can be removed or represented as generic raw/provisional objects without waiting for full semantic reconstruction.
- **Cheap discriminator:** Reconcile the actual top-level calibration objects in the selected XML one-by-one against V58 and only their directly relevant Findings/WO evidence; do not repeat ROM scans or helper censuses.
- **Information gain:** This identifies the smallest safe Release 1 build and separates actual representation blockers from merely unresolved physical semantics.

## Release dispositions

Apply exactly one disposition to each baseline calibration object:

1. **INCLUDE — ESTABLISHED:** address/extent, storage type, geometry, axes and displayed scaling are supported; any physical name and units used are supported.
2. **INCLUDE — RAW/PROVISIONAL:** address/extent, storage type and geometry are supported, but physical function, units or engineering conversion remain unresolved. Use a generic, non-misleading name and raw scaling. A sample-index axis is allowed only if RomRaider can display it without implying a physical operating domain; label it explicitly as an index, never as a measured breakpoint axis. Mark such objects as not tune-ready on physical meaning/units.
3. **EXCLUDE:** address/extent, type, geometry, required axis representation or a material representation conflict is unresolved. Record the precise reason.

Unknown physical function alone is not grounds for exclusion. No donor name, curve resemblance, plausible range or numerical coincidence can establish a physical name, unit, conversion or query domain.

## Exact scope

1. Enumerate every **top-level calibration data object** in the selected full-definition baseline. Distinguish calibration objects from nested axis/scale children and display overlays; preserve distinct runtime-selected objects even when payload bytes are identical.
2. For each object, record:
   - baseline name and storage address;
   - byte extent, storage type, signedness and byte order where known;
   - geometry and orientation;
   - axis addresses/values/order or implicit/index-only representation;
   - current scaling and whether it is target-proven, raw, conditional or unsupported;
   - current semantic label and whether the label is supported, generic or overclaimed;
   - exact supporting FND/REC IDs and source WO/report anchors;
   - Release 1 disposition and concise reason;
   - any exact structural blocker that could change the disposition.
3. Reconcile V58's current candidate/register information with the Findings index. Read only relevant FND/REC records and source WO reports. Treat the V58 workbook as the current engineering baseline; V53–V57 counts are historical unless rechecked.
4. Apply later corrections and reconciliations to the selected baseline. Do not automatically preserve an old XML name/scaling simply because it exists in the baseline.
5. Identify only the **minimum** remaining Release 1 blockers. A new trace is justified only if it can resolve a concrete address, extent, type, geometry, axis, scaling, naming or inclusion conflict. Group related blockers sharing one reader/helper/evidence method; do not create one WO per address.
6. Produce `CALIBRATIONS/RELEASE1_SCOPE_MATRIX.csv` with one row per top-level calibration object and columns for address, baseline label, extent/type, geometry, axis, scaling, evidence links, release disposition, reason and blocker/follow-up. The report must summarize counts by disposition and list the highest-impact corrections/exclusions.
