## Objective

Name each calibration table/curve by the diagnostic variable used to query it, by joining its actual reader query RAM address(es) to the existing Consult-II Mode $22 and OBD Mode $01 source/name maps.

**Core rule:** a curve queried by a RAM variable that the diagnostic name map identifies as coolant temperature is a coolant-temperature curve. Do not require the table's query cell to be the exact same RAM cell as an OBD PID source when the existing Consult/query-semantic evidence already identifies the query variable. The name describes the **query variable**, not necessarily the table's physical output or downstream purpose.

This is a join/reconciliation task across existing files. Do not repeat the ROM reader census or perform broad new disassembly.

## Bounded method

1. Enumerate every table row in the 179-row catalogue and every additional reader-verified calibration table already represented in the current provisional definition/inventory but absent from the 179-row catalogue. Do not rediscover tables.
2. Extract each table's actual query RAM address(es) from the existing query expression and traced reader inputs. Preserve query position (X/Y, r5/r6, etc.), width, signedness, scale/transform, and whether the value is direct, copied, rescaled, or computed.
3. Join each query address against:
   - Consult map RAM pointer/source addresses (`ptr1_addr`, `ptr2_addr`), including CID and any available Mode 01 cross-match;
   - OBD K-line and CAN source-address fields, retaining the SAE name, unit, formula and source handler;
   - existing `query_pid_semantics` labels and their provenance.
4. Produce one row per table/query-coordinate in `INDEX/calibration_query_variable_names.tsv`. Required columns: table address; geometry/storage; query position; query expression; query RAM source(s); matched Consult CID(s); matched OBD PID(s); diagnostic variable label; proposed table/curve name; transform/scale; match class; evidence source(s); confidence; unresolved caveat.
5. Assign a physical variable name when the existing diagnostic/query map supports it, even if the table's query cell is a derived/rescaled RAM value rather than the exact OBD source cell. Preserve wording such as `coolant-temperature-derived` or `rescaled intake-air temperature` where the transformation is material.
6. Keep **query-variable identity** separate from **diagnostic-source equivalence**:
   - Same-cell/direct match is one match class.
   - Derived/rescaled/copy relationship is another.
   - A known diagnostic variable label on the query cell remains usable for naming even if its source cell differs from the OBD PID's raw source.
   - Do not claim exact OBD/Consult equivalence without same-cell or fully explained derivation evidence.
7. For two-coordinate maps, name both query variables where supported (e.g. `Coolant Temperature × [other variable]`). For a single-query curve, use that variable in the curve name. If no defensible diagnostic name exists, retain a generic address/query label; do not guess.
8. Explicitly audit the WO65239 examples:
   - `FFFF84B8` — existing `NTC_AN27_rescaled(ECT)` lead; associated tables include `0x0A8A2`, `0x0DE5E`, `0x0E4EC`, `0x0E63C`, `0x0E7D8`, `0x0E7E0`, `0x0E898`, `0x0EBC8`, `0x0EDF0`, `0x0EFFC`, `0x0F0FE`, `0x0F3E6`, `0x0F48E`, `0x100BE`, `0x10FEA` (one query position), and `0x12A0E`. Confirm exact current list from inputs rather than assuming this list is exhaustive.
   - `FFFF84BF` — existing `NTC_AN31_rescaled(IAT)` lead; associated tables include `0x0E984`, `0x0E9BC`, and `0x10FEA` (other query position).
   - `FFFF85DA` — RPM diagnostic identity, including the direct match at `0x10984`.
   - `FFFF84A4` — OBD PID 0x43 absolute-load source; preserve the `2×/saturation` transform for `0x0A0F2`.
9. Reconcile every old proposed name that conflicts with the query-variable join. Preserve historical names and state whether they describe query variable, output/consumer, or an unsupported physical-purpose hypothesis.
