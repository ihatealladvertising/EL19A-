## 3. Result

### 3.1 Producer of `FFFF937C`/`FFFF937E`

Both words are written **only** in `sub_90384` (the `FFFF9324` block initialiser), at
`0x9041A` and `0x9041C`:

```
00090384  4F 13        stc.l   gbr, @-r15
00090386  90 A9        mov.w   word_904DC, r0 ; h'FFFF9324   -> GBR = FFFF9324
00090388  40 1E        ldc     r0, gbr
...
000903BA  60 43        mov     r4, r0            ; r4 = IVECT1 = 0
000903BC  C0 C0        mov.b   r0, @((byte_93E4 - h'9324),gbr)
...
0009041A  C1 2C        mov.w   r0, @((word_937C - h'9324),gbr)   ; FFFF937C ← 0
0009041C  C1 2D        mov.w   r0, @((word_937E - h'9324),gbr)   ; FFFF937E ← 0
```

* `r0 = 0` (r4 = `IVECT1` = 0, the reset vector immediate), so both words are **initialised to 0**.
* **No other writer** exists in the listing (resolver: 2 writes, both in `sub_90384`).
* **No reader** is resolved statically (resolver: 0 reads; unresolved candidates are the generic
  fuzzy set and are not evidence).

Conclusion: `FFFF937C`/`FFFF937E` are **initialisation-only zero fields**. There is no live
update source; any "live" value would have to come from an indirect/base-register path that the
resolver cannot resolve (same limitation as WO65163).

### 3.2 Descriptor gates

The same initialiser writes the byte fields `FFFF93E4`–`FFFF93FD` (the "descriptor gates") to 0
in the same pass (`0x903BC`–`0x9042C` and following), alongside the word fields `FFFF9344`–`FFFF937A`.
The whole `FFFF9324` block is therefore a **zero-initialised descriptor/gate table** whose
fields are populated at boot by `sub_90384`. No runtime updater is visible statically.

## 4. Domain conclusion

`FFFF937C`/`FFFF937E` and the descriptor-gate bytes are boot-time zero fields in the `FFFF9324`
descriptor block. There is no live producer; the only writer is the initialiser `sub_90384`. The
block is treated as a descriptor/gate table (WO65103/WO65104), but its runtime consumers are not
resolvable with the current tooling.

## 5. Residual unknowns

1. Runtime readers of `FFFF937C`/`FFFF937E` and of the gate bytes (none found statically; likely
   base-register-indirect, as in WO65163).
2. Whether any field is updated after boot by an indirect path.
