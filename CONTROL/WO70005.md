## Answer in one paragraph

`UWORD[FFFFB644]` has exactly one reader — the `loc_47C1E` reload two instructions later (`0x047C1E` `mov.w word_47C8E,r6`), which passes `extu.w` of it to `sub_491BC` as `r6` at `0x047C2C`. `U16[FFFF11F0]` has exactly one reader, in a different routine: `sub_599AE` reads **both** bytes at `0x059DB6`/`0x059DBC` (`r14 = 0xFFFF1054`, offsets `0x19C`/`0x19D`), **adds the high and low bytes together**, compares the sum with the ROM byte `U8[0x86A9] = 0x32` (50), and stores the clamped excess `max(0, hi+lo-50)` into `UWORD[FFFF20E0+0x06]`. Within the same routine, `UWORD[FFFF20E0+0x06] == 0` sets `UBYTE[FFFF1104] = 3`. No MMIO, lamp, serial or queue write is reached: the status network's only 16-bit value publication ends in an internal state byte. Classification: **INTERNAL STATE — terminal named**. The result does add one piece of calibration-domain evidence: ROM `0x86A9` is used as that comparison threshold and is not represented in the catalogue or the Release 1 matrix.

## 2. What the reader computes

`sub_599AE`, `0x059DAA`–`0x059DEE`:

```
0x059DB0  r0 = 0x67 ; shll2 → 0x19C
0x059DB6  r2 = U8[FFFF11F0]        ; high byte of FFFFB644
0x059DB8  r0 = 0x19D
0x059DBC  r7 = U8[FFFF11F1]        ; low byte
0x059DBE  exts.w r2,r2
0x059DC0  r0 = U8[0x869A+0x0F] = U8[0x86A9] = 0x32 (50) ; r4 = extu.b
0x059DC4  exts.w r7,r5
0x059DC8  r2 = r2 + r5             ; SUM of the two bytes, not the word value
0x059DCA  cmp/ge r4,r2   ; if sum >= 50
0x059DD0  (else r6 = 0)
0x059DE2..0x059DE8  r6 = exts.w(extu.b(U8[FFFF11F0])) + r7 - r4
0x059DEA  r5 = 0xFFFF20E0 ; 0x059DEE mov.w r0,@(6,r5) → UWORD[FFFF20E0+0x06] = r6
```

Two details worth recording:

- The reader **adds** the high and low bytes rather than reassembling the word. With `hi + lo` compared against a single-byte limit of 50, at most one of the two can be large; in practice the value that survives is `hi + lo - 50` when that is non-negative.
- The threshold is a **ROM byte**, `U8[0x86A9] = 0x32`. The surrounding bytes are `0x869A`: `19 19 00 0A 01 0A 19 14 01 05 07 0F 0F 00 00 32 32 0A`; `0x86A9` and `0x86AA` are both `0x32`.

0x059E10  r5 = 0xFFFF20E0
0x059E12  r0 = UWORD[FFFF20E0+0x06]
0x059E14  tst r0,r0
0x059E16  bf loc_59E20          ; nonzero → skip

## 4. Classification

**`INTERNAL STATE` (terminal named).** Neither publication reaches a named output: there is no MMIO address, no serial/queue append (`sub_33E18`/`sub_32790` do not appear in either consumer), no lamp drive, and no command payload. `FFFFB644` is consumed once as a scalar argument to `sub_491BC` (which stashes it to its own stack at `0x0491D0`/`0x0491E0`), and `FFFF11F0` is consumed once as summed bytes against a ROM limit, producing only `FFFF20E0+6` and then `FFFF1104`.

**Identity layer advanced:** output identity, partially. The 16-bit value is not a command or a report byte — it is a **summed quantity tested against a ROM byte threshold**, and its only effect is to set or leave an internal state byte. That makes it a *threshold comparison input*, not a published measurement.
