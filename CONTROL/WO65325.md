# WO65325 — Assemble and consistency-check the complete provisional EL19A RomRaider definition

**Status:** ASSIGNED — WORKER 3 — READY  
**Priority:** P1 — NEXT MAJOR DELIVERABLE  
**Owner:** Worker 3  
**Dependencies:** WO65323 and WO65324; reuse the current XML baseline, ignition fragment, 179-row catalogue and all relevant closed semantic/reader reports.

## Objective
Produce a complete, organized, separate RomRaider definition for EL19A `f501.bin` containing all major maps, their axes, high-value support curves and the best-supported scalar/limiter inventory. Aim for high-confidence provisional coverage, not proof of every physical function.

## Method
- Integrate the map/axis consistency matrix from WO65323 and scalar/curve manifest from WO65324.
- Test the proposed calibration set as a whole: ROM extents and non-overlap; storage types and dimensions; reader/axis compatibility; orientation; value ranges; paired/duplicate relationships; scaling consistency; and coherent engine-control families.
- Prefer the arrangement that satisfies the most independent target-side constraints. Record rejected alternatives and contradictions.
- Use three explicit tiers: **Established**, **High-confidence provisional**, **Exploratory**. Preserve generic labels where function is unresolved; mark speculative names visibly as provisional.
- Use MR16DDT/Juke as a close architectural donor for shared structures and control strategies, while separating forced-induction-only features. Donor evidence never overrides EL19A evidence.
- Do not omit a structurally strong table solely because its exact physical function remains unknown. Do not force ignition/fuel labels where target-side evidence contradicts them.

## Deliverable
1. A new, separate, full RomRaider XML definition for `f501.bin`; do not overwrite existing XMLs or prototypes.
2. A concise validation report listing object counts by tier and type, axes/scalars coverage, unresolved scaling, conflicts, duplicate placements, and any RomRaider schema/load checks actually performed.
3. A short exception list of high-impact missing or contradictory objects.

## Safety and quality
Preserve original ROM bytes and raw calibration values. Do not invent metadata, checksums, dimensions, axes or scaling. Every speculative field must be labeled. Do not modify the workbook, protected YouTube evidence file, existing XMLs or other workers' reports. If the two prerequisite manifests are incomplete, continue only the integration that is supported and explicitly mark gaps; do not fabricate coverage.

## Stop conditions
Stop when the standalone definition is internally consistent and every included object has a traceable evidence source and confidence tier. Report unverified editor/load behavior honestly.
