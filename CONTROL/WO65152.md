## 1. Decision question

Does the CF48D donor contain a demonstrable **bank selector** choosing between
`QH0/ Torque Conversion Map` (`0xA78C`) and `QH0/ Torque Conversion Map Trustful` (`0xDBCA`)?

**Answer: no.** Both members are read unconditionally in the same periodic task pass through
separate interpolation wrappers that differ only in pointer constants; the two 512-byte tables and
both axis pairs are **byte-identical**; the only code that touches both members is a
plausibility monitor on the *input query*, not a selector on the table.

## 5. Scheduling — both members run in the same pass

- The donor task-pointer array starts at `0x33BC` (237 entries, 4 bytes each).
- `loc_5AEA8` (normal wrapper) is entry **116** (`0x358C`); `loc_5AF9C` (trustful wrapper) is entry
  **191** (`0x36B8`); `loc_5AE80` (caller of the inline trustful reader `sub_5AB78`) is entry **200**
  (`0x36DC`).
- `sub_2C38` executes a contiguous 123-entry slice starting at `0x3560` (`mov #h'7B, r13` at
  `0x2F4E`, loop at `0x2F52`), i.e. task indices 105–227. Indices 116, 191 and 200 all fall inside
  that single slice, so the normal and trustful QH0 readers are invoked in the **same** task pass.
- The slice is reached by straight-line fall-through from the preceding bit-write block
  (`0x2F4C–0x2F50`); no branch targets the run's first entry from outside, and no conditional selects
  one member over the other.

Consequently, there is no either/or branch between the normal and trustful tables: both are computed
on every pass and their results are stored in disjoint RAM cells (`+0x8E0` vs `+0xBA6`).

## 7. Result

**Bounded negative for the bank-selector hypothesis.** In the CF48D donor:

1. `0xA78C` and `0xDBCA` are complete 16×16 UWORD BE surfaces with byte-identical payloads and
   byte-identical axis pairs.
2. Both are read unconditionally in one and the same 123-task pass; the normal and trustful wrappers
   are instruction-identical interpolators differing only in pointer constants.
3. The only shared consumer computes `|normal_query − trustful_query|`, stores it and raises a fault
   above `0x51E`; it does not choose a surface.

Any "normal vs trustful" selection that may exist in this ECU therefore lives outside this pair's
read path (downstream of the stored results or in a mode not exercised by this static trace) and is
not demonstrable here.
