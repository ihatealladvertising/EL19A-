## Scope and method

1. Inventory objects and exact bytes/widths only within ROM `0x7800–0x9B00`.
2. Select a small number of scalar-like objects with concrete direct code references. Prefer candidates whose reader/writer shows a threshold comparison, bound/clamp, constant transfer, or other directly observable scalar use; exclude obvious multi-point lookup tables unless needed to disambiguate a scalar.
3. Resolve direct literal/pool and fixed-address references from the annotated listing. For each selected candidate, check actual instruction width and signedness, pool contents, function/GBR context, and branch/delay-slot behavior needed for the immediate use. Record the exact PC and stop at unsupported provenance/CFG transitions.
4. Report raw machine facts separately from provisional family hypotheses. Preserve unknown units, scaling, and meanings. A taxonomy label remains a lead unless EL19A code proves it.
5. Keep all analysis read-only. No ROM/listing/XML/script/evidence/workbook edits; no broad unrelated trace or new persistent index.

## Selection criteria

- Address lies within `0x7800–0x9B00`.
- Object boundary and storage width are supported by bytes/listing, not donor metadata alone.
- At least one concrete code reference resolves to the object; include exact reader/writer PC and effective address.
- Include only immediate behavior established by the bounded instruction trace; do not infer units, calibration semantics, or a hardware endpoint.
- Prefer independent scalar candidates across target families; do not inflate the result with adjacent points from a single table.

## Acceptance and stop conditions

- Every reported candidate has reproducible source hashes, exact address/width/raw bytes, direct reference PC and context, immediate behavior, confidence, and unresolved limitations.
- Report exclusions and bounded negatives with the exact methods applied; do not claim a complete census.
- Stop tracing a candidate at unsupported register/GBR provenance, an indirect transfer, unsupported CFG join, or unproven call preservation. Stop and record the precise boundary if a trace enters active-WO RAM ranges `FFFF85C4–FFFF85FF` or `FFFF860B–FFFF860F`; continue other independent candidates.
- Do not expand the ROM window except for a strictly necessary bounded reader/consumer trace.
- Exclude semantic catalog completion, donor/A2L validation, multi-point map reanalysis, code modification, calibration modification, and workbook/XML integration.
