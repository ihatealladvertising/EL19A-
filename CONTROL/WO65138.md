## V6 donor candidates

- `mTTVOULM`: 8-point UBYTE curve at `0xDC4A`, output `COMP_0529_S` = 0.3575 degrees; axis pointer `mTTVONBP` at `0xDC3A`, 8-point UBYTE, `COMP_0000` = 25 rpm per count; function `KF7-350.4M[14]`.
- `mTTVOULMS`: 8-point UBYTE curve at `0xDC52`, same output conversion; axis pointer `mTTVONBPS` at `0xDC42`, same 25 rpm/count encoding; function `KF7-350.4P[13]`.
- Function descriptions: `KF7-350.4M` = target throttle-opening calculation, main section; `KF7-350.4P` = corresponding sub-calculation section.

## Required tests

1. Decode the V6 two curves and both axis arrays. Record every raw point, exact COMPU_METHOD formula, units and A2L function description.
2. Compare V6 axes with target fragment values and, more importantly, the actual EL19A callsite query/axis mechanism. Prove whether the target axis is ROM-resident, fixed in code, or only an XML hypothesis.
3. Compare main/sub curve payloads: determine whether the V6 pair are identical or distinct and whether EL19A's identical payloads have equivalent branch/caller selection.
4. Check if target value conversion can independently be shown as 0.3575 degrees per raw count. Do not treat a matching A2L conversion as proof that the EL19A logger/UI scale is the same.
5. Relate the V6 main/sub function split to target callsite and consumer paths, then classify the relationship as strong equivalent, shared calibration family, partial analogue or rejected.
6. Preserve any mismatch: a V6 main/sub distinction does not mean the target's two byte-identical curves have distinct runtime behavior.
