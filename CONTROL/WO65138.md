## Objective

Test the proposed one-to-one relationship between EL19A's 8-point UBYTE main/sub throttle upper-limit curves and the V6 A2L's corresponding main/sub throttle upper-limit curves.

## Result

**Classification: shared calibration family / strong functional analogue.** Structure, scale, axis encoding, and function description all match. Direct payload comparison is not performable (no V6 ROM available; CF48D.bin is the wrong ECU). EL19A's two curves are byte-identical, unlike the V6's distinct main/sub function split.

## EL19A target-side findings (ROM-resident, verified)

**ROM:** `VERSA f501.bin`, MD5 `46991697c502052752a2cabcb84c9e27`

### Curve payloads (8 UBYTE each)

| Address | Label | Raw bytes | Decoded (×0.3575 deg) |
|---------|-------|-----------|----------------------|
| 0xF3D6 | `mTTVOULM` (main) | FF FF 43 43 A8 C4 E0 FF | 91.16 91.16 23.95 23.95 60.06 70.07 80.08 91.16 |
| 0xF3DE | `mTTVOULMS` (sub) | FF FF 43 43 A8 C4 E0 FF | 91.16 91.16 23.95 23.95 60.06 70.07 80.08 91.16 |

Both curves are **byte-identical**. `0xFF` decodes to `91.1625°` — exactly the A2L `COMP_0529_S` max, i.e. "no effective limit" at the endpoints.

### Axis arrays (8 UBYTE each, ROM-resident at fixed addresses)

| Address | Label | Raw bytes | Decoded (×25 rpm) |
|---------|-------|-----------|-------------------|
| 0xF3C6 | main axis | 00 01 02 1C 58 68 70 80 | 0 25 50 700 2200 2600 2800 3200 rpm |
| 0xF3CE | sub axis | 00 01 02 1C 58 68 70 80 | 0 25 50 700 2200 2600 2800 3200 rpm |

Both axes are **byte-identical**. Axis is **ROM-resident** (actual data at fixed addresses), not a static/XML hypothesis. Non-uniform spacing (dense at low RPM, sparse at high RPM).

### Callsite mechanism (listing `EL19A_Complete_Disassembly_ANNOTATED_V3_NEXT6_16_ALL_PENDING_ANNOTATIONS.lst`, SHA-256 `148385bb...`)

**Callsite 1** @ `0x6583E`–`0x65848`:
- `r4 = 0xF3D6` (table base), `r5 = 0xF3C6` (axis base), input byte from `FFFF85A9`
- `jsr sub_22EFC` — descending UBYTE axis search (`sub_233CC`) + interpolation (`sub_231C8`)

**Callsite 2** @ `0x6822E`–`0x68238`:
- `r4 = 0xF3DE` (table base), `r5 = 0xF3CE` (axis base), input byte from `FFFF85A9`
- `jsr sub_22EFC` — same mechanism

Both callsites share the **same input source** (`byte at FFFF85A9`) and the **same lookup helper** (`sub_22EFC`). The target has no runtime main/sub branch distinction at these callsites — both use identical table/axis/input.

### Scale verification

`COMP_0529_S` = `0.3575 deg/pt` (RAT_FUNC, coeffs `0 1 0 0 0 0.3575`). EL19A `0xFF` = 255 × 0.3575 = `91.1625°`, matching the A2L documented max exactly. The `0.3575°` provisional scale is **independently confirmed** by the value range, not merely adopted from the A2L.

Axis scale `COMP_0000` = `25 rpm/pt` (RAT_FUNC, coeffs `0 1 0 0 0 25`). EL19A axis point `0x80` = 128 × 25 = `3200 rpm`, within the A2L documented 0–6375 rpm range.
