## Objective
Extend the completed bounded CAN work in WO65108 to the remaining active HCAN2 (CAN1) mailbox/register set. Identify mailbox configuration, TX/RX direction, message identifiers where statically recoverable, and associated RAM payload buffers.

## Required work
1. Reuse `INDEX/sh7058_mmio_census.tsv`, WO65106 endpoint inventory, WO65108 mailbox findings, WO65103 transport graph and merged structural indexes.
2. Enumerate HCAN2 registers actually accessed by code; distinguish control/status/configuration registers from mailbox data registers.
3. Trace each unaccounted mailbox slot through setup, TX/RX dispatch and buffer pointer arithmetic. Record exact MMIO offsets, access width, masks, message ID construction and RAM buffer extent.
4. Identify first consumers/producers of payload bytes and relate only proven fields to existing RAM structures.
5. Compare against HCAN1 only to identify common driver structure; do not assume channel symmetry.

## Acceptance criteria
- Every active HCAN2 register in the census is dispositioned as mailbox, controller config/status, unrelated alias, or unresolved.
- Mailbox table includes register address, direction, ID/mask evidence, payload pointer/extent, caller/function, and evidence grade.
- No vehicle signal name (ABS/VSS, TCM, IPDM, cluster, etc.) unless a message ID, payload decoder or independent code path supports it.
- Identify exact coverage added beyond WO65108; no repeat of MB12 or MB27–30 work except to validate shared driver behavior.

## Boundaries
Read-only, bounded to HCAN2. No new MMIO census, broad register scan, ROM/LST/XML/workbook/catalogue/index/script/tool changes. No physical vehicle testing or bus injection. Reuse all existing indexes and verify effective addresses against the canonical EL19A listing.
