# WO65063 — UWORD Threshold-Parameter Block `0x9700–0x9800`: Absolute-Pointer Reader Census and Gate Classification

**Status:** ACTIVE (concurrent with WO65062 by explicit user authorization, 2026-11-20)
**Opened:** 2026-11-20
**Priority:** P1 — foundation for the register's recommended 1D scalar/limiter sweep (main `CF48D` gap)

## Decision question

For the 128 UWORD slots in ROM `0x9700–0x9800`, which slots are actually consumed by code, through which absolute-pointer load, at what width and displacement, and which of those reads feed a compare-and-branch (threshold gate) rather than a plain data transfer?

## Inputs and identity

- ROM: `VERSA f501.bin`, 1 MiB. MD5 `46991697c502052752a2cabcb84c9e27` — **re-verified this session**. SHA-256 `bfe037e8e6c389e2a90214047058eb6dc3bcaaaac5b5931bf98a3f5d9f64fd6a` — re-verified.
- Listing: `EL19A_Complete_Disassembly_ANNOTATED_V3_NEXT6_16_ALL_PENDING_ANNOTATIONS.lst`, 27,045,080 bytes, MD5 `99635224d16ab7705445e27bf233e549` — **re-verified**, matching the value recorded in WO65062.
- Listing parse: 399,781 instruction/data rows; 306,688 `CODE`, 29,217 `DATA`, 63,876 `UNDEFINED`; continuous coverage `0x000000–0x0FFFFF`.
- **DEPENDS_ON:** none open. Uses the literal-pool resolution method already accepted in WO65061/WO65062 (`mov.l off_*, rN ; h'XXXX` comments carry the resolved long).
- Scratch parsers were run outside the repository (`/tmp`) and are **not** persisted; no new shared tool or index artifact was created.

## Scope

ROM `0x9700–0x9800` inclusive (128 UWORD slots). Methods applied:

1. Complete `mov.l` literal-pool load census with resolved value inside the window.
2. For each load, first same-register memory access, resolved to byte EA where the addressing form is `@Rn` or `@(disp,Rn)`; `@(R0,Rn)` treated as dynamic.
3. Forward scan for the first `cmp/*` after that access, plus the immediately following branch.
4. Slot-level coverage: which of the 128 slots are reached, with what width.

## Detailed traces (three selected sites)

### 1. `0x97AE` = `0x1A2C` (6700) — two-channel saturation ceiling in `sub_5919A`

`sub_5919A` sets `GBR = 0xFFFF8D5C` at `0x591AE` (`word_592F2` = `h'8D5C`, `ldc r0,gbr`).

- `0x59862 mov.l off_599DC,r2 ; h'97AE` → `0x59864 extu.w r13,r0` → `0x59866 mov.w @r2,r5` (= 6700) → `0x59868 extu.w r5,r5` → `0x5986A cmp/ge r5,r0` → `0x5986C bf 0x59874`; on the not-less path `0x5986E bra 0x59874` / `0x59870 mov r5,r0`.
- Net effect: `r0 = min(r13, 0x1A2C)`, stored at `0x5987A mov.w r0,@(h'6C,gbr)` → RAM `FFFF8DC8`.
- Repeated for a second channel at `0x5987C–0x5988A` with `r12` in place of `r13`.
- `r13` originates at `0x591BC mov r7,r13` (a function argument), `extu.w`-normalised at `0x591C0`.

Classification: **hard saturation ceiling on two input channels** into a 16-bit RAM field. It is a calibration *limit* in the strict sense (code cannot emit more than 6700), but this WO does **not** establish that the quantity is engine speed, nor its units — the same routine saturates at `±0x8000`/`0x7FFF` elsewhere, so the field is a signed/normalised 16-bit engineering quantity, not a proven RPM register.

### 2. `0x97F6` / `0x97F8` / `0x97FA` — descending three-stage ladder in `INT_ATU02_ICI0A`

Enclosing routine `sub_25D36` is `INT_ATU02_ICI0A` (entry `0x25D5A`), `GBR = 0xFFFF1054` (`0x25D7E`), `r9 = 0xFFFF1990` (`0x25D88`).

Compared operand provenance (bounded, one hop):

- `0x25DD4 mov.w @(h'16,r10),r0` with `r10 = ATUII_TCNT1A_W` (`word_25ED6` = `h'F440`) → capture timer count.
- `0x25DD2 mov.w @(r0,r8),r5` with `r0 = h'23C` → previous stored value at `FFFF1054+0x23C`.
- `0x25DEC sub r5,r7` → `r7` = counter delta (edge interval); stored at `FFFF1990+0x26E` (`0x25DF2`) and `FFFF1990+0x29E` (`0x25E06`) when `FFFF1E54+3` bit `0x10` is set; otherwise the slot receives `0xFFFFFFFF` (`0x25DF8`).
- At `0x260DA` `r0 = h'29E`, `0x260DE mov.w @(r0,r9),r4` → the compared value is the captured **interval**, not a rate.

Ladder: `0x260E0` reads 10469 → `cmp/ge` → `bf 0x26110`; `0x26110` reads 6250 → `bf 0x26144`; `0x26144` reads 5312 → `bf 0x261D8`. Each accepted rung latches a status code: `FFFF1990+0x1AF..0x1B1`, `FFFF9916+0x6E` copied to `FFFFA378+0xEBB..0xEBE`, and `FFFF1EBD+0xDA..0xDD`.

Classification: **three descending interval thresholds gating a status-latch ladder**. Because the operand is a timer delta, thresholds are in capture-clock counts. Any RPM interpretation requires a divisor from the capture clock, which is **not** established here.

### 3. `0x9758` record — seven loads, five fixed-offset consumers, all in `sub_6D4BC`

Record base `0x9758`; consumed offsets `+0` (`FFFF`), `+2` (`0000`), `+4` (`0280`=640), `+6` (`FFFF`), `+8` (`0500`=1280), `+A` (`005B`=91).

- `0x6D528`: `cmp/hs r2,r6` against `0xFFFF` gates bit 2 of an output byte (`or #2` / `and #h'FD` at `0x6D534/0x6D536`).
- `0x6D892`: `cmp/hi r2,r13` against 640 → `bt 0x6D8BA`.
- `0x6D672`: `cmp/ge r7,r5` against `0xFFFF` → `bt 0x6D68C`.
- `0x6D72A`: `cmp/ge r4,r14` against 1280 → `bt 0x6D738`.
- `0x6D5F6` and `0x6D7A2`: `cmp/hi` against 91 → `bt 0x6D630` / `bf 0x6D7BA`.
- `0x6D89C` reads `+2` (0) without a compare.

Note: two of the five thresholds are `0xFFFF`, so their gates can only trigger on an exact `0xFFFF` operand — consistent with a "disabled / not-applicable" encoding rather than a live limit. This is recorded as an observation, not a proven convention.

## Bounded negatives

- No byte-width, longword, GBR-relative, `@(R0,Rn)`-first-access, DMA or block-copy access into `0x9700–0x9800` was found **by this method**. Method = 84 absolute literal-pool loads + first same-register memory operand + up to 13 following instructions.
- This is **not** a whole-ROM absence proof: `@(R0,Rn)` reads from *other* bases whose `R0` range is unproven can still alias into the block, and no base-sibling/index sweep was performed on this window. The 78-slot "unreached" list is unreached **by absolute pointer only**.
- No writer to these ROM slots exists (ROM is read-only); no IDA-symbol semantics were assumed for any address in the block.

## Unresolved items / dependencies

1. Semantic identity and units for every gate value remain unproven. `6700` (`0x97AE`), `6250`/`5312`/`10469` (`0x97F8`/`0x97FA`/`0x97F6`) are the strongest structural candidates for speed/rotation limits but have **no** proven unit or reader-side divisor.
2. Two `0xFFFF` thresholds in the `0x9758` record: `0x9758` and `0x975E`. Whether `0xFFFF` is the "disabled" sentinel is unproven.
3. Operand provenance was traced for the two detailed traces only; the other 32 gate operands are recorded by compare/branch only.
4. The 78 unreached slots may be consumed through index/alias forms outside this method.
5. `0x971A` (11586) and `0x971C` (7200), and the signed-looking pair `0x971E`/`0x9720` (`7EB5`/`8148`), are uncatalogued in the discovery register; they are surfaced here as leads, not candidates.
