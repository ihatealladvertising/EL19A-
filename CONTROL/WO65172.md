## Bounded work

### A. Re-verify the FFFF170A consumer and store destination in `sub_B2300`

`sub_B2300` entry (PC 0xB2300) sets `GBR = FFFF2F00` at 0xB2306–0xB2308 (`mov.l off_B2544, r0 ; h'FFFF2F00`; `ldc r0, gbr`). This is the **only** `ldc` to `gbr` within `sub_B2300` (0xB2300–0xB25xx), so `GBR = FFFF2F00` throughout the routine.

At the `FFFF8CCC.bit4`-set branch (`loc_B2458`, PC 0xB2458):
```
000B2458  D4 43   mov.l   off_B2568, r4    ; r4 = h'FFFF1054
000B245A  90 70   mov.w   word_B253E, r0   ; r0 = h'6B6
000B245C  02 12   stc     gbr, r2          ; r2 = GBR = h'FFFF2F00
000B245E  00 4C   mov.b   @(r0,r4), r0     ; r0 = UBYTE[h'FFFF1054 + h'6B6] = UBYTE[h'FFFF170A]
000B2460  32 7C   add     r7, r2           ; r2 = h'FFFF2F00 + h'012F = h'FFFF302F
000B2462  80 21   mov.b   r0, @(1,r2)      ; store UBYTE[h'FFFF170A] at h'FFFF3030
```

`r7 = h'012F` is set at 0xB23F8 (`mov.w word_B2454, r7 ; h'12F`) and is unchanged between there and 0xB2460.

**Correction to WO65098:** the store destination is **fixed address `FFFF3030`** (`FFFF2F00 + 0x12F + 1`), **not** `FFFF2F00 + (UBYTE[FFFF1E71] & 7) + 1`. `UBYTE[FFFF1E71]` is never referenced in `sub_B2300`; `r7` is the constant `0x12F`. WO65098's dynamic-address claim is incorrect.

`FFFF170A` appears only once as a label declaration (LST line 445511, `.res.b 1`) and has no other code consumers — `sub_B2300` at 0xB245E is its sole reader.

## Closeout findings (2026-11-22)

**Status:** CLOSED — BOUNDED COMPLETE (bounded negative).

### 1. `FFFF170A` consumer — CONFIRMED

`sub_B2300` at PC 0xB245E reads `UBYTE[FFFF170A]` via `mov.b @(r0,r4), r0` (r4=FFFF1054, r0=0x6B6), gated by `FFFF8CCC.bit4` (BT at 0xB2424). This is the sole code consumer of `FFFF170A`.

### 2. Store destination — CORRECTED

The byte is stored to **fixed address `FFFF3030`** at PC 0xB2462 (`mov.b r0, @(1,r2)` where r2 = GBR(FFFF2F00) + 0x12F + 1). WO65098's claim of `FFFF2F00 + (UBYTE[FFFF1E71] & 7) + 1` is incorrect: `UBYTE[FFFF1E71]` is never referenced in `sub_B2300`, and `r7 = 0x12F` is constant.

### 3. Subsequent reader — NONE FOUND
