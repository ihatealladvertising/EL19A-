## 1. Premise correction — there is no dynamic index

WO65098 recorded the destination of the `FFFF170A` store as:

```
FFFF2F00 + (UBYTE[FFFF1E71] & 7) + 1
```

The pinned listing does not support that form. The store is at `0xB2458–0xB2462`:

| PC | Opcode | Effect |
|---|---|---|
| `0xB2458` | `mov.l off_B2568, r4 ; h'FFFF1054` | `r4 = FFFF1054` |
| `0xB245A` | `mov.w word_B253E, r0 ; h'6B6` | `r0 = 0x6B6` |
| `0xB245C` | `stc gbr, r2` | `r2 = GBR` |
| `0xB245E` | `mov.b @(r0,r4), r0` | `r0 = UBYTE[FFFF170A]` |
| `0xB2460` | `add r7, r2` | `r2 = GBR + r7` |
| `0xB2462` | `mov.b r0, @(1,r2)` | store at `GBR + r7 + 1` |

`r7` is not derived from `FFFF1E71`. It is loaded from a constant pool word holding `0x012F` (`word_B2454`, re-loaded at `0xB23EC`, `0xB23F8`, `0xB2448`, `word_B2638` at `0xB25E6`, `word_B27A2`/`word_B27F2` at `0xB2668`/`0xB27B0`, `word_B3366` at `0xB326A`). `GBR` is `FFFF2F00`, loaded at `0xB2306–0xB2308`:

```
000B2306  mov.l off_B2544, r0 ; h'FFFF2F00
000B2308  ldc   r0, gbr
```

Therefore the effective address is **`0xFFFF302F + 1 = 0xFFFF3030`**, a static address. The byte `FFFF1E71` is *not* an index there: its bit 4 is one of the status bits mirrored into `FFFF302F` (see §3). WO65098's parenthetical is withdrawn. There is no index, no mask, no wrap, and no variable slot width to establish.

`FFFF1E71 & 7` appears nowhere in the pinned listing in this path; the only `FFFF1E71` accesses in `sub_B2300` are bit tests at `0xB2340` (bit 4) and `0xB2494` (bit 0), and in `sub_B263C` at `0xB2682` (bits 4 and 5).

## 2. Record extent and base derivation

The three routines that address this area all load `GBR = FFFF2F00` from a literal and add a constant register:

| Routine | GBR load | Offset constant | Base reached |
|---|---|---|---|
| `sub_B2300` | `0xB2306/0xB2308` | `0x12F` (`word_B23B4`/`word_B2454`) | `FFFF302F` |
| `sub_B263C` | `0xB2644/0xB2646` | `0x12F` (`word_B27A2`) | `FFFF302F` |
| `sub_B3258` | `0xB3262/0xB3264` | `0x12F` (`word_B3366`) | `FFFF302F` |

Byte accesses use `@(disp,rN)` on that computed base; the highest displacement used in this record is `7`, so the touched extent is **`0xFFFF302F–0xFFFF3036`, 8 bytes**. The listing declares these eight addresses only as

```
FFFF302F  FF   UNDEFINED .res.b 1
... (through FFFF3034)
```

with no symbolic or longword literal reference anywhere in the image, which is why WO65118's `base_disp`/`base_r0` index does not contain this record: the index resolves `GBR+disp` and immediate-offset bases, not `stc gbr,rN ; add rK,rN ; @(d,rN)` chains. The record is therefore an index blind spot, not an unreferenced object.

## 6. Dispatch context and lifecycle

`EVIDENCE/WO65120_call_graph.tsv` records `sub_B05B4` as the sole caller of all three:

```
sub_B05B4 000B075C jsr @r3 -> sub_B3258
sub_B05B4 000B07A2 jsr @r3 -> sub_B263C
sub_B05B4 000B07AC jsr @r3 -> sub_B2300
```

`sub_B05B4` also loads `GBR = FFFF2F00` (`0xB05C2/0xB05C4`) so the record is addressed consistently across the three. `sub_B2300` and `sub_B263C` each save/restore `GBR`, `PR` and their used registers, and `sub_B3258` additionally uses the `FFFF2F00` copy in `r12` for the shadow fields.

Lifecycle established in bounded form:

1. `sub_B3258` refreshes bytes `FFFF302F`, `FFFF3030`, `FFFF3031`, `FFFF3032`, `FFFF3033` from measured/status bytes and writes the same values into a parallel area (`FFFF3334`, `FFFF324C`, `FFFF3320`).
2. Exactly one of `sub_B2300` (when `ROM[0x87C8].bit7 = 0`) or `sub_B263C` (when it is `1`) then overwrites/merges the same eight bytes with a per-build set of mirrored status bits, plus the `0x320`-scaled `sub_21AC0` byte and, for `sub_B2300` only, `FFFF3030` from either the `0x14`-scaled byte or `FFFF170A` (`ROM[0x8CCC].bit4`).
3. `sub_B2300`'s record-refresh path itself is skipped entirely when `ROM[0x8CD3].bit7 = 1`.

The eight bytes are therefore a **per-cycle observation/status image refreshed by one of two mutually exclusive ROM-selected variants**, not a per-sample dynamic array and not an indexed record table.

Every access inside the record is either a store or a read-modify-write **inside the producing routine itself**. No instruction in the pinned image reads `FFFF302F–FFFF3036` for a decision or calculation outside the blocks listed in §3–§5.

Consequently: **no external reader, no decision/use, and no actuator, injector, ignition, torque or diagnostic-report endpoint is established for this record** by static direct-reference analysis. The record's only demonstrated use is as a status-bit mirror destination, with `FFFF3030` carrying the WO65098 `FFFF170A` byte (or its `0x14`-scaled alternative) as one 8-bit field.

## 13. Highest-value next discriminator

Enumerate the writer of the byte at `FFFF2F00+0x334` (`FFFF3334`) and of `FFFF3260`/`FFFF311E`, which the three producers copy into `FFFF3036`, `FFFF3034` and `FFFF3035`. Those bytes are the only record fields carrying an 8-bit measured-looking value from outside the flag-mirror set; establishing their producers would decide whether the record is a pure status image or also carries one measured quantity. A second, independent discriminator is a runtime breakpoint on `0xFFFF3030` to observe whether any packet/DMA path reads the record, which static analysis cannot exclude.
