## Objective

Produce a concise read-only reuse map for the current SH-2 analysis code. Identify what the future Reader Trace engine should reuse and where the verified implementation boundary ends. This is a light advisory review, not an implementation assignment.

## Bounded questions

1. Identify concrete functions/helpers that can be reused for address normalization, pointer promotion/dereference, register tracking, GBR/RAM accesses, and result provenance.
2. List opcode/instruction families handled only where directly evident in the named source files.
3. Summarize existing tests and the exact behaviors each test proves.
4. Separate implemented capabilities from gaps: path-sensitive control flow, delay slots, call clobber/return effects, query transforms, result-to-consumer linkage, source/profile pinning and unusual lookup geometry.
5. Recommend the narrowest adapter boundary. Do not recommend copying or duplicating the existing SH-2 decoder.
