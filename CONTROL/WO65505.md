## Objective

WO65493 proved that `FFFF1820`, `FFFF1830`, `FFFF1838` and `FFFF1840` are read but never written in the listing, while `FFFF1820` is simultaneously a `jsr @r6` call target at `0x4BB0`. Decide between the two remaining explanations: the `FFFF1800` block is written by a transport the index does not model (block copy, pointer table, computed pointer, `movca.l`), or it is a RAM overlay whose contents in the running application are not established by this ROM image at all.

## Mandatory falsifiable hypothesis

- **Identity layer advanced:** provenance of an entire RAM block that four semantic cells depend on.
- **Hypothesis:** the block is filled by a **block copy** (a routine whose source and destination are both computed), so a writer exists but is invisible to the literal/displacement index.
- **Evidence:** WO65493 §3 (no store, one `jsr` target, ROM literal `0x4D54` = `FF FF 18 20` verified); WO65118 header `method_limits`; the reset/programming sequence at `0x4B40`–`0x4BBE`.
- **Prediction:** a copy routine will have a destination in `FFFF1800`–`FFFF1840` computed in a register, a source in ROM, and a length constant; conversely, if no such routine exists in the image, the overlay explanation stands and the block's running-phase values are simply not derivable from static analysis.
- **Cheap discriminator:** enumerate `movca.l` sites, then all loops that write through a register-held destination with a fixed count (bounded to loops whose count ≤ 0x40) — this is a scan of the *transport forms only*, not of all addressing.
- **Information gain:** either restores a producer for `FFFF1840`/`FFFF1820` and reopens the physical question, or closes the block as non-derivable and removes it from every future naming attempt.
- **Result:** to be recorded on closeout.

## Scope

1. All `movca.l` occurrences in the listing (there should be very few) and their destinations.
2. Bounded enumeration of copy loops: a `mov`-into-`@rN` store inside a loop whose counter is a constant ≤ `0x40`, where the destination register is derived from a literal in `FFFF17D0`–`FFFF1900`.
3. If a candidate is found, decode at most two of them and state source, destination and length.
4. Decide whether `FFFF1820`'s `jsr` target is code installed by that transport, and therefore whether `sub_36E02`'s error term reads a level or code bytes.

## Required deliverable

- The enumeration (counts must be stated even when zero), the decoded candidate(s) if any, and a verdict: transport found / overlay proven / unresolved.
- An additive correction to WO65493 §3 and §6 if the transport is found.
- An explicit statement of what remains underivable, so no later WO re-asks it.
