## Answer 2 — `sub_9D26C` is a fixed-gain scaled-delta primitive

`sub_9D26C` (`0x09D26C`, 24 instructions, called with `r4` and `r5`):

```
0x09D26E  r6 = (u16)r4                     extu.w
0x09D270  r5 = (u16)r5                     extu.w
0x09D272  r6 = r6 - r5                     signed 16-bit difference
0x09D274  if r6 == 0 -> return r6 (=0)     tst/bt loc_9D298
0x09D278  r5 = off_9D4B4 = 0x8AD0          ROM byte, U8[0x8AD0] = h'70 = 112
0x09D27A  r2 = (u8)U8[0x8AD0]
0x09D27C  macl = r6 * r2                   mul.l, 64-bit product
0x09D282  r6 = 0xFFFF                      upper sentinel
0x09D284  r2 = macl
0x09D286..0x09D28E  r2 >>= 5 (five shar)   arithmetic shift = floor(/32)
0x09D290  if r2 > 0xFFFF -> r2 = 0xFFFF    cmp/gt + clamp
0x09D298  return r0 = r2
```

**Contract:** `sub_9D26C(a,b) = min(0xFFFF, floor(112/32 · (a − b))) = min(0xFFFF, floor(3.5 · (a − b)))` with `a = (u16)r4`, `b = (u16)r5`; returns `0` when `a == b`; negative results are **not** clamped inside the callee — every caller adds `cmp/pz r0` + `bt` and substitutes `IVECT1` (= `0`) when the quotient is negative.

`IVECT1` is the ROM symbol at address `0` (the reset vector, `00000000 00 00 26 4C .data.l Poweron_Reset`), so `mov #IVECT1,rN` assembles an immediate of `0`. The three clamp epilogues at `0x0A143A`–`0x0A1440`, `0x0A19DA`–`0x0A19E0` and `0x0A2B20`–`0x0A2B26` are therefore "negative → 0", not a non-zero sentinel.

Effective producer expression, identical at all three value writers (`0x0A1436`/`0x0A1446` in `sub_A1090`, `0x0A19D6`/`0x0A19E6` in `sub_A14F0`, `0x0A2B1C`/`0x0A2B2A` in `sub_A2594`):

```
FFFF2478 <- max(0, min(0xFFFF, floor(3.5 * ( U16[FFFF22BC] - U16[FFFF84F4] ))))
             where FFFF22BC = FFFF2150+0x16C   (displacement built as mov #h'5B,r0 / shll2)
                   FFFF84F4 = FFFF84D4+0x20   (0x60-byte shadow block, WO64857/WO65739)
```

In `sub_A2594` the `0x16C` operand is read through the base register `r13 = FFFF2150` and in `sub_A2594`'s sibling entry through `@(h'16C,gbr)` after `ldc` of `FFFF2150` at `0x0A259E` — same cell, two notations.

This is a **target-versus-reference, fixed-gain, non-negative deviation register**. Its inputs are not calibration tables: `FFFF22BC` is a RAM word in the `FFFF2150` band and `FFFF84F4` is a field of the `FFFF84D4` shadow copy. `FFFF2478` is therefore a *derived* 16-bit quantity, not a calibration mirror.

## Answer 4 — the single consumer folds the cell into a saturating signed error term at `FFFF246C`

`sub_A6650` (`0x0A6650`) is the only reader. Guarded by `UBYTE[FFFF34B3+0x35].bit4` (`0x0A6662`), `UBYTE[FFFF34B3+0x02].bit5` and `UBYTE[FFFF34B3+0x98].bit4`, it computes (`r13`/`gbr` = `FFFF2150`):

```
hop A  (0x0A66B4-0x0A66D8)                          [consecutive-sample delta]
   r6 = U16[FFFF247E] - U16[FFFF2482]         (0x32E - 0x332, both extu.w)
   r5 = U16[FFFF2474]                          (0x324)
   if r5 != 0 :  var_1C = sub_21AC0(divisor=r5, dividend=r6)   -> r6 / u
   else       :  var_1C = 0xFFFF               (divide-by-zero sentinel)

hop B  (0x0A66DE-0x0A66FE)                          [this cell's delta]
   r5 = U16[FFFF2478] - U16[FFFF247E]         (0x328 - 0x32E, both extu.w)
   if U8[0x84AB] != 0 :  r6 = sub_21AC0(divisor=U8[0x84AB], dividend=r5)
   else               :  r6 = 0xFFFF

combine (0x0A6704-0x0A671A)
   r5 = var_1C - r6
   clamp: low -0x8000 (mov #h'80 / shll8), high 0x7FFF ; signed saturate
   U16[FFFF2150+0x31C] = FFFF246C  <- r5       (0x0A671A-0x0A671C)
```

`sub_21AC0` is a signed integer divide (`tst r0,r0` zero guard, `div0s`/`div0u`/`div1` chain) with `r0` = **divisor** and `r1` = **dividend**, already established in WO65064 — reused here, not re-derived.

Two ROM constants drive the arithmetic, both plain calibration bytes read as constants (no table lookup, no axis, no interpolation):

- `U8[0x8AD0] = h'70 = 112` — the fixed gain inside `sub_9D26C` (÷32 after multiplication). No donor label found for `0x8AD0`.
- `U8[0x84AB] = h'32 = 50` — the hop-B divisor. ROM dump `000084A8  00 / 000084A9 00 1E 32` gives `0x84A8=0`, `0x84A9=0`, `0x84AA=0x1E`, `0x84AB=0x32`. WO65306 lists the donor A2L `mDQACON` at `0x000084AB` (`VALUE`, `REC_UBYTE_C`, scale `x*0.015625`, L/min, `0..3.984`, "A/C drive compensation air qty (inclination)").

**What this means for the calibration question:** the consumer touches one donor-labelled calibration byte, and it uses it as a *divisor in a normalisation*, not as a table or axis. No lookup helper (`sub_22C38`/`sub_22C78`/`sub_22D30`/`sub_22F54`/`sub_22B44` family) is called anywhere on this path, and no MMIO store is reached: the chain terminates in `FFFF246C`, a RAM word in the same reset group.

## Reconciliation (additive — WO65892 unedited)

- **WO65892 said:** `bit0` is a "new result published" latch — "set by whichever producer last wrote the `FFFF2150` output band, tested and cleared by the single consumer `sub_A14F0` after it folds the result into `FFFF2150+0x328`".
- **Corrected:** every located `bit0` set site accompanies a **band re-initialisation or an early exit**, not a value publication. `0x0A088E` sets bit0 (`mov #h'26,r0 / or.b #1`) and then branches to `loc_A08EC`, which writes `FFFF2150+0x3DA` and **zeroes** `0x328`, `0x2A4`, `0x33A`, `0x33C`, `0x31C` (`0x0A08F2`–`0x0A0906`, all with `r2 = IVECT1 = 0`). `0x0A5402` does the same at `0x0A5408`–`0x0A5420`. `0x0A1A28` sits on the tail `loc_A1A26`, reached by the three early-exit branches `0x0A1510`, `0x0A151A`, `0x0A1524` (gated on `FFFF3564.bit4`, `FFFF354B.bit5`, `FFFF34D2.bit4`) and returns without storing anything.
- **So bit0 is a work-request / band-reset latch**: "the `FFFF2150` measurement band must be recomputed", cleared by `sub_A14F0` only after it has actually written a fresh `FFFF2478`. The consumer-side sequence in WO65892 is unchanged; only the producer-side semantic is corrected.
- **Corollary:** the value writers to `FFFF2478` are the three `sub_9D26C` callers, **not** the two `IVECT1` writers. WO65892's row `0x0A5402 … after storing to FFFF2150+0x115/0x3DA/0x328/0x2A4/0x33A/0x33C` is accurate as a store list but must not be read as a publication of a computed value into `0x328`.
- **Confidence:** high (each site read directly at its PC). **Limit:** the `0x000A06xx`–`0x000A08xx` producer block was read only far enough to establish what `0x0A08F2`–`0x0A0906` store; its other cells are outside this WO.
