## Findings

### Map storage and per-map output

Each map is 64 signed big-endian words (`8×8`, `0x80` bytes); the next map begins immediately after the previous map. SH-2 `mov.w` sign-extends each fetched cell, and the result is written unchanged as a word into its own internal RAM slot.

| ROM table | Signed cell range / unique cell values | Indexed read PC | Output store PC / destination |
|---|---:|---:|---|
| `0x0B422–0x0B4A1` | `-7066..-6569` / 17 | `0x96C7A` | `0x96C7E` → `FFFF2150+0x748` |
| `0x0B4A2–0x0B521` | `-1553..-1090` / 18 | `0x96C6E` | `0x96C76` → `FFFF2150+0x74A` |

### Shared query and indexing mechanics

- `sub_969C2` is reached by the direct call at `0x70882` through the pointer at `0x70A74`. It sets GBR to `FFFF9C10` at `0x969D8`.
- Row index `r13` uses unsigned query `UWORD[FFFF1D12+0x30]` = `UWORD[FFFF1D42]`, loaded/zero-extended at `0x96B28–0x96B2E` and reloaded at `0x96BEE–0x96BF0`. Its explicit UWORD axis is `0xFEB0–0xFEBF`: `[200, 550, 900, 1100, 1400, 1800, 2200, 5000]`.
- Column index `r4` uses unsigned query `UWORD[FFFF859C+0x16]` = `UWORD[FFFF85B2]`, zero-extended at `0x96A12–0x96A14`. Its explicit UWORD axis is `0xFD9C–0xFDAB`: `[80, 112, 144, 176, 208, 240, 272, 800]`.
- Both searches start at index 0 and advance while the query is greater than or equal to the current axis value, stopping at the first strictly greater value or index 7. Exact equality advances to the following entry; queries at or above the last entry saturate at index 7. No scale transform or interpolation is applied in these four map reads.
- The cell byte offset is `16*r13 + 2*r4`, shared by all four tables; each cell is a discrete row/column selection. `0xFEA0` is also scanned earlier in this routine for a separate calculation; immediately before the inline maps, `r4` is reset and the map's column axis is loaded from `0xFD9C`.

### Functional boundary

The four maps are parallel inputs to one indexed lookup sequence in `sub_969C2`, not four separately identified software functions. Their values are staged in distinct adjacent words at `FFFF2150+0x748..0x74E`. The bounded trace does not establish a semantic identity for any slot, a later consumer, units, or a physical endpoint.

No required access fell within WO65062's `FFFF85C4–FFFF85FF` or `FFFF860B–FFFF860F` ranges: the only query in that general structure is `FFFF85B2`, below the WO65062 slice. No WO65062 investigation was duplicated or changed.

**Confidence:** HIGH for ROM extents, signed-word interpretation, selector mechanics, and RAM destinations; unresolved for semantic purpose and downstream/physical meaning.
