**Status:** ACTIVE (concurrent with WO65062/WO65063 by explicit user authorization, 2026-11-20)

## Decision question

For the 128 UWORD slots in ROM `0x9700–0x9800`, which slots are actually consumed by code, through which absolute-pointer load, at what width and displacement, and which of those reads feed a compare-and-branch (threshold gate) rather than a plain data transfer?

## Scope

ROM `0x9700–0x9800` inclusive (128 UWORD slots). Methods applied:

1. Complete `mov.l` literal-pool load census with resolved value inside the window.
2. For each load, first same-register memory access, resolved to byte EA where the addressing form is `@Rn` or `@(disp,Rn)`; `@(R0,Rn)` treated as dynamic.
3. Forward scan for the first `cmp/*` after that access, plus the immediately following branch.
4. Slot-level coverage: which of the 128 slots are reached, with what width.

## Detailed traces (three selected sites)

### 1. `0x97AE` = `0x1A2C` (6700) — two-channel saturation ceiling in `sub_5919A`

`sub_5919A` sets `GBR = 0xFFFF8D5C` at `0x591AE` (`word_592F2` = `h'8D5C`, `ldc r0,gbr`).

- `0x59862 mov.l off_599DC,r2 ; h'97AE` → `0x59864 extu.w r13,r0` → `0x59866 mov.w @r2,r5` (= 6700) → `0x59868 extu.w r5,r5` → `0x5986A cmp/ge r5,r0` → `0x5986C bf 0x59874`; on the not-less path `0x5986E bra 0x59874` / `0x59870 mov r5,r0`.
- Net effect: `r0 = min(r13, 0x1A2C)`, stored at `0x5987A mov.w r0,@(h'6C,gbr)` → RAM `FFFF8DC8`.
- Repeated for a second channel at `0x5987C–0x5988A` with `r12` in place of `r13`.
- `r13` originates at `0x591BC mov r7,r13` (a function argument), `extu.w`-normalised at `0x591C0`.

Classification: **hard saturation ceiling on two input channels** into a 16-bit RAM field. It is a calibration *limit* in the strict sense (code cannot emit more than 6700), but this WO does **not** establish that the quantity is engine speed, nor its units — the same routine saturates at `±0x8000`/`0x7FFF` elsewhere, so the field is a signed/normalised 16-bit engineering quantity, not a proven RPM register.

### 2. `0x97F6` / `0x97F8` / `0x97FA` — descending three-stage ladder in `INT_ATU02_ICI0A`

Enclosing routine `sub_25D36` is `INT_ATU02_ICI0A` (entry `0x25D5A`), `GBR = 0xFFFF1054` (`0x25D7E`), `r9 = 0xFFFF1990` (`0x25D88`).

Compared operand provenance (bounded, one hop):

- `0x25DD4 mov.w @(h'16,r10),r0` with `r10 = ATUII_TCNT1A_W` (`word_25ED6` = `h'F440`) → capture timer count.
- `0x25DD2 mov.w @(r0,r8),r5` with `r0 = h'23C` → previous stored value at `FFFF1054+0x23C`.
- `0x25DEC sub r5,r7` → `r7` = counter delta (edge interval); stored at `FFFF1990+0x26E` (`0x25DF2`) and `FFFF1990+0x29E` (`0x25E06`) when `FFFF1E54+3` bit `0x10` is set; otherwise the slot receives `0xFFFFFFFF` (`0x25DF8`).
- At `0x260DA` `r0 = h'29E`, `0x260DE mov.w @(r0,r9),r4` → the compared value is the captured **interval**, not a rate.

Ladder: `0x260E0` reads 10469 → `cmp/ge` → `bf 0x26110`; `0x26110` reads 6250 → `bf 0x26144`; `0x26144` reads 5312 → `bf 0x261D8`. Each accepted rung latches a status code: `FFFF1990+0x1AF..0x1B1`, `FFFF9916+0x6E` copied to `FFFFA378+0xEBB..0xEBE`, and `FFFF1EBD+0xDA..0xDD`.

Classification: **three descending interval thresholds gating a status-latch ladder**. Because the operand is a timer delta, thresholds are in capture-clock counts. Any RPM interpretation requires a divisor from the capture clock, which is **not** established here.

### `971A` = 11586 — conversion divisor, not a gate

`0x6C02C mov.w @r5,r2` (`r5` = `off_6C1E4` → `h'971A`) → `0x6C030 extu.w r2,r0` (so `r0` = 11586) → `0x6C032 jsr @r10` (`off_6C1E8` = `sub_21AC0`), delay slot `0x6C034 mov r6,r1`. `sub_21AC0` is a signed division routine (`tst r0,r0` zero guard, then `div0s r0,r1` / `div0u` / 8–16 × `div1 r0,r1`), so `r0` is the **divisor** and `r1` the dividend. The `cmp/ge r13,r0` at `0x6C036` therefore compares the **quotient**, not the slot value: `r13 = 0xFFFF8000` (`0x6C020`/`0x6C024`), and `0x6C040 cmp/gt` against `0x7FFF` completes a saturate-to-signed-16-bit. Dividend `r6` at the call = `min(word[FFFF1054+0x5D0] × word[FFFF1054+0x3E6], 65535) × word[FFFF1054+0x4FE]` (`0x6C000–0x6C02E`). Result is written toward `GBR+0x16C` (`0x6C04C`). 11586 is a **scale divisor**.

### `971C` = 7200 — fallback constant in an output record

`0x8D44C cmp/hs r5,r2` with `r5 = 1` tests a byte; `0x8D44E bf 0x8D45C` takes the false path, which is `0x8D45C mov.l off_8D50C,r4 ; h'971C` → `0x8D462 mov.w @r4,r2` → `0x8D464 mov.w r2,@r5` — a **store** of 7200, no compare. The true path stores `word[0x95A0]` instead (`0x8D450–0x8D45A`). The same pair repeats at `0x8D46A–0x8D47C` for the next field. So 7200 is the default written when the selection byte is 0; the live alternative is the neighbouring-block word `0x95A0`, which is **outside** `0x9700–0x9800` and untraced here.

### `9754` = 31232 — subtractive span endpoint

All five loads are `mov.w @rN` and all feed `31232 − word[FFFF9860+0xFF88]`:

- `0x73256 mov.w @r2,r5` → `0x73262 sub r7,r6` with `r7 = word[FFFF9860+0xFF88]`; then `r1 = r6×255` (`0x73264 shll8`, `0x7326A sub r6,r1`), divided by `word[0x936E]` via `sub_21AC0` (`0x7326C`), then compared to `r8` (`0x73270`).
- Same shape at `0x7328C`, `0x73A18`, `0x73A48`.
- `0x0B966C`–`0x0B9682`: `r6 = 31232 − word[FFFF9916+0xFF88]`, then `cmp/pz r6` / `bf` → `r6 = 0` when negative. This is the `cmp/pz r6` site section C already excluded from the threshold list; here 31232 is the **subtraction reference**, i.e. a span/offset constant.

`0x9756` = 15616 = exactly `0x7A00/2` sits immediately after it — a 2:1 pair worth carrying into the neighbouring-window pass. No semantic claim.

### `9760` = 1280 — minimum on a scaled value (`sub_6D4BC`)

`0x6D72A mov.l off_6D938,r3 ; h'9758` → `0x6D72E mov.w @(8,r3),r0` (1280) → `0x6D730 extu.w r0,r4` → `0x6D732 cmp/ge r4,r14` → `bt 0x6D738`, else `0x6D736 mov r4,r14`. Net: `r14 = max(r14,1280)`, then stored by `0x6D73C mov.w r14,@(word_6D7B2,r9)` (`r9 = FFFF2150`, `word_6D7B2` = `h'892`).

Operand chain immediately above: coefficient `word[0x10BA4 + 2×n]` with `n` = byte `word[FFFF84B4+2]` capped at 4 (`0x6D6EC–0x6D704`), `mul.l` by `word[FFFF84C8+0x48]`, 5 × `shar` (÷32) (`0x6D70C–0x6D71A`), then `sub_21BE4` with `r0 = 25` (also `div0u`/`div1` → divide) — a `×coef ÷32 ÷25` correction chain. `0x6D722 cmp/hi` against `0x9700` = 8192 selects the converted value only above 8192, otherwise `word[FFFF84C8+0x48]` itself is used. 1280 is a **lower bound on that corrected value**, not a saturation ceiling.
