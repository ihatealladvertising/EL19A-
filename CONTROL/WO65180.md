## Coordinator investigation result — 2026-11-22

### 1. Corrected callsite identity and argument flow

The pinned LST proves that 0x39FD2 is not a helper call. It loads the first table base (0x0B756) into r4. The actual helper calls are 0x39FE2 for 0x0B756 and 0x39FF4 for 0x0B7D6.

loc_39FB8 establishes GBR=FFFF86D4 at 0x39FC6/0x39FC8, reserves a four-byte local argument area at 0x39FCA, and loads r10=FFFF8494 at 0x39FCC and r11=FFFF859C at 0x39FCE.

| Helper call | Table base (r4) | Axis 1 (r5) | Query 1 (r7) | Axis 2 (r6) | Query 2 (stack arg) | Result store |
|---|---|---|---|---|---|---|
| 0x39FE2 | 0x0B756 (loaded at 0x39FD2) | 0x0FCFC | UWORD[FFFF85B2] | 0x0FD3C | UWORD[FFFF8494] | UWORD[FFFF86E2] at 0x39FE6 |
| 0x39FF4 | 0x0B7D6 (loaded at 0x39FEE) | 0x0FCFC | UWORD[FFFF85B2] | 0x0FD3C | UWORD[FFFF8494] | UWORD[FFFF86E0] at 0x39FFA |

Instruction-level argument setup:

- 0x39FD0 mov.w @r10,r0 reads UWORD[FFFF8494]; 0x39FD4 stores it in the local stack argument slot at @(2,r15).
- 0x39FD6 mov.w @(0x16,r11),r0 reads UWORD[FFFF859C+0x16] = UWORD[FFFF85B2]; 0x39FDC extu.w r0,r7 zero-extends it for axis 1.
- 0x39FD8/0x39FDA load the two ROM axis pointers; 0x39FE0 mov r12,r5 supplies axis 1; the delay slot at 0x39FE4 mov r13,r6 supplies axis 2 to the 0x39FE2 call.
- For the second map, 0x39FEA reloads UWORD[FFFF8494]; 0x39FEC restores axis 2 in r6; 0x39FEE loads 0x0B7D6; 0x39FF0 refreshes the same stack argument; 0x39FF2 reloads UWORD[FFFF85B2]. The 0x39FF4 call's delay slot, 0x39FF6 extu.w r0,r7, sets query 1 before helper entry.

Both query values are passed as raw unsigned words. No scaling, unit conversion or arithmetic transform is applied at either callsite. sub_22CF8 zero-extends the word queries, calls sub_2340C for each supplied UWORD axis, and performs the existing UWORD 8×8 interpolation. The table result is a raw UWORD; no output engineering-unit conversion is applied in the helper or immediately after either call.

### 2. The two maps are both evaluated, not mutually selected

The two calls execute sequentially in the same loc_39FB8 path:
1. 0x0B756 is looked up and stored to FFFF86E2.
2. 0x0B7D6 is then looked up with the same queries and axes and stored to FFFF86E0.

There is no selector branch between these calls choosing one map instead of the other. The evidence supports two parallel lookup terms, not mutually exclusive operating-mode banks. This corrects any interpretation of the pair as a proven selector-controlled normal/trustful or acceleration/deceleration bank pair.

### 3. First meaningful consumers and output arithmetic

The routine continues under GBR=FFFF86D4. The first reads of the two staged results are separate but closely parallel accumulator paths.

#### Map 0x0B756 → FFFF86E2 → FFFF3456

- 0x3A0DA loads LONG[FFFF86D4].
- 0x3A0D8 loads UWORD[FFFFA3A4].
- First read of the map result: 0x3A0E0 mov.w @(0x0E,gbr),r0 reads UWORD[FFFF86E2]; it is zero-extended at 0x3A0E4.
- 0x3A0EA adds this map result to the running accumulator.
- 0x3A0EC reads UWORD[FFFF2150+0x1FC]; 0x3A0EE adds it as a further term.
- The sum is compared with 0x17FFF at 0x3A0F0. When above the ceiling, the output is 0xFFFF; otherwise the code checks against 0x8000, emits zero if below that bias, or subtracts 0x8000.
- The resulting UWORD is stored to FFFF3456 at 0x3A128. The bounded pre-output accumulator is also staged as LONG[FFFF86DC] at 0x3A0F8 on the non-over-ceiling path.

#### Map 0x0B7D6 → FFFF86E0 → FFFF3458

- 0x3A12E loads LONG[FFFF86D8].
- 0x3A12C loads UWORD[FFFFA3A6].
- First read of the map result: 0x3A134 mov.w @(0x0C,gbr),r0 reads UWORD[FFFF86E0]; it is zero-extended at 0x3A138.
- 0x3A13A adds the map result to the running accumulator.
- 0x3A142 reads UWORD[FFFF2150+0x1FE]; 0x3A144 adds it as the final term.
- The same 0x17FFF ceiling and 0x8000 bias handling apply: above ceiling emits 0xFFFF; below bias emits zero; otherwise the bias is subtracted.
- The resulting UWORD is stored to FFFF3458 at 0x3A164. The bounded pre-output accumulator is also staged as LONG[FFFF86D8] at 0x3A14E on the non-over-ceiling path.

Software-role result: these are parallel correction contributions to two separate accumulators/outputs, not a selectable map pair. The result is added to the respective LONG state and two other UWORD terms, subjected to a shared ceiling/bias transformation, and emitted at FFFF3456 or FFFF3458. The downstream physical role of either output remains unknown.

### 4. Meaning of the constant 0x0B7D6 surface

WO65137's raw map decode establishes all 64 cells of 0x0B7D6 as 0x8000; no payload/axis decode was repeated here. Since the helper returns the constant surface value, its contribution to the second accumulator is the constant UWORD 0x8000. The consuming path then applies an 0x8000 bias subtraction (or zero-floor) after summing the other terms. Therefore, within the observed arithmetic, the constant map supplies the neutral bias term rather than an independently varying correction.

This is stronger than calling the table disabled: the map is read and its returned value participates in the active accumulator path. It is not evidence that the table is a trustful/secondary bank, nor does it prove why the calibration is constant.
