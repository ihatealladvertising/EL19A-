## Objective

WO65733 proved the `unk_FFFF2150` limit fields `A1C`/`A1E`/`A20`/`A22` are written by the leaf routine at `0x6D4A0`–`0x6D4B0` from registers `r14` (→`A1C`), `r13` (→`A1E`), `r7` (→`A20`) and `r4` (→`A22`, after `r4 := max(r4, U16[FFFF2BA2])` at `0x6D496`–`0x6D49E`). It stopped at the routine's `rts` and did not trace where those four registers come from. This WO closes that gap: **what computes the values the bound publisher commits?**

## Mandatory falsifiable hypothesis

- **Identity layer advanced:** input identity (the value source of the `FFFF1640` clamp bounds).
- **Hypothesis:** the four bound values are read from existing RAM measurements (the fields themselves, a single limit word, or a table indexed by a mode selector), i.e. the publisher *forwards* an already-computed bound rather than deriving a new one.
- **Evidence:** WO65733 §3 cluster 2 (register map, `r14 = 0x7FFF` seen in cluster 1 at `0x29C44`, the `max()` against `FFFF2BA2`); WO65733 §3 cluster 3 (`sub_67D0C` stamps `0x7FFF`, so `0x7FFF` is the "no limit" sentinel).
- **Prediction:** if the hypothesis holds, each of `r4`, `r7`, `r13`, `r14` is loaded from a RAM address (or a `0x7FFF` immediate) within the enclosing function before `0x6D4A0`; if instead an arithmetic derivation appears (scaling, multiplication, table interpolation), the hypothesis is rejected and the bounds become firmware-derived.
- **Cheap discriminator:** find the enclosing function start for `0x6D4A0` and read backwards to the first store to each of the four registers; classify each as RAM-load / ROM-literal / computed.
- **Information gain:** decides whether the clamp bounds are forwarded (and therefore nameable by their source measurement) or genuinely computed (and must stay opaque).

## Scope

1. Locate the function containing `0x6D4A0` (search backwards for its prologue and the nearest label) and report its start and end.
2. For each of `r14`, `r13`, `r7`, `r4`, report the **first** instruction that establishes the value used at `0x6D4A4`/`0x6D4A8`/`0x6D4AC`/`0x6D4B0`, with PC, form and source (RAM address, ROM literal, or arithmetic).
3. Classify each of the four as `forwarded-from-RAM`, `constant`, or `computed`; for `forwarded-from-RAM`, record the source address and whether it is a known measurement.
4. Trace at most **one** level further for any `computed` value (the operation and its operands only).
5. State whether `FFFF2BA2` (the `max()` operand) is itself written by either initializer cluster, or only read.
6. Stop at an indirect dispatcher, a peripheral/CAN read, or after the four register sources plus one level.

## Result — upstream register sources

**Verdict: the simple-forwarding hypothesis is rejected.** The publisher commits a branch-selected set of existing RAM state values, including a minimum-selection operation and a sentinel-backed clamp. The sources are not established physical measurements and receive no calibration names.

**Enclosing function:** sub_6D274, start 0x6D274, end 0x6D4BA (RTS at 0x6D4B8; delay-slot restore at 0x6D4BA). The publisher at 0x6D4A0 is reached after the status/selection logic below.

### Active path selection for f501.bin

Two ROM bytes determine the relevant control-flow path:

- U8[0x8405] = 0x0C, so bit 0 is clear. At 0x6D420–0x6D424, TST #1 sets T=1 and BF/S at 0x6D422 is not taken. Execution falls through into the state-selection path at 0x6D426; its delay-slot instruction at 0x6D424 still copies r6 to r7.
- U8[0x8B0E] = 0x02, so bit 0 is clear. The later TST/BT at 0x6D436–0x6D43A selects the A2E branch; the corresponding test at 0x6D48A–0x6D492 also selects A2E.

The remaining branch selector is RAM byte U8[FFFF3628+0x0C] bit 6. Both outcomes are recorded below.

### One-level source detail

- FFFF9910 and FFFF990E are UWORD members of the FFFF9860 RAM block (offsets +0xB0 and +0xAE). FFFF9910 supplies the pre-clamp r4 value when the 0x60 status mask is nonzero; FFFF990E supplies r14 when the 0x50 status mask is nonzero. Neither is copied to r7 on the active bit-6-clear path, because r6 is overwritten with 0x8000 at 0x6D418 before r7 is assigned at 0x6D424. No existing diagnostic-variable/crosswalk label establishes either as a physical measurement. Their producers are not chased.
- FFFF2B7E (A2E), FFFF2BA2 (A52) and FFFF2BB2 (A62) are fields in the FFFF2150 firmware-state band. A2E is initialized by sub_67D0C to 0x7FFF; A52 is initialized to 0x8000 as detailed below; A62 has no physical label established here.
- The status selector is U8[FFFF3628+0x0C].bit6. No semantic name is assigned to this flag.
- The pre-branch calculation uses U16[0x90C8] = 0x030C and U16[FFFF9910] / 0x7FFF to form a minimum for r13, but this value is overwritten by the active A2E load. No measurement identity is inferred from that dead result path.

### FFFF2BA2 writer check and correction

**FFFF2BA2 is written by initializer cluster 3; it is not read-only.**

- In sub_67D0C, r4 = FFFF2150 and r2 is initially loaded from U16[0x90CC] = 0x7FFF. Fourteen listed fields are written with that value.
- At 0x67D54, r2 is replaced by immediate 0x80. At 0x67D56 the A52 offset is loaded; 0x67D58 shifts r2 left by 8. Its low word is 0x8000.
- At 0x67D5A, that 0x8000 is stored at offset A52, i.e. FFFF2150+0xA52 = FFFF2BA2. The RTS delay slot at 0x67D60 stores the same 0x8000 at A58 (FFFF2BA8).
- Cluster 1 at 0x29C10–0x29CBC writes A54 and other listed fields but does not write A52. Cluster 3 is the identified initializer writer for FFFF2BA2.
- The publisher reads U16[FFFF2BA2] at 0x6D496 on the bit-6-clear path. On the bit-6-set path it loads the same field directly into r4 at 0x6D448.

**Correction to WO65733 §3:** its statement that all sixteen sub_67D0C fields receive 0x7FFF is too broad: fourteen receive 0x7FFF, but A52 and A58 receive 0x8000. Its description of the 0x6D496 operation as r4 := max(r4,U16[FFFF2BA2]) is also reversed. The instructions 0x6D498–0x6D49E implement a signed minimum selection, not a maximum. This correction is recorded here only; WO65733 and FINDINGS/INDEX.md were not edited under this WO's authorization.

### Resulting bound interpretation

- r13 is forwarded from the existing A2E RAM state field on the active f501 path.
- r14 is selected from U16[FFFF990E] or zero on the bit-6-clear path, and from A62 on the bit-6-set path. r7 is 0x8000 on the bit-6-clear path and A62 on the bit-6-set path.
- r4 is computed by a signed minimum operation involving A52; A52's initializer value is 0x8000, but no global writer census was performed, so runtime persistence of that value is not asserted.
- None of the four source addresses is established as a physical sensor measurement or a calibration table. Keep the band as firmware state; do not add a physical name, unit, scaling or RR object.
