## Objective

WO65730 proved that in the donor A2L family the `-64` is a **display conversion** (`COMP_0245 "X-64deg"`) attached to the trimming maps `vLADVTRM`/`vADVTRMAP`/`vADVTRM`, and that the target's ignition-family objects (`0x9B2E`, `0x9C2E`, `0x9DAE`) are raw UBYTE with no established conversion. The open target-side question is concrete: **does any instruction apply a 64-count bias to a selected ignition-family map value before its first meaningful consumer?** Decide supported / rejected / unresolved.

## Mandatory falsifiable hypothesis

- **Identity layer advanced:** output identity (scaling of the ignition-family maps).
- **Hypothesis:** the EL19A ignition-family map output receives a 64-count bias (the structural analogue of the donor's `X-64deg`), so the raw UBYTE is not the final angle.
- **Evidence:** WO65730 §2/§4 (donor conversion and the absent/unresolved target stages); WO65287 (no raw-to-degree conversion in its bounded path); the v1 definition's `Raw_UBYTE` scaling for `0x9B2E`/`0x9C2E`/`0x9DAE`.
- **Prediction:** if the bias exists, an `add #h'40` / `add #-64` / `sub #h'40` (or a 64-valued literal-pool word added to the map result) will appear between the map read and its first consumer; if the map result reaches a consumer unmodified, the hypothesis is rejected.
- **Cheap discriminator:** from the reader that consumes `0x9B2E`/`0x9C2E`/`0x9DAE`, follow the result register to its first consumer and look only for 64-valued biases (`h'40`, `h'C0`, `#-64`) on that path.
- **Information gain:** either gives the EL19A ignition maps a defensible bias (changing their XML scaling note) or confirms they must stay raw — both outcomes are decisive and neither requires the donor chain.

## Scope

1. Identify the reader(s) that return the `0x9B2E`/`0x9C2E`/`0x9DAE` payload and the register carrying the result (reuse WO65287's trace; do not re-census the tables).
2. Follow that result to its **first** consumer. Report the instruction sequence between read and consumer.
3. Search that bounded window for a 64-count bias in any form: `add #h'40`, `add #h'C0` (i.e. −64), `sub #h'40`, a pool word `00 40`/`FF C0` used in an add, or an explicit `exts`/`extu` followed by an offset add.
4. Report every bias found with PC, form and width; state whether it applies to the map value or to a different operand in the window.
5. State the verdict for each of the three maps separately, since they are runtime-selected aliases of different payloads.
6. Stop at an indirect dispatcher, a CAN/ADC read, or after the first consumer of each map.

## Result — target-side 64-count bias test

**Verdict: HYPOTHESIS REJECTED for 0x9B2E, 0x9C2E and 0x9DAE.** No +64, -64, 0x40, 0xC0 or equivalent literal-pool bias is applied to any selected map result before its first meaningful consumer. Keep all three calibration objects as raw UBYTE; do not add a 64-count offset or degree conversion.
