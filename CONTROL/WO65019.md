## Findings / closeout — 2026-11-17

### TRAPA vector rule
- SH7058 SH-2 TRAPA dispatch reads the longword at `VBR + (imm × 4)`; execution resumes at the fetched address plus 4. For `#0x3E`, vector slot offset is `0xF8). Source: Renesas SH-2E Software Manual, Rev. 2.00, §7.2.65, p.162; SH7058 Hardware Manual Rev.3.0, Table 6.4 / Table 6.3, p.89. (The instruction is not a generic jump to one fixed ROM handler.)

### Site results
1. **`0x26BC` — ROM `INT_TRAPA62` confirmed; conditional startup/reset path.**
   - `Poweron_Reset` checks the longword at `0xFFF84` against `0x4E4855F9`; if unequal it tests bit0 of byte `0xFFF80`. Either signature match or bit0 set reaches `0x26B8`.
   - Loads VBR=`0x20004` at `0x26BA`; slot=`0x20004+0xF8=0x200FC`; vector longword=`0x00025004` → `INT_TRAPA62`.
   - `INT_TRAPA62` calls `sub_20DCE` at `0x250A6–0x250A8`, so this is a confirmed route into the 122-callback dispatcher. After return, `Poweron_Reset` sets VBR=`IVECT1` (zero) at `0x26C4`. This is a conditional startup/reset event, not evidence of a periodic cadence.
2. **`0x10F4` — VBR inherited; conditional handler.**
   - Located in `sub_1082`, in the `r0==0x11` branch after `sci_send_message_type2` at `0x10F0`; next instruction sets `r5=IVECT1`, then executes TRAPA.
   - No VBR write occurs in the local call window. Under VBR=0, slot `0x00F8` contains `0x000026F8` → `loc_26F8`, a separate initialization/re-entry sequence (stack reset, `sub_2AA4`, `sub_3E54`, `sub_3B64`, `sub_2A2C`, `sub_42DA`, then `sub_3A0)); it is not `INT_TRAPA62`.
   - Runtime VBR at this site is not globally proven: it depends on preceding context. Temporary VBR changes at `0x982/0xC4A` save and restore the prior VBR; other code can explicitly select alternate bases. Do not attribute this site to the 122-callback dispatcher without establishing its live VBR.
3. **`0x157E` — custom RAM vector slot; target unresolved.**
   - In `loc_154E`; reached only if `sub_33FE()` returns `0x40` and byte `FFFF83D3` equals `2`.
   - Explicitly loads VBR=`FFFF8504` at `0x157C`; vector slot is `FFFF85FC`. This is RAM, not the ROM vector at `0x200FC`; its runtime longword target is not established. No evidence links this site to `INT_TRAPA62`.
4. **`0xB8766` — alternate VBR; no valid handler identified.**
   - In `sub_B862C`, called from `0xB59A0` and `0xB5CA4` for input-byte paths where `r4 >= 0xF0`.
   - `r1` is loaded with `0x6F00` from literal `off_B86B8` at `0xB8630` and remains the VBR value at `0xB8764`. Vector slot=`0x6FF8`; ROM bytes there are `FF FF FF FF`, not a valid code pointer. Treat this as an invalid/sentinel vector path; exact intended recovery behavior is unresolved. It does not establish a route to `INT_TRAPA62`.

### Additional direct-dispatch path
- `alt_Poweron_Reset` at `0x21A9C` branches to `loc_21AA8`, which sets VBR=`0x20004` and directly jumps to `INT_TRAPA62` at `0x21AB2`. This is a separate direct trampoline, not one of the four TRAPA instructions; it confirms another controlled entry to the handler.

## Conclusion
- Four actual `trapa #0x3E` code sites exist: `0x10F4`, `0x157E`, `0x26BC`, `0xB8766`.
- Only `0x26BC` is directly proven to route through ROM vector `0x200FC` to `INT_TRAPA62 → sub_20DCE`. The separate `alt_Poweron_Reset` trampoline also reaches `INT_TRAPA62` without a TRAPA instruction.
- The other sites use inherited, RAM-based, or alternate VBR contexts; none is proven to invoke the 122-entry callback dispatcher.
- No fixed periodic cadence is established. The contexts observed are conditional startup, SCI/message event, state-gated RAM-vector call, and high-byte input/helper path.
