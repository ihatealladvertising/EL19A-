## Objective
Produce an exact, reproducible byte-coverage ledger for EL19A ROM range `0x8000–0x18000`, subtracting all verified table/data extents, axes, diagnostic records and scalar pools to isolate unaccounted ROM islands.

## Required work
1. Pin canonical ROM and listing identities; reuse merged table catalogue, XML v3, ignition fragment, DTC/Consult indexes and prior scalar/limiter sweep results.
2. Build a normalized interval inventory with source, start/end (exclusive), confidence, storage type and overlap/alias notes. Do not treat a candidate start address or fixed 256-byte probe as a verified extent.
3. Include only reader/format-supported extents; distinguish verified objects, provisional candidates, known code, padding/fill and unclassified bytes.
4. Compute union coverage and exact residual intervals; report non-0xFF and 0xFF byte counts per residual island.
5. Rank residual islands by evidence: code/data references, literal pointer targets, indexed/computed access clues, alignment and density. Recommend bounded next probes without executing them.

## Acceptance criteria
- Reproducible interval ledger and summary counts; overlapping extents are unioned once and separately reported.
- Every subtraction has a cited source record and confidence grade.
- Explicitly reconcile the 76 XML v3 tables, 6 ignition/knock fragment entries, 179 catalogue entries, known axes, DTC/Consult blocks and completed scalar pools, without double-counting.
- Output exact residual ranges and top 25 unexplained islands with reason for priority.
- Clearly state that unaccounted bytes are not automatically calibration tables.

## Boundaries
Read-only accounting only. No new broad scan or speculative table census; no ROM/LST/XML/workbook/catalogue/index/script/tool edits. Reuse existing interval evidence. If a source does not provide a trustworthy extent, leave it unaccounted and flag it—do not invent a size.

### 5. Reconciliation / contradiction notes
1. XML v3 76 + ignition 6 + catalogue 179 rows overlap heavily; overlaps are unioned once (2,264 duplicate bytes).
2. `INDEX/dtc_198_crosswalk.tsv` gives slot 0 (P0500) `rec_rom_addr 0x12E38`, but WO65090/WO65107 put the 197-record block start at `0x12E44`; `0x12E38–0x12E43` (12 B) is left unaccounted and flagged. Not resolved here.
3. `0x12E38` is also the selector-table address read by `sub_74212` (WO65171) — a second, independent consumer claim on the same bytes; supports leaving it unaccounted until reconciled.
4. 198 DTC descriptor pointer targets all fall inside `0x1135A–0x119C4`; objects are pointer-proven but unsized, so the island stays residual.
