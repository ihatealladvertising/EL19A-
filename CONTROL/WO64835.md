## Stage 3 — TEST results (2026-11-16)

### Query provenance — traced to CAN mailbox word
- `sub_AAAE0` loads UWORD `FFFFA324+0x14 = FFFFA338`, shifts right eight and zero-extends the result. Thus `q = byte0(FFFFA338 word)`; on SH-2 big-endian this is the first byte of the 16-bit word.
- At PC `0x20F68–0x20F72`, a 0x28-byte copy refreshes `FFFFA324` from `FFFFA34C`; therefore query word source is `FFFFA360` (source block +0x14).
- `sub_288B4` runs with GBR=`FFFFA34C`; PC `0x28932` loads symbol `HCAN1_MB12[0][1]_W` at `FFFFDA80`, and PC `0x28938` stores that UWORD at GBR+0x14 = `FFFFA360`. So the lookup query is the **first byte of HCAN1 mailbox 12 data bytes 0–1**.
- The same word is also copied by `sub_288B4` to `FFFFB336` and `FFFFB5AE`. A second bounded path (`sub_387B4`, PC `0x387C8`) reads the same mailbox word and can place its high byte into `FFFF8578`, subject to a status gate at `FFFFB600.bit7`.
- `sub_288B4` is called from `sub_241EE`; the scheduler/update cadence and CAN arbitration/message identifier were not established. The label identifies the mailbox payload address, not the frame ID or signal definition. No local ADC read is present in this query-producing path.

### Axis endpoint behaviour — confirmed for this exact object
- Axis bytes: `00 05 06 19 32 4B 64 7D 96 AF C8 E1 FF FF FF FF`; data bytes: `00 00 46 4B 52 5A 61 68 6F 76 7D 85 8D 8D 8D 8D`.
- `sub_233CC` scans downward from index 15. For queries 0–254 the four repeated terminal `FF` points are skipped and the top interpolation interval is index 11 (`E1`) to index 12 (`FF`). Queries below the lowest axis breakpoint clamp to index 0; query 255 exact-matches the final duplicate at index 15.
- On exact-breakpoint paths the helper retains raw Q in the fraction register. `sub_231C8` uses the high 16 bits of the product without rounding. Since both the data delta and raw Q are at most 255, `delta × Q < 65536`; the exact-point interpolation adjustment is therefore zero and the exact data point is preserved.
- At q=255, `sub_22F28` physically reads data[index15] and the adjacent byte at F072. F072 is `0x1B`. This is a one-byte look-ahead beyond the 16-point logical payload, but the raw fraction is only 255/65536 and the product truncates to zero, so the returned value remains data[15] = `0x8D`. Record the adjacent read; do not count F072 as a logical table point.

### Output consumers — traced to internal control use
- `sub_AAAE0` stores the returned UBYTE at `FFFF2150+0x848 = FFFF2998` (PC `0xAAAFE`).
- Eleven direct reader sites of offset `0x848` from base `FFFF2150` were found in the bounded listing: PCs `0x75C56`, `0x9C54C`, `0x9CF86`, `0x9EA60`, `0x9ED08`, `0x9F2F4`, `0x9F630`, `0xA0DBA`, `0xA1204`, `0xA1924`, `0xA6052`.
- The consumers treat the byte as an unsigned numeric operand: multiply by runtime bytes/values, scale (often ×2), saturate to UWORD `0xFFFF`, then apply range/validity comparisons and set or clear internal flags/state. Example: `0x75C56` tests the lookup result for zero; when nonzero it scales another calculated value and calls `sub_21BE4`, storing to `FFFF3454+0x24`. The `0x9C54C` / `0x9CF86` / `0x9EA60` families similarly multiply it by other runtime operands and use the result in threshold qualification.
- Furthest demonstrated endpoint is internal numeric correction/qualification and status state. No direct ADC pin, physical pressure sensor connector, CAN frame ID, or terminal actuator/peripheral write was established.
