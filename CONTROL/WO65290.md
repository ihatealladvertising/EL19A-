## Mandatory falsifiable hypothesis record

- **Identity layer advanced:** function identity, input/axis identity and output identity. No physical-semantic promotion.
- **Hypothesis:** E700 and E708 may be dwell-related curves and A452 may participate in an ignition/idle schedule; donor labels and morphology alone cannot name them.
- **Evidence:** exact EL19A ROM addresses, instruction PCs, caller/reader contracts, target ROM bytes, and source-class separation between target evidence and donor/XML metadata.
- **Prediction:** if supported, a target-side reader/caller/consumer path and query/axis inputs should distinguish dwell voltage/RPM compensation from idle/cranking spark correction.
- **Cheap discriminator:** bounded reuse of existing reports/indexes plus narrow LST/ROM reads at the three named candidates and their immediate callers only.
- **Result:** **weakened/rejected for semantic promotion.** E700 has a verified reader and consumer path, but its query collapses to constant `8` in this ROM; E708's result is a dead store; A452 has verified reader/axes and reaches a multi-curve control scheduler, but no spark/dwell/idle/crank endpoint or battery/RPM/idle-state input was found.
- **Information gain:** separates structural validity from function. Generic RR rows can be retained with verified geometry; ignition/dwell names cannot be safely populated.

## Executive finding

The dwell-family hypothesis is supported only at the **donor morphological-fingerprint** layer. On the target, E700 and E708 are separate 8×1 UBYTE reads by the same fixed-grid helper in one gated `loc_451C2` body. E700's output reaches a bounded state byte; E708's output never leaves staging. A452 is a structurally valid 8×8 UBYTE map with explicit axes, but its immediate caller is a generic multi-curve scaling/combination routine with temperature-like and unresolved numeric inputs. No target instruction in this bounded scope identifies battery voltage, engine speed, coolant temperature, idle state or cranking state for any of the three candidates.

`FFFF99F0.bit6` gates entry to the E700/E708 block (`0x45170–0x45178`); the physical meaning of that gate is unresolved.

## 1. E700 / E708 — exact target reader and dataflow

### Geometry and reader references

| Candidate | Extent / storage | Reader call PC | Helper | Query cell | Output cell | Grid |
|---|---|---|---|---|---|---|
| `0x0E700` | `E700–E707`, 8×1 UBYTE | `0x452DA` | `sub_22DF8` | `FFFF11B8` | `FFFF11B9` | fixed `0,32,64,96,128,160,192,224` (`loc_23508`, WO65060/WO65133) |
| `0x0E708` | `E708–E70F`, 8×1 UBYTE | `0x452EE` | `sub_22DF8` | `FFFF11BC` | `FFFF11BD` | same fixed grid |

`sub_22DF8` zero-extends the query, returns the last byte when query `>= 0xE0`, otherwise jumps to `loc_23508` for the fixed-grid interpolation path. It is a generic 8-point UBYTE reader, not an ignition-specific routine.

ROM payloads read directly from the pinned target:

- `0xE700`: `01 3B 60 7C 96 A4 B4 C4` — strictly increasing.
- `0xE708`: `FF FF FF FF B2 8F 7F 4F` — four sentinel bytes then descending values.

### E700 downstream arithmetic

1. `0x452FA–0x45308`: E700 result from `FFFF11B9` is zero-extended and multiplied by `r12 = 450`, then by the E708 result still held in `r5`.
2. `0x4530A`: `sub_21AC0` is called with divisor `0x14000`; the delay slot at `0x4530C` supplies the product as `r1`. `sub_21AC0` is a signed divide/saturate helper, not a spark-specific routine.
3. `0x4530E–0x4531E`: quotient is clamped to a byte and staged at `FFFF1054+0x4A3 = FFFF14F7`.
4. `0x45320–0x4532A`: that byte is compared with the earlier clamped byte at `FFFF14F6` and the lower value is kept.
5. `0x45332`: final byte stored to `FFFF1D12+0x3B = FFFF1D4D`.
6. `0x45334–0x45340`: if `U8[FFFF3628+0x0A] = FFFF3632` has bit 3 set, the final byte is overridden to `0x18`. No downstream consumer of `FFFF1D4D` was traced in this bounded scope.

This is a real consumer path, but it terminates in internal state. It does not reach a coil command, dwell accumulator, igniter MMIO, idle-speed target or cranking decision. The constant E700 query and the dead E708 output further weaken a dwell-voltage/RPM interpretation.

## 2. A452 — verified geometry, unresolved scheduler role

### Reader and axes

- Data: `0xA452–0xA491`, 64 bytes, 8×8 UBYTE.
- Direct reader: `sub_22C00 @ 0xAEE4C`, the only direct caller indexed for A452 (WO64963).
- Caller: `sub_AEE10`, called once from `sub_AE5C4` at `0xAE6BC`; the delay slot sets `r4=0`, so the indexed output byte uses offset 0.
- GBR in `sub_AEE10` is `FFFF1028` (`0xAEE24–0xAEE26`).
- Reader arguments:
  - `R4 = 0xA452`.
  - `R5 = 0xF576`, first axis; bytes `14 18 20 28 38 48 58 70`.
  - `R6 = 0xF57E`, second axis; bytes `41 50 64 78 82 8C 96 9B`.
  - `R7 = U8[FFFF84BA]` (NTC-derived temperature byte per WO65056), staged from `0xAEE34`.
  - Stack query for the second axis is `U8[FFFF85A4]`, staged at `0xAEE3E`; its producer remains unresolved (WO64869).
- Payload: all eight 8-byte rows are `61 60 50 5B 5E 60 63 64` (seven distinct values). One registered axis is therefore numerically inert for this ROM even though both pointers are structurally valid.
