## Threshold comparison logic (WO65183 reconciliation)

In `sub_3FAEC` (labelled sub_403D8 in WO65183), the comparison occurs at **0x403D2**:

```
0x403CA: jsr @r2 ; sub_3784  → returns value in r6
0x403CE: mov.l r5, @(h'60+var_2C,r15)  ; r5 = ROM[0x7B4D] byte value
0x403D0: mov.l @(h'60+var_2C,r15), r6
0x403D2: cmp/ge  r6, r0          ; r0 = #0xA (ROM[0x8550] = mDSHCUT = 10 raw = -40°C)
0x403D4: bf      loc_40434       ; if r6 < 0xA → jump to loc_40434 (bit5 cleared)
```

- **ROM threshold**: `ROM[0x8550] = 0x0A` (user-verified: mDSHCUT, UBYTE, °C = raw − 50 → -40°C)
- **Query**: value returned by `sub_3784` in r6 (not FFFF84BA directly — see below)
- **When query >= 0xA**: execution continues past `loc_40434`; FFFF1DB4.bit5 **preserved** (existing value retained)
- **When query < 0xA**: branch to `loc_40434`; FFFF1DB4.bit5 **forced clear** (write at 0x4044A with bit5=0)

**Critical finding**: The compared value is the **return of `sub_3784`**, not a direct read of FFFF84BA. The FFFF84BA read at 0x40426 occurs **after** the comparison (at `loc_40422` path), in a different conditional block. FFFF84BA is **not the compared query** in this threshold gate.
