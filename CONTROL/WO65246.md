## Objective

Resolve the untraced whole-byte write candidate at PC `0x63CEE` in `sub_5FA70` against the proven hysteresis update of `FFFF1D81.bit5` in `sub_4E24C`. This byte controls a meaningful downstream query choice: when bit5 is set, the `0xAF72/0xADF2` path can force its second map query to `0xFF`, selecting the last column.

The question: does the whole-byte store at `0x63CEE` preserve, initialize, replace or clear the hysteresis bit, and under what path conditions?

## EA proof — 0x63CEE targets FFFF1D81

| Address | Bytes | Mnemonic | Effect |
|---------|-------|----------|--------|
| 0x63CE8 | D6 80 | `mov.l off_63EEC, r6` | R6 = 0xFFFF1D80 (data at 0x63EEC: `FF FF 1D 80` big-endian) |
| 0x63CEE | 80 61 | `mov.b r0, @(1,r6)` | EA = R6 + 1 = 0xFFFF1D81; byte store |

**Result:** EA = 0xFFFF1D81 proven. The store at `0x63CEE` is an exact whole-byte write to `FFFF1D81`. Width = byte. Base = immediate constant 0xFFFF1D80 loaded via literal pool `off_63EEC`, not GBR-relative. No GBR involvement.

## Guard / branch condition

The store at `0x63CEE` is **unconditional** on this code path — no branch guards it directly. It always executes when reached. The only conditionality is the bit-6 forcing at `0x63CD8`–`0x63CE2`, which depends on an unrelated state value in R6 (low byte compared against 4), not on FFFF1D81 itself.

## Effect on `0xAF72`/`0xADF2` query2 selector

The consumer at `0xAE8E0` (`WO65189` §3) tests `UBYTE[FFFF1D81] & 0x20` (bit5). Since the whole-byte writer preserves bit5 (it reads FFFF1D81 and writes it back, changing at most bit 6), this write path does **not** alter the hysteresis bit and therefore does **not** affect the query2 selector. The `0xAF72`/`0xADF2` forced-last-column condition (query2 = 0xFF when bit5 set and `ROM[0x86CC].bit0` == 1) remains governed solely by `sub_4E24C`'s hysteresis chronology.

## Result

**BOUNDED COMPLETE — SUPPORTED.** The whole-byte writer at `0x63CEE`:
- Targets `FFFF1D81` exactly (EA proven: R6 = 0xFFFF1D80 from `off_63EEC`, store at +1 offset)
- Sources its value from `FFFF1D81` itself (read at 0x637EE, spilled to [SP+0x30], reloaded at 0x63CDC)
- Preserves bit5 (only bit 6 may be conditionally forced)
- Is unconditional on this code path; bit-6 forcing is conditional on unrelated state

The E810 hysteresis bit5 latch is not overwritten, initialized, or cleared by this path. The `0xAF72`/`0xADF2` query2 forced-last-column selector remains stable under this writer.
