## Objective

Test the remaining narrow possibility that the F3D6-derived `0x0F712` 32-point UWORD lookup results staged at `FFFF1630/FFFF1632` have downstream consumers through register-indexed, GBR-relative or computed-base aliases not covered by the earlier exact-address searches.

## Mandatory falsifiable hypothesis

- **Identity layer advanced:** output identity and function identity.
- **Hypothesis:** one or both F3D6 result stages may feed a later state/control consumer through an aliasing access path, although the earlier bounded exact-address searches found no direct reader.
- **Evidence:** WO65223 proves the table lookup at `0x68964` writes UWORD results to `FFFF1630` and `FFFF1632`; WO65097 traces the separate arithmetic producer and records the unresolved later endpoint. WO65223's exact-address LST/EADict search found no verified direct readers and explicitly left register-indexed/computed-base aliases open.
- **Prediction:** the existing EA/GBR/RAM indexes or a small, exact base-rooted inspection will reveal an alias read/consumer, or establish that the bounded indexes contain no usable alias path.
- **Cheap discriminator:** inspect only alias-capable accesses resolving to the two exact byte ranges, using the existing indexes and known base roots; do not perform a global RAM search.
- **Information gain:** determines whether these 32-point curve outputs have any statically supported downstream role beyond internal staging.

## Scope

1. Reuse WO65223's correction separating the F3D6 `0x0F712` table path from the distinct `FFFF10CC` arithmetic producer. Do not merge the two producer branches.
2. Start with the existing effective-address dictionary, GBR map, RAM byte/bit cross-reference and call graph. Resolve only entries that can alias `FFFF1630–FFFF1633` through known base-rooted, GBR-relative, register-indexed or overlapping word/long accesses.
3. For each candidate, verify the actual effective address, access width, signedness, read/write direction and instruction PC against the pinned listing. Reject false aliases.
4. If a valid consumer is found, follow it only through the first consequential arithmetic/state destination or named output boundary. Keep the lookup result distinct from the alternate arithmetic producer at `0x68914–0x68958`.
5. If no valid alias consumer exists in the supplied indexes, record a bounded negative and the exact unsearched alias boundary; do not claim global absence.
