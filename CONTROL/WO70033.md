## Observations

1. **`0x0AFF2` call site `0x5B3C0` (function entry `0x5B33A`).** `0x5B3AE` `mov.l off_5B454,r4` = `0x0AFF2`; `0x5B3B4` `mov.l off_5B458,r5` = `0x0E5CC`; `0x5B3BE` `mov.l off_5B45C,r6` = `0x0E5C8`; `0x5B3A6` `mov.l off_5B450,r2` = `0x22B44`; `0x5B3C0` `jsr @r2`. The delay slot `0x5B3C2` `extu.b r0,r7` carries the query: `0x5B3BC` `mov.b @(h'DB,gbr),r0` under `gbr = 0xFFFF84C9` installed at `0x5B340`–`0x5B342` (`word_5B3D8` = `FFFF84C9`), so the query is **`U8[0xFFFF85A4]`, unsigned byte**.

2. **`0x0E5E8` call site `0x5B57E` is one of four sibling tables, not a single-table call.** `0x5B560` `tst r6,r6` and `0x5B568`/`0x5B574` `cmp/gt r2,r7` (with `r2 = 1` from `0x5B566`) choose among four pool literals loaded into `r4`: `off_5B6E0` = `0x0E5D8`, `off_5B6E4` = `0x0E5E0`, `off_5B6E8` = `0x0E5D0`, `off_5B6EC` = `0x0E5E8`; `0x5B57C` `mov.l off_5B6F0,r2` = `0x22DF8`; `0x5B57E` `jsr @r2`. The per-call export records only the last literal (`r4 = 0x0E5E8`); the three siblings are **absent from the 291-address catalogue**.

3. **The export's `r5 = 0x0FF` at `0x5B57E` is a static-window artefact, corrected here.** The listing computes `r5` at `0x5B540`–`0x5B55E`: `mul.l r5,r2`; `sts macl,r5`; `shlr8`; `shlr2`×3; `shlr` (total `>>15`); `add #-0x20`; `cmp/pz` with a zero floor at `0x5B552`–`0x5B554`; then `r2 = 0xFFFFFFFF`, `extu.b` → `0xFF`, `cmp/gt` clamping `r5` to `0xFF` at `0x5B55A`–`0x5B55E`. The query is therefore **`clamp(((U32 product) >> 15) − 0x20, 0, 0xFF)`**, a computed value, and `0xFF` is the clamp ceiling (`r2`), not the query. This is the same class of correction already recorded in `FND-000025` observation 8.

4. **Helper contracts (read from code).** `sub_22B44` (`0x22B44`–`0x22B72`): `extu.b r7,r7`, moves the query into `r5` and calls `sub_233CC` twice with `r4 = 3` — first with `r5` (axis `0x0E5CC`) and then with `r6` (axis `0x0E5C8`) after `0x22B58` `mov r6,r0` and `0x22B5A` `mov.l @(h'10+arg_0,r15),r5` — stacking both indices, then tail-jumps to `loc_231F8` with `r5 = 4`. `loc_231F8` (`0x231F8`–`0x2324C`) builds the byte offset `r0 = 4*row_index + column_index`, then interpolates through `sub_231C8` over the corner bytes at the two pointers. **The same unsigned byte drives both axes.** `sub_22DF8` (`0x22DF8`–`0x22E06`): `q >= 0xE0` returns `UBYTE[table+7]`, else `loc_23508` (8-point UBYTE interpolation) — identical to the contract already published in `FND-000025` observation 8.

5. **Axis identities and payloads (first target-side record for this map).** `0x0E5C8` = `00 01 02 03` (4 × UBYTE) and `0x0E5CC` = `0E 28 60 88` = 14 / 40 / 96 / 136 (4 × UBYTE), both strictly ascending, both ending at `0x0E5D0`. The catalogue records both as `consumer_tables = [0x0AFF2]` with `shared_count = 1`; `0x0E5CC` is `axis1` and `0x0E5C8` is `axis2`, matching the `r5`/`r6` argument order in observation 4.

6. **Both payloads are numerically inert.** `0x0AFF2`–`0x0B001` is 16 × `0x00` (`sha256 374708ff…`). `0x0E5E8`–`0x0E5EF` is 8 × `0x00` (`sha256 af5570f5…`), and so are its siblings `0x0E5D0`, `0x0E5D8`, `0x0E5E0` (8 × `0x00` each, same hash). Every lookup result is therefore `0x00` for any query, so the traced downstream product is `0x0000` on this ROM regardless of input.

7. **One shared first consumer for both calls.** The 3-D path continues `0x5B3C4` `extu.b r0,r2`; `0x5B3C8` `mov.b @(h'908,r12),r6` with `r12 = 0xFFFF2150` (from `off_5B448`, `0x5B368`) → `U8[0xFFFF2150+0x908]`; `0x5B3CA` `extu.b r6,r5`; `0x5B3CC` `bra loc_5B58C`; `0x5B3CE` `mulu r2,r5`. The 2-D path continues `0x5B582`–`0x5B58A` with the identical `U8[0xFFFF2150+0x908]` multiplier. Both converge at `0x5B58C` `sts macl,r2`; `0x5B58E` `mov.w word_5B5AA,r0` = `0x106`; `0x5B590` `mov.w r2,@(r0,r13)` with `r13 = 0xFFFF1054` → **`U16[0xFFFF115A]`** (`0xFFFF1054+0x106`). The 3-D path additionally stores its inline table element to `U8[0xFFFF1054+0x490]` = `0xFFFF14E4` (`0x5B3B2`–`0x5B3B6`) and pushes it at `0x5B3BA`.

8. **A second, uncatalogued 4 × 4 table is read at `0x5B3B0`.** `0x5B3A2` `mov.l off_5B44C,r5` = `0x0B002`; `0x5B3AA` `add #-4,r5` → base `0x0AFFE`; `0x5B3A0`–`0x5B3AC` compute `r0 = 4*r + c` with `r = clamp(U8[0xFFFF84C9],1,4)` (`0x5B388`–`0x5B39E`) and `c = clamp(U8[0xFFFF84CA],0,3)` (`0x5B37E`–`0x5B386`); `0x5B3B0` `mov.b @(r0,r5),r6`. The `-4` compensates the one-based row index, so the effective element address is `0x0B002 + 4*(r−1) + c`, i.e. a **4 × 4 UBYTE table spanning `0x0B002`–`0x0B011`, all `0x00`**, distinct from the helper's `0x0AFF2` argument. The single `r4 = 0x0AFF2` export row does not represent this table, and the catalogue has no `0x0B002` entry.

9. **Donor declarations (geometry and metadata only).** V6 `mTDATDDS`: `MAP 0x0000AD5E REC_UBYTE_C 0 COMP_0237_S 0 0.99609375`, axes `COM_AXIS mTDATDN` (4 pts, 0–12750) and `COM_AXIS mTDATDGP` (4 pts, 0–255), `FUNCTION_LIST KF7-385.2[18]`. Juke `mTDATDDS`: `MAP 0x0000C20E REC_UBYTE_C 0 COMP_0175_S 0 0.99609375`, same two axes. V6 `mTDATDPRE`: `CURVE 0x0000CF36 REC_UBYTE_C 0 COMP_0237_S 0 0.99609375` with `FIX_AXIS COMP_0315_S 8 10 80`, `FIX_AXIS_PAR_DIST 0 1 8`. Juke `mTDATDPRE`: `CURVE 0x00011CC0`, same 8-point fixed grid, `COMP_0175_S`. Both are described as down-shift torque-decrease-rate coefficients. Neither donor coordinate equals any EL19A address, and the two donors place the same symbols at different coordinates (`0x0AD5E` vs `0x0C20E`; `0x0CF36` vs `0x11CC0`).

## Limitations

- No physical identity, units, conversion or strategy role is established for `0x0AFF2`, `0x0E5E8`, `0x0B002` or the three sibling curves. The donor names remain hypotheses.
- `U16[0xFFFF115A]` (`0xFFFF1054+0x106`) and `U8[0xFFFF2150+0x908]` are named only by address and offset; their producers and meaning were not traced beyond the multiplication.
- The two selector flags at `0x5B560` (`tst r6,r6`) and `0x5B568`/`0x5B574` (`cmp/gt r2,r7`) were identified mechanically; their semantic meaning and the origin of `r6`/`r7` in the enclosing function were not traced.
- `0xFFFF85A4` is reused here as a query source; its own producer path is outside this WO and was not re-derived (see `FND-000025`).
- The `0x0E5E8` export row's `r5` value is superseded by observation 3; the export file itself was not edited.
- Coverage claim: two of two named target objects plus their group; no other candidate in the `0x0AFF2` region was examined.
