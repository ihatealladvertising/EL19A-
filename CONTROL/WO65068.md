## Findings and disposition

### Query handoff and independent gate

- At the enclosing `sub_A90BA` call site, `R12=FFFF859C` (`0xA91D4`). `0xA91DE` reads `UWORD[FFFF859C+0x16] = UWORD[FFFF85B2]` into R0; `0xA91E2` copies it to R5. `0xA91E0` separately reads `UWORD[FFFF8494]` into R4. The value briefly copied to R4 by the delay slot at `0xA91DA` is overwritten at `0xA91E0` before the C0D6 call.
- In `sub_A95BA`, `0xA95C0` copies caller R5 to R7 (first query), and `0xA95C6` copies caller R4 to R0; the `jsr` delay-slot store at `0xA95D4` passes that second query on the stack. `sub_22D30` zero-extends both words (`0x22D34`, `0x22D48`) and returns its lookup value in R0. The lookup arguments remain in the WO64928 order; no caller-side query transform is observed in this path.
- The gate is a separate argument: `0xA95C2` copies caller R6 to local R14 and `0xA95CE` zero-extends its low byte. It is not either query and is not the caller's saved R14 value. Its runtime source is unresolved: the last local R6 definition is `0xA913E`, followed by calls at `0xA9166` (`sub_A8F4A`), `0xA91CE` (`sub_A8EF4`) and `0xA91D8` (`sub_A95EC`); R6 preservation across those calls is not established.

### Return handling, gate and output

- The helper result is a UWORD in R0. `0xA95D4` is the `jsr` delay-slot instruction and therefore executes before the lookup; it stores the second query (still in R0 from `0xA95C6`) to the helper's stack argument. There is no stack-local result store. After the helper returns, the result remains in R0 with no arithmetic or sign conversion, and `0xA95EA` returns it unchanged.
- `tst R14,R14` at `0xA95D6` followed by `bt/s` at `0xA95D8` gates the output. If the zero-extended gate byte is zero, the delay-slot `mov R0,R2` at `0xA95DA` supplies the lookup result. If nonzero, the same delay slot runs and `0xA95DC` overwrites R2 with zero. The merge at `0xA95DE` therefore stores the raw UWORD result for gate zero and zero otherwise.
- `0xA95DE` loads base `FFFF2150`; `0xA95E0` loads offset `0x7E6`; the UWORD store at `0xA95E2` writes to **`FFFF2936`**.
- The enclosing call at `0xA91E8` copies returned R0 to R6 in its delay slot (`0xA91EA`), but that copy has no local read before `0xA9200` overwrites R6 with a different byte load. The bounded caller-local software role established here is a **gate-controlled UWORD lookup-output stage at `FFFF2936`**. Stop at this global RAM staging boundary; downstream consumers and physical meaning are not established.
- The query source `FFFF85B2` is below WO65062's active range; neither this trace nor its output store enters `FFFF85C4–FFFF85FF` or `FFFF860B–FFFF860F`.

**Confidence:** high for the query handoff, helper return register, gate polarity, UWORD width and exact output EA; unresolved for the gate byte's upstream R6 provenance and any downstream/physical identity. No fuel/AFR, ignition/knock or other semantic label is assigned.
