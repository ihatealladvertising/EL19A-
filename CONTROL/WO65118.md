## Method (bounded)

1. Parse concordant listing CODE lines exactly as in prior structural work; verify raw bytes at each cited PC against the ROM and drop/list mismatches. Report full concordance counts.
2. Recompute function extents and per-function GBR internally: local `ldc` only, short pool annotations read from actual ROM bytes, branch/label invalidation, `ldc.l @r15+,gbr` as caller restore. A function with 0 or >1 distinct provable GBR gets no GBR attribution.
3. For every RAM memory operand (`@(disp,GBR)`, `@(r0,GBR)`, `@(disp,Rn)`, `@(r0,Rn)`, `@(disp,PC)` pool form), resolve base and index from provable straight-line sources; compute `address = (base + offset) mod 2^32`; emit only `>= FFFF0000`. Width scaling b=1, w=2, l=4 for raw displacements; symbolic `label ± h'..` expressions evaluated as byte displacements.
4. Derive direction from operand position/mnemonic. Derive bit metadata from immediate bit forms:
   - `and.b #imm,@mem` → `rmw` / `cleared` / mask `~imm & 0xFF`;
   - `or.b #imm,@mem` → `rmw` / `set` / `imm`;
   - `xor.b #imm,@mem` → `rmw` / `toggled` / `imm`;
   - `tst #imm,@mem`, `tst.b #imm,@mem` → `read` / `tested` / `imm`;
   - `and/or/xor/tst #imm,Rn` immediately after a provable RAM byte load into `Rn`, in the same straight-line region → attribute `tested` (and or xor: `set`/`toggled`) to that RAM address and record the mask in the memory row's note. Register provenance is invalidated on any write to `Rn`, any branch or any label.
   - Note: the playbook records `tst #imm` sets T when the bit is **clear**; polarity is recorded as a fact, never applied to infer semantics.
5. Deduplicate identical rows. Every operand whose base, index or displacement cannot be proven gets one unresolved row. Nothing is emitted as address zero.
6. Regressions, reported verbatim pass/fail:
   - **R1** RAM `FFFF85DF` → exactly two readers at `0x46BDE` and `0x47014`, both `base_r0` (`FFFF85C4 + 0x1B`).
   - **R2** RAM `FFFF85E0` → zero accesses (no over-reach one byte past R1).
   - **R3** RAM `FFFF1DB4` → reader at `0x4042C` and writer at `0x4044A`.
   - **R4** negative control: `PKIOR_W` (`FFFFF770`) must produce **no** emitted row from stale GBR.
   - **R5** ROM-GBR over-reach: no emitted RAM row in `FFFF8xxx` attributed to base `0000821E`.
   - Comparisons (reported, not hard-gated): `FFFF860D` bit-3/bit-5 reader count (~35 in the index) and `FFFF84BA` (126 readers, no writer via closed helper-family censuses). Any difference is explained by method boundary, never silently adjusted.
