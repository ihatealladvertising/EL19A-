## 1. Objective

Add a narrow, provenance-pinned adapter from the existing `build_static_indices.full_rom_analysis()` raw per-call `cat_calls` result into the Reader Trace graph. The adapter must attach query and result-store evidence only to the exact `reader_pc` that matches the graph's `call_ref.call_pc`.

This closes the current adapter boundary: per-address aggregate summaries deliberately do not distribute query/result data across multiple readers. The new adapter consumes the original per-call records instead; it must not copy or reimplement SH-2 decoding.

## 2. Exact input contract

Existing producer (reuse only):
- `tools/build_static_indices.py::full_rom_analysis`
- Raw per-call shape: `cat_calls[table_ea] -> [{reader_pc, func, helper, q_inputs, dests}]`
- Each destination tuple is `(ram_ea, width, write_pc, instruction_text, is_tainted)`.

New adapter contract:
- Accept a versioned, deterministic JSON document exported from the raw per-call records.
- Pin the decoded ROM SHA-256 and exact Stage-16 listing-member SHA-256 in that document.
- Require an existing graph evidence reference whose SHA-256 matches the exported document bytes.
- Select only exact target EA + exact call PC + exact helper identity. Never fan out to another call for the same table.
- Preserve query RAM/register origin and taint-proven stores as `derived`.
- Keep `near` stores `heuristic` with an unresolved boundary; do not link them as lookup-result causality.
- Keep downstream reads and physical semantics unresolved.

## 4. Required tests

At minimum:
1. One table with two reader calls; only the graph's exact call PC receives query/result edges.
2. Correct target EA, call PC, helper and decoded ROM identity are required.
3. A query origin becomes a derived RAM-to-register-to-call path.
4. A tainted destination becomes a derived per-call result/store path.
5. A `near` destination remains heuristic and creates an unresolved boundary.
6. Wrong call, wrong target, malformed destination, missing evidence or hash mismatch is rejected.
7. Output is deterministic and graph enrichment is idempotent.
8. Pipeline integration leaves aggregate multi-reader query/result fields unattached when the per-call document is supplied; existing pipeline calls remain backward-compatible.
