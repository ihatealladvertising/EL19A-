## 2. Producer — the 0x60-byte snapshot copy (new finding, byte-verified)

Enclosing function: `sub_20DCE` (LST label at `0x20DCE`), immediately after `sub_2088C` in the same handler region. Call sequence:

| PC | Instruction | Effect |
|---|---|---|
| `0x20E32` | `mov.l off_20EA0, r9 ; h'21F3C` | r9 = `copy_longwords_by_size` dispatcher |
| `0x20EEA` | `mov.w word_21024, r2 ; h'FFFF8534` | **source** base = `FFFF8534` |
| `0x20EEC` | `mov.w word_21026, r1 ; h'FFFF84D4` | **destination** base = `FFFF84D4` |
| `0x20EF0` | `jsr @r9` | call dispatcher |
| `0x20EF2` (delay slot) | `mov #h'60, r0` | length = `0x60` bytes (24 longwords) |

Dispatcher verification (`0x21F3C`): `0x21F3E mov #h'40,r3`, `0x21F40 cmp/hs r0,r3`, `0x21F42 bf loc_21FDC` — with `r0=0x60 >= 0x40` the generic path is taken. `loc_21FDC` (`0x21FDE mov r2,r3`; `0x21FE0 add r0,r3`) computes end = source+0x60, then `0x21FE2 mov.l @r2+,r0` / `0x21FE4 cmp/hs r2,r3` / `0x21FE8 mov.l r0,@r1` / `0x21FF2 bra loc_21FE2` / `0x21FF4 add #8,r1` copies every longword across the full 0x60-byte range.

**Offset mapping:** `FFFF84FE = FFFF84D4 + 0x2A` and source `FFFF8534 + 0x2A = FFFF855E`; `0x2A < 0x60`, so the copy writes the cell. Therefore:

> `UWORD[FFFF84FE] = UWORD[FFFF855E]` after each snapshot copy.

The word straddles longword boundary `0x28-0x2B`, which is likewise fully copied. No transform, guard or arithmetic is applied to this field by the copy path.
