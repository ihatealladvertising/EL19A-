## Question

`0x0296B4`-`0x0296BA` reads ROM byte `0x000083A8` and stores it to `FFFF36BE`. Is ROM `0x83A8` a catalogued calibration object, and who reads the RAM copy?

## Answer

**The ROM byte is a constant zero, and the RAM copy is never read.** This is a vestigial zero-initialisation, not a calibration mirror.

### The ROM source

The listing resolves `0x000083A8` to the symbol **`byte_83A8:`** with the content `.datab.b 2, 0` — two zero bytes (`00 00`). It is the first element of a small hand-written data block (`0x8394`-`0x83C0`) of literals and table fragments:

```
0x8398  .data.b h'1C
0x8399  .data.b h'3B, 1
0x839D  .data.b h'FF, 1, h'FF
0x83A4  .data.b 1
0x83A5  .data.b h'14, 0, h'1E
0x83A8  .datab.b 2, 0          <- the source of FFFF36BE
0x83AA  .data.w h'7B4D
```

**Catalogue check:** `CALIBRATIONS/discovered_tables_catalog.csv` contains **no entries anywhere in `0x8300`-`0x83FF`**; the block is not a catalogued table, and it is not a varying table a reader helper would have picked up. It is also not reachable as a table: the only ROM-address literal for `0x83A8` is `off_29888` at `0x029888` (`00 00 83 A8`), used solely at `0x0296B4`.

**Do not confuse it with `h'FFFF83A8`**, which appears as a pool word at `0x00000EC0` and `0x00002ADA` (`word_EC0`, `word_2ADA`) and is a **RAM** word at `0xFFFF83A8`. That is a different object; the ROM byte is `0x000083A8`.

### The RAM copy

Own-base resolution over all GBR-relative sites, plus every absolute pointer literal, finds **exactly one access to `FFFF36BE`** — the store itself:

```
0x0296B4  mov.l off_29888,r2   ; r2 = 0x000083A8
0x0296B6  mov.b @r2,r0         ; r0 = UBYTE[0x000083A8] = 0x00
0x0296B8  mov.b @r6,r2
0x0296BA  mov.b r0,@(h'AA,gbr) ; GBR FFFF3614 + 0xAA = FFFF36BE
```

- **Writers: 1** (`0x0296BA`).
- **Readers: 0.** No `mov.b @(h'AA,gbr),r0` under base `FFFF3614` exists, and the literal `FF FF 36 BE` does not occur in any pool, so the cell is never addressed absolutely either.

`FFFF36BE` therefore holds a constant zero that nothing consumes: a dead store inside the `loc_29500` block of the `0x029500` routine.

## Classification

**`INTERNAL CONSTANT IMAGE`** — a ROM zero constant copied once into an unread RAM cell. It is **not** `CALIBRATION-MIRROR`: the source is not a catalogued or varying table, contains no non-zero payload, and the destination has no consumer.
