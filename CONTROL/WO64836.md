## Hardware-layout correction reference

The official Renesas SH7058 Hardware Manual §16.3.1 / Figure 16.3 defines the message-buffer layout. For HCAN1 MB12:
- `FFFFDA80`: MB12[0][1], message-control / identifier word (STDID, RTR, IDE, EXID high).
- `FFFFDA82`: MB12[2][3], remaining EXID bits.
- `FFFFDA84`: MB12[4][5], MBC/DLC.
- `FFFFDA86`: MB12[6], timestamp.
- `FFFFDA88`: MB12[7][8], actual message data bytes 0/1; following data at DA8A/DA8C/DA8E.

This correction supersedes any earlier description of FFFFDA80 as payload byte 0. Manual: https://www.renesas.com/en/document/mah/sh-2e-sh7058-f-ztat-tm-hardware-manual, printed pp. 526 and 528.


## Stage 3 — TEST results (2026-11-16): mailbox 12 inactive in initialization

### Startup and mailbox configuration
- Reset/init sequence reaches `sub_2AA4` at PC `0x26BE`; `sub_2AA4` calls `sub_2562` at `0x2ABC–0x2AC0`.
- `sub_2562` calls `sub_2478`, then branches to mailbox initialization loop `loc_24C2`.
- `loc_24C2` sets mailbox base pointer to `FFFFD900), mailbox stride to `0x20), MBC/config value to `0x0700`, and initializes 27 consecutive mailboxes (index 0 through 26). The loop writes `0x0700` to each mailbox's `MBx[4][5]` control word at base+4, and zero to the corresponding message-control/ID word at base+0.
- MB12 is within this initialized range: `FFFFD900 + 12×0x20 = FFFFDA80`. Thus:
  - MB12 message-control/identifier word `FFFFDA80` is initialized to `0x0000`.
  - MB12 configuration word `FFFFDA84` is initialized to `0x0700`.
- In Figure 16.3 / §16.3.2, MBC[2:0] occupies bits 10:8 of MBx[4][5]. Therefore `0x0700` means MBC=`111`. The Renesas SH7058 manual explicitly defines MBC=111 as an **inactive mailbox**: it does not receive or transmit regardless of TXPR or other settings.
- Other setup calls after the mailbox loop (`sub_275C`, `sub_28EE`, `sub_2982`) do not configure MB12; the bounded listing shows no MB12-specific reactivation/configuration. Exact-symbol find for `HCAN1_MB12[4][5]_W` returns only its peripheral data declaration, not a code write.

### Actual data field
- Per Figure 16.3, actual MB12 data bytes 0–7 are at `FFFFDA88–FFFFDA8F`; the control word is not payload.
- The bounded target listing has no code references to MB12 data words `[7][8]`, `[9][10]`, `[11][12]` or `[13][14]` beyond their peripheral declarations. The only code reads of `FFFFDA80` are the previously documented control-word reads in `sub_288B4` and `sub_387B4`.
- As configured in the observed initialization, MB12 is inactive and its control word is zero; there is no evidence that live payload bytes can populate it in this state.

### Consequence for F062 query
- `sub_AAAE0` takes the upper byte of the copied `FFFFDA80) word as query. In the observed initialized MB12 state that word is `0x0000`, so q=0.
- E0CE axis point 0 is 0 and F062 data point 0 is 0. Therefore this input returns table point 0 (0x00), not a pressure estimate derived from a received message.
- The exact Juke mTRPAMB/mLPAMB byte fingerprint remains true, but the target runtime behavior does not support an active ambient-pressure input. Any later undocumented/indirect reconfiguration is not established by this bounded source pass.
