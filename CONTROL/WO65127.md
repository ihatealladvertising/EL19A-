## Mandatory discrepancy audit

1. **E904 dynamic address / GBR distinction**
   - Keep `r13` as a general register distinct from GBR. Resolve the effective base for the write at `0x87C68` (`[r13 + stack[0x50] + 0x5C5]`) from its actual producer/caller setup.
   - Separately resolve the GBR base used by the `GBR+0x73.bit3` write at `0x87CE0`; do not infer it from nearby literal-pool addresses.
   - Confirm the first consumer, or record the precise bounded stop point if it cannot be established.

2. **E914 flag chronology and threshold**
   - Reconcile the flag set at `0x882B2` with the read/test at `0x880F4–0x880F8`. The read PC is earlier than the set PC; determine whether it is a prior-state / previous-pass gate and identify any actual post-write reader before naming it a downstream consumer.
   - Resolve the effective GBR base used at both PCs independently. Do not assume the same base without proof.
   - Verify the query clamp, `0x905C` pointer dereference and threshold: the report records `WORD[0x905C] = 0x00F0 = 240`. Keep the pointer address distinct from the dereferenced threshold value.

3. **E934 query and destination corrections**
   - Audit the `0x3A06A` claim in WO65126. The reported instruction is `mov.w @(0x14,r2),r0`, which loads **r0**, not **r6**; it cannot by itself establish the query passed in r6 to `sub_3A178`. Reconstruct r6 from its actual definitions through the `0x3A072` call, including loop/index operations and any call-preserved/clobbered assumptions.
   - Resolve the caller's r0 at `sub_39FC8` entry and its `ldc r0,gbr`. Reconcile against WO65058's reported `GBR=FFFF86D4`; do not retain the “unresolved” statement without checking the existing caller evidence.
   - Distinguish `FFFF2150+0x5C8 = FFFF2718` (the fixed result byte) from the separate lead `FFFF86D4+0x1B = FFFF86EF`. Establish whether the latter is written, read, a separate field, or a false association.
   - Verify `r14` at `0x45E18–0x45E4E`. Do not treat the `0x5C8` clear or adjacent `0x5C9` read as an E934 semantic consumer unless the base and execution order prove that relationship.

4. **Cross-path synthesis**
   - Compare table extent/width, axis object/width, query producer, helper contract, mode/branch gates, result storage, threshold arithmetic and first valid reader for all three paths.
   - Separate physical ROM adjacency, shared helper use, shared caller/control flow and shared physical calibration meaning. Shared `sub_231C8` interpolation alone does not prove a common calibration function.
   - Reconcile the catalogue and WO65058/WO64842 records where claims overlap. Preserve exact source/PC references and report contradictions rather than silently choosing one statement.
