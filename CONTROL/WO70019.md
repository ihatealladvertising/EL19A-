## Objective

Validate and organize the reported recurring calibration payloads across the available Nissan ROM set. Produce an address-independent exact-payload map showing which EL19A reader-backed objects recur in which donor ROMs, where they relocate, and where same-geometry objects differ. This is a bounded cross-ROM data task, not a new broad firmware scan or semantic reverse-engineering campaign.

## Required work

1. Verify each input's file size, SHA-256, recognized CPU/FID where available, image base/layout, and scan success. Record decoder and tool source hashes.
2. Reuse the existing SH705x workbench and cross-ROM scanner to enumerate helper-backed table objects for each ROM. Do not modify tools or create a new generic scanner.
3. For each EL19A helper-backed object, compare exact payload bytes against objects in the other ROMs independent of address. A match requires equal byte extent and identical bytes; report SHA-256 and both source addresses. Preserve element type/geometry as separate fields.
4. Record same-address/same-geometry differing payloads and same-geometry non-identical candidates separately from exact matches. Do not conflate shared data with shared strategy.
5. Prioritize objects already in the selected full-definition baseline and the 179-row reader-backed catalogue, then add remaining EL19A helper-backed objects when the available scan output supports it. Explicitly identify the scope of any incomplete comparison.
6. Cross-reference the current `EVIDENCE/EL19A_22_FINGERPRINT_JOIN_2026-11-26.md` and previous donor screen reports. Reconcile rather than repeat already verified exact-payload claims; independently re-hash the source slices for any match promoted into the matrix.
7. Do not infer physical names, units, conversions or axis meanings from matching bytes. Keep exact payload, same geometry, function-level correspondence and semantic identity as separate evidence classes.

## Output

Create `CONTROL/WO70019_PAYLOAD_RECONCILIATION.tsv` and a concise `CONTROL/WO70019.md` report.

Required TSV columns:

`target_address, target_geometry, element_type, byte_extent, target_payload_sha256, donor_rom_path, donor_rom_sha256, donor_address, donor_geometry, donor_element_type, donor_payload_sha256, comparison_class, exact_byte_match, prior_report_or_finding, verification_status, unresolved_boundary`.

Use one row per target/donor comparison. Exact matches should be grouped by payload SHA in the report, while the TSV retains each source ROM/address pair. Include negative/no-match status for every target object within the stated scan coverage; do not omit unmatched targets.

## Evidence and interpretation rules

- Only byte-for-byte equality over the full verified extent qualifies as exact payload.
- A same-address match is not sufficient; a same-geometry match is not an exact match.
- A donor A2L name is metadata only and must not be promoted to EL19A.
- No new XML, catalogue or scope-matrix objects are authorized by this WO.
- Reuse prior payload and caller work; no duplicate helper census, no re-tracing already closed target readers.

## Acceptance criteria

- All 11 inputs have a recorded success/failure and immutable identity.
- The matrix contains a complete, explicitly scoped target-to-donor comparison for every EL19A object emitted by the chosen scanner runs.
- Every exact match is re-hashed and source-addressed; every non-match has a clear comparison class.
- Report includes a short list of the strongest multi-ROM conserved payload groups and the most important EL19A-unique/variant-specific objects, without semantic overreach.
- Findings disposition is stated. If a calibration interpretation materially changes, promote the finding; otherwise NOT REQUIRED.
