## 3. Implementation

- **Generator:** `EVIDENCE/WO65116_function_gbr_map_generator.py`, stdlib-only Python 3, version `WO65116-GBRMAP-1.3.0` (embedded in both TSV headers). Uses `argparse`; defaults resolve relative to its own directory. Run command:
  `python EVIDENCE/WO65116_function_gbr_map_generator.py --listing <extracted V3_NEXT6_16 .lst>`
- **No `tools/` entry was created.** WO65115 owns the repository's first tool entry; this generator is an evidence-reproduction artifact in `EVIDENCE/`.
- **Function starts:** every label whose next PC-bearing listing line is `CODE`, excluding `loc_`/`locret_` branch targets. This captures `sub_XXXX`, named functions and interrupt entries; data labels such as `PKIOR_W` (a RAM word at `FFFFF770`) are excluded by construction.
- **Extent:** from the label PC to the final concordant `rts`/`rte` before the next code-start label, including its delay slot; where no return is found, the extent is bounded by the next code-start label and the site is recorded as unresolved.
- **GBR establishment:** only a local `ldc Rn,gbr` whose register value is provable from a preceding pool load or immediate in the same straight-line region. Branch instructions and intervening labels invalidate provenance. A short pool annotation such as `h'821E` is **not guessed**: the four bytes at the labelled pool address are read from the ROM. `ldc.l @r15+,gbr` is recorded as a caller restore, never as a new base value.
- **Conservatism:** a `gbr_value` of `?` and any state other than `established_full` is a lead, not a confirmed base. Multiple distinct values in one extent are reported as `multiple_values`, never collapsed.
- **Mandatory unresolved set:** every unprovable `ldc`, every ambiguous value, every GBR use without local establishment, every GBR operand outside any extent, every no-return extent and every discordant PC is written to the second TSV.

## 5. Limitations

- Computed pointers, pointer tables, block-copy and `movca.l` transport are **not modelled**; none of this is evidence of absence.
- GBR inherited across a call is not attributed to a callee without a local `ldc`; such functions are leads.
- Function extents are listing-label/return approximations, not a proof of OS-level function boundaries; 87 extents had no return site.
- 341 `established_partial` and 382 unprovable `ldc` sites remain unresolved by design; 50 multi-value functions require path-sensitive analysis.
- No reader/writer classification, no calibration semantics, no physical units, no fuel-cut conclusion and no workbook/XML/catalogue integration were performed.
