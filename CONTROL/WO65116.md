## Method (bounded)

1. Parse every listing line of the form `PC  BYTES  CODE  MNEMONIC OPERANDS`; compare `BYTES` at `PC` against the ROM. Cite only concordant PCs; a mismatch goes to the unresolved file and is not emitted in the map.
2. Collect `sub_XXXX:` labels (function starts) and all code PCs; compute `end_pc` from the furthest `rts`/`rte`/`jmp @rN` before the next `sub_` label, else the next `sub_` label address.
3. Within each extent, find `ldc Rn,gbr` and `ldc.l @r15+,gbr`. Resolve `Rn` only from an immediately preceding, non-overwritten 32-bit pool load carrying an explicit `; h'XXXXXXXX` annotation or a `mov #imm`; otherwise mark partial/none. `ldc.l @r15+,gbr` is a caller restore, never a new base value.
4. Count GBR operand uses per extent. A function that uses GBR but establishes no local value is listed in the unresolved file as inherited, not assigned a value.
5. Deduplicate distinct resolved values per function; more than one value is `multiple_values` and goes to the unresolved file with all sites.
6. Repeat spot checks against the three playbook GBR anchors (`sub_403D8`, `sub_3BA88`, `sub_46E3E`) and the `PKIOR_W` stale-GBR failure mode.

## Acceptance / stop condition

- ROM and listing hashes verified; code-line PC concordance reported with exact counts.
- Both TSVs generated by the extraction pass (no hand editing), with complete header blocks.
- Every `sub_` label has exactly one map row; every function with an unresolved GBR condition has an unresolved row.
- Playbook GBR anchors agree with the listing; no callee is attributed a caller's GBR.
