## 0. Specification arithmetic correction — MUST READ

The WO65509 title, objective and scope repeatedly assert `FFFF2150 + 0x5AC = FFFF20FC`. That arithmetic is **wrong**. Independent verification:

- `off_801C0` data at `0x801C0` is `FF FF 21 50` = `0xFFFF2150` (LST L268964 `off_801C0:` / `DATA .data.l unk_FFFF2150`; raw ROM bytes at `0x801C0` confirmed).
- `word_800E0` at `0x800E0` is `05 AC` = `0x05AC` (LST L268837).
- The `0x800CA` instruction bytes are `06 25` = `mov.w r2, @(r0,r6)` (raw ROM confirmed). SH-4 `@(r0,r6)` addressing is `EA = r6 + r0`, with `mov.w` sign-extending `0x05AC` to the positive `0x000005AC`.
- `0xFFFF2150 + 0x000005AC = 0xFFFF26FC`. The subtraction check `FFFF20FC − 05AC = FFFF1B50` confirms `FFFF20FC` would require a base of `FFFF1B50`, which does not exist in this path (`h'1B50` has one unrelated ROM-data-table hit at `0x984C`, not a code base).

Therefore the real endpoint investigated and dispositioned here is **FFFF26FC**. `FFFF20FC` remains a 0-row phantom in both indexes and has 0 direct LST hits; it is not an address reached by any accepted access. The WO ID and technical scope (the terminal word write exposed by WO65500) are unchanged — only the endpoint arithmetic is corrected.
