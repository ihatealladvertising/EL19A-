## Objective

Trace the first meaningful readers and downstream consequences of UWORD outputs `FFFF3456` and `FFFF3458`, produced by the parallel 8×8 correction-map paths documented in WO65180. Determine whether these outputs remain internal correction state, feed a shared control calculation, or reach a demonstrable actuator/MMIO/CAN endpoint.

## Evidence to reuse

- `CONTROL/WO65180.md`: exact map calls, queries, result staging and separate accumulators. `0x0B756 → FFFF86E2 → FFFF3456`; `0x0B7D6 → FFFF86E0 → FFFF3458`. Both paths add their map contribution to separate LONG state and two UWORD terms, apply the same 0x17FFF ceiling / 0x8000 bias transform, and store independent UWORD results. The two maps execute sequentially; the outputs are parallel correction contributions, not alternate banks.
- `CONTROL/WO65137.md`: payload/axis geometry and donor-comparison limitations; no repeat of table decoding.
- `CONTROL/WO65116.md`–`WO65122.md`: existing RAM byte/bit, effective-address, function/GBR and call-graph indexes. Verify actual effective addresses in the listing, particularly where WO65117's displacement column is known to double-scale.

## Scope

1. Find all direct reads of `FFFF3456` and `FFFF3458` using the existing indexes; verify operand widths and effective addresses against the pinned listing.
2. Trace each output independently to its first meaningful consumer, including any copy, arithmetic, clamp, comparison, selector, accumulator, state transition or cross-channel combination.
3. If a reader feeds a shared downstream variable, trace only far enough to establish the shared consumer and distinguish the two input contributions.
4. Test for a concrete MMIO/peripheral, timer/ATU/TPU, HCAN or diagnostic endpoint only where a direct code path supports it. Stop at the first computed pointer, dispatch, DMA or external boundary.
5. State whether either output is read as UWORD, byte, signed word or long and whether any later reinterpretation changes its role.

## No-repeat / exclusions

- Do not repeat WO65180's lookup arguments, map output staging, accumulators, ceiling/bias arithmetic or physical-domain speculation.
- Do not infer that these values are trims, fuel, spark, throttle, torque or actuator commands from their names or numeric range.
- No broad RAM scan, global xref regeneration, helper census, or unrelated map trace.
- Read-only. No ROM/LST/XML/A2L/workbook/catalogue/index/script/tool/Library changes.

## Deliverables and stop boundary

Provide exact first-reader PCs, operand widths, effective addresses, branch conditions, subsequent destinations and the longest verified consumer chain for each output. Include any shared convergence point and a clear endpoint classification: internal state, software control decision, MMIO/peripheral, CAN/diagnostic, or unresolved. Separate structural/software-role confidence from physical identity. A bounded no-consumer result is acceptable if the exact search coverage is recorded.
