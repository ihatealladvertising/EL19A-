## Checkpoint 2 — callback dataflow, pointer-writer audit, and output boundary

### Callback input selection and helper
- `prepare_85DF_and_19BF` at `0x59B58` sets GBR=`FFFF1C78`.
- It reads UWORD `FFFF1CAE` (+0x36) at `0x59B64` and UWORD `FFFF1CCC` (+0x54) at `0x59B68`, selects their maximum, extracts its high byte, and caps that byte at `0x7F`. The selected UWORD is retained for subsequent output arithmetic.
- It reads UBYTE `FFFF1C93` (+0x1B) at `0x59B88` and `FFFF1CD6` (+0x5E) at `0x59B8E`. It forms the bounded arithmetic `FFFF1C93 + FFFF1CD6 - 0x80` (0..255), passes the result to `calculate_and_update_1C01` at `0x59BB4`, then stores the helper-returned `r2` byte to `FFFF1990+0x2F = FFFF19BF` at `0x59BB6`. This stored result is not simply the pre-helper sum.
- `calculate_and_update_1C01` at `0x599F0` sets GBR=`FFFF1990`. It reads prior `FFFF19BF` at `0x59A46`, uses `FFFF1CA8+0x29` and `+0x3A` as query inputs to fixed ROM lookups (including `F38E` and `F092)), and performs fixed-point multiply/scale and clamp operations. It writes the helper state byte at `FFFF1990+0x41 = FFFF19D1` at `0x59B1A` / `0x59B32`; the updated `FFFF19BF` is then written by the caller at `0x59BB6`.
- Startup/initialization code at `0x28C86–0x28C94` also writes `0x80` to `FFFF1990+0x2F = FFFF19BF`. This confirms a stored feedback/state byte initialized to `0x80` and later updated by the helper path. Do not assign a physical semantic label.

### Conditional FFFF85DF and FFFF85E0 path
- After the helper call, `prepare_85DF_and_19BF` reads `FFFF1990+0x41 = FFFF19D1` at `0x59BBE` and combines it with the selected UWORD from `FFFF1CAE/FFFF1CCC` to form the candidate byte for `FFFF85DF`.
- The write to `FFFF85DF = FFFF85C4+0x1B` is gated:
  - If `FFFF3616 & 0x0C` is nonzero, it writes zero at `0x59BF2`.
  - Otherwise, if `FFFF1E68.bit2` is set, it writes the `r5` candidate at `0x59C04).
  - Otherwise, it writes `r13` (the capped high byte of the selected maximum UWORD) at `0x59C02`.
- The wrapper `callback_update_85E0` calls the producer and then tests `FFFF1E68.bit2` at `0x59C54`. If set, it copies `FFFF85DF` to `FFFF85E0` at `0x59CA2–0x59CA6). If clear, it derives a bounded/scaled byte from `FFFF1CCC` (read at `0x59C5C)) and writes that to `FFFF85E0` at `0x59CA6`. **Correction is explicit:** the set-bit branch copies 85DF; the clear-bit branch computes from 1CCC.
- Therefore E974's effect through `FFFF1C93` can influence the `r5 → FFFF85DF → FFFF85E0` path only when the `FFFF1E68.bit2` branch selects `r5` and the `FFFF3616` 0x0C mask does not force zero. The shared bit then causes the wrapper to copy 85DF into 85E0. This is a confirmed conditional internal data/control path, not a demonstrated physical ADC/actuator command.
