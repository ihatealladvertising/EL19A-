## Falsifiable hypothesis record

- **Identity layer advanced:** input identity and function identity.
- **Hypothesis (from the WO):** `FFFF184C` is populated from `FFFF848E` on one branch and updated by a separate bounded calculation in `sub_36D80`.
- **Result:** **SUPPORTED for the mechanism, UNRESOLVED for the source.**
  - The two-branch structure is confirmed exactly: a one-shot copy of `U16[FFFF848E]`, then a per-call first-order update in the same routine.
  - `FFFF848E` itself has **no producer** in the supplied indexes or static listing scan; the nearest writes in its 16-byte block are to `FFFF8490` (byte, `sub_36166`) and `FFFF8492` (word, `sub_3615A`), not `FFFF848E`. Source class therefore stays unresolved.
- **Information gain:** the multiply/divide structure shows the query is a **rate-compensated level**, not a direct sensor pass-through and not a normalised control fraction, which rules out reading the `0x0FEE0` curve as a plain measured-vs-parameter function.

**Divide helper note.** `sub_21BE4` (`0x21BE4–0x21C7A`) is the standard SH-2 `div0u`/`div1` unsigned routine, guard-clamped for zero divisor (`tst r0,r0` → `loc_21C6E`) and for a divisor that does not fit 16 bits. Its `rts` delay slot at `0x21C0E` is `extu.b r1,r0`, so the caller receives the **low byte of the quotient** in `r0`, i.e. a 0–255 result, not a full 16/32-bit quotient. That 8-bit clamp is a second, independent bound on the correction magnitude.

**Net contract (verified):**

```
FFFF184C := U16[FFFF848E]                                   (first call / latch clear)
FFFF184C := U16[FFFF848E] - byte( 335 * U32[FFFF2EC0+0x1C] / 65536
                                  / min(U16[FFFF184C] + 80, 0xFFFF) )   (subsequent calls)
```

No path reads or writes any RAM outside `FFFF184C`, `FFFF35C6`, `FFFF848A+4`, `FFFF2EC0+0x1C`, or `FFFF2F00`-style GBR state. No interrupt, DMA, peripheral or dispatcher is entered inside the routine.

## Query transformation and supported numeric range

- Reader path unchanged and **not re-derived** (WO65132): `U16[FFFF184C]` read at `0x369E0`, zero-extended, `<< 4` at `0x369E6/0x369E8`, lookup `sub_22E98` at `0x369EA`, result stored `FFFF84A4+2 = FFFF84A6` at `0x369F2`.
- Helper saturation (WO65132): query `>= 0x3F00` saturates to the top entry. Therefore the **usable input domain is `FFFF184C ≤ 0x3F0` (1008)**; above that the table is flat at the last entry (`0x18FB` = 6395). At `FFFF184C = 0` the query is 0 and the first entry (`0x0000`) is selected.
- Because the producer subtracts a positive correction from `U16[FFFF848E]`, any `FFFF848E` above ~1008+quota will saturate the lookup. This bounds the meaningful measurement range even though the measurement's own identity is unknown.
- Independent ROM evidence about `FFFF848E`'s magnitude domain: sibling routine `sub_36A80` compares it against ROM words `0x9142 = 0x02BC` (700) and `0x9144 = 0x0258` (600) (`0x36AB4–0x36ABE`, `0x36B06–0x36B10`), and the neighbouring comparators at `0x9140 = 0x50`, `0x9146 = 0x03D4` (980) are used in the same structured test family. So the field is a **16-bit engineering quantity in roughly the 0–1000 band** (calibration constants, not proven units).
