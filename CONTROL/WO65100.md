## Track A — `FFFFA71C` downstream calculation

### Writer and update conditions

- `sub_6CCFE` first tests `FFFF8B52.bit4` at `0x6CD00–0x6CD06`. When clear, the routine returns without running the chain. When set, it calls `sub_6CB06`, `sub_6CB56`, `sub_6CBC2`, then `sub_6CC22`, before branching to `loc_6CC8C` (`sub_6CC8C`).
- In `sub_6CC22`, UBYTE `FFFF864A` is tested for bit 6 at `0x6CC24–0x6CC2A`; UBYTE `FFFF1D99+0x50` is tested for bit 7 at `0x6CC2C–0x6CC34`. Either failed gate returns before the new state value is stored. If a gate bypasses the writer, the following consumer still runs under the parent bit-4 path and can use the retained `FFFFA71C` value.
- The writer establishes base `FFFFA378` and displacement `0x3A4` at `0x6CC80–0x6CC82`. The RTS delay-slot instruction at `0x6CC86` is `mov.w R2,@(R0,R4)`, which writes UWORD `FFFFA378+0x3A4 = FFFFA71C`. SH-2 delay-slot execution is material here: the store executes as the return delay slot.

### Exact state update and correction to WO65099

- The update uses UWORD `FFFF1054+0x200 = FFFF1254` and the prior UWORD `FFFFA71C`; its branch thresholds and step values are read relative to ROM base `0x93BC`.
- If `FFFF1254 < 0x7C28` (ROM UWORD at `0x93C6`), the old state is increased by `0x0009` (ROM UWORD at `0x93C0`).
- At or above that lower threshold, the old state is held until `FFFF1254 > 0x83D7` (ROM UWORD at `0x93C4`); above that upper threshold the old state is reduced by `0x00C4` (ROM UWORD at `0x93BC`).
- The resulting UWORD is bounded below by `0x8000` and above by ROM UWORD `0x9999` at `0x93BE`, then stored to `FFFFA71C`.
- **Correction:** WO65099 described the range as `0x8000…0x7FFF`. That upper bound was incorrect. The actual upper-limit operand at ROM `0x93BE` is `0x9999`; the accepted state range from the inspected comparisons is `0x8000…0x9999`. The earlier range statement must not be reused.

### Direct downstream consumer

- `sub_6CC8C` is entered directly by the parent `sub_6CCFE` after the `sub_6CC22` call.
- At `0x6CCC0`, R7 is loaded with base `FFFFA378`; `0x6CCC4` loads displacement `0x3A4`; `0x6CCC6` executes `mov.w @(R0,R7),R2`. The effective address is UWORD `FFFFA71C`.
- `0x6CCC8` zero-extends that UWORD into R7. The routine has already formed a signed baseline R5 from the centered `sub_22D68` result (the helper return is centered by subtracting `0x8000` at `0x6CCB2–0x6CCBA`) and loaded signed UWORD `FFFF1054+0x5EC = FFFF15B0` into R6.
- When R6 is below the baseline R5, the branch at `0x6CCBE` bypasses the multiply path and stores R6 directly to UWORD `FFFF1054+0x5F4 = FFFF1648` at `0x6CCF0`.
- Otherwise, the code forms `R6-R5` at `0x6CCC2`, multiplies that delta by the zero-extended `FFFFA71C` at `0x6CCCC`, takes MACL and shifts it right 15 bits (`0x6CCCE–0x6CCD8`), then adds the baseline at `0x6CCDA`. The result is saturated to signed 16-bit limits `[-32768,32767]` at `0x6CCDC–0x6CCE6` and stored as UWORD at `FFFF1648` (`0x6CCEC/0x6CCF0`).
- The raw coefficient range `0x8000…0x9999` corresponds to a Q15 multiplier of approximately `1.0…1.2` when divided by `0x8000`. In the observed consumer it scales a baseline-to-input delta and adds that adjusted delta to the baseline. This is a code-level multiplicative/gain correction, not a simple 0–1 interpolation weight. No physical units or engine subsystem are established.

### Track A coverage and limits

- The exact `FFFFA71C` token is present as a RAM allocation, not a direct absolute code operand. The confirmed direct code reader is the proven `FFFFA378+0x3A4` UWORD access at `0x6CCC6`; the writer is the proven same-base UWORD store at `0x6CC86`.
