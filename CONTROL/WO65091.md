## Decision question

What writes or transfers supply UWORD `FFFF85B2` (also addressed as `FFFF859C+0x16`), the common query input reused by several otherwise distinct lookup families? Resolve a concrete producer path if static evidence supports one; otherwise establish the precise bounded writer/transfer boundary without inferring the field's physical meaning.

## Why this is high priority

The same UWORD is consumed by:
- paired 16×16 UBYTE surfaces `0x9C2E/0x9DAE` (caller `0x42B9C–0x42BC8`);
- dynamic-axis 16×16 UBYTE map `0x9B2E` (multiple callers around `0x473xx–0x476xx`);
- 8×8 UBYTE map `0xAB22` (caller around `0x4E2AE`);
- four inline 8×8 SWORD channels `0x0B422/0x0B4A2/0x0B522/0x0B5A2` in `sub_969C2`.

One producer trace can therefore resolve the runtime query provenance across several high-value table groups.

## First confirmed correction — sub_969C2 query is local, not incoming R12

At entry `sub_969C2` saves R12, but later assigns it locally:
- `0x969EC`: load base `FFFF859C` into R13.
- `0x96A12`: read UWORD `@(0x16,R13)` = `FFFF85B2`.
- `0x96A14`: `extu.w r0,r12`; this zero-extends the UWORD into R12.
- `0x96A16`: test R12.
- R12 is not redefined between `0x96A14` and the final-axis search at `0x96C12–0x96C28`; that search compares UWORD axis `0xFD9C` entries against this query at `0x96C1C`.
- The lookup's final column index is therefore derived from UWORD `FFFF85B2`, not an untraced incoming dispatcher R12 value. The scheduled/direct call at `0x70882` is not the source of this query value.

Confirm the bytes against the pinned ROM and preserve the exact branch/index/clamp semantics. Do not infer a physical sensor or engineering unit.

### 2. Correction: inline-map R12 is locally loaded from FFFF85B2

| PC | Instruction / effective operation |
|---:|---|
| `0x969EC` | `mov.w word_...,r13` → R13 = `FFFF859C` |
| `0x96A12` | `mov.w @(0x16,r13),r0` → read UWORD `FFFF85B2` |
| `0x96A14` | `extu.w r0,r12` → zero-extend into R12 |
| `0x96A16` | test R12 |
| `0x96C12–0x96C28` | final column-axis search against UWORD axis `0xFD9C`, using this R12 |
| `0x96C1C` | compare selected UWORD axis point with R12 |

No R12 redefinition occurs between `0x96A14` and the final axis search. Therefore the SWORD-map column coordinate is a local read of `FFFF85B2`, not an unresolved incoming dispatcher R12. The actual caller at `0x70882` is not the producer of this query field.

This corrects the `sub_969C2` query-provenance statement in WO65089. WO65089's map geometry, indexing and output staging remain unchanged.

### 5. Remaining verified dynamic writer capability

The only concrete writer path identified that can target `FFFF85B2` is the previously documented receive-side callback/parser `loc_1D64 → sub_1C5C` (WO65062 Checkpoint 18 and Corrections 18a–18b):

- Packet selector byte P[0] = `0x34` selects callback-table entry 4 at ROM `0x4DF0`, which points to `loc_1D64`.
- The dispatch path advances R9 by one at `0x35E4`; JSR delay slot `0x35FA` passes R4 = P+1.
- Parser marker requires P[1] = `0x80`; following packet bytes encode a destination address, a length, and payload bytes.
- The parser is gated by transformed UWORD `FFFF8230`: `sub_33FE` returns `(UWORD[FFFF8230] << 1) >> 8`; the `0x40` comparison therefore admits `FFFF8230=0x2000–0x207F`. The selector-specific status byte must also permit the callback.
- `sub_1C5C` validates destination and end against `FFFF8500–FFFFBD00`, then copies payload bytes to the record-supplied destination. `FFFF85B2` is inside that accepted RAM interval. A payload of length at least two could write the UWORD at that address if its destination is `FFFF85B2` (or overlaps it).
- Instruction bytes at `0x1D64`, `0x1C5C`, `0x1CDA`, `0x1CE6`, `0x1CF0`, `0x1D0A`, `0x1D0C`, `0x35DE`, `0x35E4`, `0x35F4`, and `0x35FA` were checked against the original ROM; all matched the listing.

**Critical limit:** no runtime packet satisfying the dispatch/marker/status gates, no actual packet destination/length, and no payload bytes targeting `FFFF85B2` were established. This is a verified capability / runtime-conditional potential writer, not proof that the field is written in normal operation.
