## Objective

Resolve the two remaining inputs of the `0x0CD56` 16x16 UWORD map read found in WO65293: the row selector `r14` used as `0xCD56 + r14`, and the numeric domain of the query `U16[FFFF1D72] + 0x8000` passed to `sub_22F80` with axis `0x0FEC0`. Determine whether the selector is a small state/gear/mode index or an unproven computed offset, and whether the centred query is a signed physical quantity or an internal staged value.

## Mandatory falsifiable hypothesis

- **Identity layer advanced:** input identity and function identity.
- **Hypothesis:** `r14` is a bounded row index (0..15, 32-byte stride) selected by one software state, and the `+0x8000` term means the query is a signed, zero-centred quantity stored as offset-binary in `FFFF1D72`.
- **Evidence:** WO65293 records `0x6915A` reading `U16[FFFF1D12+0x60]` (=`FFFF1D72`), `0x6915E` adding `0x8000`, `0x69160`/`0x6917C` loading table base `0xCD56`, axis `0xFEC0`, reader `sub_22F80`, results stored at `FFFF1054+0x5C0` and `+0x5C6`; WO65293 also records `FFFF1D72` being written at `0x6B278` by the same table's earlier read.
- **Prediction:** a bounded caller/guard trace at `sub_690C6` will show `r14` assigned from a small enumerated state or a bounded multiply-by-32, and will show whether `FFFF1D72` is reused unchanged or re-derived before the centred lookup.
- **Cheap discriminator:** inspect only `sub_690C6`'s entry/argument setup and the writer of `FFFF1D72` at `0x6B278`, using the existing call-graph and RAM indexes before touching the listing.
- **Information gain:** separates a mode/row-selected calibration from an unbounded computed-pointer access, which decides whether `0x0CD56` can ever receive a defensible axis description.

## Scope

1. Reuse WO65293's verified read at `0x69150–0x69186`; do not re-derive it.
2. Determine `r14` at `sub_690C6` entry: caller(s) via `EVIDENCE/WO65120_call_graph.tsv`, the register's origin, any clamp/branch that bounds it to the 16-row range, and the exact stride (32 bytes per row for UWORD x16).
3. Determine `FFFF1D72`'s writer chain: confirm the `0x6B278` store inside `sub_6B236`/`sub_6B25C` context, whether the value is reused unchanged at `0x6915A`, and whether any saturation (`0x3F00`-style) or masking applies before `+0x8000`.
4. Record exact PCs, widths, signedness and branch conditions for each accepted step.
5. If `r14` resolves to an unproven computed pointer, or `FFFF1D72` reaches an interrupt/acquisition boundary, stop there and keep both fields generic.

## Required deliverable

- Exact unresolved boundary, reused evidence and explicit no-repeat list.
