## 2. Falsifiable hypothesis record

- **Identity layer advanced:** function identity (family level only); architecture correspondence where the evidence is structural.
- **Hypothesis:** MR16DDT and MR18DE share Nissan ECU/control architecture and naturally aspirated control families, while boost/charge-air control adds distinct MR16DDT-only families.
- **Evidence:** EL19A target-side geometry/readers/queries from closed lanes (WO65323 §4, WO65305, WO65293/WO65296, WO65181); Juke donor metadata read directly from `RFCC_2XHK19BDF1.a2l` (symbol, description, type, deposit, address, axis references, `COMPU_METHOD` coefficients). Donor and target evidence are kept in separate columns throughout §4.
- **Prediction:** shared families should show correspondence in *conversion constants and axis conventions* (an unusual, checkable fingerprint), not merely in names or dimensions; forced-induction families should have explicit pressure/WG/solenoid dependencies and no target-side analogue.
- **Cheap discriminator:** compare donor `COMPU_METHOD` coefficient sets against EL19A raw axis ranges for the same geometry, and classify a bounded set of families. No new ROM/LST scan.
- **Result:** **PARTIALLY SUPPORTED.** Shared architecture is supported structurally (same CPU/generator template; identical conversion conventions — `×0.125 %/count`, `×3.125 rpm/count`, `×50 rpm/count`, `×0.78125 %/count`, `raw−64 deg` — are exactly the conventions that make EL19A's observed raw axis ranges land on physical quantities). Forced-induction-only families are identified donor-side and have **no** EL19A counterpart reached by any closed lane. No shared family is promoted to a target-side function name: every EL19A counterpart remains at its earlier tier.
- **Information gain:** (i) it corrects which A2L is the Juke donor, so three READY Worker 2 WOs are known to be extracting V6 metadata; (ii) it supplies a finite, checkable set of donor conversion constants that become the next target-side discriminators; (iii) it separates turbo-only families so they are never used to name EL19A objects.

### 4.3 Additional rejections (explicit false matches)

1. **Address/declaration-order matching.** `mMKLMRTH` sits at donor `0x11937` — an odd address inside a UBYTE grid — and is a 3×3 `FIX_AXIS` map (`FIX_AXIS_PAR_DIST 0 1 3`). 3. **`mMITANDA`/`mMITANDD` donor semantics vs target selector.** WO65305 proved the target `FFFF85FB.bit7` selector is fed by a correction comparison, not an accel/decel flag.
