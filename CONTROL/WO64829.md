## Checkpoint 1 — lookup reader, query construction and table data (2026-11-15)

### Generic reader mechanics — confirmed from instructions
- `sub_22E10` loads threshold `0xF0), zero-extends query `r5`, and returns immediately when query `>=0xF0). On this path the retained return value is `0xF0` (sentinel; no table sample).
- For queries `0x00..0xEF`, the branch to `0x2350C` initializes `r3=0` in the jump delay slot. Four `shlr r5 / rotcr r3` pairs split the query into table index `q >> 4` and fraction nibble `q & 0x0F). `swap.w r3,r3` places the fraction into the Q16 multiplier position, equivalent to `(q & 0x0F) << 12`.
- The reader takes the byte path: it reads adjacent UBYTE values at `base + (q >> 4)` and `base + (q >> 4) + 1), then calls `sub_231C8`. Because `q<0xF0`, indices are 0..14 and the second point is at most index 15.
- `sub_231C8` interpolates between first sample `A) and second sample `B) with fraction `f=(q & 0x0F)/16`. The two compare branches implement the same directional rule:
  - if `B >= A`: `A + floor((B-A)×(q&0x0F)/16)`;
  - if `B < A`: `A - floor((A-B)×(q&0x0F)/16)`.
  There is no rounding-to-nearest; the integer change is truncated. A prior inline note describing the descending branch as starting from B is not supported by the actual register flow and is corrected here.
- This is a 16-point UBYTE linear interpolator with a 1/16 fractional grid and an explicit `0xF0` out-of-domain sentinel. The reader mechanics do not identify the table's physical function or units.

### First lookup — base `0xF38E`
- `calculate_and_update_1C01` reads UBYTEs `FFFF1CA8+0x29` and `FFFF1CA8+0x3A) at `0x59A08` / `0x59A0C). It computes their difference and clamps negative values to zero.
- Query construction is `q1 = min(4 × max(byte[+0x29] - byte[+0x3A], 0), 255)`.
- Therefore `q1 >= 0xF0` (and returns the sentinel instead of sampling the table) when the nonnegative delta is at least 60. For deltas 0..59, the interpolation coordinate is delta/4 (quarter-step increments across the table).
- Table bytes at `0xF38E..0xF39D`:
  `7D 7C 76 6E 66 60 5A 53 4D 46 40 3A 33 2D 26 20`.
- Returned first-lookup byte is stored at `FFFF1990+0x27D` (`0x59A44`).

### Feedback multiply and second lookup — base `0xF092`
- The prior UBYTE feedback state `FFFF19BF` is read at `0x59A46`. It is multiplied by the first lookup result at `0x59A4A`.
- `sub_223FE` itself performs signed `R0 >> 6` (five explicit `shar` instructions plus the `rts` delay-slot `shar`). The call is to `sub_223FC`, which has one additional leading `shar` at `0x223FC); therefore the complete multiply path applies seven arithmetic right shifts, i.e. `floor(product/128)` for these nonnegative UBYTE operands.
- The result is capped at `0x80` at `0x59A52–0x59A5E` and stored at `FFFF1990+0x28D). Define `v = min(floor(FFFF19BF_prior × first_lookup / 128), 128)`.
- Second query construction is `q2 = min(2 × (128-v), 255)`. Thus `q2 >= 0xF0) for `v <= 8` and the reader returns the `0xF0` sentinel; for `v=9..128`, the lookup samples the table.

  `00 08 0C 0F 14 19 1E 23 28 2D 32 37 3C 41 46 4B`.
- Returned second-lookup byte is stored at `FFFF1990+0x28E` (`0x59A8E`).

## Checkpoint 2 — signed state selection, feedback return and flag transfer (2026-11-15)

### Exact second-lookup result conditioning
- Let `S2` be the UBYTE result returned by the `0xF092` lookup. The `0xF0` early-return sentinel is consumed as numeric UBYTE value 240; it is not treated as a missing-data/zero result.
- The helper reads `x = UBYTE(FFFF1990+0x1F1)` at `0x59A90–0x59A94), then forms `D = clamp_signed(S2 - x, -128, +127)`. The negative saturation is implemented with sign-extended immediate `0x80` (−128), not positive 128; the upper limit is `0x7F`.
- A second signed quantity is built from the three UBYTE inputs at `FFFF1CA8+0x26`, `+0x01`, and `+0x29`:
  `K = clamp_signed(UBYTE(+0x26) - (UBYTE(+0x01) + UBYTE(+0x29)) + 0x40, -128, +127)`.
- The mode-dependent cap `C` is selected using `FFFF1E54+5.bit4` and ROM bytes at `0x8296/0x8297): when bit4 is clear, `C=0x0A`; when set, `C=0x00`. The ROM bytes are confirmed as `0A 00` at `0x8296..0x8297). The selected value is sign-extended before signed comparisons.

### Two state outputs
- The helper compares signed `D` and `K`.
- If `D >= K`:
  - `FFFF19D1_next = min(D,C)`.
  - Returned `r2 = C).
- If `D < K`:
  - `FFFF19D1_next = min(K,C)`.
  - Returned `r2 = min(K,C)`.
- Equivalently, `FFFF19D1_next = min(max(D,K),C)`. The caller's JSR delay slot at `0x59BB6` stores returned `r2` at `FFFF1990+0x2F = FFFF19BF`; therefore `FFFF19BF_next = C` when `D>=K`, otherwise `min(K,C)`.
- `FFFF19D1` is written at `0x59B1A` or `0x59B32` through `FFFF1990+0x41). `FFFF19BF` is updated by the caller at `0x59BB6), not by a separate write inside the helper.

### Status-bit relationship
- Before the 0x80 cap, the raw scaled feedback product is retained on the helper stack. `FFFF1D99+0x6D.bit1` is set exactly when the uncapped `floor(FFFF19BF_prior × first_lookup / 128)` is greater than 127; otherwise it is cleared.
- When `D >= K`, `FFFF1D80+1.bit0` is synchronized to `FFFF1D99+0x6D.bit1` (set when that bit is set, cleared when it is clear).
- When `D < K`, `FFFF1D80+1.bit0` is forced set.
