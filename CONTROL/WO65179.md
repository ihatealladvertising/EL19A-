# WO65179 — CF48D-to-EL19A structural table fingerprint crosswalk

**Status:** CLOSED — BOUNDED COMPLETE  
**Owner:** current session (claimed 2026-11-22)

## Objective
Develop a donor-to-target structural fingerprint comparison for CF48D XML table objects against EL19A catalogue candidates, using code-reader topology and normalized data shape rather than address coincidence or XML names alone.

## Dependencies
WO65142/WO65143 closed donor inventory; reader/extent evidence from WO65150–WO65161 where available; EL19A catalogue and reader evidence from WO65110, WO65116–WO65122 and relevant closed consumer traces. This WO may prepare a schema and assess readiness while donor reader WOs remain incomplete, but must not claim a final high-confidence match until the required donor-side evidence exists.

## Required work
1. Define a fingerprint schema: storage width/signedness, dimensions, axis widths/values, scaling, helper signature/argument order, query source, clamp/interpolation idiom, caller topology and first consumer.
2. Normalize donor and EL19A evidence into comparable features while preserving missing/unknown fields.
3. Match candidates using independent feature groups; report the evidence contributing to each score and sensitivity to missing features.
4. Manually validate the top candidate pairs against donor and EL19A listings; keep address mapping and semantic naming separate.
5. Produce a ranked hypothesis table plus false-match controls and a list of donor objects not ready for comparison.

## Acceptance criteria
- No score or confidence is driven solely by similar values, dimensions, names or address offsets.
- Every proposed pair cites exact reader/axis/consumer evidence on both ROMs, or is explicitly marked provisional/incomplete.
- Cross-ROM similarity is a hypothesis generator only; no CF48D label, address, unit or meaning is transferred to EL19A.
- Deliver a reproducible method, ranked candidate pairs and a clear "not comparable yet" set.

## Boundaries
Read-only and donor/target evidence comparison only. No XML/catalogue/workbook edits, no ROM/LST edits, no automated bulk semantic promotion and no broad scans. Reuse completed donor/target reports; no repeat of fixed 256-byte donor profiles or completed helper censuses.

### 2. Fingerprint schema (independent feature groups)
| Group | Features | Value-independent? |
|---|---|---|
| G1 Storage | element width, signedness, dims, row stride | yes |
| G2 Axis | implicit/fixed vs explicit; axis width; points; per-axis transform (e.g. ×4) | yes (point values excluded) |
| G3 Helper idiom | helper body sequence: search routine(s), max-index argument, interpolation chunk, column count | yes |
| G4 Call convention | r4 map, r5/r6 axis ptrs, r7 query 1, stack query 2; query widths | yes |
| G5 Topology | selector type (RAM bit / arg / none), pair/bank structure, sequential vs conditional reads, staging | yes |
| G6 Consumer | first consumer / output transform | partial on both ROMs |
A pair is only proposed if ≥3 independent groups match; G1 (dims/width) alone is never sufficient. Payload values, names and address offsets are not features.

- Address coincidence and XML names were never scored.
