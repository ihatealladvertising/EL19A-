# WO64877 — Correlate QDSPT Branch Flags with Transmission Range State

- **Status:** COMPLETE — no defensible D/N correlation found
- **Date:** 2026-11-16
- **Source:** `EL19A_Complete_Disassembly_ANNOTATED_V3_NEXT6_16_ALL_PENDING_ANNOTATIONS.lst`, Library ref `file_00000000fc2c820eb592f21d9c27911c`.
- **Depends on:** WO64875–WO64876.

## Findings

- The E688/0x848B path requires both FFFF85F8.bit4 and FFFF8600.bit6. This is a two-condition state gate, not by itself proof of Drive or Neutral selection.
- FFFF85F8.bit4 and FFFF8600.bit6 producers remain unresolved in the bounded direct-reference audit.
- FFFF85FF is a multi-byte status structure with numerous readers. Initialization copies its first three bytes to FFFF8602; no verified transmission-range/neutral source or explicit gear-state comparator was found in the audited neighborhoods.
- The related timer/status logic around `0x25080–0x250B6` modifies FFFF85F9, not the branch bits. The `sub_3BA88` logic consumes FFFF85F8+1 and other status values, but does not prove gear identity.
- Therefore the paired 0x848A/0x848B operands remain structurally confirmed but cannot be mapped to D/N from present evidence.

## Decision

Keep the pair as generic **E678-branch scalar 0x848A** and **E688-branch scalar 0x848B**. Do not promote `mDDSHPTD/N` labels or D/N suffixes yet.

## Recommended next lead

Investigate the producer of the broader FFFF85FF status structure, beginning with the pointer/copy origin at `0x20FB4–0x20FBE`, rather than continuing to scan the two bit addresses in isolation. No workbook/XML/ROM/LST edits.

## Coordinator erratum — E678/E688 gate polarity (2026-11-22)

The earlier selection wording above is superseded by the verified branch truth table in `CONTROL/WO65183.md` §3 (also reconciled in WO65015): while the calculation runs (`FFFF860B.bit3=0`), E688/`0x848B` is selected only when `FFFF85F8.bit4=0` **and** `FFFF8600.bit6=0`. If either bit is set, E678/`0x848A` is selected. When `FFFF860B.bit3=1`, both lookup calculations are bypassed. The flags' physical names and any Drive/Neutral interpretation remain unproven. This correction changes the selector polarity record only; it does not change table geometry, query mechanics, or calibration semantics.
