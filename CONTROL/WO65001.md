# WO65001 — A652 / AC12 paired 4×4 UBYTE reader and axis audit

**Status:** BOUNDED PASS — both physical placements and their shared reader/axis contract verified.  
**Target:** EL19A `f501.bin` · 1 MiB · MD5 `46991697c502052752a2cabcb84c9e27` · SH7058 · FID `8CMCKRN5`  
**Scope:** V56 candidate entries A652 and AC12 only. Establish extents, payload identity, reader, axis pointers/order, raw/scaled behavior, caller query form and immediate result staging. No semantic or donor-name transfer.

## Binary identity and payloads

- A652 extent: `0xA652–0xA661`, 16 UBYTE values, 4×4.
- AC12 extent: `0xAC12–0xAC21`, 16 UBYTE values, 4×4.
- Payloads are byte-identical; MD5 `69606a5d47e7d4686c4252a51db0053b`.
- Values (row-major byte order):
  ```
  27 2A 33 39
  20 25 2A 30
  15 1B 1F 25
  15 1A 1D 22
  ```
- Shared axis candidates:
  - `E2A1–E2A4`: `10 18 38 40`, UBYTE.
  - `E0A2–E0A5`: `40 66 99 CD`, UBYTE.
- Both axes are strictly increasing. Each physical map placement uses the same exact payload and axis pair.

## Reader contract

`sub_22B44` at `0x22B44`:
- Calls `sub_233CC` twice; both axes are compared as raw UBYTE values (no ×4 transform at this wrapper).
- First axis pointer arrives in R5; first query arrives in R7.
- Second axis pointer arrives in R6; second UBYTE query is caller-stack supplied.
- Helper uses four-point limits (`R4=3` to each axis search; `R5=4` to the 4×4 interpolation core at `loc_231F8`).
- No ROM axis scaling or generated axis is involved.

## Caller 1 — A652

At `0x4DB6C–0x4DB82`:
- R7 is loaded with `FFFF859C`; `0x4DB72` reads UBYTE `FFFF859C+8`, and the call delay slot at `0x4DB7E` zero-extends it into R7 (first-axis query).
- `0x4DB70` stores caller R12 into the outgoing stack slot used as the second query; its upstream source is not resolved in this scope.
- R4=`A652`, R5=`E2A1`, R6=`E0A2`; calls `sub_22B44` at `0x4DB7C`.
- Returned UBYTE is staged to a caller stack local at `0x4DB82`.

## Caller 2 — AC12

At `0x4B5FE–0x4B616`:
- `0x4B604` reads UBYTE `FFFF859C+8`; call delay slot at `0x4B610` zero-extends it into R7 (first-axis query).
- `0x4B602` stores the current R2 byte into the outgoing stack slot used as the second query; the prior calculation/source of R2 is outside this bounded scope.
- R4=`AC12`, R5=`E2A1`, R6=`E0A2`; calls `sub_22B44` at `0x4B60E`.
- Returned UBYTE is staged at caller structure offset `R10+0x42E` by `0x4B616`.

## Disposition

**Confirmed:** two distinct 4×4 UBYTE placements; identical 16-byte payload; same explicit raw axes E2A1/E0A2 in the same R5/R6 argument order; same `sub_22B44` reader; first query is UBYTE `FFFF859C+8` at both callers; second query is stack-supplied and caller-specific.

**Not assigned:** physical X/Y names or units for E2A1/E0A2; semantic purpose of either map; physical subsystem or actuator endpoint.

**Unresolved:** provenance of the second query at each caller (R12 at A652; R2 at AC12); any wider consumer/actuator chain. Stop here: these do not affect the confirmed candidate geometry or axis-reader contract.
