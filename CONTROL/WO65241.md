# WO65241 — Minimal SH-2 Execution Pilot on sub_22CB8

**Status:** ASSIGNED — WORKER 3 — READY  
**Priority:** P2 — falsifiable execution-method pilot  
**Workstream:** SEMANTIC / DYNAMIC-EXECUTION PILOT  
**Owner:** Worker 3  
**Branch:** `main`  
**Target:** EL19A `VERSA f501.bin`, 1 MiB, MD5 `46991697c502052752a2cabcb84c9e27`, SH7058/SH705822N, big-endian SH-2

## Objective

Test whether a minimal, function-local SH-2 interpreter can execute the EL19A 16×16 UBYTE lookup path at `sub_22CB8` and reproduce its result for controlled inputs. Use this as a bounded pilot for execution-based validation of table orientation, axis order, interpolation and sentinel behavior.

This is **not** a full ECU emulator. The purpose is to prove or disprove that a small, deterministic CPU/memory slice is sufficient for one pure software lookup path.

## Existing evidence to reuse

- `CONTROL/WO65109.md`: `sub_22CB8` reader contract and callers; three maps `0x9B2E`, `0x9C2E`, `0x9DAE`.
- `CONTROL/WO64968.md`: fixed-axis pair; `0x42BB2` calls map `0x9C2E`, `0x42BC8` calls `0x9DAE`; first helper axis pointer is `0xE4BC` (×4 breakpoint comparison), second is `0xE4AC` (raw comparison).
- `CONTROL/WO64895.md`: RP-004 `loc_23254` behavior — low seven bits enter interpolation and bit 7 from the first sampled cell is propagated; keep this separate from RP-006.
- `CONTROL/WO65204.md`: prior static instruction skeleton; no execution was attempted.
- Pinned raw ROM and NEXT6_16 listing identified in the above reports.

## Bounded execution target

Execute only the reachable lookup call path needed to obtain the `sub_22CB8` result:
- entry `sub_22CB8 @ 0x22CB8`;
- axis helpers `sub_2344C` and `sub_233CC`;
- tail/interpolation path `loc_23254` and `sub_231C8`, to the extent actually reached;
- only any additional tiny helper that is directly necessary to return from this call path.

Implement only the SH-2 instructions and architectural state required by this reachable path. Account for big-endian ROM/RAM access, register and stack behavior, PR/return flow, condition/T-bit behavior, branch delay slots and indirect calls/jumps. Prove the implemented instruction subset against the pinned listing/raw bytes before relying on the outputs.

## Test plan

1. Use the fixed-axis callsites at `0x42BB2` (table `0x9C2E`) and `0x42BC8` (table `0x9DAE`) as the primary test harness. Reconstruct the exact entry register/stack inputs from the existing callsite evidence; verify rather than assume the query values.
2. Execute against the real ROM table and axis bytes where local source artifacts are available. Record the exact query pair and returned UBYTE for each test.
3. Use a **non-symmetric synthetic 16×16 table** in scratch memory, with deliberately distinct row/column values, to distinguish the expected orientation from its transpose. This is the decisive row-versus-column discriminator; a symmetric or byte-identical target map alone cannot settle orientation.
4. Test a minimal boundary set: below first breakpoint, exact breakpoint, between adjacent breakpoints, above last breakpoint, and participating sample values exercising the RP-004 bit-7 propagation path. Keep RP-006's separate sentinel contract out of this call unless a direct caller requires it.
5. Compare interpreter outputs against an independently written scalar reference implementation of the verified reader contract. Report exact vectors and all mismatches. Do not use the same interpreter code to generate its own expected values.

## Falsifiable acceptance test

The pilot succeeds only if:
- executed instructions and branch paths match the pinned target bytes/listing;
- a non-symmetric table produces the reference result for the expected axis/stride interpretation and a different result for the transposed interpretation on at least one discriminating vector;
- real-ROM vectors, where available, match the independent scalar model;
- boundary and bit-7 behavior match the verified RP-004 contract.

If the interpreter disagrees with the scalar model, preserve the failing vector and diagnose it. Do not “correct” the reference model to fit the emulator.

## Implementation / safety limits

- A transient, worker-local scratch implementation is authorized solely for this pilot. Do not commit the prototype, add a repository script/tool, install a new dependency or create reusable infrastructure.
- Model ROM and ordinary RAM/stack only. This path must not require live peripherals; do not fabricate peripheral behavior. If a required read reaches MMIO, an interrupt, timer or hardware-dependent state, record the exact boundary and stop rather than building a peripheral model.
- No whole-firmware execution, scheduler/interrupt simulation, complete SH7058 peripheral stubs, simulated vehicle, live-vehicle testing or RPM/coolant/load response sweep.
- No ROM/LST/IDB/XML/A2L/workbook/catalogue/index/script/tool/Library edits. No permanent local artifacts.
- Only authorized repository output: `CONTROL/WO65241.md`; Worker 3 may update only its own lifecycle/queue entries in `CONTROL/active_work_orders.md` at closeout.
