## Bounded work

### 1. Outer gate — `FFFF860B.bit3` bypass

At `sub_403D8` entry, `GBR = FFFF1028` (PC `0x404E8-0x404EA`). Then:

```
000404EC  9C 86   mov.w   word_404FC, r12  ; r12 = h'FFFF860B
000404EE  60 C0   mov.b   @r12, r0         ; r0 = UBYTE[FFFF860B]
000404F0  C9 08   and     #8, r0           ; test bit 3 (0x08)
000404F2  20 08   tst     r0, r0
000404F4  8F 10   bf/s    loc_40418        ; if bit3 CLEAR, continue; if SET, bypass
```

- `FFFF860B.bit3 = 1` → branch to `loc_40418` (PC `0x40418`), which stores IVECT1 at `FFFF2150+0x622` and returns — **both E678 and E688 lookups are bypassed**.
- `FFFF860B.bit3 = 0` → fall through to inner branch selection.

No static writer for `FFFF860B.bit3` found in bounded search (100+ read sites across the listing, zero `mov.b` store targeting this bit).

### 3. `0x8550` threshold comparison vs `FFFF84BA` query

After the E688/E678 table base is selected, `sub_403D8` reads the query value:

```
00040422  92 6C   mov.w   word_404FE, r2   ; r2 = h'FFFF84B4
00040424  DD 74   mov.l   off_405F8, r13   ; r13 = h'FFFF1D99
00040426  84 26   mov.b   @(6,r2), r0      ; r0 = UBYTE[FFFF84B4+6] = UBYTE[FFFF84BA]
00040428  65 0C   extu.b  r0, r5           ; r5 = query (UBYTE)
0004042A  E0 1B   mov     #h'1B, r0        ; r0 = 0x1B
0004042C  04 DC   mov.b   @(r0,r13), r4    ; r4 = UBYTE[FFFF1D99+0x1B] = UBYTE[FFFF1DB4]
```

Then the `0x8550` comparison:

```
00040436  D3 71   mov.l   off_405FC, r3    ; r3 = h'8550 (ROM address)
00040438  60 43   mov     r4, r0           ; r0 = UBYTE[FFFF1DB4]
0004043A  62 30   mov.b   @r3, r2          ; r2 = ROM[0x8550] = 0x0A
0004043C  62 2C   extu.b  r2, r2
0004043E  35 22   cmp/hs   r2, r5          ; compare query(0x85AE-derived) vs 0x8550(0x0A)
00040440  8D 01   bt/s    loc_40446        ; if query >= 0x0A: skip bit-5 clear
00040442  CB 20   or      #h'20, r0        ; set bit 5 (only when query < 0x0A)
00040444  C9 DF   and     #h'DF, r0        ; clear bit 5 (only when query < 0x0A)
```

Behavior:
- **Query >= 0x0A** (`0x8550` value): `FFFF1DB4.bit5` is **preserved** (branch skips the or/and)
- **Query < 0x0A**: `FFFF1DB4.bit5` is **cleared** (`or #0x20` sets bit 5, `and #0xDF` clears it — net: bit 5 forced to 0)
- Result written back to `FFFF1DB4` at PC `0x40446-0x4044A`: `mov r0, r2; mov.b r2, @(r0,r13)` where r0=0x1B, r13=FFFF1D99 → address `FFFF1DB4`

ROM `0x8550 = 0x0A` (shipped value). The query `FFFF84BA` comes from `FFFF84B4+6` — no static writer found for either `FFFF84BA` or `FFFF1DB4` (both declared `.res.b 1`).

### 4. `FFFF1DB4.bit5` — write provenance

`FFFF1DB4` declared at LST line 447379: `FFFF1DB4  FF  UNDEFINED .res.b 1` — no static initializer writer.

The **only write** to `FFFF1DB4.bit5` found in bounded search is in `sub_403D8` itself (PC `0x40442-0x4044A`), which **clears** bit 5 when query < `0x8550`. No instruction was found that **sets** bit 5. The bit ships as `0xFF` (all bits set per `.res.b 1` declaration) but may be dynamically cleared by `sub_403D8` on subsequent executions when the query falls below the `0x8550` threshold.
