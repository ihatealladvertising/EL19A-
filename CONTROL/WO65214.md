# WO65214 — CF48D BIN ↔ XML metadata reconstruction benchmark

**Status:** RESERVED — NOT STARTED; unclaimed  
**Priority:** P1 · **Class:** BINARY / XML BENCHMARK  
**Inputs:** `EVIDENCE/CF48D.bin`, `EVIDENCE/CF48D.xml`, `EVIDENCE/CF48D.bin.lst` (hashes/provenance in WO65156).

## Objective
Treat the matched CF48D BIN/XML pair as a controlled benchmark to measure exactly which RomRaider XML definition fields can be reconstructed from raw binary plus the XML's metadata, and which cannot.

## Tasks
1. Verify current hashes and provenance of the BIN/XML/LST triplet; do not rely only on historical statements.
2. Parse XML entries into a normalized field inventory: address, type, dimensions, axes, storage width/signedness, endian, scaling, units, limits, names/descriptions and category/group.
3. For a stratified representative sample across all XML object types/layouts, reconstruct raw payloads and axes from BIN; compare against XML declarations.
4. Validate address base/origin, byte order, record extent, axis storage, shared axes, duplicate placements and any non-contiguous/offset layout.
5. Classify each field as recoverable from BIN alone, recoverable only with XML/A2L metadata, derivable from reader/disassembly, or not recoverable without external semantic knowledge.
6. Reuse existing WO65150–WO65158 CF48D raw-byte and reader findings; do not repeat their specific consumer traces or broad payload extraction. Expand only where needed to cover an untested XML layout class.
7. Produce a machine-readable field-availability matrix suitable for the final synthesis.

## Deliverables
- `CONTROL/WO65214.md` and a compact additive TSV matrix if useful.
- No edits to CF48D BIN/XML/LST or other protected artifacts.

## Acceptance criteria
- Representative coverage spans every distinct XML storage/layout pattern, or explicitly lists uncovered patterns.
- At least one raw-byte reconstruction per covered pattern agrees with the XML declaration.
- Recoverability classification is field-specific and evidence-backed.
- Clear distinction between structural reconstruction and physical calibration semantics.

## Stop conditions / exclusions
No donor-to-EL19A address/name/unit transfer; no repeated completed CF48D reader traces; no XML modification, workbook update, catalogue/index/tool changes, or ROM/LST edits.
