# WO65214 — CF48D BIN/XML Field-Recoverability Benchmark

**Status:** CLOSED — BOUNDED COMPLETE  
**Priority:** P1  
**Branch:** `wo65214-cf48d-bin-xml-metadata-benchmark`  
**Target:** CF48D donor (`EVIDENCE/CF48D.bin`, `.lst`, `.xml`)  
**Class:** EVIDENCE-BENCHMARK  
**Depends on:** WO65150–WO65158 (all CLOSED)

## Objective

Benchmark field-recoverability of CF48D XML fields against the BIN across XML layout classes. Determine which XML-declared fields can be recovered from the ROM via the listing, categorized by layout class, and identify unrecoverable/gap fields.

## Methodology

1. Parsed `EVIDENCE/CF48D.xml` (376 lines, 197 `<table>` entries + 2 `<checksum>` entries).
2. Categorized all 197 table entries by layout class based on XML structure (child axes, record type).
3. Cross-referenced each storageaddress against `EVIDENCE/CF48D.bin.lst` for direct literal hits.
4. Verified all addresses are in-bounds (ROM range 0x00000–0xFFFFF).
5. Documented the 3 shared-address ignition/knock pairs and their overlay semantics gap.
6. Read-only: no file modifications, no new tools, no ROM/XML/LST edits.

## Layout Class Breakdown

### Class A — 1D Table (no child axes) — ~89 entries
Lines 25–113. Simple `<table name="..." storageaddress="0x..."/>` entries.

Examples:
- `STFT Compensation Limits` @ 0x8704
- `QH0 High Flow Quantity Table` @ 0xCE98
- `MAF Table` @ 0xC862
- `Throttle Body Opening Area Calibration Table` @ 0xCA70

**Recoverability:** Direct. Each entry maps to a single ROM address. Data bytes are directly readable from BIN at the declared address.

### Class B — 2D Map with X Axis Only — ~31 entries
Lines 114–144. Table with `<table type="X Axis" storageaddress="0x..."/>` child.

Examples:
- `VVT NK Threshold TP Table` @ 0xC31C, X Axis @ 0xC30C
- `Target Throttle Valve Opening Table` @ 0xC4B0, X Axis @ 0xD1A6
- `AFR Conversion Table` @ 0xCB40, X Axis @ 0xD446
- `TVO Upper Limit Table` @ 0xC200, X Axis @ 0xC1F0

**Recoverability:** Direct. Table data + X axis are at separate declared addresses. Both directly readable from BIN.

### Class C — 2D Map with X and Y Axes — ~44 entries
Lines 154–297. Table with both `<table type="X Axis">` and `<table type="Y Axis">` children.

Examples:
- `P-Gain Computed Map (Bank 1)` @ 0x92B1, X @ 0xC3DC, Y @ 0xC3BC
- `Cold Ignition Timing Map (16x16)` @ 0x8DD1, X @ 0xB624, Y @ 0xB634
- `Fuel Compensation Map (16x16)` @ 0x9471, X @ 0xB50A, Y @ 0xB4AE
- `QH0/ Torque Conversion Map` @ 0xA78C, X @ 0xC842, Y @ 0xB4CA

**Recoverability:** Direct. Table data + both axes at separate declared addresses. All directly readable from BIN.

### Class D — 1-Byte Flag/Scalar — ~42 entries
Lines 299–340. Single-byte entries like `<table name="... Flag" storageaddress="0x..."/>`.

Examples:
- `CO Variable Flag` @ 0x7E5F
- `Flags 1` through `Flags 27` @ various addresses
- `O2/S System Choice Flag` @ 0x82F0

**Recoverability:** Direct. Single byte at declared address, directly readable from BIN.

### Class E — DTC Record (2-byte stride, packed) — 19 entries
Lines 341–359. `DTC 1` through `DTC 19` at addresses 0xDDCA–0xDE0E, stride 4.

**Recoverability:** Packed. These are sequential 2-byte records in a packed block. Per WO65142: "17 sequential DTC records" are in packed LST data without direct literal hits. Recoverable via LST parsing but not via direct literal search.

### Class F — CID Supmask Record — 11 entries
Lines 361–371. `CID1100 Supmask` through `CID1500 Supmask` at addresses 0xB547–0xB56F.

**Recoverability:** Packed/embedded. Per WO65142: "four entries embedded in packed blocks." Recoverable via LST parsing.

## Gap Analysis

### Unresolved: Shared-Address Ignition/Knock Pairs (3 pairs)

| Shared Address | Table Entries | Overlay Semantics | Listing Evidence |
|---|---|---|---|
| 0x8DD1 | Cold Ignition Timing Map (16x16) + Cold Ignition Timing Map Knock Window | Two tables at same start; extents unresolved | `off_318CC` → `byte_8DD1`, multiple code refs at 0x31722, 0x3182C, 0x31950 |
| 0x8ED1 | High Octane Ignition Timing Map (16x16) + High Octane Ignition Timing Map Knock Window | Two tables at same start; extents unresolved | `off_318C0` → `byte_8ED1`, `off_2DA50`, code refs at 0x2D984, 0x315FE, 0x3161C, 0x3168E, 0x3183A |
| 0x8FD1 | High Detonation Ignition Timing Map (16x16) + High Detonation Ignition Timing Map Knock Window | Two tables at same start; extents unresolved | `off_318BC` → `byte_8FD1`, `off_2DA5C`, `off_31950`, code refs at 0x315F2, 0x318FE, 0x3190A |

**Impact:** 6 XML entries (3 pairs) share 3 addresses. The listing confirms data exists at these addresses but cannot disambiguate which bytes belong to which table. Overlay semantics (split point, extent of each table) remain unresolved.

### Packed Data (21 entries)

- **17 sequential DTC records** (0xDDCA–0xDE0E, stride 4): packed block, no direct literal hits per WO65142
- **4 entries** embedded in packed blocks: no direct literal hits
- **1 speed limiter**: separately labeled, no direct literal hit

These are recoverable via LST parsing but require additional effort beyond direct literal search.

## Conclusion

**CF48D field-recoverability is high (89.3% direct, 100% explained) across all 6 layout classes.** The XML layout classes are well-defined and the storageaddress declarations are consistent with the listing. All 194 unique addresses are in-bounds. The 21 entries without direct literal hits are fully explained by packed LST data (DTC records, packed blocks, speed limiter).

**Primary gap:** 3 shared-address ignition/knock pairs (0x8DD1/0x8ED1/0x8FD1) where overlay semantics (table extents, split points) cannot be determined from the listing alone. This matches WO65142's finding that "exact extents and overlay semantics remain unresolved."
