## 1. Reader family and shared helper contract (method)

Both objects are read by `sub_22CF8`, whose contract is fixed by the shared interpolation core it tail-jumps into. This was derived from code, not assumed from the matcher.

### 1.1 `sub_22CF8` argument contract (0x22CF8–0x22D26)

```text
sub_22CF8:                              ; r4 = map base, r5 = axis A, r6 = axis B,
                                        ; r7 = query A, stack arg (0x10+arg_0) = query B
0x22CF8  sts.l pr,@-r15
0x22CFA  mov.l r4,@-r15                 ; save map pointer
0x22CFC  extu.w r7,r7                   ; query A is UWORD
0x22CFE  mov   r5,r0                    ; r0 = axis A
0x22D00  mov   r7,r5                    ; r5 = query A
0x22D02  mov.l off_22D2C,r7 ; sub_2340C
0x22D04  jsr   @r7
0x22D06  mov   #h'E,r4                  ; delay slot: start offset 0xE  => 8×UWORD axis
0x22D08  mov.l r4,@-r15                 ; save index/fraction pair (index in r4, frac in r5)
0x22D0A  mov.l r5,@-r15
0x22D0C  mov   r6,r0                    ; r0 = axis B
0x22D0E  mov.l @(h'10+arg_0,r15),r5      ; r5 = query B from caller stack arg
0x22D10  extu.w r5,r5
0x22D12  jsr   @r7                      ; same search helper
0x22D14  mov   #h'E,r4                  ; delay slot: 8×UWORD axis again
0x22D16  mov.l @r15+,r1                 ; r1 = fraction A
0x22D18  mov.l @r15+,r0                 ; r0 = byte offset A
0x22D1A  mov   r4,r2                    ; r2 = byte offset B
0x22D1C  mov   r5,r3                    ; r3 = fraction B
0x22D1E  mov.l @r15+,r4                 ; r4 = map pointer
0x22D20  lds.l @r15+,pr
0x22D22  mov.l off_22D28,r7 ; loc_232D0
0x22D24  jmp   @r7
0x22D26  mov   #8,r5                    ; delay slot: column count / row stride = 8
```

The tail jump is to `loc_232D0`, the **UWORD** 2D interpolation core:

```text
0x232D0  mov.l r8,@-r15 ; sts.l pr,@-r15 ; sts macl,r7
0x232D6  mulu  r5,r0                    ; (2*rowIndex) * 8  -> row byte offset
0x232D8  add   r2,r4                    ; + (2*colIndex)
0x232DA  sts   macl,r0
0x232DC  lds   r7,macl
0x232DE  shll  r5                       ; r5 = 8*2 = 16 bytes = one row of 8 UWORD
0x232E0  add   r0,r4
0x232E2  add   r4,r5                    ; r5 = next row
0x232EC  mov.w @r4,r1                   ; bilinear cell: (row,col), (row,col+1)
0x232EE  mov.w @(2,r4),r0
0x232FC  mov.w @r5,r1                   ; (row+1,col), (row+1,col+1)
0x232FE  mov.w @(2,r5),r0
                                        ; -> sub_231C8 twice (MUL.L high word, no rounding)
```

Therefore, for `sub_22CF8`:

- **row count = axis-A length = 8** (start offset `0xE` = last UWORD element of an 8-entry axis; `sub_2340C` decrements by 2);
- **column count = 8** (immediate at `0x22D26`);
- element width **UWORD, big-endian**, read via `mov.w @r4` / `@(2,r4)`;
- table byte address = `base + 16*rowIndex + 2*colIndex`;
- **storage = 8 × 8 = 64 UWORD = 128 bytes.**

`sub_2340C` (the axis search) confirms the 8-entry UWORD geometry: `mov r4,r3`, loop `mov.w @(r0,r4),r1` / `extu.w` / `cmp/eq r1,r5` / `cmp/hi r1,r5`, `add #-2,r4` per step, exact-match returns the raw fraction, interior returns `floor((Q-axis[i])*65536/(axis[i+1]-axis[i]))` via `sub_23700`; below-range returns index 0 / fraction 0.

### 1.2 Why 128 bytes, not 256

The reported "8×8 … 128 elements / 256 bytes" is arithmetically impossible for an 8×8 UWORD grid (8×8 = 64 elements = 128 bytes), and the 256-byte reading is also *physically* excluded by the catalogue:

| Address | Catalogued extent | Object |
|---|---|---|
| `0x0D656`–`0x0D855` | 512 B | 16×16 UWORD BE, `sub_22D30` @ `0x66E3C` |
| **`0x0D856`–`0x0D8D5`** | **128 B (this WO)** | **8×8 UWORD BE, `sub_22CF8` @ `0x6B1DE`** |
| `0x0D8D6`–`0x0DAD5` | 512 B | 16×16 UWORD BE, `sub_22AFC` @ `0x5C28E` |

`0x0D856 + 128 = 0x0D8D6`, exactly the start of an already reader-verified 16×16 table. A 256-byte `0x0D856` would overlap it. The all-`0x8000` fill of `0x0D856` also stops exactly at `0x0D8D5`; `0x0D8D6` begins with `7E E3 7F B8 …`. The gap-filling 128-byte extent is therefore structurally bounded on both sides.

For `0x0C2D6` the lower bound is `0x0C0D6`+512 = `0x0C2D5` (16×16 UWORD BE, `sub_22D30`), and the region `0x0C356`–`0x0C3D5` is a further 128 bytes of `0x00`, distinct from the next catalogued object `0x0C3D6` (8×8 UWORD BE, `sub_22CF8` @ `0x6F6DC`). `0x0C2D6`'s `0x1000` fill stops at `0x0C355`. The reachable extent is 8 rows (axis length) × 8 columns = 128 bytes; the following 128 zero bytes are **not reachable by this reader** and are not claimed.

The catalogue already contains a `sub_22CF8` 8×8 UWORD member at `0x0C3D6`, so this geometry class was previously established; WO70009 adds two more members.

- Immediately preceded by the 512-byte 16×16 table at `0x0D656`; immediately followed by the 512-byte 16×16 table at `0x0D8D6`.

### 2.2 Callsite and enclosing function

The physical meaning of the composite is **not** established here.

## 3. Object B — `0x0C2D6`

- Extent `0x0C2D6`–`0x0C355`, 128 bytes, UWORD big-endian, 8 rows × 8 columns (row stride 16 bytes).

Two consequences worth recording:

1. **The row query is a ROM constant zero.** `0xA324` is a ROM literal used as a pointer; `0x0A324`–`0x0A343` is 32 zero bytes, so `U16[0x0A338] = 0x0000`. The descending axis search then returns index 0, fraction 0 (`locret_23444`), so in this stock ROM the surface is read as **row 0 only** — it degenerates to its first row.
2. **The column query `U16[FFFF13D8]` is the same cell used by `0x0D856`.** This is the strongest target-side corroboration of the donor pairing (both donor maps carry the same second-axis quantity `COMP_0065`).

`0xFE00` is adjacent to `0xFDF0` (`+0x10`), matching the callsite idiom. `0xFE10` begins an unrelated ascending vector `0000 1FE0 3FC0 5FA0 …`, so the `0xFE00` object ends at `0xFE0F`.

**Unresolved:** `sub_2340C` is written for ascending axes (`cmp/hi` + decrement). With the descending `0xFE00` axis, a query below all entries falls through to index 0/fraction 0 and an exact hit returns the raw fraction. The interpolation contract for a descending breakpoint axis is **not established**; do not present `0xFE00` as an ordinary ascending query axis.

## 4. Reconciling the reported "companion caller references"

The matcher claimed companion references (`0x1100A`, `0x10954`, `0x0CD56`) with donor symbols `mTTQH0ST`, `mTMAXPTQ`, `mMTTE`. Their actual target roles, from the listing:

| Address | Actual target role | Reader / callsite | Geometry (catalogue) | Donor symbol | Donor declaration |
|---|---|---|---|---|---|
| `0x1100A` | 32-point UWORD curve (**not** an axis of `0x0D856`) | `sub_22FAC` @ `0x6B19E` (in `sub_6B160`) | 32×1 UWORD BE, axis `0x10EEA` | `mTTQH0ST` | `CURVE … REC_UWORD_C`, one 32-pt axis `mTTGADNV` |
| `0x0CD56` | 16×16 UWORD map (**not** an axis of either) | `sub_22D68` @ `0x6B1B0` **and** `0x6FBDA`/`0x6FC40` | 16×16 UWORD BE, axes `0x0E2C9` (U8×16), `0x0FEC0` (U16×16) | `mMTTE` | `MAP … REC_UWORD_C`, two 16-pt axes |
| `0x10954` | 16-point UWORD curve (**not** an axis of `0x0C2D6`) | `sub_22F80` @ `0x6FC18` (else-branch alternate) | 16×1 UWORD BE, axis `0xF912` | `mTMAXPTQ` | `CURVE … REC_UWORD_C`, one 16-pt axis |

- **Sibling, not axis.** Each companion is an independent lookup in the same enclosing function that feeds the same downstream arithmetic. The genuine axes of each 8×8 map are separate 8-entry UWORD vectors immediately adjacent to each other and passed as `r5`/`r6`, with `+0x10` between them. None of the companions has 8 entries except `0x0CD56`, whose 16×16 geometry cannot be an axis of an 8-row grid.
- **`0x0CD56` is not discriminating.** It appears in `sub_6B160` (`0x6B1A6`) and in `sub_6FCFE`'s body (`0x6FC34`, `0x6FC40`), and additional sites elsewhere (`0x66146`, `0x69160`, `0x69174`, `0x6919E`, `0x6967C`, `0x6B6D6`, `0x6CC9E`, `0x6FBD0`). A "shared companion" that both candidates share cannot corroborate a 1:1 pairing.
- **The 1:1 claim is unsupported.** The matcher source, documentation and pair-level raw output are absent from `main`; this WO did not reconstruct them. Independent structural correspondence is real for *geometry class* (8×8 UWORD with two 8-point axes) but does not establish symbol assignment.
