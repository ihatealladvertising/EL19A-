## Question

Are EL19A addresses `0x0D856` and `0x0C2D6` genuine 8×8 UWORD lookup maps, and do their caller constellations independently support the reported dual-donor candidates `mTEHOSMAP` and `mMPAMBFAC`?

## Reported lead — test each object independently

The user-reported A2L matcher describes:
- `0x0D856` → candidate `mTEHOSMAP`, with companion caller references `0x1100A` (candidate `mTTQH0ST`) and `0x0CD56` (candidate `mMTTE`);
- `0x0C2D6` → candidate `mMPAMBFAC`, with companion caller references `0x10954` (candidate `mTMAXPTQ`) and `0x0CD56` (candidate `mMTTE`).

The summary reports 1:1 V6+Juke structural consensus, but the matcher source, documentation and pair-level raw outputs are not committed. Treat every donor label and companion relationship as a hypothesis. Do not assume that the companion addresses are axes; determine their actual reader roles from the target helper arguments.

## Exact scope

For **each** of `0x0D856` and `0x0C2D6`:

1. Confirm the exact ROM bytes, minimum extent, element width, signedness and byte order. Test the reported 8×8 UWORD BE geometry (128 elements / 256 bytes) rather than assuming it.
2. Identify each exact code callsite that supplies the address as table data. Trace the complete helper argument contract from the callsite through the lookup helper: data pointer, axis pointer(s), query value(s), dimensions, indexing, interpolation, clamp and return/output register.
3. Resolve the enclosing target function and all sibling lookup calls needed to test the reported constellation:
   - for `0x0D856`, inspect the actual roles of `0x1100A` and `0x0CD56`;
   - for `0x0C2D6`, inspect the actual roles of `0x10954` and `0x0CD56`.
   Do not presume these are three axes or three tables in the same grid. Record exact call PCs and registers.
4. Establish the actual query sources and the first consumer only far enough to distinguish competing table/axis interpretations or support a displayed axis. Do not expand into unrelated engine-control semantics.
5. Locate `mTEHOSMAP` and `mMPAMBFAC` independently in both donor A2Ls. Record their declarations, storage, dimensions, axis definitions, conversion methods and function memberships. Keep V6 A2L pairing caveat from WO65212 in force; validate the relevant Juke S19 mapping for each symbol before making a Juke payload comparison.
6. Compare target and donor evidence in separate columns: function correspondence, geometry, axis/scale, payload, caller constellation, and semantic identity. Do not collapse these into a match score.
7. Reconcile `0x0CD56` use with REC-000021 and WO65060. Preserve the linked `0x0FEC0` axis relationship; do not create a duplicate correction or change its meaning.
8. Check whether either target map is already in the current catalogue, scope matrix or XML. Add only verified structural rows to the catalogue using its existing schema. Do not add donor names or unverified axes.
