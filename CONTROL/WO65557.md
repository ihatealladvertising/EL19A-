## 1. Decision

Diagnostic illustration of why the gap rule matters: if the ineligible payload-only anchors `E424`/`F2B2` were used to bracket `F062`, linear interpolation would predict Juke `0x126E1` for `mTRPAMB` against the declared `0x1270A` — a 41-byte error. A plausible-looking offset is not an exact correspondence and cannot be scored as a true positive.

## 6. Minimum input needed for a future test

1. A second **distinct** ROM/definition pair with its own definition file that shares at least three exact, discriminative payload-plus-axis fingerprints with EL19A, or an independently produced definition for a second Juke build so held-out addresses are not the same A2L declarations used for training.
2. Independent confirmation that the EL19A definition addresses used as anchors are correct (reader/listing evidence plus a non-`[S]` row), not only byte coincidence.
3. A held-out set of definition addresses withheld before prediction, plus enough anchors on both sides of each held-out address to avoid interpolating across an unsupported discontinuity.

Until those inputs exist, any unknown-scalar application of this method would be an unverified address overlay. No such application, automatic label, XML edit or vehicle action is authorized by this result.
