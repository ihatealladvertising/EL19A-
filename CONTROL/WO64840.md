### Query producer — closed

Instruction path in the annotated LST:
1. `sub_3470C` sets GBR=`FFFF8594`, reads UWORD `FFFF8596`, shifts it right three and stores the result at `FFFF85CE` (`0x3471A–0x3472C`).
2. `sub_34680` reads UWORD `FFFF85CE`, shifts it right three, caps at `0xFF), and writes the byte to `FFFF85D0` (`0x34680–0x346CA`). The caller's JSR delay slot also stores the returned UWORD query at `FFFF85DA` (`0x34778–0x3477A`).
3. The established `FFFF85C4 → FFFF859C` 0x28-byte copy carries `FFFF85D0 → FFFF85A8`.

Therefore:
`FFFF85A8 = min(U16[FFFF8596] >> 6, 255)`.
The adjacent E424 query from `sub_346E0` is `FFFF85A9 = min(U16[FFFF8596] >> 7, 255)`. They share an upstream timer-derived source but use different shifts; they are not interchangeable.

WO64827 established the upstream producer: `sub_257AC` forms timer-capture interval `FFFF85E4); `sub_34476` uses the 48,000,000 timer constant divided by that interval, saturates to UWORD `FFFF8596), and gates validity with `FFFF99E9.bit3`. This proves a timer-rate-derived query, not a calibrated RPM value. Pulse/event-to-revolution relationship remains unknown.

### Query-to-axis test — partial with endpoint incompatibility

- The donor mapping would require q=RPM/12.5; its stated 3000-RPM endpoint maps to q=240 (`0xF0)).
- `sub_22E10` returns numeric sentinel `0xF0` immediately for every q≥`0xF0`; it does not sample the table at this boundary.
- Thus the last donor point at 3000 RPM (raw `0x00`) is not reachable under the proposed linear mapping; q=240–255 all return sentinel 240. q=0–239 can address/interpolate the first 15 logical intervals.
- Target query is derived from timer-rate value `FFFF8596`, but the physical conversion to RPM is unproven. The target code does not establish q=RPM/12.5.
- Disposition: **PARTIAL / UNRESOLVED**, with a definite top-end boundary mismatch if the donor RPM mapping is assumed. Do not transfer the RPM axis into EL19A.
