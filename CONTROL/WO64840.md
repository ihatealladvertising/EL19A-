## Stage 3 — TEST results (2026-11-16)

### Query provenance — current timer-derived value confirmed
- The 0x28-byte block copy at PC `0x20F06` moves source `FFFF85C4` to destination `FFFF859C`; destination query `FFFF85A8` is source byte `FFFF85D0`.
- The structure routine spanning `0x3470C–0x347A8` computes `UWORD[FFFF85CE] = UWORD[FFFF8596] >> 3` at PC `0x3472C`.
- Its call to `sub_34680` (PC `0x34778`) calculates `q = min(UWORD[FFFF85CE] >> 4,255)` and stores it to `FFFF85D0` (PC `0x346CA), in the branch delay slot.
- The immediately following `sub_346E0` call (PC `0x3477C`) applies the same shift/cap and stores it to `FFFF85D1` at PC `0x346F8` (RTS delay slot).
- Therefore, on this producer path, **`FFFF85A8 == FFFF85A9 == min(UWORD[FFFF8596] >> 7,255)`**. These are adjacent copied bytes but are independently written from the same current timer-derived index.
- WO64827 established `FFFF8596` is generated from timer-capture delta via `sub_257AC → FFFF85E4 → sub_34476`, including a 48,000,000 divisor and UWORD saturation/fallback. The physical event/revolution relationship and unit conversion to engine RPM remain unresolved.
- Donor mTTNKAS axis equivalence would require q=RPM/12.5. The target relation is `min(UWORD[FFFF8596]>>7,255)`; without a proven capture-event-per-revolution ratio, the donor 200-RPM axis is not validated.

### F2B2 result and downstream use
- `sub_4DC32` stores F2B2 lookup output at `FFFF1054+0x571 = FFFF15C5` (PC `0x4DD74`).
- The same routine uses it in an unsigned three-byte product:
  - `T = UBYTE(FFFF15C5)` (F2B2 lookup result)
  - `U = UBYTE(FFFF1054+0x312)`
  - `V = UBYTE(FFFF1054+0x564)`
  - `P = floor(U × V × T / 64)`, using `sub_223FE` arithmetic `>>6`. The operands are UBYTE and the product fits in 32 bits.
- If P exceeds 0xFFFF, the contribution is capped to 0xFFFF. It is then added to prior UWORD `FFFF2150+0x606 = FFFF2756`, capped again to 0xFFFF, and stored at `FFFF1054+0x29C = FFFF12F0` (PC `0x4DDC8–0x4DDDE`).
- The target therefore applies a /64 fixed-point scale to the combined product containing F2B2. This is mathematically compatible with the donor raw/64 data conversion, but does not establish the donor mTTNKAS physical description.
- Furthest established endpoint is the internal accumulated/saturated UWORD `FFFF12F0`. No direct engine-speed command, fuel-cut event, injector/ignition output, physical actuator or peripheral endpoint is demonstrated.
