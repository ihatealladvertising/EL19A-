### 5. `sub_22F28` helper mechanics — VERIFIED

sub_22F28 (listing line 26572): r4=table(0x0E934), r5=axis(0x0E082), r6=query(UBYTE).

**Helper chain:**
- `extu.b r6, r5` → r5 = zero-extend(query byte)
- Calls `sub_233CC`(r0=axis_base, r5=query) — **UBYTE axis search** (descending scan, unlike sub_2340C's UWORD BE ascending search)

### A. Query lineage and query byte — corrected

- The literal-store routine entry is **`sub_288B4` @ `0x288B4`**, not `sub_288BE`; `0x288BE` is only the sixth prologue push. Sole caller is `jsr sub_288B4` at `0x241F2`.
- `0x288C4–0x288C6`: `GBR = FFFFA34C`; `0x28932`: `mov.w word_28A62,r2` with ROM bytes `DA 80` = `0xDA80`; `0x28938`: `mov.w r0,@(0x14,gbr)` stores that literal into `UWORD[FFFFA360]`.
- `0x20F68–0x20F72`: source `FFFFA34C`, destination `FFFFA324`, dispatch to `sub_21FFC`, delay-slot length `0x28`. The table slot `[0x2205C+0x28] = [0x22084] = 0x22032`; the 10-longword copier at `0x2203E–0x22044` performs `mov.l @(0x14,r2),r0` / `mov.l r0,@(0x14,r1)`, so `UWORD[FFFFA338] = 0xDA80`.
- The accepted report is right that `0x3A06A` loads a full UWORD into `r0`, but the delay slot of `bsr sub_3A178` at `0x3A072` is `0x3A074 mov r0,r6`, so that full UWORD **is** the incoming argument. Inside `sub_3A178`, `0x3A190–0x3A1A6` (`extu.w`, `shlr8`, `swap.w`, `exts.b`, `xtrct`, `extu.b`) reduce it to `q = (Q >> 8) & 0xFF = 0xDA`. This settles the transferred “r0 vs r6” discrepancy.
- Static liveness caveat: the chain is proven to exist and be reachable in code, but no execution-time ordering proof is available from the listing.

### C. First valid consumers — corrected
