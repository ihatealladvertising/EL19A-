### 5. `sub_22F28` helper mechanics — VERIFIED

sub_22F28 (listing line 26572): r4=table(0x0E934), r5=axis(0x0E082), r6=query(UBYTE).

**Helper chain:**
- `extu.b r6, r5` → r5 = zero-extend(query byte)
- Calls `sub_233CC`(r0=axis_base, r5=query) — **UBYTE axis search** (descending scan, unlike sub_2340C's UWORD BE ascending search)
- `mov #h'F, r4` → r4 = 15 (offset for second table byte)
- Reads `BYTE[table_base + 15]` (r1) and `BYTE[table_base + 16]` (r0) — adjacent payload bytes
- Jumps to `sub_231C8`(r0=upper_byte, r1=lower_byte, r2=upper_zero_extended, r3=query) — endpoint interpolation

**sub_233CC** (listing line 27285): Descending UBYTE axis search. Scans axis bytes from high index down, exact match returns index; otherwise locates segment and computes fraction via `sub_23700` (DIV1). Returns index in r4, fraction in r5.

**sub_231C8** (listing line 26981): Endpoint interpolation with `mul.l` high word, no rounding. Same helper as used by sub_22FD8/sub_22F80 (E904/E914 path).

**Key difference from E904/E914:** E934 uses `sub_22F28`→`sub_233CC` (UBYTE axis, descending scan) while E904/E914 use `sub_22FD8`/`sub_22F80`→`sub_2340C` (UWORD BE axis, ascending scan). Different reader, different axis width.

## E904/E914 comparison — VERIFIED

| Aspect | E904 (WO65124) | E914 (WO65125) | E934 (WO65126) |
|--------|---------------|----------------|----------------|
| Table | `0x0E904` (16 UBYTE) | `0x0E914` (16 UBYTE) | `0x0E934` (16 UBYTE) |
| Axis | `0x0FA62` (16 UWORD BE) | `0x0FA82` (16 UWORD BE) | `0x0E082` (16 UBYTE) |
| Reader | `sub_22FD8` | `sub_22FD8` | `sub_22F28` |
| Axis search | `sub_2340C` (UWORD BE, ascending) | `sub_2340C` (UWORD BE, ascending) | `sub_233CC` (UBYTE, descending) |
| Interpolation | `sub_231C8` | `sub_231C8` | `sub_231C8` |
| Query source | Dynamic RAM WORD | (UBYTE×UWORD)>>4 saturated | UWORD[FFFFA324+0x14] via sub_3A178 |
| First output | `[r13+FFFF2150+0x5C5]` | `[r13+FFFF2150+0x5C6]` | `[FFFF2150+0x5C8]` = FFFF2718 |
| Follow-on reader | None | None | `sub_22F80` ×2 (table h'102FC, axis h'112CA) |
| Flag set | GBR+0x73.bit3 | GBR+0x72.bit4 | None found |

**Conclusion:** E934 uses a **different reader** (`sub_22F28` vs `sub_22FD8`), **different axis width** (UBYTE vs UWORD BE), **different axis search** (`sub_233CC` descending vs `sub_2340C` ascending), **different query source**, and **no flag output**. It shares only the `sub_231C8` interpolation helper with E904/E914. Not the same executed path — separate callsite (`0x3A1AA` vs `0x87C4E`/`0x8822C`), separate reader, separate axis width.
