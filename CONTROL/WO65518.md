## Objective

Resolve the genuine 0-row byte cell exposed by WO65509's corrected `FFFF2150`-based terminal write. The same `r12=FFFF2150` routine that writes `FFFF26FC` also loads `r0=h'588` from three separate constants (`word_80652`, `word_80780`, `word_808A4`) and performs `mov.b @(r0,r12),r2` / `mov.b r4,@(r0,r12)` byte accesses at `FFFF2150+0x588 = FFFF26D8`. A fourth constant (`word_803B8`, `0x8032A`) appears in an earlier routine with a different base that must be proved independently.

WO65509 found **15 exact `h'588` text rows**: 11 CODE (`0x8032A`, `0x805C4`, `0x805F0`, `0x8060E`, `0x8063A`, `0x80676`, `0x806C0`, `0x80706`, `0x8072E`, `0x80794`, `0x807DE`) and 4 DATA (`0x803B8`, `0x80652`, `0x80780`, `0x808A4`). Test whether this cell reaches a consequential compare, state export, previously dispositioned cell or one of the six discriminator cells.

## Scope

1. Using WO65117/WO65118 plus targeted pinned-listing checks, enumerate every direct reader/writer of the logical `FFFF26D8` cell with exact PCs, raw bytes, base provenance and immediate next compare, state write or call. Declare explicitly that `FFFF26D8` and `000026D8` have **0 exact rows** in their respective indexes and that `h'26D8`/`h'FFFF26D8` have 0 LST hits. The `FFFF1B50` literal has one unrelated ROM data-table hit at `0x984C` (`.data.l ... h'1B500C8 ...`), not a code base; reject it explicitly.
2. Account for all 15 exact `h'588` rows: 11 CODE and 4 DATA. Group the CODE rows by which DATA constant they load: `word_803B8` (`0x8032A`), `word_80652` (`0x805C4`, `0x805F0`, `0x8060E`, `0x8063A`), `word_80780` (`0x80676`, `0x806C0`, `0x80706`, `0x8072E`), `word_808A4` (`0x80794`, `0x807DE`).
3. Re-prove each base independently: `r12=FFFF2150` at `0x80582` (`off_80664`) with 0 intervening writes for the `word_80652` and `word_808A4` rows; determine the base for the `word_80780` rows (same routine — prove or exclude stale `r12` inheritance); determine the base for `0x8032A` in the earlier routine. Recompute `FFFF2150+0x588=FFFF26D8` once per proved base. Keep distinct from `FFFF26FC` (WO65509, `h'5AC` word), `FFFF24D5/D6/D8` (`h'385/386/388` byte, WO65500), `FFFF2150` itself, `FFFF1054` and `FFFF1600`.
4. Follow only the first consequence per accepted access: for each byte read, record the immediate compare/branch; for each byte write, record the value and the gating condition. Do not retrace helper bodies or the full SR mask sequence.
5. Note but do not retrace `FFFF26FC` (WO65509), `FFFF2150`, `FFFFA6FD`/`FFFFA378` (`h'385/386/388`, WO65500), `FFFF1054`/`FFFF1600`, `FFFF1D12`, `0x8B42`/`0x8A88` tables, the SR interrupt-mask path, helper bodies or ROM table contents.
6. Check direct absolute literals, `@(h'588,gbr)` and other scaled-GBR forms. `FFFF26D8` is 0 mod 4, so an aligned longword could start there; confirm by absence of a `mov.l @(r0,rN)` whose EA recomputes to `FFFF26D8` within six instructions after any `h'588` literal.
7. Run one bounded discriminator against `FFFF2BF6`, `FFFF3085`, `FFFF3031`, `FFFF11B8`, `FFFF11BC` and `FFFF130B`; a negative is acceptable. No physical family name, unit or conversion may be promoted from these state cells.
