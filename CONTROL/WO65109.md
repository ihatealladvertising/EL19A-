### `0x9B2E` GBR resolution

The `0x473xx` routine sets **GBR = `0xE4AC`** at `0x472EE–0x472F0` (`mov.l off_4758C,r0` → `0xE4AC`; `ldc r0,gbr`). Therefore `r6 = GBR = 0xE4AC` and `r5 = GBR+0x10 = 0xE4BC`. The fragment's declared axes for `0x9B2E` are **correct**. This resolves the listing's earlier "absolute GBR unresolved" caveat for this caller family.

## Mismatches / unsupported declarations

1. **`0x9C2E` and `0x9DAE` are the same 256 bytes.** The fragment presents them as "High Octane" and "High Detonation" maps. The ROM content does not support distinct matrix contents. The selector at `FFFF1D7D.bit7` chooses between two addresses, but the payload is identical. Record the addresses as aliases unless independent code evidence distinguishes their use.

2. **Axis role labels are reversed between fragment and reader convention.** The fragment declares X=`0xE4BC` and Y=`0xE4AC`. The listing/reader convention is Y=`0xE4BC` (first axis, ×4 helper) and X=`0xE4AC` (second axis, raw helper). The addresses and 16×16 geometry are confirmed; the grid orientation is therefore ambiguous in the XML.

3. **`Knock_Window_Flag` (`floor(x/128)`, bit 7) is not supported at the `0x9C2E`/`0x9DAE` fixed-axis callsite.** Both results are explicitly masked with `and #0x7F` at `0x42BB6` and `0x42BCC`. The bit is discarded before the differential. It is a real bit in the payload, but this code path does not consume it.

4. **`Ign_Degrees` (`(x%128)-64`) is a display convention, not an executed conversion.** The reader returns a raw UBYTE. The confirmed paths use the low 7 bits directly (masked) or split them from bit 7; no `-64` offset is applied in the reader or the first downstream computation. The low-7-bit/bit-7 separation is supported; the exact affine display value is not established by code.

5. **`0x9B2E` bit 7 is consumed; `0x9C2E`/`0x9DAE` bit 7 is not (at the paired callsite).** The fragment treats all three knock-window views identically. The target code distinguishes them: `0x9B2E` callers explicitly save bit 7, while the paired `0x9C2E`/`0x9DAE` path masks it off. This is an address-dependent difference the fragment does not express.
