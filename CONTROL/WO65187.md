## Objective

Resolve the writer conditions and chronology of RAM bit `FFFF99E7.bit3`, which controls the table-versus-non-table branch in the F3D6 and F3DE handler paths. Determine:
1. Which code reads `FFFF99E7.bit3` and routes to F3D6 vs F3DE (table path) vs non-table.
2. Which code WRITES/sets `FFFF99E7.bit3` and when (chronology relative to the gate reads).
3. Initial/power-on state of `FFFF99E7`.

## Checkpoint 1 — bit3 readers (table-path gates)

`FFFF99E7.bit3` is read at exactly two gate sites. Both load `FFFF99E7` into a register, load the byte at offset 0 (`@rN`), test mask `#8` (bit3), and branch to the table handler when bit3 is SET.

00065832  C8 08   tst     #8, r0                       ; test bit3
00065834  89 03   bt      loc_6583E                    ; if bit3 SET -> table path

Fall-through (bit3 CLEAR) goes to a non-table path using `gbr+6` (lines 199349–199351).
Taken branch target `loc_6583E` (line 199354) loads `off_65944 = h'F3D6` into `r4` and proceeds through `sub_22EFC` — the F3D6 table path.

### Gate summary

| bit3 state | Gate A | Gate B |
|------------|--------|--------|
| SET (=1)   | F3D6 table path | F3DE table path |
| CLEAR (=0) | non-table (gbr+6) | non-table (index computation) |

So `FFFF99E7.bit3` is a **table-enable gate**: SET selects the table-handler path (F3D6 or F3DE); CLEAR selects a non-table path.

## Checkpoint 3 — writer of bit3 (unresolved)

**No static writer for `FFFF99E7.bit3` was identified.**

- No `mov.b @rN, r0; or #8, r0; mov.b r0, @rN` read-modify-write sequence targets `FFFF99E7` offset 0.
- No direct `mov.b rM, @rN` offset-0 store to `FFFF99E7` was found at any of the 40 address-constant load sites.
- No `mov.w`/`mov.l` store to a neighboring address (`FFFF99E6`, `FFFF99E4`) that would overlap bit3 of `FFFF99E7` was tied to `FFFF99E7` via static tracking.

The writer is therefore either:
(a) a `mov.b rM, @rN` direct full-byte store where `rN = FFFF99E7` but the load-to-store register lifetime spans instructions not adjacent in the listing (not resolvable by local load-site scan), or
(b) a word/dword store to a neighboring RAM address, or
(c) set during power-on initialization not represented as a direct constant-offset store in the listing.

Chronology relative to the F3D6/F3DE gate reads cannot be established without the writer's address.

## Current assessment / stop boundary

- **Confirmed:** `FFFF99E7.bit3` is read at two table-path gates: Gate A (0x0006582E) routes SET → F3D6, CLEAR → non-table; Gate B (0x00068200) routes SET → F3DE, CLEAR → non-table. bit3 SET enables the table path; bit3 CLEAR selects the non-table path.
- **Initial state:** data-section `byte_99E7 = 0xFE` (bit3 = 0); RAM power-on init not confirmed.
- **Not confirmed:** the writer that sets/clears `FFFF99E7.bit3`, and hence the chronology of bit3 state relative to the F3D6/F3DE gate decisions.
- **Bounded stop:** 10/10 representative `FFFF99E7` load sites scanned; all read bit5 or FFFF99E8, none write bit3. No bit3 writer found by static load-site scan. Further resolution requires dynamic execution tracing (breakpoint/watch on `FFFF99E7`, or instruction-level trace of the two gate addresses) to observe when bit3 transitions and which writer sets it.
