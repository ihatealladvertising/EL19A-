- `sub_969C2` loads `R13=FFFF859C` at `0x969EC`. `0x969FA` reads `UWORD[FFFF859C+0x16] = UWORD[FFFF85B2]` into R0 (second query). `0x969FC` reads `UWORD[FFFF8494]` through R7 into R14; `0x96A02` zero-extends that first query into R7.
- The call setup is `R4=0xB956` (`0x969FE`), `R5=0x10994` (`0x96A00`), `R6=0xFDAC` (`0x96A04`), and `R7=UWORD[FFFF8494]`; `0x96A08` calls `sub_22D30`. The `jsr` delay-slot instruction at `0x96A0A` stores the still-live second query R0 to the caller's stack argument area; it is not a store of the lookup result.
- `sub_22D30` zero-extends the first query at `0x22D34` and the stack-passed second query at `0x22D48`, performs the two axis searches, and tail-jumps at `0x22D5A` to the interpolation path. That path returns through R0 at `0x23324` (`rts`). Reused structural contract: interpolated UWORD from the B956 UWORD map, as documented in WO64928 and corroborated by WO65067's return-register trace.

### Caller-local result handling

- After return, `0x96A0C` copies R0 to R7 without extension or arithmetic. `0x96A0E` loads offset `0x68E`; `0x96A10` performs `mov.w R7,@(R0,R11)`. With R11=`FFFF2150` from `0x969EA`, this stores the low UWORD to **`FFFF27DE`** (`FFFF2150+0x68E`).
- No signed/unsigned conversion, arithmetic, comparison, or conditional gate is applied to the returned value before the store. Its caller-visible use is UWORD staging. This remains separate from the preceding FC90 result stored at `FFFF27DC` by `0x969F8` (WO65049).
- Immediately after the result store, `0x96A12–0x96A1C` re-reads `UWORD[FFFF85B2]`, zero-extends and tests it, then writes the resulting boolean byte to a stack local. That is a query-presence flag formed after the B956 output store; it does not gate the B956 result. Later consumers of that local flag are outside this bounded result trace.

The work stops at that global RAM staging boundary; no downstream global xref or physical endpoint was pursued.
