### 2. Timer-derived lineage reconciliation (reused, not repeated)

From WO65092/WO65181 (bounded reuse): `sub_3443C` computes `FFFF8596` from `FFFF85E4` using `sub_21BE4` with dividend `0x02DC6C00` and gate/clear behavior on `FFFF99E9.bit3`; `sub_3470C` computes `FFFF85DA = (UWORD[FFFF8596] >> 3)` and stores it via BSR delay-slot write to `FFFF8594+0x46=FFFF85DA`; `sub_20DCE` copies 40 bytes from `FFFF85C4` to `FFFF859C`, making `FFFF85DA` (`+0x16`) visible as `FFFF85B2` snapshot. WO65181 explicitly records that raw timer/capture units and physical RPM meaning remain unresolved.

**Reconciliation:** timer-derived runtime UWORD `FFFF85DA` is the same RAM cell consumed by PID $0C handlers and the 10984 query. Diagnostic naming ("Engine speed RPM") is consistent with the `*50`/`/4` encoding chain, but physical unit/axis conversion remains a target-side inference boundary where timer units are unresolved.
