## Coordinator technical closeout — 2026-11-22

**Disposition:** BOUNDED COMPLETE. The firmware confirms two distinct NTC acquisition paths on MCU inputs AN27 and AN31; it does not identify the vehicle sensor assigned to either input. The SH7058 device manual bounds the external analog reference but does not establish its actual board voltage. The former exact 20 mV/count and 160 mV/step comparison is corrected below.

### 1. Correct channel interpretation

The `sub_253C0` input is an 8-bit channel index. The verified ADC2 branch covers indices `0x18..0x1F`, subtracts `0x18` to obtain the local ADC2 channel index, configures `ADCSR2_B` and retrieves the corresponding result register.

| Call site | Helper argument | ADC unit/local channel | MCU analog input | Target-side acquisition |
|---|---:|---|---|---|
| `0x28B24` | `0x1B` | ADC2 / channel 3 | **AN27** | raw UWORD at `FFFF1798+0x1C`; `>>2`; `0xF406`; curve byte to `FFFF84BB+6 = FFFF84C1` |
| `0x28B5E` | `0x1F` | ADC2 / channel 7 | **AN31** | raw UWORD at `FFFF1798+0x1A`; `>>2`; `0xF406`; curve byte to `FFFF84BB+1 = FFFF84BC` |

The signal names are confirmed by the Renesas SH7058 F-ZTAT Hardware Manual, Rev. 3.0, Section 1.3 / Table 1.3. For the FP-256H package, AN27 is pin 116 and AN31 is pin 123; for BP-272 the corresponding locations are P18 and R18. Package pin references are conditional on the actual package fitted to this ECU. This confirms **MCU input identity only**, not coolant or intake-air sensor wiring.

### 2. ADC reference: device constraint, not firmware calibration

The ADC2 helper's register activity at `0x2546A–0x25490` addresses `ADCSR2_B` / `ADCR2_B` to select and start the channel conversion and poll conversion status. No firmware-selected reference-voltage value is present in this sequence. The SH7058 exposes analog-reference supply pins `AVref`, separate from the AN input pins.

The SH7058 Rev. 3 hardware manual (as reproduced in the Renesas SH7058/SH7058S/SH7059 comparison manual, left-hand SH7058 column, §17.6 Usage Notes, p.648) specifies, when A/D is used:

- `AVcc = 5.0 V ± 0.5 V`;
- `AVss = Vss`;
- `AVref = 4.5 V to AVcc`.

Therefore the specified device-level AVref range is 4.5–5.5 V, subject to the actual AVcc. AVref is an external analog reference input, not a firmware-selected A/D calibration parameter. No schematic, board trace, populated reference component value or measurement establishing the ECU's actual AVref was found in the pinned repository evidence. The actual reference is **not observable from this ROM** and remains unresolved at the board-level AVref connection.

### 3. Corrected physical-scale arithmetic

For an ideal 10-bit conversion spanning AVss to AVref, followed by the verified unsigned `>>2` staging, one staged 8-bit count corresponds approximately to:

`AVref / 256`.

| AVref assumption | mV per staged count | mV per 8-count `0xF406` interval |
|---:|---:|---:|
| 4.5 V (device lower bound) | 17.578125 | 140.625 |
| 5.0 V (nominal AVcc, not proven AVref) | 19.53125 | 156.25 |
| 5.12 V | 20.0 | 160.0 |
| 5.5 V (maximum allowed if AVcc is 5.5 V) | 21.484375 | 171.875 |

Consequences:

- The old shorthand `5000/1024 ≈ 4.883 mV/raw count` is correct, but after grouping four raw counts via `>>2`, the result is approximately 19.531 mV/staged count at 5.0 V, not exactly 20.
- The V6 `mTTWN` axis conversion of 160 mV/point is matched exactly by an 8-count EL19A step only at AVref = 5.12 V under this ideal conversion model.
- 5.12 V is within the SH7058 device's allowed AVref interval, so an exact match is numerically possible, but it is **not proven**.
- At nominal 5.0 V, the arithmetic comparison is approximately 156.25 mV/step, around 2.34% below 160 mV.
- The donor relationship remains a strong structural/function-family candidate; exact physical-scale equivalence must be downgraded from an implied nominal-5-V exact match to a conditional compatibility requiring actual board AVref evidence.

### 4. Downstream role disposition

The two channels have separate, identifiable NTC paths, but current target evidence does not assign coolant versus intake-air roles:

| Channel | Target-side downstream evidence | What it establishes | Physical role |
|---|---|---|---|
| AN27 / `0x1B` | curve output `FFFF84C1` read by `sub_35570` at `0x35578`; bounds `0x0A..0xAA`; rescaled output written to `FFFF84BF` at `0x355AC`; used by the `sub_353EC` processing family | independent validity/range normalization and downstream temperature-like byte path | Coolant vs IAT unresolved |
| AN31 / `0x1F` | curve output `FFFF84BC`; read by `sub_357A4` at `0x357B0`; same `0x0A..0xAA` acceptance range and rescaling family; further diagnostic/status calculation in `sub_3597C` reads `FFFF84BC` and writes `FFFFA34C+8` | independent NTC validity/rescaling and additional status/delta processing | Coolant vs IAT unresolved |

Both paths use the same `0xF406` payload and the same basic NTC normalization family. The asymmetric downstream status/diagnostic activity is not sufficient to label AN31 as coolant or IAT. No proven coolant fan/warm-up consumer on one path, or air-charge/ambient compensation consumer on the other, was established in this bounded trace. The donor A2L's function list mentioning coolant and intake air is not target-side wiring proof.
