# WO65083 — Targeted 1D Scalar / Limiter Discovery in ROM 0x7800–0x9500

**Status:** BOUNDED COMPLETE — CLOSED (2026-11-21)

## Decision question

Can the uncovered ROM interval `0x7800–0x9500` yield a bounded, evidence-backed inventory of 1D scalar/limiter candidates, with direct readers distinguished from helper parameters, axes, map data, and unrelated constants?

## Rationale / priority

- The current operational register identifies the 1D scalar/limiter tier as EL19A's largest remaining functional gap.
- WO65060's CF48D comparison found dozens of candidate scalar constants in `0x7800–0x9B00`.
- WO65064 has now completed reader/operand-provenance work across `0x9500–0x9B00`; this WO deliberately excludes that completed interval and concentrates on `0x7800–0x9500`.
- High-payoff outcome: reduce the scalar gap to a defensible list of read placements and usage classes, then select a few high-signal sites for dataflow follow-up. No value-pattern-only semantic promotion.

## Inputs / identity

- ROM: `VERSA f501.bin`, 1 MiB; MD5 `46991697c502052752a2cabcb84c9e27`; SHA-256 `bfe037e8e6c389e2a90214047058eb6dc3bcaaaac5b5931bf98a3f5d9f64fd6a`.
- Primary listing: `EL19A_Complete_Disassembly_ANNOTATED_V3_NEXT6_16_ALL_PENDING_ANNOTATIONS.lst`, 27,045,080 bytes; MD5 `99635224d16ab7705445e27bf233e549`; SHA-256 `148385bbec91f6a491dcaa403962836f709c2f273df9a17ec51f1dea5f7f4549`.
- Method reference: `EVIDENCE/EL19A ROM Analysis Method Playbook for Other Workers.md`.

## Scope

1. Census references that resolve to ROM data in `0x7800–0x94FF` through the bounded literal-pool/pointer forms described below.
2. Record exact ROM effective address, access PC, access width, literal/base PC, enclosing function if available, raw ROM value, and first meaningful use.
3. Classify each reached location as one of:
   - **direct scalar/threshold candidate** — slot value is compared directly with a runtime value;
   - **arithmetic scalar/coefficient candidate** — slot value enters multiply/divide/shift/add/subtract or normalization;
   - **helper parameter** — slot value is passed to a helper and the helper result, not the slot itself, is subsequently compared/used;
   - **RAM-shadow/record initializer** — ROM value copied into RAM or a structure;
   - **axis / map / curve / descriptor data** — not a 1D scalar;
   - **unclassified** — insufficient provenance.
4. Apply operand-provenance checks to a small high-signal subset (repeated references, compare candidates, or clear limiter-like arithmetic) and document each source boundary.

## Method / hop budget

- Verify the supplied ROM and listing identities before analysis; do not modify either.
- Use current listing and existing indexes as read-only sources. Scratch computations may be ephemeral; do not create or persist new scripts, tools, indexes, or generated files.
- First pass: literal-pool load → actual first memory operand through the loaded base register, including explicit displacement. Keep dynamic `@(R0,Rn)` cases unresolved unless R0 and the base are proven at the access.
- Also inspect directly referenced UWORD/UBYTE literal pools where a code instruction loads the scalar value rather than a pointer, but do not treat every immediate as a data placement.
- Second pass: identify the value's first compare/arithmetic/helper/copy use. Preserve SH-2 signedness, sign/zero extension, branch polarity, delay slots and call boundaries.
- Follow no more than 3 value-definition hops and 1 call/return boundary per selected candidate unless a concrete dependency justifies extension.
- Count references at the actual memory operand, not at pointer-load or compare PCs. A candidate is not a threshold merely because a compare appears nearby.

## Exclusions

- Exclude ROM `0x9500–0x9B00` (WO65064), and do not repeat its censuses or operand-provenance work.
- No whole-ROM sweep outside the specified interval; no DTC/CID extraction; no calibration XML, Master Workbook, discovery catalogue, ROM, LST, IDB, or source-script edits.
- No semantic name, physical unit, scale, or table geometry from numerical resemblance alone.
- Do not create new persistent scripts, helper tools, or indexes; do not upload anything to the Library.

## Acceptance / stop condition

- Deliver an address-sorted table of reached placements grouped by usage class, a concise coverage statement with exact method boundaries, and an unresolved-sites list.
- Deep-trace a limited high-signal subset; stop when a candidate depends on unproven caller state, dynamic index, undocumented helper input semantics, or runtime/peripheral state outside the hop budget.
- Bounded negative findings only. Unreached bytes are "not reached by this method", never "unused".
- Close only if the inventory and method limits are explicit and the findings are internally consistent; otherwise leave the WO active with the exact next action.

## Expected storage

- Technical findings and checkpoint/closeout live in this WO record.

## Checkpoint 1 — bounded reader census and selected scalar provenance (2026-11-21)

### A. Integrity and census

ROM and listing byte hashes were recomputed from the materialized read-only files and match the identity block above.

A bounded first-access parser reviewed `mov.l off_*,Rn` literal-pool loads whose resolved base lies in `0x7800–0x94FF`. For each load, it followed the loaded base register through at most 16 subsequent CODE instructions and stopped at an explicit base-register rewrite or control-flow instruction. The first `mov.b/w/l` direct or fixed-displacement memory operand through that base register was recorded. The method does not resolve a dynamic `@(R0,Rn)` effective address unless the offset is statically explicit in the operand.

| Measure | Result |
|---|---:|
| Literal-pool base loads in range | 3,962 |
| Unique literal-pool base values | 1,838 |
| First memory operands resolved by method | 3,663 |
| No first memory operand within method boundary | 299 |
| First accesses: UBYTE read | 3,164 |
| First accesses: UWORD read | 498 |
| First accesses: U32 write | 1 |
| Distinct first-access EAs | 1,995 |
| Distinct EAs with repeated first accesses | 627 |

The 299 non-resolved cases break down as 44 explicit base-register rewrites, 212 control-flow boundaries, and 43 reaching the 16-instruction window without a qualifying operand. These are unresolved by this method, not negative accesses. This is a pointer-rooted first-access inventory, not a whole-ROM effective-address census; later uses after the first operation, indirect aliases, indexed aliases with dynamic offsets, block copies, DMA, and non-literal pointer roots are outside the count.

The 1,995 distinct first-access EAs include many byte-sized descriptor/flag locations (for example, `0x8CD3` is reached 114 times as a byte). High reference count alone therefore does not identify a scalar calibration.

### D. Direct numeric literal loads

A separate text census of direct `mov.w word_*,Rn ; h'<value>` loads found 228 code references carrying 16 distinct values within the numeric interval `0x7800–0x94FF`. Of these, **198 are `0x7FFF`**. The remainder have low occurrence counts (1–5 each) and were not semantically traced in this bounded pass. This is a numeric-literal census, not a memory read at those ROM addresses; it is kept separate from the pointer-root results above.

### E. Findings and stop boundaries

- Confirmed high-value result: ROM constants `0x913A/0x913C` (956/78) and `0x91C2/0x91C4/0x91C6` (964/1000/60) are direct UWORD comparison operands against runtime values. They belong in a candidate register as **unlabelled threshold/boundary constants**, not named RPM/temperature/torque/fueling scalars.
- `0x9220`=10 is directly compared to stack and record UWORD fields, but the evidence is consistent with a count/record guard and does not prove a tuning role.
- `0x934C`=100 is used as an arithmetic bias; `0x9126`=500 and `0x9268`=50 are copied into runtime record fields. These may be scalar configuration values but lack the evidence needed to call them calibration limits.
- The many repeated byte reads in the pointer-root census are commonly descriptor/flag fields and were not promoted. The scan does not identify table geometry.
- Remaining work needed for semantic names/units includes caller provenance for the selected RAM record/index in `sub_86900`, the consumer semantics of the 60/964/1000 bound groups, the exact record meaning of the 10 guard, and the source/unit for the 100 bias. Those questions exceed this census's narrow first-access plus limited dataflow scope.
- Bounded negatives are only as stated: first-access results for literal-pool roots and the selected direct numeric word-literal census. No claim is made that unreached locations are unused, or that computed/indexed/DMA/copy paths are absent.
