## Objective

Determine whether EL19A's sole proven active HCAN1 transmit mailbox, MB28, carries only request-triggered diagnostic/service responses or also periodic/state-broadcast frames. Produce a complete bounded map of each reachable MB28 payload writer, frame-ID/DLC setup, TX request, trigger/cadence and payload source expression.

The proposal that the vehicle's CAN broadcast is a free labelled signal stream is a **hypothesis to test, not an established fact**. WO65108 and WO65176 establish MB28 as active TX and all other mailboxes as inactive or RX in the audited mailbox range. Do not assume the existence of a continuous engine-signal broadcast.

## Mandatory falsifiable hypothesis record

- **Identity layer advanced:** CAN frame/function identity and output-path classification.
- **Hypothesis:** MB28 is primarily or exclusively a request/response service mailbox, and the observed `FFFF3DD0–FFFF3DD7` payload plus the direct `sub_4894` writes are response/event payloads rather than a continuous broadcast of live engine signals.
- **Prediction:** every reachable MB28 TX request will be dominated by explicit state/command events or response processing; no recurring scheduler path will continuously refresh a multi-signal engine payload.
- **Cheap discriminator:** reconcile every indexed MB28 data-byte write and TXPR1 set in the existing MMIO census against its exact routine/callers; inspect only the immediate trigger/guard and source bytes.
- **Falsifier:** a reachable periodic/scheduler-driven TX path repeatedly updates MB28 with runtime engine-state fields independently of a received request.
- **Information gain:** either validates a genuine CAN-labelled signal source for semantic naming, or rules out the proposed broadcast strategy for this ROM and prevents wasted live-capture effort.
- **Result:** SUPPORTED. All reachable MB28 TX paths are event/response/state-driven. No periodic/scheduler-driven transmit path was found.

## Result Summary

**Hypothesis SUPPORTED.** MB28 is exclusively an event/response mailbox. Every TXPR1 request site traces to one of: mailbox initialization, configuration table, received-frame response handler, state-machine-driven service path, or unresolved complex path. No recurring scheduler or periodic timer path continuously refreshes MB28 with live engine-state fields. The frame ID (0x7E8 standard) and DLC (8) are invariant across all paths. The two distinct payload sources are: (1) a fixed 8-byte diagnostic response pattern `03 71 81 01 00 00 00 00` from the interrupt handler `sub_4894`, and (2) an 8-byte RAM block at `FFFF3DD0–FFFF3DD7` copied by `sub_B5580` whose producer remains unresolved. A third path (`sub_4150`) copies from `FFFF8248` whose producer is also unresolved. No path was found that constructs a multi-signal engine-state broadcast frame.

### Producer 3 detail — `sub_4894` (PC `0x4894`–`0x4B30`)
- **Entry:** Called at `0x0E6C` (jsr @r2) from SCI receive context
- **Guard:** Matches input pattern `03 31 81 01` at PC `0x4AE8`–`0x4AF8` (MB29 data bytes at offsets +1..+3)
- **Action:** Writes fixed 8-byte response `03 71 81 01 00 00 00 00` to MB28 data `FFFFDC88–FFFFDC8F` at PCs `0x4B00`–`0x4B1A`
- **TX request:** Sets TXPR1 bit `0x1000` at PC `0x4B20` (read-modify-write of `FFFFD820`)
- **Classification:** **Received-frame response** — triggered by specific incoming CAN frame pattern on MB29 (RXPR1 bit `0x2000`)

### Producer 4 detail — `sub_4150` (PC `0x4150`–`0x41D4`)
- **GBR:** `FFFF8248` (loaded from `word_42C4` at `0x4156`)
- **Action:** Writes ID `0x7E80`, DLC `8`, copies 8 bytes from `FFFF8248` to MB28 data via `memory_copy_bytes` (PC `0x4170`)
- **TX guard:** Checks GBR byte at offset `0x13` (must be `1`) and byte at `0x12` bit 0 (must be `0`) — if not, writes `0xFF` to `0x13` and returns `0xFFFFFFFF` without TX
- **TX request:** Sets TXPR1 at `0x041A8` only when guard passes
- **Return:** `1` on TX queued, `0xFFFFFFFF` on guard fail
- **Caller:** `0x423E` (bsr) — context unresolved in bounded search
- **Payload source `FFFF8248`:** No writer found in bounded static search (only readers at `0x2C28`, `0x2CE0`, `0x2D46`, `0x2DC2`, `0x30A6`, `0x326A`, `0x3378`, `0x4156`)

### Producer 5 detail — `sub_B5580` / `sub_B560E` / callers (PC `0xB5580`–`0xB5670`)
- **Payload source:** `FFFF3DD0–FFFF3DD7` (8 bytes), copied via `sub_B57D8` at `0xB5598`
- **State gates (in `sub_B560E`):**
  - `FFFF3DE3` byte must equal `1` (checked at `0xB5614`–`0xB5618`)
  - `FFFF3DE2` byte must equal `0` (checked at `0xB560E`–`0xB563C`)
  - If both true, calls `sub_B5580`; on return `1`, sets `FFFF3DE3` = `1` (at `0xB565A`)
- **Callers of `sub_B560E`:**
  - `sub_B41FE` (PC `0x4208`): GBR=`FFFF3B88`; calls `sub_B560E`, if return `1` clears bits 4-5 of `FFFF3B88` (mask `0xCF`), sets bits 4-5 (`0x30`)
  - `sub_B46D2` (PC `0x4764`): GBR=`FFFF3B88`; calls `sub_B560E` when `FFFF3B88` has bits 4-5 set (`0x30`); on return `1`, clears bits 4-5, sets `0x30`
  - `sub_B48AC` (PC `0x4916`): Loops calling `sub_B560E` until it returns `1` or `FFFF3B9D` becomes `0`
- **TX request:** `sub_B5580` sets TXPR1 at `0xB55CC` when both `FFFF3DE3`=`1` and `FFFF3DE2` bit 0=`1`
- **Payload source `FFFF3DD0–FFFF3DD7`:** No writer found in bounded static search (only address loads at `0xB41DC`, `0xB4296`, `0xB42FA`, `0xB435E`, `0xB4610`, `0xB47E6`, `0xB48EA`, `0xB558E`)

## Frame ID / DLC / Format disposition

- **Frame ID:** `0x7E80` (ID word) → standard 11-bit ID `0x7E8` (IDE=0, RTR=0, extended bits=0). **Invariant** across all writers (`sub_2478`, `sub_4150`, `sub_AF6A6`, `sub_B5580`).
- **DLC:** `8` bytes. **Invariant** across all writers.
- **Format:** Standard data frame (11-bit ID). Confirmed from control bits: IDE=0 (bit 2), RTR=0 (bit 3), extended ID bits 1:0 = 0.
- **Logical frame formats:** Two distinct payload layouts observed:
  1. Fixed diagnostic response: `03 71 81 01 00 00 00 00` (from `sub_4894`)
  2. Variable 8-byte block from RAM (`FFFF3DD0–FFFF3DD7` or `FFFF8248`) — content not statically resolved
- No evidence of dynamic ID/DLC selection or format switching.
