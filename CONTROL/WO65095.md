### Crosswalk and runtime evidence

- **Geometry / reader:** both are 16 consecutive UBYTE objects. `sub_403D8` passes `0xE688` to `sub_22E10` at `0x404C2–0x404C6`, or `0xE678` at `0x40512–0x40516`. The helper's implicit query grid is `0,16,...,240`; it rejects query `>=0xF0` and interpolates adjacent UBYTE cells. No explicit axis pointer is passed.
- **Selection:** the E688 branch requires `FFFF85F8.bit4=1` and `FFFF8600.bit6=1`; otherwise the E678 branch is used. The outer `FFFF860B.bit3` condition can bypass both table calls. The flag names/modes are not established. Because the payloads are byte-identical, code shows two separately addressed conditional objects but does not assign V57's primary/Alt names to either address.
- **Query:** caller forms `q = min(UWORD[FFFF85AE] >> 1, 0xFF)`; `sub_22E10` then rejects `q >= 0xF0`. `FFFF85AE` is supplied by the timer-capture-derived chain (`FFFF85E4 -> FFFF8596 -> FFFF85D6 -> FFFF85AE`). Timer/event units and an EL19A engine-RPM conversion are not proven. The V57 axis `0..6000 RPM` at `400 RPM/point` must not be imported as an EL19A axis.
- **Scale / destination:** the runtime byte factor is `FFFF1676 = FFFF1054+0x622`, proven by prior trace to be binary `0x00/0xFF), not a ×2 physical conversion. Each table result × this factor is stored as UWORD at `FFFF1054+0x39C = FFFF13F0`. The V57 raw×2 equality is a display-value fingerprint only; it does not establish EL19A runtime L/min units or scaling.
- **Consumer boundary:** the intermediate participates in the same routine's gated selection and can feed UWORD `FFFF1018` at `0x4057C`. Prior exhaustive audit established `FFFF1018` has no ROM-code readers and no DMA/DTC consumer. The live `sub_403D8` output path through `FFFF1054+0x394` / `FFFF1014` is separate; do not attribute that active path to E678/E688. No airflow, throttle, actuator or physical-output endpoint is demonstrated for this pair.
