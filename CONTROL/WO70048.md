## Objective

Perform a recursive, read-only inventory of every XML file under `EVIDENCE/`, including all nested directories (especially `EVIDENCE/rr roms/`). Reconcile these XML definitions and fragments against the current Nissan master-ROM/family index, the RomRaider reference index, and the existing EL19A target-side calibration evidence. Identify which files contain useful calibration metadata, which are duplicates/near-duplicates, which ROM identities and vehicle applications they describe, and which entries can be linked to EL19A candidates without transferring unsupported semantics.

The immediate motivation is that a previous top-level-oriented review identified only a subset of the nested XML evidence. The recursive tree currently includes donor definitions such as CF48D, CF49A, 6J107, 6J109, 6Y324 and 9J00B, as well as the EL19A A2L-alignment fragments and WO65324 previews. Treat this list as an initial lead, not a complete inventory; discover the actual set from the repository tree.

## Required bounded work

1. Enumerate the complete recursive `EVIDENCE/**/*.xml` set from the Git tree at a pinned `main` commit. Record the tree commit, every XML path, blob SHA and byte size. Report duplicate content by blob SHA and likely near-duplicates separately; do not silently collapse files with distinct paths.
2. Parse each XML defensively. Extract ROM identity fields (`xmlid`, internal ID, ECU ID, make/model/year/market where present) and table/scaling counts. For each table capture storage address, name, category, dimensions, storage type, endian, scaling reference, axis addresses/labels/units and any explicit ROM applicability. Preserve missing/invalid fields rather than guessing.
3. Classify each source as target definition, target fragment/preview, donor ROM definition, generic/shared definition, or unknown. State the evidence used for each classification. Do not treat file location or filename alone as proof of ROM identity.
4. Reconcile donor definitions against the current master-ROM/family index and the RomRaider reference index. Identify which ROM codes/FIDs can be linked confidently, which remain ambiguous, and which XML sources are absent from the index. Separate XML identity from ROM binary identity.
5. Compare XML table entries against EL19A target-side candidates and findings using exact storage address, geometry, storage representation, axis references, scaling, payload fingerprints where available, and cited reader evidence. Distinguish:
   - exact structural correspondence;
   - same address but conflicting geometry/representation;
   - exact payload match at a different ROM/address;
   - name/symbol-only or scaling-only similarity;
   - no supported relationship.
6. Produce a ranked shortlist of XML sources and specific entries worth further EL19A investigation. Explicitly call out potentially useful comparisons including CF48D↔CF49A, 6J107↔6J109, and the 1,550-entry versus 900-entry EL19A A2L alignment fragments. Determine whether the larger fragment contains entries absent from v2; do not assume one supersedes the other.
7. Reconcile prior negative results, especially WO65557 donor false-positive exclusions and WO70026 structural-only donor conservation. Do not revive rejected donor relationships without new target-side evidence.

- Preserve conflicting and negative evidence. Do not overwrite prior conclusions; identify any proposed correction as a new reconciliation candidate.
- Do not allocate FND/REC IDs unless a material target-side calibration interpretation is established. If no new target-side interpretation is established, Findings disposition is `NOT REQUIRED`. If a material contradiction to an existing finding is established, prepare the required ID-neutral reconciliation draft under the worker protocol and stop short of global ID allocation while publication is locked.
