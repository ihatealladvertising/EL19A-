## Objective

Establish whether EL19A address `0x0F10E` is genuinely read as a 16×1 UBYTE calibration curve and, if so, document its target-side reader/query contract and first meaningful consumer.

The 22-fingerprint join found an exact 16-byte match between EE310 donor `0x09E4C` and EL19A `0x0F10E–0x0F11D`. Release 1 currently includes `0x0F10E` as a provisional curve named “Cranking Fuel Value vs Coolant,” while WO65162 classified this row as provisional / discovery-only. That provisional label and the donor match do not establish target function.

## Required work

1. Verify target bytes at `0x0F10E–0x0F11D` and exact target identity.
2. Search the Stage-16 EL19A listing and current reader/call inventories for every reference to the exact address, including PC-relative literal loads and any constructed pointer. Do not assume a reader exists because the XML declares the object.
3. If read by a lookup helper, record the caller PC, helper, data pointer, widths/signedness, call arguments, query source and transforms, axis source (or explicit absence), interpolation/search/clamp mechanics and result destination.
4. Trace the result to its first meaningful consumer. Stop at the first unresolved producer or consumer boundary; do not pursue a broad fuel/injector/AFR hunt.
5. If there are no target reads, state the bounded negative and whether the XML/scope entry is unsupported by the available target-side reference evidence.
