## Objective

Trace separate readers for adjacent eight-point UBYTE curves `0x0E700` and `0x0E708`; determine whether they form one paired mechanism (shared query, shared output, combined downstream consumer) or two independent reads.

## Methodology

1. Located all ROM references to `0x0E700` and `0x0E708` as literal-pool entries / reader addresses in the pinned EL19A listing.
2. Traced the single function containing both reads: `loc_451C2` (0x451C2–0x45350), entered via `bt/s loc_451C2` from caller `sub_45160` at 0x45178.
3. Identified query input cells, output staging cells, and downstream consumers for each curve.
4. Checked all staging cells (`FFF11B8–FFF11BF`) for external readers/writers across the entire listing.
5. Read-only: no new tools, no ROM/listing edits, no broad census beyond the bounded function.

## Finding — Not a Paired Mechanism

**0x0E700 and 0x0E708 do NOT form one paired mechanism.** They are two independent 8×1 UBYTE curve reads:

| Dimension | Curve 0x0E700 | Curve 0x0E708 | Shared? |
|---|---|---|---|
| Reader helper | `sub_22DF8` | `sub_22DF8` | Yes (same helper) |
| Query input cell | `FFF11B8` (written within function) | `FFF11BC` (never written — garbage) | No |
| Query source | Computed clamp from `h'85AD+3/4/6` | Uninitialized RAM `FFF11BC` | No |
| Output staging cell | `FFF11B9` | `FFF11BD` | No |
| Output consumer | `FFF11B9` → r6 → `sub_21AC0` | **None** — dead store at `FFF11BD` | No |
| Downstream effect | Feeds `sub_22AC0` multiply-accumulate chain | Computed and discarded | No |

**Key evidence of independence:**
1. Separate query cells (`FFF11B8` vs `FFF11BC`) — curve 0x0E700's query is computed within the function; curve 0x0E708's query reads never-written RAM.
2. Separate output cells (`FFF11B9` vs `FFF11BD`) — no shared staging.
3. Curve 0x0E700's result is consumed downstream (into `r6` → `sub_21AC0`); curve 0x0E708's result is written to `FFF11BD` and never read — a dead store.
4. No combined downstream consumer reads both results together.

The curves are adjacent in ROM (0x0E700 and 0x0E708, exactly 8 bytes apart = 8 points × 1 byte each), but this is coincidental layout, not a paired mechanism.
