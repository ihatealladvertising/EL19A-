# WO66051 — The `0x08AF6E` frame is routine-private scratch; `sub_8AD7C` read-modify-writes 14 status bytes in place

## Answer in one paragraph

The `0x08AF6E` block **never leaves `sub_8AD7C`**. It is this routine's own stack frame — allocated `add #h'FFFFFF7C, r15` at `0x08AD94` (−0x84 bytes) and released `add #h'FFFFFF84, r15` at `0x08B3E0` immediately before `ldc.l`/`lds.l`/`rts` — and it is addressed only through immediate `@(imm,r15)` displacements: there is **no `mov r15,rN`** anywhere in the 1,018-line routine, so no frame pointer is ever formed. The routine makes exactly **two** calls, `bsr sub_8B3FE` (`0x08AEB8`) and `bsr sub_8B87E` (`0x08B2F8`), and neither receives the frame: the second takes a scalar index (`mov #0xE,r4`) and is a pure query returning `UBYTE[FFFFA074 + idx*3 + 2].bit3`. Every one of the 14 copied status bytes is written **back to the same cell it came from** (`0x08B16E`–`0x08B2F6`), so the outward product is an in-place bit merge over the `FFFF34C1` block plus counter maintenance in `FFFF2150` — no diagnostic frame, no serial/queue append, no MMIO. Classification: **INTERNAL STATE — terminal named**.

## 3. What the frame also contains (it is not a status snapshot)

Three slots are not copies of status bytes:

- **Slot `0x4C`** (word): `0x08AF22` `r2 = 0x8635`, `0x08AF2A` `mov.b @r2,r5` → `extu.b` → `shll8` → `mov.w r4,@(0x4C,r15)`. A 16-bit value formed as `UBYTE[0x8635] << 8`; `0x08AFA6`/`0x08B068` read it back as the word operand of two `cmp/hs` comparisons.
- **Slots `0x44`/`0x48`**: single-byte flags set from branch outcomes — `0x08AF2C`/`0x08AF32` clear them (`mov #0,r6`), `0x08AFBC`/`0x08B006` set them to 1, and `0x08B032`/`0x08B0F0` branch on them.
- **Slot `0x74`** (long) and **slot `0x78`** (word): accumulator words built from `UWORD[FFFF2150+0x8AE]` / `+0x8AC` / `+0x200` with `0xFFFFFFFF` saturation (`0x08B04A`–`0x08B080`, `0x08B096`–`0x08B128`, `0x08B192`–`0x08B1B4`).

So the block is a **mixed workspace** (copied status bytes + comparison header + control flags + counters), not the contiguous diagnostic frame the WO hypothesised.

## 4. Frame destination

- **Not passed to a callee.** Only two calls exist in the routine; `0x08B2F8` `bsr sub_8B87E` has `mov #0xE,r4` in its delay slot (a plain index into `0xFFFFA074`), and `0x08AEB8` `bsr sub_8B3FE` has no r15-derived argument. `sub_8B87E` is a leaf query: `r0 = UBYTE[FFFFA074 + r4*3 + 2]`, `tst #8` → 0/1, `rts`.
- **Not copied to RAM.** No loop or block-copy instruction consumes `r15+0x44`–`0x70`; every slot is read back by an explicit `@(imm,r15)`, and the values are then either compared or written to a single `gbr` cell.
- **Not a queue payload.** No `sub_33E18` byte-ring append or `sub_32790` wrapper appears anywhere in the routine, so WO65907's append contracts are not engaged.
- **Discarded at `rts`.** `0x08B3E0` releases the 0x84 bytes and `0x08B3F2` returns; the slot contents are simply abandoned.

## 5. Outward product

The routine's only externally visible effects are single-byte stores into `FFFF34C1`-relative cells (`0x08B16E`–`0x08B36E`, `0x08B3A4`), i.e. **in-place updates of the same 14 status bytes it read**, plus three counter words at `UWORD[FFFF2150+0x8AE]`, `+0x8AC` and `UBYTE[FFFF2150+0x200]`, plus one `0x1E` write to `UBYTE[FFFF1E7C+0x0D]` = `FFFF1E89` on the `loc_8B02C`/`loc_8AFC2` path. No serial port, message buffer, lamp or MMIO address is touched.

**Classification: `INTERNAL STATE` (terminal named).** The status network still has no reader outside the firmware's own logic, and the `0x08AF6E` block is not evidence of a diagnostic publication path — it is scratch.

## 6. Scope limit recorded, not overrun

348 pool words reference `FFFF34C1` (`grep` over the pinned listing), so a block-level xref of every `FFFF34xx` consumer is well beyond this WO's two-hop boundary and was **not** attempted. This report therefore claims only what the frame's own fate proves: this routine publishes nothing. It does not claim that no other routine publishes those cells.
