## Answer in one paragraph

The "32-byte object" is **three adjacent objects**. `0x0F01C`–`0x0F02B` is a 16×1 UBYTE curve (108,108,108,108,108,100,96,92,88,84,76,60,60,60,60,60) read once by `sub_2245C`-style `sub_22E10` interpolation at call PC **`0x048E60`** in `sub_48D2E`; `0x0F02C`–`0x0F02F` is a **separate 4-entry UBYTE floor table** (`26 30 36 3E` = 38,48,54,62) indexed 0–3 by a computed bin and loaded through `off_48FFC` at `0x048EFE`; `0x0F030` is a terminator and `0x0F031`–`0x0F03F` is an unrelated 15-byte ascending ramp. Both curve lookups — `0xF01C` and its companion `0xEE68` — use the **same single query** as WO66048's pair: `U8[FFFF84B4+0x04]` = `FFFF84B8`, the rescaled AN27 NTC coolant-temperature image. The two results are offset (`+0x18`), floored at `table[bin]` and at `UBYTE[0x8B9D]=0x04`, and published as `UBYTE[FFFF1054+0x3ED]` = `FFFF1441` and `UBYTE[FFFF1054+0x330]` = `FFFF1384`. No idle, dashpot, throttle or actuator sink is reached, and no RPM value is read anywhere on the path.

**Warm-up hypothesis verdict: WEAKENED** — input identity (coolant temperature) is supported; function and output identity are not.

The WO's "call context `0x48FE8`" is the **pool address**, not the call PC; the call itself is at `0x048E60`, matching WO65038's recorded call PC. These are the only two references into the `0x0F01C` region.

## 2. Exact geometry (the 32-byte premise is void)

ROM bytes `0x0F01C`–`0x0F03F` verified from `EVIDENCE/VERSA f501.bin`:

```

0F02C: 26 30 36 3e                                       4-entry bin floor table
0F030: 00                                                terminator
0F031: 02 0b 14 1c 25 30 40 50 61 71 81 96 a2 b2 c2      15-byte ascending ramp (not read here)
```

| Object | Extent | Type | Geometry | Values |
|---|---|---|---|---|
| `0x0F01C` | `0x0F01C`–`0x0F02B` (16 B) | UBYTE | 16×1 curve on the `sub_22E10` grid | 108,108,108,108,108,100,96,92,88,84,76,60,60,60,60,60 |
| `0x0F02C` | `0x0F02C`–`0x0F02F` (4 B) | UBYTE | 4-entry **bin-indexed** table (index 0–3, no physical axis) | 38,48,54,62 |

Companion looked up in the same block: `0x0EE68`–`0x0EE77` (16 B) = `50 50 50 50 50 48 44 40 3C 38 38 30 30 30 30 38` (80,80,80,80,80,72,68,64,60,56,56,48,48,48,48,56).

WO65291's row `F01C … 32 B (16×1 or 2×16) … 0x00–0x81 rising` spans all three objects; its "rising 0x00–0x81" range comes from the unrelated ramp at `0x0F031`, not from the curve. The curve is strictly non-increasing. The Release 1 matrix/XML already narrowed the extent to 16 B with `sizey="16"`, which is correct; the bin table is **not** represented anywhere.

## 3. Query contract

- `0x048E58` `mov.w word_48F22,r7` → `r7 = 0xFFFF84B4` (sign-extended `mov.w`, `FND-000012`).
- `0x048E5C` `mov.b @(4,r7),r0` → `r0 = UBYTE[FFFF84B8]`; the `jsr` delay slot `0x048E62 extu.b r0,r5` passes it as the query.
- Companion `0x048E68` `mov.l off_48FF0,r4 ; h'EE68`; `0x048E6A` reloads the identical byte; `0x048E6E` `extu.b r0,r5` in the delay slot.
- No arithmetic, shift or intermediate cell between the load and either call.

`FFFF84B8` is the rescaled AN27 NTC coolant-temperature image (`FND-000018` §4, catalogue rows `0x0F406`/`0x0DE5E`/`0x10FEA`, WO65239/WO65739). Both curves are therefore queried by coolant temperature on the fixed `sub_22E10` grid (`0,16,…,224` plus entry 15 as the `>= 240` clamp, per `FND-000018` §2). **No RPM value is read anywhere in `sub_48D2E` on this path.**

## 5. Post-processing, bin selector and publication

1. **Offset** (`0x048E7A`–`0x048ED2`): if `UBYTE[FFFF362E].bit2` is set, `UBYTE[0x8565] = 0x18` is added to both results **and** to the `r11` accumulator, each with `cmp/gt 0xFF` saturation. Identical pattern to WO66048's `0x0F01C`-sibling block.
2. **Bin selector** (`0x048ED4`–`0x048EFC`): counts how many ROM thresholds `UBYTE[0xE21A..0xE21C]` = `06 08 0C` (6, 8, 12) are `<= UBYTE[FFFF84D4+0x10]` = `FFFF84E4`, capped at 3 → bin `r4` ∈ 0–3. This is the same three-threshold selector recorded in `FND-000016`/`REC-000020` for `0x0E21A`, here applied to `FFFF84E4`.
3. **Floor at the bin table** (`0x048EFE`–`0x048F26`): `r5 = UBYTE[0x0F02C + bin]`; `r13 = max(F01C_result, r5)` and `r12 = max(EE68_result, r5)` via `cmp/ge`.
4. **Additional floor** (`0x048F48`–`0x048F5A`): `UBYTE[0x8B98+5] = UBYTE[0x8B9D] = 0x04` applied to both.
5. **Publication** (`0x048F8A`–`0x048F90`, `r10 = 0xFFFF1054` from `off_48FD8`):
   - `mov.b r13,@(0x3ED,r10)` → **`UBYTE[FFFF1441]`**
   - `mov.b r12,@(0x330,r10)` → **`UBYTE[FFFF1384]`**

After the stores the routine continues with `FFFF1D7C` bit7 (`0x048F92`), `FFFF860B` bit3 (`0x048F9C`), `UBYTE[FFFF8531]` (`0x048FAE`) and the same `UBYTE[FFFF85A9]` threshold cell that WO66048 found (`0x048FB6`–`0x048FCA`) — but that is beyond this WO's first-consumer boundary.

## 6. Caller and first meaningful consumer

`sub_48D2E` is called from `loc_47C0A` — `0x047C0A` `jsr @r3` with `r3 = 0x48D2E` (`off_47CD0`) — inside `loc_47B54`, the `0x0218F8`-dispatched routine that also calls `sub_488BA` at `0x047BDA` (WO66048). The two readers are siblings in the same periodic step, and their results feed the same downstream block.

**First meaningful consumer:** the two byte stores `0x048F8C`/`0x048F90` into `FFFF1441` and `FFFF1384`. The values leave `sub_48D2E` only as those two clamped bytes; there is no lookup-helper call, MMIO access or actuator store on the boundary.

## 7. Warm-up comparison and verdict

- **Compatible signal: coolant temperature only.** Both curves are queried on `FFFF84B8`; the bin selector reads `FFFF84E4` and the gates read status bytes. No RPM operand exists.
- The falling curve shapes are a **temperature** dependence; the 2026-11-25 log (ECT 32–57 °C) shares only that signal with this path, so its RPM trend cannot corroborate these tables.
- **Verdict: WEAKENED.** Input identity supported; function identity (a clamped coolant-derived selection with a bin-dependent floor) established structurally but not physically named; output identity is two RAM bytes, not a control request.
- The owner-directed best-guess `Rpm_x25` presentation has **no target-side support**: the query is not RPM. That is recorded as evidence, not as an instruction to change the owner's presentation decision.
