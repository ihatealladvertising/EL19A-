# WO65556 — Trace selected actuator outputs backward to calibration candidates

**Status:** ASSIGNED — WORKER 3 — READY  
**Priority:** P1  
**Branch:** `main`  
**Authorized output:** `CONTROL/WO65556.md` only  
**Dependencies:** Existing MMIO census `INDEX/sh7058_mmio_census.tsv`; WO65258 (MB28 CAN path) is context only, not an actuator trace.

## Objective
Perform a sink-first, target-side trace from a very small number of existing actuator/output endpoints backward through command variables and calculations to any calibration reader results. The purpose is to bridge the current gap between verified lookup mechanics and physical output identity.

## Bounded selection and scope
1. Reuse the existing MMIO census; do not repeat or broaden it.
2. Select at most two promising actuator/output endpoints already represented in the census, prioritizing endpoints with clear write sites and plausible engine-control relevance (e.g. injector, ignition/coil, electronic throttle, idle-air or fuel-pump command paths only where the census actually supports them).
3. For each selected endpoint, trace backward only far enough to identify the command variable, immediate calculation/selector, and any direct lookup/helper result feeding it.
4. If an endpoint has no defensible actuator interpretation or no tractable writer, reject it quickly and document the reason; do not substitute an unsupported MMIO meaning.
5. Reuse completed reader/helper and axis work; trace any discovered lookup only to its existing reader/query evidence, avoiding a duplicate helper census.

## Required evidence
- Exact MMIO address/register, width and write PC(s).
- Writer routine and the branch/timing conditions relevant to the write.
- Immediate source variable(s), arithmetic, scaling, saturation and unit evidence.
- Backward chain to any lookup result: table address, helper, query construction, axes and first meaningful consumer.
- Separate established facts from candidate physical interpretations.
- State whether the chain establishes input identity, function identity and/or output identity. A calibration table is not semantically identified merely because it is upstream of an actuator.
- Include one falsifiable hypothesis, predicted observation, cheapest discriminator and result.

## Reuse / no-repeat exclusions
- Reuse `INDEX/sh7058_mmio_census.tsv`, WO65258 and existing completed table-reader traces.
- Do not repeat the MMIO census, CAN mailbox trace or diagnostic query join.
- Do not perform a broad peripheral sweep, hardware emulation, live-vehicle test or indiscriminate search for all actuators.
- Do not infer physical units from register names or donor labels.
- Do not modify ROM/LST, XML, workbook, inventory, scripts, tools or findings index.

## Deliverable and stop boundary
Commit a report for no more than two endpoints. A valid result may be positive, negative or partial. Stop at the first unresolved hardware/driver boundary or after tracing the lookup result to its first meaningful consumer. Identify a separate follow-on only if a concrete, bounded discriminator exists.

## Semantic hypothesis record
- **Identity layer:** primarily output identity; may also advance function/input identity if the backward chain supports it.
- **Hypothesis:** at least one selected actuator command path is computed from a traceable calibration lookup result.
- **Evidence:** existing census entry plus exact target ROM/LST PCs and linked reader/helper WOs.
- **Prediction:** the sink writer's command source can be followed to a specific calculation and, if present, a lookup result under a known branch.
- **Cheap discriminator:** inspect only the selected endpoint's writer and immediate source chain before expanding to upstream callers.
- **Result:** unresolved until traced.
- **Information gain:** connects calibration data to a concrete control output, or rules out attractive but unsupported table-to-actuator interpretations.
