## Falsifiable hypothesis record

- **Identity layer advanced:** output identity and function identity.
- **Hypothesis:** both cells are *target levels* for a closed-loop or rate-based controller, so each should be read by one routine that compares it against a measurement and produces an actuation or state command.
- **Evidence:** WO65313 write-side facts (`FFFF1810` at `0x36A76`; `FFFF9992` at `0x38BA6`); LST windows `0x36A30–0x36A7E`, `0x36E02–0x3706E`, `0x38B7E–0x38BA6`; `EVIDENCE/WO65118_ram_byte_bit_xref.tsv` (with its 2× word-address inflation caveat, WO65263); LST symbol scan for `FFFF1810`/`FFFF9992`.
- **Prediction:** each cell has a small, bounded reader set whose immediate arithmetic is a comparison/subtraction against another level, followed by a command write.
- **Cheap discriminator:** enumerate readers from the existing RAM cross-reference and the LST symbol table, then decode the first consumer of each.
- **Result:** **SPLIT.** `FFFF1810` **is** a regulated target: it is compared against `FFFF1820`, the error is scaled by a ROM gain and rate-limited into two integrator cells. `FFFF9992` **has no consumer outside its own routine**: its only other access is the blend's previous-value read, so it is staging, not a published value.
- **Information gain:** converts one cell into a verified setpoint with a decoded controller and closes the other as a dead end, which removes it from the list of tables that could ever receive a defensible RR output label.

## 2. `FFFF1810` — first consumer `sub_36E02` (`0x36E52`…`0x37066`)

Gate chain before the comparison: `U8[FFFF85F6].bit7` (`0x36E0E–0x36E20`), `U8[FFFF861A+2].bit5` (`0x36E1A–0x36E22`), `U8[FFFF861A+5].bit4` (`0x36E2A–0x36E34`); the middle gate also writes `U8[FFFF38DF+6] = 3` when it fires.

Arithmetic actually executed:

1. `0x36E52` `r0 = U16[FFFF1810]`, `0x36E56` `r6 = extu.w r0` — the **setpoint**.
2. `0x36E58` `r0 = U16[FFFF1820]`, `0x36E5A` `r5 = extu.w r0` — the **compared level**.
3. `0x36E5C` `r2 = U8[0x8307]` (ROM gain, byte at `disk 0x8304+7`); `0x36E5E` `r6 = r6 − r5` — the **error**.
4. `0x36E64` `mul.l r6,r2` → `macl`; `0x36E6A–0x36E78` sign-corrected rounding (`tst #7`, `add #8`) then `shar` ×3 — i.e. **error × gain / 8**.
5. `0x36E80`–`0x36E8C`: branch on `U8[FFFF1E3F+1].bit3`; either take `U16[FFFF1838]` or its negation, staged on the stack (`0x36EE0`/`0x36EE2`).
6. `0x36EE6`–`0x36EFE`: on a negative scaled error the routine stores `0` into `FFFF1818` (`0x36EEE`); otherwise it clamps the increment against `0xFFFFFFFF` and splits it (`0x36EF0–0x36EFE`).
7. `0x37026`–`0x37066` (the second `FFFF1810` read, the `loc_37022` entry): `r2 = U8[0x8C2B]`, `r5 = 256`, `r5 = 256 − r2×U16[FFFF1810]`, multiplied by `U32[FFFF1824]`, `shar`×2 / `shlr2`×4 — a saturating weighted blend.
8. Destinations: `U16[FFFF1818]` (`0x37066`, also `0x36EEE`) and `U32[FFFF1814]` (`0x37060`), both clamped to `0xFFFF`.

**Classification: (a) regulated target.** `FFFF1810` is the setpoint of a proportional, rate-limited update loop whose error drives the integrator/rate cells `FFFF1814` and `FFFF1818`. Software role confidence **HIGH** (byte-verified setpoint, subtraction, gain, rounding, clamps, two destinations). Physical domain **UNRESOLVED**: neither `FFFF1820` (compared level) nor `FFFF1838` (the branch-selected offset) has an established producer in scope, and the gain `U8[0x8307]` is an unlabelled ROM byte.

## 3. `FFFF9992` — no external consumer
