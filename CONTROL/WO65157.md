* The surrounding bytes `FFFF91A3`–`FFFF91B6` form a small state block updated in the same
  pass (`0x607A0`–`0x60810`).

### 3. Selector chronology: FFFF2401.bit7 controls the map base

The selection is performed in the same parent routine before the map call, not inferred from XML names.

- At 0x22F5A, sub_22F46 installs GBR=FFFF1D98.
- At 0x22E40–0x22E46, the routine reads FFFF2401 into r14.
- At 0x22E96, it reads UWORD[FFFF1D9A] into r0/r6.
- At 0x22E9C–0x22EA0, it reads UWORD[r8+0x24], zero-extends it, and multiplies it by 4.
- At 0x22EA2–0x22EA4, cmp/hs tests whether 4 × UWORD[r8+0x24] is greater than or equal to UWORD[FFFF1D9A].
- If that comparison is false (the UWORD at FFFF1D9A is greater), 0x22EAA/0x22EAC sets bit 7 in the saved FFFF2401 byte. If true, 0x22EAE/0x22EB2 clears bit 7. The updated byte is stored to FFFF2401 at 0x22EB6.
- The map selection follows at 0x23200–0x2320A: default r4=0x91F1; if FFFF2401.bit7 is clear, r4 is replaced with 0x91B1. Thus bit7 set selects 0x91F1; bit7 clear selects 0x91B1.

This establishes a threshold/feedback selector. Its comparison uses a UWORD read at FFFF1D9A, whereas the later table result is byte-stored at FFFF1D9A; the adjacent byte and full UWORD field construction are not resolved here. The source/base represented by r8 and the meaning/units of r8+0x24 are also unresolved. Do not collapse this mechanism into an “acceleration/deceleration” mode selector.

The listing shows another read of FFFF2401 at 0x2A8C–0x2A8E in sub_299E, where its value is copied to FFFF2402; that is a reader/copy, not the map-selection write. The direct writer/update established in this path is 0x22EB6. No other direct FFFF2401 write was established in the reviewed references.
