## Decision question

Resolve the producer/dataflow and scheduling relationships behind shared UWORD query field `FFFF85B2`. Preliminary static evidence indicates a three-stage chain:

1. A callback updates UWORD `FFFF8596` from UDWORD `FFFF85E4` using `sub_21BE4` and constant `0x02DC6C00`, gated by `FFFF99E9.bit3`.
2. A second callback computes `FFFF85DA = UWORD[FFFF8596] >> 3` and writes it through a BSR delay slot.
3. A 40-byte block copy from `FFFF85C4` to `FFFF859C` makes destination `FFFF85B2` receive source `FFFF85DA`.

Establish each operation, helper arithmetic, callback-table identity, interrupt/caller conditions, and what can/cannot be inferred about temporal freshness. Do not infer an engineering unit or physical control domain.

## Why this is high payoff

WO65091 established that `FFFF85B2` is the common UWORD query used by paired surfaces `0x9C2E/0x9DAE`, dynamic-axis map `0x9B2E`, map `0xAB22`, and the inline SWORD maps. Its bounded direct writer audit found no fixed/static writer; it noted only a potential packet-parser writer. The new copy/producer chain appears to provide a concrete ordinary software dataflow path and corrects the earlier unresolved-source boundary.

### 2. Stage 1 — FFFF85E4 → FFFF8596

#### Timer-delta source at FFFF85E4

`sub_2088C` is called from two interrupt routines:
- `INT_ATU02_ICI0A` at `0x268E0`;
- `INT_ATU12_IMI1AE` at `0x276A8`.

Each entry to `sub_2088C` calls `sub_257AC` at `0x208A6`, then `sub_25804` at `0x208AC`. After these calls it dispatches nine callbacks from table `dword_21A64` at `0x20984–0x20996`. The first table entry at `0x21A64` is `0x34464` (`loc_34464`), which runs the wrapper for `sub_34476`.

Verified `sub_257AC` behavior:
- GBR is set to `FFFF85C4` at `0x257B0`.
- It reads UBYTE `FFFF1E64\) at `0x257B4`; `tst #1` followed by `bf locret_257EE` means **bit 0 set exits without updating**. Bit 0 clear proceeds.
- It reads UBYTE `FFFF20C4+0x0C` at `0x257BC\). If nonzero, it stores UDWORD `0xFFFFFFFF` at `FFFF85E4` in the branch delay slot at `0x257C6\). If zero, it calculates the counter delta:
  - current UDWORD: `FFFF1054+0x48C = FFFF14E0\), loaded at `0x257CC\);
  - previous UDWORD: `FFFF85C4+0x8C = FFFF8650\), loaded at `0x257CE\);
  - subtracts previous from current at `0x257D4\); when current is lower, the path additionally adds `-1` at `0x257D6\);
  - shifts right five using `shlr2`, `shlr2`, `shlr` at `0x257D8–0x257DC\);
  - stores UDWORD to `FFFF85E4` at `0x257E0\).
- The valid-delta path sets bit 6 of UBYTE `FFFF8627` at `0x257E4\), then updates previous value `FFFF8650\) from current `FFFF14E0` at `0x257E6–0x257EC\).

Thus the established machine expression is:
```
d = (current - previous) modulo 2^32
if current < previous:
    d = d - 1 modulo 2^32
FFFF85E4 = d >> 5
```
This is a timer/counter-delta-derived UDWORD. Its physical clock, unit and external timing source are not assigned.

#### UWORD calculation at FFFF8596 — corrected TST/BF polarity

Callback wrapper `loc_34464` calls `sub_34476` at `0x34466\), followed by `sub_344A4` and `sub_344B6\).

At `sub_34476`:
- `0x34478–0x3447A` reads UBYTE `FFFF99E9`.
- `0x3447C` is `tst #8,r0`; `0x3447E` is `bf loc_3449A`.
- SH-2 TST sets T when the masked result is zero; BF branches when T=0. Therefore:
  - **bit 3 set:** branch to `loc_3449A`, set R2=0, then store UWORD zero to `FFFF8596`;
  - **bit 3 clear:** continue through the division/cap path.
- This corrects the earlier V3 annotation / preliminary comment that said the *set* path calculates. The raw instruction sequence proves the opposite polarity.
- In the calculate path, R4 is set to `FFFF8596`, R1 to `0x02DC6C00 = 48,000,000`, and the JSR delay slot at `0x3448A` loads UDWORD `FFFF8596+0x4E = FFFF85E4` into R0. The call at `0x34488` enters `sub_21BE4`.
- `sub_21BE4` checks for zero divisor; otherwise its `div0u/div1` paths implement unsigned integer division with R1 as numerator and R0 as divisor. Here the quotient input is therefore `48,000,000 / UDWORD[FFFF85E4]`. The caller compares the result unsigned against `0xFFFF` at `0x34490–0x34498`, clamps to `0xFFFF`, and stores UWORD to `FFFF8596` in RTS delay slot `0x344A2`.
- If `FFFF85E4=0`, `sub_21BE4` takes its zero-divisor path, returns zero, and writes the helper's zero-divisor marker `0x0000044E` to `FFFF983C`.

Supported expression for this callback:
```
if FFFF99E9.bit3 == 1:
    FFFF8596 = 0
else:
    FFFF8596 = min(0xFFFF, unsigned_integer_quotient(48000000, FFFF85E4))
```
The quotient is a code-derived integer. No unit is inferred.

Sibling callback `sub_344A4` is separate: it reads `FFFF8596`, shifts right six, and writes UWORD `FFFF85D6` at `0x344B4`. Do not confuse `FFFF85D6` with the `>>3` path to `FFFF85DA`.

### 3. Stage 2 — FFFF8596 → FFFF85DA

`sub_209A6` is called by `INT_ATU31_IMI3A` at `0x20854`. It sets GBR to `FFFF8596` at `0x209B8–0x209BA\) and uses status byte `FFFF8641`.

The six-entry callback table is `off_21858`:
| Index | ROM pointer |
|---:|---:|
| 0 | `0x253A2` |
| 1 | `0x3470C` |
| 2 | `0x347C4` |
| 3 | `0x43C40` |
| 4 | `0x5337E` |
| 5 | `0x70C4C` |

The group is dispatched at `0x20BD8–0x20BEA`: R12 starts at 0, R14 at 6, table pointer R13 is `0x21858`, and each callback pointer is called before the loop advances. Index 1 therefore invokes `loc_3470C`.

**Exact status conditions** (using SH-2 TST/BF/BT semantics):
- At entry `0x209BE–0x209C4`, `tst #2` / `bt loc_209C8` means the loop proceeds only when `FFFF8641.bit1` is clear; otherwise it exits.
- The later status byte is re-read at `0x209FC`. The path to the `0x21858` group requires:
  - bit 7 clear (`0x209FE–0x20A00`, otherwise the `0x216EC` callback group is selected);
  - bit 6 clear (`0x20A66–0x20A68\), otherwise the `0x2170C` group runs);
  - bit 5 clear (`0x20B60–0x20B62\), otherwise the `0x21744` group runs);
  - bit 3 set (`0x20BC8–0x20BCA\); bit 3 clear skips the six-entry `0x21858` group.
- Equivalently, on the status-byte snapshot in R0 at `0x209FC`, the selected pattern is `(R0 & 0xE8) == 0x08`. The earlier entry condition (bit 1 clear at `0x209BE`) is separate.

Within `loc_3470C`:
- `0x34716–0x34718` sets GBR=`FFFF8594`.
- `0x3471A` reads UWORD at GBR+2 = `FFFF8596`.
- `0x3471E` zero-extends; `0x34722` shifts right two; `0x34724` shifts right one; `0x34726` zero-extends to R13. Thus R13 = UWORD[`FFFF8596`] >> 3.
- `0x34776` explicitly moves R13 into R0; `0x34778` executes BSR `sub_34680`.
- Crucially, the BSR delay slot at `0x3477A` executes **before** entering `sub_34680`: `mov.w r0,@(0x46,gbr)`. It stores the pre-call R0 value, so the exact write is UWORD `FFFF8594+0x46 = FFFF85DA = UWORD[FFFF8596] >> 3`. It is not the helper's return value.
- The subsequent calls at `0x3477C` and later are after this store.

### 4. Stage 3 — FFFF85DA → FFFF85B2 snapshot

`INT_TRAPA62` calls `sub_20DCE` at `0x250A8`. Before each call, its loop at `0x25098–0x2509C` reads UBYTE `FFFF8634+0x0D = FFFF8641` and executes `tst #1` / `bt loc_25098`; it waits while bit 0 is clear and proceeds when bit 0 is set. After the call and its post-processing, it branches back to `loc_2508E` at `0x250C8`. No wall-clock cadence is assigned.

Inside `sub_20DCE`:
- GBR is set to `FFFF85EC` at `0x20DE0–0x20DE2`.
- SR interrupt-mask bits are set to `0xF0` at `0x20DE6–0x20DF2`; there is no local mask-lowering instruction before the 40-byte copy.
- `0x20EFA` loads R1=`FFFF859C` (destination base).
- `0x20F06` loads R2=`FFFF85C4` (source base).
- `0x20F08` calls `sub_21FFC`; its JSR delay slot `0x20F0A` sets R0=`0x28` (40 bytes).
- `sub_21FFC` uses R0 as byte length, R1 as destination and R2 as source. The table lookup at `0x22000–0x22004` selects from `0x2205C`; length `0x28` selects the pointer at `0x22084`, which is `0x22032`. The unrolled stub at `0x22032–0x22058` copies ten longwords (40 bytes), offsets `0x00–0x24\), from source to the same offsets at destination.
- Consequently source UWORD `FFFF85C4+0x16 = FFFF85DA` is copied byte-for-byte to destination UWORD `FFFF859C+0x16 = FFFF85B2`. The copy covers the two bytes at offsets `+0x16/+0x17`; the effective writer is the 40-byte block transfer, not a direct `mov.w` store to `FFFF85B2`.

### 5. Combined dataflow and freshness

The statically established lineage is:

```
FFFF14E0 / FFFF8650
   └─ sub_257AC: modular counter difference (underflow path subtracts 1), >>5
       └─ UDWORD FFFF85E4
           └─ sub_34476, when FFFF99E9.bit3 clear:
               unsigned integer quotient 48,000,000 / FFFF85E4, capped UWORD
               └─ UWORD FFFF8596
                   └─ loc_3470C, when selected by FFFF8641 status gates:
                       UWORD FFFF8596 >>3 → FFFF85DA
                           └─ sub_20DCE 40-byte snapshot:
                               UWORD FFFF85DA → UWORD FFFF85B2
```

Timing boundary:
- Stage 1 is ordered within each `sub_2088C` entry: `sub_257AC` and `sub_25804` run before the nine-entry `0x21A64` callback loop, whose first entry is `loc_34464`. If the timer-delta update gates permit, the later `sub_34476` callback can use the newly written `FFFF85E4` in that same entry.
- Stage 2 is a separate `INT_ATU31_IMI3A → sub_209A6` callback group selected by the status-byte pattern above.
- Stage 3 is a separate `INT_TRAPA62` wait/snapshot loop. It copies the current source field when the bit-0 wait gate releases.
- **No global ordering or freshness guarantee is proven between the stage-2 callback and stage-3 snapshot**, or between distinct interrupt/service invocations. If the stage-2 status gate has not run since an earlier update, `FFFF85DA` may be old; the later 40-byte copy will still snapshot that current (possibly stale) value into `FFFF85B2`.
- The receive-side packet parser documented in WO65062/WO65091 remains an additional runtime-conditional potential writer to destinations in the allowed RAM window. This WO does not establish that an actual packet targets `FFFF85B2`.
