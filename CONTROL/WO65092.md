## Decision question

Resolve the producer/dataflow and scheduling relationships behind shared UWORD query field \`FFFF85B2\`. Preliminary static evidence indicates a three-stage chain:

1. A callback updates UWORD \`FFFF8596\` from UDWORD \`FFFF85E4\` using \`sub_21BE4\` and constant \`0x02DC6C00\`, gated by \`FFFF99E9.bit3\`.
2. A second callback computes \`FFFF85DA = UWORD[FFFF8596] >> 3\` and writes it through a BSR delay slot.
3. A 40-byte block copy from \`FFFF85C4\` to \`FFFF859C\` makes destination \`FFFF85B2\` receive source \`FFFF85DA\`.

Establish each operation, helper arithmetic, callback-table identity, interrupt/caller conditions, and what can/cannot be inferred about temporal freshness. Do not infer an engineering unit or physical control domain.

## Why this is high payoff

WO65091 established that \`FFFF85B2\` is the common UWORD query used by paired surfaces \`0x9C2E/0x9DAE\`, dynamic-axis map \`0x9B2E\`, map \`0xAB22\`, and the inline SWORD maps. Its bounded direct writer audit found no fixed/static writer; it noted only a potential packet-parser writer. The new copy/producer chain appears to provide a concrete ordinary software dataflow path and corrects the earlier unresolved-source boundary.

## Preliminary exact code leads to verify

### A. Snapshot copy into FFFF85B2

Within \`sub_20DCE\`:
- \`0x20EFA\`: load destination base R1 = \`FFFF859C\`.
- \`0x20F06\`: load source base R2 = \`FFFF85C4\`.
- \`0x20F08\`: call \`sub_21FFC\`.
- JSR delay slot \`0x20F0A\`: R0 = \`0x28\` (40 bytes).
- \`sub_21FFC\` contract in listing: R0 = length; R1 = destination; R2 = source; dispatches to an unrolled copy stub via pointer table \`0x2205C\`.
- Offset mapping: \`FFFF859C + 0x16 = FFFF85B2\`; corresponding source byte/word offset is \`FFFF85C4 + 0x16 = FFFF85DA\`.

Verify helper's exact byte/longword copy geometry and confirm the UWORD at source offset +0x16 is preserved byte-for-byte to the destination UWORD. Establish the direct caller context of this \`sub_20DCE\` invocation and the status/wait loop conditions around it.

### B. FFFF85DA producer

Callback \`loc_3470C\` appears as table entry 1 in \`off_21858\` at ROM \`0x2185C\`. Preliminary sequence:
- \`0x34716–0x34718\`: establish GBR = \`FFFF8594\`.
- \`0x3471A\`: read UWORD \`FFFF8596\`.
- \`0x3471E–0x34724\`: zero-extend and shift right 3.
- \`0x34776\`: move derived R13 into R0.
- \`0x34778\`: BSR \`sub_34680\`.
- \`0x3477A\`: delay-slot store \`mov.w r0,@(0x46,gbr)\`; verify SH-2 BSR delay-slot ordering. If executed before the branch target, this store consumes the pre-call derived R0, not \`sub_34680\`'s return.
- Effective destination \`FFFF8594+0x46 = FFFF85DA\`.

Verify all instructions, data dependencies, return/delay-slot semantics, and whether any branch can bypass the store. Do not attribute the stored value to the helper return unless instruction order proves it.

### C. FFFF8596 producer and helper arithmetic

Callback wrapper at \`0x34464\` calls, in sequence, \`sub_34476\`, \`sub_344A4\`, and \`sub_344B6\). Preliminary \`sub_34476\` facts:
- Tests UBYTE \`FFFF99E9.bit3\` at \`0x34478–0x3447E\`.
- Set path: loads R4 = \`FFFF8596\`; R1 = \`0x02DC6C00\`; R0 = \`0x4E\` is used in the JSR delay slot \`0x3448A\` to load UDWORD \`FFFF8596+0x4E = FFFF85E4\`; calls \`sub_21BE4\`.
- Returned value is capped at UWORD \`0xFFFF\`; RTS delay slot \`0x344A2\` stores R2 to \`FFFF8596\`.
- Clear path loads immediate zero into R2 and reaches the same store.
- \`sub_344A4\` subsequently reads \`FFFF8596\`, shifts right six, and stores at \`FFFF85D6\`; this is adjacent but distinct from the \`>>3\` path used to create \`FFFF85DA\`.

Verify helper operand order and exact quotient/fixed-point operation; trace only the source and first caller/context needed. Reuse WO65062's existing \`FFFF85E4\` producer evidence; do not repeat its writer census.
