## Question

The single `FFFF1D80`-based routine (`0x036518`) reads `FFFF1DB7` and `FFFF1DA7`, sets/clears `FFFF1DA7.bit5`, writes `FFFF1DB7` and `FFFF1D81`, and calls `sub_33E18`. Do these flag bytes reach a named torque/throttle/dashpot output?

## Falsifiable hypotheses

1. `FFFF1DB7` / `FFFF1DA7` feed a named command output. **Result: REJECTED.**
2. They are internal monitor-condition state bytes with no named output. **Result: SUPPORTED.**

## What the routine computes

Entry is reachable only through the dispatch table entry at `0x0218F4` (`.data.l loc_36518`), alongside unrelated monitor routines (`loc_9A352`, `loc_47B54`, `loc_4BBD0`, …). Sequence:

1. `r7 = UBYTE[FFFF1DB7]`, `r1 = UBYTE[FFFF1D81]`.
2. If `UBYTE[0x8405].bit0` is set, skip to step 5.
3. Condition evaluation: `UBYTE[FFFF859C+0xD]` compared (`cmp/hi`) against `UBYTE[0x89E9]`; when the byte at `FFFF859C+0xD` is **not** above the threshold, `FFFF1DA7.bit5` is **cleared** (`0x036572`/`0x036574`). When it is above, `UBYTE[FFFF85FF+0xC].bit3` and `UBYTE[FFFF85FF].bit7` and `UBYTE[FFFF1F9A-0x40]` are consulted; the bit5 **set** happens at `0x036560` only when `UBYTE[FFFF85FF+0xC].bit3` is clear, `UBYTE[FFFF1F9A-0x40]` is nonzero and `UBYTE[FFFF85FF].bit7` is clear.
4. `FFFF1DB7` is rewritten at `0x0365A6` from `r7` with bit4 set (`or #h'10`) when `U16[FFFF84D4+0x12] >= U16[0x96C8]` and `UBYTE[FFFF99F4+0xA].bit1` is clear, otherwise with bit4 cleared (`and #h'EF`).
5. `FFFF1DA7.bit5` and the new `FFFF1DB7` bit4 are then tested jointly (`0x0365D8`, `0x0365DE`); `FFFF1DB7.bit4 == 0` or `FFFF1DA7.bit5 == 0` routes to `0x0365EE`, which sets `FFFF1D81.bit7`; the latched path clears `FFFF1D81.bit7` at `0x036614` when `UBYTE[FFFF1F9A+0x5A]` is zero.
6. Either path leaves through `locret_36616`.

`sub_33E18` is not a named output: it appends a byte to a ring/queue rooted at `FFFF2F00` (index at `FFFF2F00+0x416`, store `mov.b r4,@(r0,r2)`, index increment and `rts`).

## Verdict

`FFFF1DB7.bit4` is an edge/state memo of a threshold comparison, `FFFF1DA7.bit5` is the matching "condition active" latch, and `FFFF1D81.bit7` is the publication bit. Their only consumers are each other and the `FFFF1F9A` status publication; the queue append is a diagnostic sink. No torque, throttle, dashpot or actuator command is reached.

**Classification: INTERNAL STATE FLAG (monitor condition memo/latch, no named output).** None of `FFFF1DA7`, `FFFF1DB7`, `FFFF1D81` may receive a calibration definition or name.

This closes the `FFFF1Dxx` flag neighbourhood opened by WO65841: `FFFF1DB4` is unreferenced (WO65865), and the three neighbours are internal monitor state.
