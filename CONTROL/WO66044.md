### Detail on reference types

**Threshold comparisons (refs 1–2):** At 0x00034AB6 and 0x00034B2E, FFFF85DA is loaded into r0 and immediately compared against the constant 24 (`mov #h'18, r6; cmp/hi r6, r0`). The branch outcome depends on whether engine speed exceeds 24. This is a gate/comparison, not a lookup argument.

**Product comparison (refs 3–5):** At 0x00035120, 0x00035156, 0x00035186 (GBR set to h'FFFF85C4 at 0x0003510A), FFFF85DA is zero-extended into r5 and compared against `shar(shar(shar(mul.l(UBYTE[FFFF8591], UBYTE[h'886B]))))` — a scaled product of two byte values. FFFF85DA serves as the comparison threshold, not a lookup query.

**Copy/store (ref 6):** At 0x000396A6 (GBR = h'FFFF8534, set at 0x00039692), FFFF85DA is loaded, stored to stack (`mov.l r0, @r15` delay slot at 0x000396AA), then stored to U16[FFFF8558] via `mov.w r0, @(h'24,gbr)` at 0x000396C0. This is a cell-to-cell copy, not a lookup argument.

**Sign check (ref 7):** At 0x000434CC (GBR = h'FFFF85C4, set at 0x000434CA), FFFF85DA is zero-extended into r6, then `add #-32` and sign-checked (`cmp/pz; bf`). This is a range/gate check, not a lookup argument.

## Comparison with FFFF85B2

FFFF85B2 (derived engine-speed mirror per WO65239) is a distinct cell from FFFF85DA. No width/byte-lane/scaling/branch proof connects them as the same signal, and neither appears as a lookup argument in any of the 7 references above.

## Judgment

**Engine-speed → table → control hypothesis: REJECTED.**

FFFF85DA is never used as a table lookup query or axis argument. All 7 exact code references use the FFFF85DA value as:
- A threshold comparison value (against 24 or against a computed scaled product)
- A sign/range check operand (after subtracting 32)
- A source for a cell-to-cell copy (to FFFF8558)

No lookup helper (sub_22F54, sub_22D30, sub_22CF8, sub_21AC0, or similar) receives FFFF85DA as an argument. There is no table-driven control path originating from FFFF85DA within bounded scope.
