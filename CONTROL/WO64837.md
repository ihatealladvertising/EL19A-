## Stage 1 — SPECULATE (reference definitions)

### Juke
- `mTTVBHOS`: CHARACTERISTIC at `0x129F2`, 8-point `REC_UBYTE_C` curve.
- Data conversion `COMP_0021` = raw ×0.390625% (100/256%).
- Axis `mLVBHOS` at `0x118A7`, 8-point UBYTE; `COMP_0457_S` = raw ×1,280,000 mV², declared range 0–326,400,000 mV².

### V6
- `mTTVBHOS`: CHARACTERISTIC at `0xDC22`, 8-point `REC_UBYTE_C` curve; data `COMP_0021` = raw ×0.390625%.
- Axis `mLVBHOS` at `0xCB17`, 8-point UBYTE; `COMP_0096_S` is declared as raw ×1/255 dimensionless, while the A2L axis descriptor still reports range 0–326,400,000 and the same `1.28×10^6 mV²` axis label.
- This is an explicit source-definition inconsistency. Juke and V6 share the data conversion, but their axis method IDs/formulae are **not equivalent as currently defined**. Do not rely on earlier summary language that called both coefficient sets equivalent without preserving this caveat.

### Existing query construction — starting point, not a completed formula
- The caller passes `R2` as the unsigned query; `R6=UBYTE(R2)` is the `sub_22EFC` query argument.
- In the routine's local `GBR=FFFF2EC0` context, `FFFF2ED5` is a derived byte. PC `0x36B76–0x36B78` writes it from a clamped difference involving `FFFF2ED6` and the current byte at `@R11`.
- ROM byte `0x8BA5` is added to `FFFF2ED5` at `0x36C44–0x36C50`.
- If the sum is zero, control takes the fallback path that sets query `R2=0xFFFF`, then byte-extends to `0xFF`.
- Otherwise the code calls `sub_21BE4` twice: first with the longword at `FFFF2ECC` and the summed byte denominator; then with the first quotient and ROM UWORD `0x03E8`. The result is capped to `0xFF`.
- `FFFF2ECC` may be set to a computed value at `0x36C04–0x36C08`, or to `0xFFFFFFFF` on the alternate path at `0x36C40–0x36C42`. Resolve the full expression and relevant gates before writing a final closed query equation.
- Initial lookup output is stored at `FFFF2EC8` and mirrored to `FFFF2EDB`.
