## Objective

Test whether original A2L CHARACTERISTIC declaration order for CURVE and VALUE objects predicts ascending calibration ROM-address order, and produce a normalized ordered 1D symbol stream for the donor A2Ls already used by the project. This is the falsifiable prerequisite for exploiting sequential 1D ordering; do not assume the premise is true.


## Scope

1. Use only the exact V6, CF48D and Juke A2L source files and source identities already cited in WO65133/WO65175; locate paths from those reports, do not fetch or modify replacements.
2. Extract every 1D CURVE and VALUE in original declaration order, retaining symbol, source line/ordinal, address, record layout, storage width/signedness, point count, conversion/unit, axis type/reference/conversion and function group where declared.
3. For each A2L independently compare declaration ordinal with ascending address order; quantify inversions, monotonic runs, duplicate/shared axes, interleaved non-1D objects and gaps. Do not sort before preserving original order.
4. Test CURVE and VALUE streams separately and together. Report whether order is exact, approximate subsequence, family-local only, or unusable.
5. Deliver a compact normalized stream in this report (or a fenced TSV appendix), plus a go/no-go decision and a small set of stable anchor correspondences already independently supported by target evidence.

## Required deliverable

A bounded report containing:
- Exact target addresses, extents, storage types, dimensions and axis/query evidence where established.
- Relevant target instruction PCs, caller/reader contract, transforms, branch conditions and first meaningful consumers where in scope.
- Separate structural, axis/scaling and functional confidence.
- Candidate-to-symbol matches and disconfirming evidence where applicable.
- RR disposition and exact unresolved boundary.
- Reused evidence and explicit no-repeat list.

## Stop conditions

Stop if original source files cannot be located/read or declaration order is not a useful constraint. Do not create scripts, extracted files, indexes, workbooks or XML; no address/name transfer. A negative pilot is a complete result.
