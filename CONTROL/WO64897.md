## Lookup contract and query

- All four use `sub_22E10`: a fixed-grid 16-point UBYTE lookup with no explicit axis pointer.
- PC `0x77F36) loads UBYTE `[FFFF859C+0x08]`.
- The code subtracts 8, clamps negative values to zero, shifts left one bit, then caps at `0xFF` using `R9=0xFF`.
- Exact query:

- This is **not** a proven `0x00–0xEF` caller-side gate. The q can reach 0xFF; `sub_22E10`'s own upper-bound behavior therefore matters (q >= 0xF0 selects the final table point).
