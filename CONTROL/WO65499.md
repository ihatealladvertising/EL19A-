## Falsifiable hypothesis record

- **Identity layer advanced:** input identity (what bounds the `FFFF1640` setpoint).
- **Hypothesis:** `r1` is a RAM block base whose `+0xA1E`/`+0xA22`/`+0xA2C` words are *adaptation/learned* limits rather than calibration constants, because the chain mixes them with `FFFF3454` (a work area) rather than with ROM addresses.
- **Evidence:** WO65487 §2 (`0x6E18A`–`0x6E1D2`); `FFFF1054`/`FFFF3628` register-base convention; `FFFF3454` as a work block.
- **Prediction:** the routine will load `r1` from a literal pool and the resolved address will fall in RAM; a ROM copy of the same values would indicate calibration limits instead.
- **Cheap discriminator:** find the routine entry, resolve the `r1` literal, compute the absolute clamp addresses, then test for a ROM mirror.
- **Result:** **SUPPORTED.** `r1` is loaded from a literal pool and resolves to **`FFFF2150`** — RAM, address-mapped only as `unk_FFFF2150`. The three clamp cells are unlabeled `.res.b` inside that block, are never written at a fixed displacement anywhere in the ROM, and the same chain writes an adapted word back into the block at `+0xA32`. No ROM mirror was found or is addressable from this code.
- **Information gain:** converts the last open item of WO65487 into an absolute address set and settles that `FFFF1640`'s bound is **not** a calibration constant that can be exposed or named — it is RAM state in a writable block, so the cell and its limits must stay opaque.

## 1. Owning routine (correction to WO65487)

WO65487 referred to the writer as `sub_6E1xx`. The routine is **`0x6E0CC`**, unlabeled (no `sub_`/`loc_` symbol at its entry):

| Item | Value | Evidence |
|---|---|---|
| Entry | **`0x6E0CC`** | `2F 96 mov.l r9, @-r15`, then `r10`–`r14` pushes through `0x6E0D6` |

| Preceding function | ends `0x6E096` `rts` / `0x6E098` delay slot, pool `0x6E09A`–`0x6E0CA` | separates it from `sub_6DF76` |

The leaf property matters: WO65487 left `r1` open partly because the routine was assumed to be a `sub_` with calls. It makes none, so `r1` set at `0x6E10A` survives unchanged to every clamp read.
