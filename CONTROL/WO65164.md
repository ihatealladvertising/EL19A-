## 3. Result — producer

**`FFFF8494` has no static producer in the listing.** The resolver reports zero writes and zero
unresolved candidates for it (no `gbr_disp`/`base_disp` unresolved row names it). It is a
read-only query input: consumed as an indexed-lookup base by 87 sites in 62 distinct functions,
and seeded as a pointer in exactly two places:

```
0004ABAC  90 65   mov.w   word_4AC7A, r0 ; h'FFFF8494
000962BC  90 55   mov.w   word_9636A, r0 ; h'FFFF8494
```

Both are `mov.w` pointer seeds (not stores), so `FFFF8494` is treated by the code as a fixed
RAM-resident query block whose contents are read, never recomputed by the routines in this listing.
Its value must be established at boot/initialisation (outside the resolvable code) or be a
configuration constant; this WO does not claim a writer.

### 3.2 Consumption pattern

`FFFF8494` is read as `UWORD` and used as a **query base** for indexed lookups: the dominant idiom
is `mov.w @rX, rY` where `rX` was loaded with `FFFF8494` (or `FFFF8494 + disp`), followed by
`shll2`/indexing and a table read. Top consumers: `sub_77608` (7 sites), `sub_86D9C` (5),
`sub_56AAA`/`sub_9E976`/`sub_9F0AC` (3 each). 62 distinct functions total. `FFFF8496` is read as
`@(0x2,rX)` (i.e. `FFFF8496`) by 13 sites, consistent with it being the second word of the same
query record.

### 3.3 Domain conclusion

`FFFF8494` is a **read-only query-record base**: a 2-word (and surrounding) RAM block whose first word
is an externally established input and whose second word (`FFFF8496`) is the C1-computed `N`-derived
scalar. It is not a single scalar with a producer in this ROM; its "domain lineage" is that of a
lookup key/pointer consumed across ~62 functions, with `FFFF8496` as its derived sibling and
`FFFF84AC` as a threshold operand that the C2 routine re-owns.
