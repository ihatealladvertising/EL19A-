## Closeout — 2026-11-22

**Result:** C3D6 is evaluated in `sub_6F5E8` (call `0x6F6DC`). Its two payload values form a **row step**: row 0 = `0x0000`, rows 1–7 = `0x8000`, and every column within a row is identical. The output is therefore a 0→`0x8000` ramp in the **first (row) query only**, interpolated across the first axis interval `0x0000–0x0064`. The second (column) query has no effect on the result in this ROM. The result, `FFFF28E6`, is used immediately as a **Q15 crossfade weight** between two curve results. The blended value is staged at `FFFF2286`. Physical meaning is not assigned.

### 2. Axes and orientation

- `sub_22CF8` searches `r5`/`r7` first and the stack/`r6` pair second (both through `sub_2340C`, 8 UWORD points). `loc_232D0` (`0x232D6–0x232E2`) forms `cell = base + off2 + 8·off1` and `next = cell + 16`, so the **first axis indexes rows** (16-byte stride) and the second axis indexes columns.
- First axis (rows) `0xFE20`: `0000 0064 00C8 012C 0190 0320 04B0 0578`. This is the explicit first axis the WO asked for; the catalogue lists it only as "explicit U16".
- Second axis (columns) `0xFE10`: `0000 1FE0 3FC0 5FA0 7F80 9F60 BF40 FF00`.
- Payload `0xC3D6–0xC455` (ROM): row 0 is all `0000`; rows 1–7 are all `8000`.
- **Consequence:** `m = 0x8000·min(q1,0x64)/0x64`, an interpolated ramp from 0 to `0x8000` that is reached at `FFFF84EA ≥ 0x64`, independent of `FFFF2462`. The two catalogue values are therefore the endpoints of a ramp, not a binary output.
