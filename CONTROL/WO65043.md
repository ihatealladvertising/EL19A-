## Scope

## Verified mechanics

- Both callers read raw UBYTE `[FFFF84B4+4] = FFFF84B8`; neither F35E call applies a caller-side conversion or clamp.
- First caller: `loc_4F8AC`, call PC `0x4F8DC`. R13 holds `FFFF84B4`; query byte is loaded at `0x4F8D8`; R4 receives F35E at `0x4F8DA`; R14 holds `sub_22E10`. Result is zero-extended and retained in R8 (`0x4F8DE–0x4F8E0`).
- The retained F35E result is passed as UWORD argument R4 to `sub_543CC` at `0x4FB0E–0x4FB14`. The helper's returned UWORD is stored at `FFFF1D12+0x48 = FFFF1D5A` (`0x4FB18–0x4FB20`). This is a direct result-dependent path to a RAM field.
- Second caller: `loc_4FBC2`, call PC `0x4FC36`. It reads the same raw query at `0x4FC34`, passes R4=F35E from `0x4FC30`, and receives the UBYTE result in R6 (`0x4FC3A`).
- The second caller zero-extends UWORD `FFFF1054+0x2FA = FFFF134E`, multiplies it by the F35E result, multiplies by 100, then shifts right 14 bits (8+2+2+2). The result is capped at `0xFFFF` and stored as UWORD at `FFFF1054+0x550 = FFFF15A4` (`0x4FC3C–0x4FC5C`).
- The staged UWORD is copied to `FFFF1D12+0x4C = FFFF1D5E` (`0x4FC98–0x4FC9E`). This is a confirmed downstream RAM destination, not a physical actuator endpoint.
- Distinct neighboring curve paths remain separate: F33E -> `FFFF1D12+0x46`; F34E -> `FFFF1054+0x54E` then `FFFF1D12+0x4A`; F36E -> `FFFF1054+0x552` then `FFFF1D12+0x4E`.
