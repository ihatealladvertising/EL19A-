## Decision and principal result

The MCU-level ATU-II clock architecture can be bounded, and a separate execution-time counter can be assigned a known divider. However, the raw source word `FFFF14E0` consumed by the `FFFF85E4` producer is **not proven to be the ATU-II channel-0 capture value or any other specific timer register**. Consequently, no absolute frequency, elapsed-time unit, or wall-clock period can yet be assigned to `FFFF85E4`, `FFFF8596`, `FFFF85DA`, or `FFFF85D6`.

The strongest positive result is a split:
- ATU-II channel 0 / `TCNT0` provides a known `φ/32` counter tick used by separate execution-time measurement code.
- `FFFF85E4` is computed from a RAM UDWORD at `FFFF14E0`, but the producer of that RAM word remains unresolved. The fact that ATU capture interrupts call the same update routine does not bridge this data-source gap.

## 1. Clock tree and hardware limits

Device-level SH7058 ATU-II clock architecture (Renesas SH7058 Rev.3 comparison table in the SH7058/SH7058S/SH7059 hardware manual):

```text
EXTAL / board clock
        |
        v
SH7058 clock generator / PLL
        |
        +---- internal clock φ
                 |
                 +---- ATU-II channel 0: φ/32
                 |       +-- TCNT0 (32-bit)
                 |       +-- ICR0A..D capture latches
                 |
                 +---- ATU-II channel 1: selectable
                         +-- (φ/32) × (1/2^n), n=0..5
                         +-- or TCLKA / TCLKB / AGCK / AGCKM
```

The manual specifies channel 0 at `φ/32`; channel 1 supports `(φ/32)×(1/2^n)`, `n=0…5`, or the listed external/gated sources. This is device capability, not proof that any given channel is the source of `FFFF14E0`. The ECU's EXTAL frequency, PLL selection, and actual `φ` were not recovered in this bounded pass. See Renesas hardware manual, Table 11.1, SH7058 column: https://www.renesas.com/en/document/mah/sh-2e-sh7059-f-ztattm-sh7058s-f-ztattm-hardware-manual (comparison rows explicitly distinguish SH7058 from SH7058S/SH7059).

## 2. Timer/peripheral configuration evidence

### Channel 0 capture path

- Vector entry `0x20154` points to `INT_ATU02_ICI0A` at `0x25D5A`.
- The handler reads the 32-bit ICR0A pair from `FFFFF434–FFFFF437` via base `FFFFF420` plus `0x14` at `0x25D9C`.
- That particular capture value is stored at `FFFF1990+0xD4 = FFFF1A64` at `0x25DA0`; it is **not** stored to `FFFF14E0` in this observed sequence.
- SH7058 channel 0 is specified to count at `φ/32`; therefore its raw counter tick is `32/φ` seconds. The actual `φ` remains unknown.
- Separate code samples `TCNT0H/TCNT0L` at `FFFFF430–FFFFF433` for execution-time deltas: `sub_209A6` and `sub_20DCE`. This establishes the `φ/32` timebase for those execution-time measurements, not for the `FFFF14E0` data word.

### Channel 1 compare/interrupt configuration

The initialization sequence in `sub_2AA4` calls `sub_2898`, `sub_2982`, and then `loc_DD0` (tail jump at `0x2AD6`):

- `sub_2982` writes zero to `TCR1A` (`FFFFF45D`) and `TCR1B` (`FFFFF45C`) at `0x2988/0x298C`.
- `sub_2898` initializes channel-1 I/O-control and interrupt/status registers; `loc_DD0` subsequently loads `OCR1 = 0x04E2` at `0xDDF0–0xDDF2`, clears `TCNT1B`, leaves `TIER1B=0`, and enables `TIER1B=1` at `0xDE00–0xDE02`.
- Vector `0x20194` points to `INT_ATU12_IMI1AE` at `0x26F46`; its handler reads the `TCNT1A` register block based at `FFFFF440`.
- This establishes channel-1 configuration and an enabled A-side interrupt source in the initialization sequence. It does **not** establish a running counter start state, decode the written-zero `TCR1A` selection into a specific source, or prove that this event updates `FFFF14E0`.

No wall-clock period is assigned to the channel-1 event. If the selected internal source were `(φ/32)×(1/2^n)`, its counter tick would be `32×2^n/φ`; external-source modes instead inherit the external/gated input period. The exact active source and start state remain open.

## 3. FFFF85E4 producer and derived values

Reuse WO65092's instruction-level trace:

1. `sub_2088C` calls `sub_257AC` at `0x208A6`.
2. `sub_257AC` requires `FFFF1E64.bit0=1`. If the second validity byte `FFFF20C4` is nonzero, it writes `0xFFFFFFFF` to `FFFF85E4`.
3. On the valid path it reads current UDWORD `FFFF1054+0x48C = FFFF14E0`, subtracts previous UDWORD `FFFF8650` with the documented unsigned underflow adjustment, shifts right five, and stores UDWORD `FFFF85E4`. It then updates `FFFF8650` from the current `FFFF14E0` value.
4. The machine expression is:
   `d = (current - previous) mod 2^32`; if `current < previous`, `d = d - 1 mod 2^32`; `FFFF85E4 = d >> 5`.
5. The producer does not directly read `TCNT0`, `ICR0A), `TCNT1A`, or another named timer register. The only established current sample is the RAM word `FFFF14E0`. WO64853's bounded audit did not establish a software, DMA/DTC, pointer-alias, or bulk-copy producer for that word.

### Quotient and downstream scaling

- `sub_34476`: if `FFFF99E9.bit3` is set, it stores zero to UWORD `FFFF8596`; if clear, it computes unsigned integer `48,000,000 / FFFF85E4`, capped at `0xFFFF`. A zero divisor follows the helper's zero-divisor path and stores zero.
- `sub_344A4`: UWORD `FFFF8596 >> 6` → UWORD `FFFF85D6`.
- `loc_3470C`: UWORD `FFFF8596 >> 3` → UWORD `FFFF85DA`; the store is in the BSR delay slot before entry to `sub_34680`.
- The 40-byte snapshot copies `FFFF85DA → FFFF85B2` and `FFFF85D6 → FFFF85AE` at corresponding offset `+0x16) and `+0x12`.
- **Correction to the work-order shorthand:** the verified `FFFF8596 → FFFF85D6` operation is `>>6`, not `>>4`. No `>>4` operation was found in this enumerated lineage. Do not insert a `>>4` stage into the clock tree.

The constant `48,000,000` is an arithmetic numerator only. It does not by itself prove that the MCU is clocked at 48 MHz, that `FFFF85E4` is in timer ticks, or that the quotient is in Hz.

## 4. Interrupt and scheduler cadence

### Event-driven producer group

- Both `INT_ATU02_ICI0A` (`0x25D5A`) and `INT_ATU12_IMI1AE` (`0x26F46`) call `sub_2088C`.
- Each `sub_2088C` entry calls `sub_257AC` and `sub_25804`, increments the byte at `FFFF85C4+0x1A = FFFF85DE`, and sets `FFFF8641.bit3`.
- A separate counter at `FFFFB634` gates the grouped decrement/callback work every second `sub_2088C` entry. Thus this part of the software has an **event-count cadence** (one producer opportunity per invocation; grouped work every two invocations), not a known millisecond rate.
- The two interrupt sources are distinct. The listing does not establish their relative rates or guarantee that they occur in a fixed alternating sequence.

### INT_TRAPA62

- The ROM vector word at `0x200FC` points to `INT_TRAPA62` at `0x25004`.
- The handler loops at `0x25098–0x2509C` while `FFFF8641.bit0` is clear; once set, it calls `sub_20DCE` at `0x250A8` and then returns to the wait loop.
- The source/setter of `FFFF8641.bit0` is unresolved. `sub_2088C` sets bits 3 and, on every second call, 2; it does not set bit 0 in the inspected sequence.
- `INT_TRAPA62` is a software TRAPA vector, not evidence of a periodic hardware interrupt. The listing has four syntactic `trapa #0x3E` sites (`0x10F4`, `0x157E`, `0x26BC`, `0xB8766`). Only `0x26BC` explicitly sets VBR to `0x20004` immediately before the trap, routing that site to the ROM vector at `0x200FC`; `0x157E` sets a RAM VBR, `0xB8766` loads VBR from R1, and the VBR state at `0x10F4` is inherited/unresolved. Do not count all four as calls to this ROM handler.
- The 122-callback `sub_20DCE` pass is event-gated by bit 0, not a fixed-rate scheduler. Its separate `TCNT0` reads measure execution elapsed counts; they do not establish how often the TRAPA service is entered.

## 6. Disposition, confidence and stop boundary

- **High confidence:** instruction-level delta arithmetic, `48,000,000` quotient, bit-3 polarity, right shifts, callback gating, timer register addresses and observed register writes in the pinned listing.
- **High confidence:** SH7058 device-level channel-0 `φ/32` divider and channel-1 clock-source capabilities per the Renesas manual.
- **Medium confidence:** channel-1 initialization interpretation as a compare/interrupt configuration; the exact running/start condition and event-period source are not closed.
- **Unresolved:** actual EXTAL frequency and PLL selection; exact runtime `φ`; whether `FFFF14E0` is populated from an ATU capture or another source; why both ATU vectors invoke the common update routine; source of `FFFF8641.bit0`; actual TRAPA entry rate; meaning of `FFFF99E9.bit3`.
- **Completed work not to repeat:** WO65062 `FFFF85E4` writer classification and ISR/callback inventories; WO65092 arithmetic, `FFFF8596`/query scaling, callback table and snapshot lineage; WO65094 `FFFF8641` callback gate and event-count behavior; WO64853 bounded DMA/DTC and `FFFF14E0` producer audit.
- **Stop:** no supported route links `FFFF14E0` to the observed ICR0A/TCNT0 value. Do not turn the 48-million numerator into an oscillator claim, do not derive RPM, and do not reopen downstream map semantics. Revisit the unresolved RAM-source edge only after the disjoint WO65103 transport graph is available.
- **Integrity:** reused the pinned ROM and annotated listing identities. WO65062 recorded a full in-ROM CODE/DATA byte-concordance preflight with zero mismatches for this same listing; this WO made no new ROM/LST edits or byte-extraction claims.
- **Integration:** this WO report and coordinator-owned operational register only. No workbook, XML, catalogue, ROM, LST, IDB, scripts/tools, Library or OneDrive changes.
