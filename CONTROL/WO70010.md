EL19A `0x0F3EE–0x0F3FD` is passed as the data pointer to the 16-point UBYTE lookup helper `sub_22E10` at actual call PC `0x40FF4`. All 16 bytes are `0x80`. The lookup therefore returns `0x80` for every query, and the caller stores that constant byte at `FFFF2778`.

| PC | Instruction | Effect |

For query `q < 240`, `loc_2350C` executes four `shlr r5 / rotcr r3` pairs (PCs `0x2350C–0x2351A`), yielding the 4-bit interval index and fractional nibble. It then adds the byte offset `2 × index` at `0x23524–0x23526` and, in the byte-table path `0x23532–0x2353A`, reads adjacent UBYTE values at indices `index` and `index+1`. `sub_231C8` at `0x2353C` performs the interpolation. Thus the 16-point implicit query grid is `0,16,32,…,224`; at `q >= 240`, the helper returns element 15 directly.

For this call:
- Data pointer R4 = `0x0F3EE`
- Query R5 = UBYTE[`FFFF84B8`], with unsigned extension in the `jsr` delay slot
- Axis = fixed implicit byte grid, not a ROM axis pointer
- Output = interpolated UBYTE in R0, stored at `FFFF2778`

## 3. Consequence of the target payload

All 16 calibration bytes are `0x80`. Therefore every possible interpolation segment has identical lower and upper endpoint values; the helper returns `0x80` regardless of the query. The saturated path also returns `0x80`.

Within this ROM image, the path has no effective calibration variation. Its observed store is the constant UBYTE `0x80` at `FFFF2778`. No downstream tracing was needed to distinguish a varying calibration from the constant object; the work order's stop boundary is satisfied at the result destination.

The query cell `FFFF84B8` is also used by other temperature-processing paths in the existing Findings/work orders. This report records the direct query source only and does not use that contextual resemblance to assign an EL19A physical identity to `0x0F3EE`.
