# WO70018 — Reconcile RomRaider screenshots and displayed cell values against EL19A

**Status:** ASSIGNED — WORKER 2 — READY  
**Priority:** P1 — independent definition validation  
**Workstream:** ROMRAIDER SCREENSHOT / CELL-VALUE VALIDATION  
**Owner:** Worker 2  
**Created:** 2026-11-26  
**Branch:** `main`

## Objective

Turn the existing RomRaider screenshots into address-indexed, independently checkable evidence. Determine which screenshots depict objects present in the EL19A ROM and whether the displayed dimensions, axes and cell values agree with the current XML and target bytes.

## Pinned inputs

- Screenshot set: all 24 images in `EVIDENCE/RR TABLES SS/` (`Capture001.PNG` through `Capture024.PNG`).
- Additional context: `EVIDENCE/common nissan tables and conventions`, `EVIDENCE/CF48D.xml`, `EVIDENCE/CF48D.bin`, `EVIDENCE/VERSA f501.bin`, `EVIDENCE/EL19A.PNG`, and the screenshot/evidence references already linked in `FINDINGS/INDEX.md`.
- Definition targets: `CALIBRATIONS/EL19A_best_guess_provisional_full_definition.xml`, `CALIBRATIONS/EL19A_release1_conservative.xml`, `CALIBRATIONS/RELEASE1_SCOPE_MATRIX_R1.csv`, and `CALIBRATIONS/discovered_tables_catalog.csv`.

## Required work

1. Inspect every screenshot and identify the displayed ROM/table address when visible, table name, dimensions, storage/display type, axis labels and values, units/scaling shown, and all legible cell values. Record unreadable/ambiguous cells explicitly rather than interpolating or guessing.
2. Identify whether the screenshot is explicitly from EL19A, CF48D, another Nissan ROM, or unknown. Do not treat a CF48D screenshot as an EL19A value source without exact payload/address reconciliation.
3. For screenshots with an identifiable EL19A address, decode the corresponding raw bytes from `VERSA f501.bin` using the correct width and endianness, and compare displayed values after applying only a documented conversion that can be reproduced from the screenshot or the matching definition.
4. For screenshots that appear to match CF48D XML objects, resolve the exact XML object and compare its table geometry, axes and cell values with the screenshot. Keep this CF48D validation separate from EL19A confirmation.
5. Cross-reference each screenshot to the current full-definition baseline, Release 1 XML, scope matrix and catalogue. Classify the object as: exact agreement; geometry agreement/value agreement; display-conversion agreement; partial/illegible; conflicting; no target match; or source unidentified.
6. Prioritize screenshots containing common Nissan maps/curves/scalars that can validate multiple candidate tables. Do not spend time interpreting unrelated vehicle logs or decorative UI.

## Output

Create `CONTROL/WO70018_SCREENSHOT_VALIDATION.tsv` and a concise `CONTROL/WO70018.md` report.

Required TSV columns:

`screenshot_path, screenshot_sha256, source_rom_identification, displayed_name, displayed_address, dimensions, displayed_storage_or_type, x_axis_label, x_axis_values, y_axis_label, y_axis_values, units_or_conversion_shown, cell_values_raw_or_displayed, legibility_status, target_rom_address_match, target_raw_payload_sha256, xml_object_match, scope_matrix_status, catalogue_status, comparison_result, discrepancy, evidence_notes`.

Use one row per screenshot/table. If a screenshot contains multiple tables, use one row per table and retain a stable screenshot identifier. Preserve cell matrices in a companion file or a documented compact serialization; do not truncate values in the evidence output.

## Evidence and interpretation rules

- A screenshot proves only what is visibly displayed and legible. It does not by itself establish target ROM storage or runtime semantics.
- Keep raw stored values, displayed values and converted values separate.
- Never invent missing axis points, cell values, table addresses, units or scaling.
- A visual match is not an exact payload match; exact byte comparisons must be separately stated.
- Reuse existing Findings and work-order evidence; do not re-investigate unrelated semantic paths.

## Acceptance criteria

- All 24 screenshots have an explicit disposition, including screenshots that cannot be identified.
- Every claimed cell-value match is reproducible from visible screenshot values and the cited ROM/XML bytes.
- Conflicts and unreadable regions are preserved as such.
- The report identifies which screenshots provide usable independent EL19A evidence and which are only donor/context evidence.
- Findings disposition is stated. Promote a material change in EL19A calibration interpretation; otherwise NOT REQUIRED.
