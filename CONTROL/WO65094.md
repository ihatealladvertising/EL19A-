## 1. Exact FFFF1778 update arithmetic

`sub_69CE8` (`0x69CE8`) establishes:
- R6 = `FFFF8613` at `0x69CE8`.
- R4 = `FFFF1054` at `0x69CEA`.
- UBYTE `[R6+1] = UBYTE[FFFF8614]` is read at `0x69CEC`.
- R5 = ROM pointer `0x11700` at `0x69CEE`; UWORD `[R5]` is loaded at `0x69CF4`.
- R0 tests bit 0 at `0x69CF0`; current UWORD `[R4+0x724] = UWORD[FFFF1778]` is loaded at `0x69CF6`.

ROM bytes at `0x11700` are `01 47`; therefore UWORD step = `0x0147` = **327**.

SH-2 TST/BT/S semantics at `0x69CF0/0x69CF8` establish the corrected polarity:
- **FFFF8614.bit0 set:** the `BT/S` does not branch to `loc_69D0C`; the fall-through adds the step (`0x69CFC`) and caps the UWORD at `0xFFFF` (`0x69CFE–0x69D0A`).
- **FFFF8614.bit0 clear:** the branch reaches `loc_69D0C`; the step is subtracted. `CMP/PZ` at `0x69D10` detects a negative result and `MOV #0,R2` at `0x69D14` floors it at zero.
- The final store is the RTS delay-slot instruction `mov.w r2,@(r0,r4)` at `0x69D1A`, after R0 is loaded with offset `0x724` at `0x69D16`. Effective write: UWORD `FFFF1778`.

Proven machine expression:

```text
old = UWORD[FFFF1778]
step = UWORD[0x11700] = 0x0147 = 327
if UBYTE[FFFF8614].bit0 == 1:
    new = min(0xFFFF, old + step)
else:
    new = max(0, old - step)
UWORD[FFFF1778] = new
```

At the mathematical bounds, it takes up to 201 increment passes from zero to saturate at `0xFFFF`, or 201 decrement passes from `0xFFFF` to reach zero. This is a count of update opportunities, not a time estimate.

## 2. Direction-byte use and producer boundary

- The direction input is bit 0 of UBYTE `FFFF8614` (base literal `FFFF8613` plus one), not a UWORD at `FFFF8613`.
- A second direct consumer occurs in `sub_6BB64`: it reads the same byte at `0x6BB6E`, tests bit 0 at `0x6BB72`, and selects a saturating UWORD add/subtract update of `FFFF1D62` using a separate ROM step at `0x9280`. This confirms bit 0 is shared by at least two accumulator/ramp operations; no physical meaning is inferred.
- Other reads of `FFFF8614` include `0x555D2` and `0x7D01C`, which test bit 1 (`0x02`), not the direction bit.
- Exact textual search finds no code literal `FFFF8614` or `h'8614`; the only explicit fixed base references to `FFFF8613` resolve to reads or an unused/overwritten base load in the examined contexts. No direct fixed-address `FFFF8614` writer is established.
- The known `sub_20DCE` local byte shuffles in WO65062 copy `FFFF860B/0C` and `FFFF860D/0E` among nearby slots; they do not establish a write to `FFFF8614`.
- WO65062/WO65091's receive-side `loc_1D64 → sub_1C5C` parser accepts record-supplied destinations within `FFFF8500–FFFFBD00`, a window containing `FFFF8614`. A packet could therefore write this byte, but no actual packet, destination, length or payload to `FFFF8614` is evidenced. This remains a runtime-conditional capability, not a proven producer.

**Disposition:** direction-bit writer and its initialization remain unresolved. No assumption is made that its default state is zero or one. The LST RAM-map `FF` placeholder is not treated as a runtime initial value.

## 3. Invocation and update opportunity

### Callback table

- `sub_20DCE` calls 122 callback entries sequentially from table `off_2187C` at ROM `0x2187C`.
- Its loop setup at `0x2120C–0x21218`: R13=`0x7A` (122), R14=`0x2187C`; each iteration loads a callback pointer (`0x21210`), calls it (`0x21212`), increments R14 by four in the JSR delay slot (`0x21214`), decrements R13 and loops until zero.
- `loc_6A1B0` is table entry **18**: table address `0x218C4`, offset `0x48` from `0x2187C`, index `0x12` (zero-based).
- `loc_6A1B0` contains the only direct `JSR sub_69D1C` reference found in the bounded listing search (`0x6A1CA–0x6A1CE`).

### Callback gates — corrected polarity

`loc_6A1B0` sets GBR to ROM byte `0x8B51` at `0x6A1B6–0x6A1B8`:
- `0x6A1BA–0x6A1C0` masks bit 5 and uses `TST`/`BT/S`. **Bit 5 clear branches to `loc_6A1DC` and skips the paired-map update.**
- When bit 5 is set, `0x6A1C4–0x6A1C8` tests bit 7 at GBR+`0x182`, effective ROM byte `0x8CD3`. **Bit 7 set branches to `loc_6A1DC` and skips the update.**
- Therefore `sub_69D1C` and its subsequent `sub_6A0D4` call run only when **`0x8B51.bit5 == 1` AND `0x8CD3.bit7 == 0`**.

### Parent wait/dispatch loop

- The `INT_TRAPA62` vector entry is at ROM `0x200FC` and points to `INT_TRAPA62` at `0x25004`.
- At `0x25098–0x2509C`, it reads UBYTE `FFFF8634+0x0D = FFFF8641`, tests bit 0, and loops while that bit is clear. When the bit is set, execution proceeds to `sub_20DCE` at `0x250A8`.
- After `sub_20DCE` returns, the interrupt routine performs post-processing and branches back to the wait loop at `0x250C8`.
- Thus callback entry 18 gets one invocation opportunity per `sub_20DCE` dispatch pass; `sub_69D1C` actually updates the weight only when the two ROM bit gates above permit it.
- This proves an event-gated dispatch relationship, not a fixed periodic frequency. The source/setter of `FFFF8641.bit0`, the frequency of TRAPA 62, and real elapsed time between successful loop passes remain unresolved.

## 4. Dataflow ordering within an eligible pass

`sub_69D1C` at `0x69D1C` executes:
1. `BSR sub_69C5C` at `0x69D20`: computes the trust/normal endpoint UWORDs and stages them at `FFFF1768`/`FFFF176A`.
2. `BSR sub_69CE8` at `0x69D24`: updates `FFFF1778` by one 327-count step, subject to `FFFF8614.bit0`.
3. Reads the updated UWORD `FFFF1778` at `0x69D2C`, selects/interpolates the two endpoints, and stages combined result at `FFFF1762` (`0x69D68`).

Therefore the current callback pass's interpolation uses the weight **after** the one-step update, not the prior weight. The pair endpoints are computed before that update.

## 5. Corrections to WO65093

The following WO65093 descriptions are superseded by the instruction-level corrections established here:

1. **Weight direction reversed:** WO65093's opening interpretation said bit 0 clear adds and bit 0 set subtracts. Actual code is bit 0 set = add/saturate; bit 0 clear = subtract/floor.
2. **Underflow result corrected:** WO65093 stated the subtract-underflow path substitutes `0xFFFF`. Instruction `0x69D14` is `MOV #0,R2` (`E2 00`), so the result floors at zero.
3. **Callback gate polarity reversed:** WO65093 stated `0x8B51.bit5` set bypasses and bit 5 clear proceeds when `0x8CD3.bit7` is set. Actual code invokes the paired-map update only when `0x8B51.bit5` is set and `0x8CD3.bit7` is clear.

The paired-map interpolation geometry, endpoint destinations, weighted formula and first-consumer analysis in WO65093 are unaffected.

## 6. Bounded coverage, confidence and unresolved items

- **High structural confidence:** literal pool roots, exact effective addresses, instruction order, delay-slot write, ROM step bytes and callback table address/index are established from the pinned annotated listing.
- **High software-role confidence:** `FFFF1778` is a UWORD interpolation weight moved by a fixed 327 step in the direction selected by `FFFF8614.bit0`; it ramps with endpoint saturation and is applied after the endpoint lookups in each eligible callback pass.
- **Physical-domain confidence:** unresolved. No timer unit, sensor identity, subsystem name or physical operating mode is assigned.
- **Unresolved:** initializer/reset value for `FFFF1778`; direct/static writer or initializer for `FFFF8614`; actual packet/runtime destination if the receive parser writes this byte; source of direction bit 0; source of `FFFF8641.bit0`; TRAPA 62 invocation frequency / elapsed time; and the physical meaning of the two endpoints and weight.
