## Findings

### 1. OBD/diagnostic service dispatcher contains explicit service 0x06 unsupported response

`sub_2C2C0` is reached from `sub_2B4A4` when the diagnostic state variable `dword_821C` (`@(h'21C,gbr)`, GBR `FFFF8000`) is `6` (`0002B710: cmp/eq #6; 0002B714..0002B71A: jsr sub_2C2C0; stores return state`).

Within `sub_2C2C0` (`0002C2C0`):
- `0002C2C4..0002C2C6`: `ldc #FFFF8440,gbr`.
- `0002C2C8`: `r5 = #FFFF8000` (request buffer base).
- `0002C2CC..0002C2D2`: loads `r4 = extu.b(byte @(3,r5))` i.e. request service byte at `FFFF8003`.
- The function performs multiple service-byte compares and branches to specific handlers.
- `0002C426: cmp/eq #6,r0` / `0002C428 bf loc_2C434` / `0002C42A..0002C42E jsr sub_2DE10` handles service `0x06`.

`sub_2DE10` (`0002DE10..0002DE16`) sets `r4=#6`, `r5=#h'11`, and tail-jumps to `sub_30830`.

`sub_30830` (`00030830..00030878`, GBR=`FFFF8105`) constructs a negative-response message in the `FFFF8105+5+index` message area: it writes `0x7F` at the current index (`0003084A`), writes `r4` (service, here `0x06`) at index+1 (`00030854`), writes `r5` (NRC, here `0x11`) at index+2 (`00030864`), clears `FFFF8212`/related state bytes, then calls `sub_2B734` (`00030870`) to finalize/checksum/update state. `sub_2B734` (`0002B734..0002B756`) calls `message_finalize_fields`, `message_buffer_checksum`, stores checksum, and updates message state via `message_update_state`.

**Interpretation:** this is an explicit static negative response for service 0x06: `7F 06 11` (serviceNotSupported NRC). This disproves OBD Mode $06 support in this bounded dispatcher path.

### 2. Bounded distinction from internal diagnostic/monitor selector families

`sub_31B88` (`00031B88`, GBR=`FFFF8464`) is a different diagnostic response builder (WO65107 context). It reads selector `byte @(h'B4,r6)` from `r6=FFFF2F00` (`00031BC0` context for nearby fields; selector read at `00031BB4..00031BC2` in surrounding block) and dispatches selector 1->`sub_31DAA` (DTC/status; WO65107), 2->`sub_32678`, 3->`sub_3270C`, 4->`sub_327FE`, 5->`sub_331E8`, 6->echo path, 0x83->`sub_33CB8`.

`sub_327FE` (`000327FE`, GBR=`FFFFB4A8`) reads `FFFF2F00+B4` as a group/TID-like selector and `FFFF2F00+B5` as sub-index (`0003280C..00032822`), performs range/bitmask gating (`E14C` table reference at `000328EA/000328F4`) and emits monitor/test-result-like records via `sub_32790`/`sub_33E18` for many sub-index cases (e.g. `00032924+` dispatch on B5 values 1..0x2F). For group values `0x80/0xA0/0xC0/0xE0` it takes the `loc_331C2` completion/unsupported path (`0003287C..000328A6`).

**Non-promotion boundary:** `sub_327FE` is an internal/diagnostic monitor-like response family behind `sub_31B88` selector 4 in the `FFFF8464/FFFF2F00` protocol. It is **not** evidence of OBD Mode $06 service support, and no OBD service 0x06 dispatch was observed to route to it in the bounded coverage. Do not label its TIDs as OBD MID/TID or misfire monitors without a proven OBD Mode $06 request/response path.
