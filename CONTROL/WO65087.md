# WO65087 — The `0x8405` Bit-0 Defaults Are Floors-of-Ceiling: 1000/800 Bound on a Shared `×727 ÷ 800` Conversion

**Status:** BOUNDED COMPLETE — CLOSED (2026-11-21)
**Target:** `VERSA f501.bin` (1 MiB SH7058, MD5 `46991697c502052752a2cabcb84c9e27`) + `EL19A_Complete_Disassembly_ANNOTATED_V3_NEXT6_16_ALL_PENDING_ANNOTATIONS(1).lst` (MD5 `99635224d16ab7705445e27bf233e549`)
**Depends on:** WO65086 (found the 1000/800 pair at `06519C` and `0686E2` and left "what the pair parameterises" open), WO65084 (`0x8405` inventory).

## Objective

WO65086 established that `0x8405` bit 0 selects `0x3E8` (1000) or `0x320` (800) in two unrelated routines, and that a runtime bit can force 800. This WO follows those two values to their use: what they bound and what the bounded value is then converted into.

## Scope and stop condition

- Method: the two already-identified selection sites (`06519C` in `sub_65174`, `0686E2` in `sub_685A6`), forward to the first use of the selected register (`r13`) and through the arithmetic immediately following it. Division semantics of `sub_21BE4` verified from its own body.
- Stop at: the first stored results. No trace of those cells' readers, no physical identity, no unit.
- Concurrency: does not reopen WO65085 (bit 7, active), WO65084's other bits, WO65086's twelve-site classification, or any closed census.

## 1. Both routines cap a value at the selected constant

`sub_65174`, `0x65216`–`0x6521E`:

```
065216 extu.w r13,r13          ; r13 = 1000 or 800
065218 extu.w r5,r2            ; r2 = computed value
06521A cmp/gt  r2,r13          ; T iff r13 > r2
06521C bt      loc_65220
06521E mov     r13,r2          ; r2 = min(value, r13)
```

`sub_685A6`, `0x6879C`–`0x687A4`:

```
06879C extu.w r5,r5            ; r5 = computed value
06879E extu.w r13,r2           ; r2 = 1000 or 800
0687A0 cmp/gt  r2,r5           ; T iff r5 > r13
0687A2 bt      loc_687A6
0687A4 mov     r5,r2           ; r2 = min(value, r13)
```

Both are the same operation with the operands swapped: **`min(value, 1000 | 800)`** — a ceiling selected by `0x8405` bit 0. Neither is a floor: in both, the path that skips the move leaves the constant as the result, which is the ceiling branch.

The capped value is stored twice:

| Routine | Value store | Result store |
|---|---|---|
| `sub_65174` | `065226 mov.w r0,@(h'18,r13)` → `FFFF9916+0x18` | conversion at `065228`–`065230`; the quotient's own store is outside the bounded window |
| `sub_685A6` | `0687AC mov.w r2,@(r0,r5)` with `r0 = 0xB4` → `FFFF9916+0xB4` | `0687B0`–`0687C0` conversion, quotient stored at `FFFF2F00+0x468` |

Both use the same record base `FFFF9916` and the same `FFFF2F00` staging area, at different offsets — a shared shape, not a shared cell.

## 2. The capped value is then converted by `×727 ÷ 800`

Both routines, immediately after the cap:

```
0687B0 / 065228   mov  #h'2D7,r0      ; 727
                  mul.l r2,r0         ; macl = value * 727
                  add  #h'49,r0       ; r0 = 727 + 73 = 800
                  jsr  @r14           ; sub_21BE4
                  sts  macl,r1        ; delay slot: dividend = value * 727
```

So the call is `sub_21BE4(divisor = 800, dividend = value × 727)`, and `sub_21BE4` is a **division**: `0x21BE4` starts `tst r0,r0` / `extu.w r0,r2` / `div0u` / `shll8 r0` / `div1` ×8 / `rotcl r1` / `rts` with `extu.b r1,r0`, and its long branch uses a full `div1` chain on the high half. It returns the quotient.

Result: **`out = (min(value, 1000 | 800) × 727) ÷ 800`**. With the low setting the maximum output is `727`; with the high setting `(1000 × 727) ÷ 800 = 908` (integer). The divisor `800` is numerically identical to the low ceiling constant `0x320`; that identity is an arithmetic fact of the encoding and nothing more is claimed from it.

## 3. The value being capped

Both routines build it identically first (`0x686F0`–`0x68708`, `0x651A8`–`0x651C6`):

```
value = word[FFFF2F00+0x466]  (sub_685A6)  /  word[FFFF9858]  (sub_65174)
value = value - word[0x942E]  (ROM = 8)
value = value + (-6)          ; i.e. subtract 14 total
clamp to >= 0                 ; cmp/pz + mov #0
```

So the bounded quantity is **a runtime word minus 14**, and the calibration bit sets its ceiling before a `727/800` scaling. Both routines also substitute `word[0x8380]` (= `0xB6`, 182) or the immediate `0x71A` (1818) for a second stage when `FFFF1E44+3` bit 3 is set — a separate mechanism, recorded here only as context.

## Findings

1. `0x8405` bit 0 selects the **ceiling** (`min`) applied to a runtime value, not a floor, offset, or gain: 1000 when set, 800 when clear (with a runtime override forcing 800 in both routines).
2. The capped value is converted in both routines by the identical `×727` then `÷800` sequence through the division helper `sub_21BE4`. Two independent callers sharing an exact constant pair and an exact conversion is the strongest indication so far that these two code paths handle the same kind of quantity.
3. Maximum converted output is `908` (bit 0 set) or `727` (clear) — values that a calibration edit of this single bit can move, on a quantity that is itself a runtime word minus 14.
4. `FFFF9916+0x18` / `+0xB4` and the `FFFF2F00+0x466..0x46C` group are the observable results of the path; no consumer of either was traced.

## Bounded negatives

- `0x3E8`/`0x320` are selected at exactly two sites, both covered here; no third `0x8405`-gated pair exists in the listing.
- No other routine in the listing uses the `×0x2D7, +0x49, sub_21BE4` sequence with a `0x8405`-derived value (the helper has many other callers with different operands).
- Neither capped value is compared against another ROM constant after the cap.
- No unit, physical quantity, or calibration name is assigned; "ceiling" describes only the `cmp/gt` + conditional move.

## Unresolved

1. What the runtime word at `FFFF2F00+0x466` (and `FFFF9858`) counts — the writer of either cell is the decisive next datum.
2. What the `×727 ÷ 800` result represents, and why the divisor equals the low ceiling constant.
3. Whether `FFFF9916+0x18`/`+0xB4` and `FFFF2F00+0x468` are later combined.
4. The `FFFF1E44+3` bit-3 alternate stage (`0x8380` byte or `0x71A`) was not worked.
