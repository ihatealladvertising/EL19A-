## Checkpoint 1 — target axis binding and query-path reconstruction (2026-11-16)

### Correction: axis order and helper binding

The target axis mapping is:
- **DFF2 = RPM-axis candidate**: bytes `08 10 18 28 38 50 68 80), exact raw breakpoint match to Juke `mITANDNE`.
- **DFFA = QH-axis candidate**: bytes `00 20 40 60 80 A0 C0 E0`, exact raw breakpoint match to Juke `mITANDQH`.

At caller `0x37BF8`, the arguments are R5=DFF2, R6=DFFA, R7=UWORD[`FFFF85DA`], stack byte=`FFFF8534+0x46 = FFFF857A`. `sub_22C38` sends R5/DFF2 to `sub_2344C` (UBYTE breakpoints scaled ×4 before comparison) and R6/DFFA to `sub_233CC` (raw UBYTE breakpoints). Therefore:
- DFF2 query is UWORD `FFFF85DA`, compared against four-times the UBYTE breakpoints.
- DFFA query is UBYTE `FFFF857A`, compared directly against the raw breakpoints.
- `loc_231F8` reads the four adjacent UBYTE cells and performs the 8×8 bilinear interpolation using the two axis fractions; `sub_231C8` truncates integer interpolation terms.

This corrects the earlier candidate-note ambiguity about which query belongs to which axis.

### Query 1 — DFF2 / RPM-axis candidate

- `sub_3470C` loads UWORD `FFFF8596`, shifts right three and stores an intermediate UWORD at `FFFF85CE`.
- Its call to `sub_34680` applies another right shift by three, caps at UBYTE `0xFF), and writes UWORD `FFFF85DA` in the JSR delay slot at PC `0x3477A).
- Exact result: `FFFF85DA = min(U16[FFFF8596] >> 6, 255)`.
- Upstream WO64827 provenance: `sub_257AC` forms a timer-capture interval; `sub_34476` computes `48,000,000 / FFFF85E4`, saturates to UWORD `FFFF8596), and gates validity with `FFFF99E9.bit3`.
- This is a timer-rate-derived query. It is **not proven to be RPM**. The donor axis would be compatible only under an additional target conversion equivalent to 12.5 RPM per query unit; no target instruction establishes that relation.

### Query 2 — DFFA / QH-axis candidate

- `sub_3723C` sets GBR=`FFFF8534` and computes a bounded UWORD input from `U16[FFFF1860]`, `U16[FFFF8546]`, and `U16[FFFF1054+0x68]`.
- The first product is shifted right nine and saturated to UWORD; the second product is shifted right eleven and added with UWORD saturation.
- For total `< 0x3C00`, the lookup query is total×4 into table `0x10AA4). For total `>= 0x3C00`, the query is total−`0x3C00` into table `0x10A84).
- The UWORD lookup is performed by `sub_22E7C`; its return is shifted right eight and stored as UBYTE `FFFF857A` at PC `0x372B2). The routine also stores the new-minus-previous query delta at `FFFF8548).
- This proves the target query producer and bounded input expression. A normalized/fraction-like role is plausible from the UBYTE output and matching raw breakpoint grid, but the physical meaning and the Juke 1/256 display unit remain unproven.

### Selector provenance

- PC `0x37BE0–0x37BEA` tests `FFFF85FB.bit7): SET selects A382; CLEAR selects A342.
- The annotated LST contains direct reads of `FFFF85FB` at PCs `0x20B9C`, `0x20FA0`, and `0x37BE4); the first two paths copy its byte to adjacent state bytes. No direct writer to `FFFF85FB` was located in the bounded literal-reference pass.
- The selector's writer/provenance and any acceleration-vs-slowdown interpretation remain **UNRESOLVED**. Do not assign A342/A382 to mMITANDA/mMITANDD.

### Map result and immediate target arithmetic

- With GBR=`FFFF1850`, `sub_22C38` returns the selected map's UBYTE interpolant; it is stored at `FFFF1852` (PC `0x37C00`).
- When the `FFFF1E40.bit5` gate permits, the result is also stored at `FFFF185A` (PC `0x37C0C`).
- The map result is then multiplied by ROM UBYTE `0x8F68), UWORD query `FFFF85DA`, and constant `0x37`; the 32-bit product is shifted right 16 and capped at `0x7FFF). The resulting UWORD is stored at `FFFF189C` and `FFFF18C4` (GBR+0x4C/+0x74) at PCs `0x37C3A/0x37C3E`.
- This is a composite runtime calculation, **not** an executed raw×0.78125% standalone map conversion. The bounded consumer check did not establish a physical output; avoid conflating same GBR offsets in unrelated routines with these addresses.
