**Owner:** Worker 3

## Objective
Use the existing HCAN1/HCAN2 MMIO census and available Sentra wiring references to trace only the most useful CAN receive/transmit mailboxes into RAM fields and selected consumers. Do not attempt a complete map of all 72 registers.

## Falsifiable hypothesis
- **Hypothesis:** at least one bounded HCAN mailbox path can be tied to a specific external vehicle signal (especially TCM torque-reduction request, transmission state/gear, vehicle speed or A/C load) through ID/mask, payload extraction, RAM destination and consumer evidence.
- **Evidence:** exact MMIO initialization/read/write PCs, CAN ID/mask configuration, buffer layout, payload extraction arithmetic, RAM writes and consumer PCs; wiring documents only as independent corroboration.
- **Prediction:** one selected message can be followed from mailbox configuration/receive handling to unpacked RAM fields and a meaningful control consumer.
- **Cheap discriminator:** identify active receive mailboxes and select no more than two candidate messages with clear ID/mask and RAM write paths; follow those only.
- **Result:** unresolved until traced.
- **Information gain:** supplies input identity for control paths and may connect TCM/vehicle requests to the QDSPT and torque-reduction investigations.
- **Identity layer:** input identity; function identity only if consumer logic is traced.

## Inputs
- `INDEX/sh7058_mmio_census.tsv` (41 HCAN2/31 HCAN1 register entries reported; verify census definitions).
- Existing wiring references reported in EVIDENCE: `2007-2012_sentra.pdf`, `2004-06-Sentra-CAN-re-wire.pdf` (verify exact paths).
- WO65258 / MB28 CAN evidence and existing CAN initialization/dispatcher code in pinned LST.

## Exact scope
1. Reuse the census; do not repeat MMIO inventory or map every register.
2. Inspect CAN controller initialization and active RX/TX mailbox configuration only far enough to establish IDs, masks, direction and buffer pointers.
3. Select at most two message paths, prioritizing TCM torque-reduction/gear state, vehicle speed or A/C/electrical load where the ROM evidence supports them.
4. Trace payload bytes/bits to RAM fields, width, signedness, scaling and first meaningful consumer. Distinguish received signal from locally derived state.
5. Use wiring PDFs only to corroborate physical network/ECU connections; do not infer message meaning from wiring labels alone.
6. Stop at unresolved scheduler/driver/hardware boundary; no protocol-wide sweep.

## Reuse / no-repeat
- Reuse WO65258 MB28 result; do not repeat its trace.
- Do not repeat DTC join or WO65556 actuator-output investigation.
- No broad MMIO/peripheral sweep, CAN emulation, live-vehicle testing, ROM/LST/index/workbook/XML/script/tool edits or Library changes.

## Deliverable / stop boundary
For at most two messages, report mailbox/register configuration, CAN IDs/masks, buffer addresses, exact extraction and RAM writes, consumer path, corroboration and confidence. Stop at the first unresolved endpoint or after the first meaningful consumer. Physical signal names require both payload and consumer evidence.
