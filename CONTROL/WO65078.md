## Checkpoint / closeout — B956 caller context (2026-11-21)

### Caller and dispatch context

- The B956 reader is in `sub_969C2` (entry `0x969C2`). Its direct caller is the dispatch sequence at `0x70880–0x70884`: `0x70880` loads `sub_969C2`, `0x70882` calls it, and `0x70884` is the delay-slot `nop`.
- This dispatch sequence is part of `loc_70788`, which saves R13/R14/PR/GBR, sets GBR to `FFFF34C1` at `0x70790–0x70792`, then calls a long sequence of routines. The call order places `sub_969C2` after `sub_968B6` and before `sub_ACA76`.
- This proves membership/order in a software dispatch batch only. No timer, interrupt cadence, period or physical subsystem is assigned.

### B956 lookup argument provenance

- `sub_969C2` establishes its own GBR as `FFFF9C10` at `0x969D6–0x969D8`; this is distinct from caller `loc_70788`'s GBR, which is saved/restored around the call.
- The preceding curve call is separate: `0x969DE` sets R4=`0xFC90`, R5=`0x111EA`; `0x969E0` reads UBYTE `FFFF84B4+6 = FFFF84BA`, zero-extends it and shifts it left 8; `0x969EE` calls `sub_22F54`. Its return is stored at `FFFF2150+0x68C = FFFF27DC` by `0x969F8`. This is not the B956 result.
- B956's call setup is explicit:
  - `0x969FC` loads UWORD from `FFFF8494` into R14.
  - `0x969FE` loads R4=`0x0B956`.
  - `0x96A00` loads R5=`0x10994`.
  - `0x96A02` zero-extends the UWORD in R14 into R7.
  - `0x96A04` loads R6=`0x0FDAC`.
  - `0x96A06–0x96A08` call `sub_22D30`.
- The helper contract confirms that the map is evaluated by `sub_22D30` with explicit axis pointers. Its implementation reads the second query from its caller stack argument at helper PC `0x22D46` and zero-extends it at `0x22D48`. No corresponding pre-call stack-argument store is visible in the bounded `sub_969C2` setup excerpt; the origin/value of this second query is therefore **unresolved at the stack-argument boundary**. No axis orientation or physical unit is inferred solely from pointer order.
- The helper's UWORD result returns in R0. Delay slot `0x96A0A` saves the raw return in a local stack slot; `0x96A0C` copies R0 to R7; `0x96A0E` loads offset `0x68E`; `0x96A10` stores UWORD R7 through R11=`FFFF2150`, yielding `FFFF27DE`. There is no intervening arithmetic or signed conversion between helper return and this store.

### Disposition, confidence and boundaries

- **High confidence:** dispatch caller and order; B956 map and axis pointer arguments; UWORD query source `FFFF8494` → R14 → zero-extended R7; helper return R0 → `FFFF27DE`; distinction from preceding FC90 curve output `FFFF27DC`.

- **Unresolved:** second `sub_22D30` query stack argument source/value; physical identity and units of B956; downstream use of `FFFF9C48`; scheduler cadence and physical execution context.
- **Bounded negative:** no explicit local stack write supplying the helper's second query was identified in the inspected `sub_969C2` pre-call sequence. This is not proof that the argument is constant or absent; incoming caller stack provenance was not expanded.
