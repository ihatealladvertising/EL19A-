## 3. Result — producer

`FFFF1D42` is a **word inside the record block at `FFFF1D12`** (`r14 = FFFF1D12`, `+0x30 = FFFF1D42`).
It is written at exactly two sites, both in `sub_56AAA`, both `mov.w r6, @(0x30,r14)`:

```
00056D04  DE 48        mov.l   off_56E28, r14 ; h'FFFF1D12
00056D06  66 03        mov     r0, r6
00056D08  E0 30        mov     #h'30, r0
00056D0A  A0 0F        bra     loc_56D2C
00056D0C  0E 65        mov.w   r6, @(r0,r14)     ; FFFF1D42 ← curve result
```

* **Path A (data present):** `r6` = return value of `sub_21BE4` (jsr at `0x56D00`, `r14 = sub_21BE4`),
  itself fed by `mul.l` of the byte at `r4` (`mov.b @r4,r2`, `extu.b`, `mul.l r6,r2` with `r6 = 0x186A`)
  and a second `mul.l r2,r6`. So the stored value is an interpolated curve result indexed by a byte
  input, scaled by `0x186A`.
* **Path B (sentinel):** `r6 = 0xFFFFFFFF` (mov #0xFFFFFFFF), written at `0x56D28` — the
  "no data / invalid row" case, mirroring the `-1` convention seen elsewhere.
