## Checkpoint 1 — target query producer and fixed-point correction (2026-11-16)

### Query source correction / exact producer

The stack values at `SP+0xAC` and `SP+0xB0` are **not two nested pointers**:
- `SP+0xB0` holds the base pointer `FFFF2150`.
- `SP+0xAC` holds a per-entry byte offset `2×R13).

For both curve paths the query is an indexed UWORD in the `FFFF2150` state block.

**E904 / `mTHOSNTP` query:**
- PC `0x87610–0x87638` reads UBYTE `FFFF859C+0x0D = FFFF85A9` and UWORD `FFFF8494`, multiplies them, then applies four arithmetic right shifts.
- Result is capped to UWORD and stored at `FFFF2150+0x5D4+2×R13` (store delay slot at `0x87638`).
- Exact equation for nonnegative operands:
  `q_NTP = min((UBYTE[FFFF85A9] × UWORD[FFFF8494]) >> 4, 0xFFFF)`.

**E914 / `mTHOSRCV` query:**
- PC `0x881C4–0x881F4` independently reads the same UBYTE `FFFF85A9` and UWORD `FFFF8494`, multiplies them and applies four arithmetic right shifts.
- It compares the result against the existing UWORD at `FFFF2150+0x80E+2×R13`; branch conditions determine whether the old query is retained or the new query is stored.
- Thus both paths use the same query-generation operands, but may preserve/update their indexed query state under different branch conditions.

WO64832 / WO64827 source chain: `FFFF85A9 = min(U16[FFFF85CE] >> 4,255)`; `FFFF8596` is timer-capture-derived through the 48,000,000/interval calculation. The UWORD `FFFF8494` is a separate runtime multiplier; its producer/physical unit remains unresolved. Therefore the target query is **timer-rate × FFFF8494 /16**, not a direct RPM value.

### Fixed-point correction

The initial Stage 3 note above describing the downstream arithmetic shift as `>>6` is incorrect and is withdrawn. Both paths call `sub_223FC`, which applies seven arithmetic right shifts: **`>>7`**. The target therefore applies a raw/128-equivalent factor within the composite product:
- E904: `interpolated_E904 × UWORD[FFFF2150+0x28A+2×R13] >> 7`.
- E914: `interpolated_E914 × UWORD[FFFF2150+0x28C+2×R13] >> 7`, followed by signed lower and upper saturation in the observed path.
- Positive operands are truncated by the arithmetic shift; the conditional `+0x7F` bias is only on the negative-product path.

This is meaningful support for the donor data conversion **inside target composite arithmetic**, but it is not a standalone conversion of the curve result.

### Direct behavioural boundaries

- E914's product is clamped to signed 16-bit range, compared against ROM UWORD `0x905C`, and can call `sub_71F74` with a separate event code; it also updates status flags and indexed internal state.
