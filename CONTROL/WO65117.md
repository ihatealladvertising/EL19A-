## 1. Decision question and outcome

Once a GBR or base register is resolved, can the listing's `@(disp,GBR)`, `@(r0,GBR)`, `@(disp,Rn)` and `@(r0,Rn)` operands be converted arithmetically into effective addresses and grouped into a shared by-base dictionary — so future traces stop re-deriving "which fields of this base are touched, where" and stop repeating the `0x55xxx` GBR over-reach error?

**Outcome: yes, within the stated static limits.** One committed generator and two generated TSVs were produced on a disjoint branch. No target list was used and no per-target reader/writer claim was made.

## 3. Implementation

- **Generator:** `EVIDENCE/WO65117_effective_address_dictionary_generator.py`, stdlib-only Python 3, version `WO65117-EADICT-1.2.0`. Run command: `python EVIDENCE/WO65117_effective_address_dictionary_generator.py --listing <extracted V3_NEXT6_16 .lst>`.
- **No `tools/` entry was created** — WO65115 retains the repository's first-tool scope.
- Function extents and GBR provenance are recomputed internally using WO65116 rules (local `ldc` only; short pool annotations resolved from ROM bytes; branch/label invalidation). 1,877 code-start labels; 667 functions with a single fully provable GBR.
- **Displacement expressions** are evaluated as signed sums of atoms, each of which must be a known listing label, decimal, `h'..` or `0x..`. This resolves nested forms such as `@((dword_821C+2 - h'821E),gbr)`. An unknown atom yields an unresolved row, never zero.
- **Index `r0`** is accepted only from a provable immediate/pool source in the same straight-line region; otherwise `index_not_provable`.
- `effective_address = (base + offset) mod 2^32`, with `offset = disp × width-scale` (b=1, w=2, l=4) for displaced forms and `offset = r0` for index forms. Rows are deduplicated and sorted by base, effective address, PC.
- `access` is derived from operand position/mnemonic only (`read`, `write`; `rmw` rule present but no resolved row triggered it). It is a structural observation, not a semantic claim.

## 5. Limitations

- Computed pointers, pointer tables, block-copy and `movca.l` transport are **not modelled**; inherited GBR and unprovable bases are reported as unresolved, never as absence.
- Displacement scaling is applied to raw `h'..` fields as b=1, w=2, l=4 per the SH-2 `@(disp,GBR)` convention. Symbolic label expressions in this listing occur only on byte accesses, so there is no independent symbolic case to cross-validate the `.w`/`.l` scaling; it is recorded as a modeling assumption.
- Effective addresses are arithmetic results from listing provenance. They are **not** proof of a live peripheral, a RAM write, or runtime reachability.
- No `rmw` row occurred; no path-sensitive control-flow analysis, no per-target reader/writer claim, no constant-vs-dereference classification.
- No semantic naming, units, calibration, fuel-cut conclusion, or workbook/XML/catalogue integration.
