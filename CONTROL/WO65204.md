## Decision question

Can normalized SH-2 instruction-byte fingerprints reliably align a bounded CF48D ignition-map reader with candidate EL19A ignition-reader functions, while rejecting common-code and false-positive matches?

## Bounded targets

- CF48D donor ignition map reader anchored at ROM `0x8ED1`.
- EL19A candidate target functions/readers associated with candidate maps `0x9B2E`, `0x9C2E`, and `0x9DAE`.
- Reuse the existing CF48D ROM/LST audit (WO65142), structural table comparison (WO65179), and EL19A reader/callgraph/effective-address indexes. Verify exact input identity from repository evidence before comparing.

## Method

1. Establish each donor and target reader's exact function boundaries and caller context from the pinned LSTs.
2. Normalize SH-2 instruction streams using a documented, conservative rule set: separate opcode/register structure from relocatable literal/displacement fields; do not erase control-flow or memory-access distinctions.
3. Compare multiple windows per function, including control-flow shape and callsite context. Report exact byte matches separately from normalized matches.
4. Use unrelated functions and known same-family routines as negative/positive controls. Quantify match uniqueness and collision rate within the bounded comparison set.
5. Validate each proposed pair manually against decisive instructions, table pointer loads, helper arguments, query construction and first consumer. A byte fingerprint alone is not a semantic match.
6. If the pilot fails to produce a unique, reproducible alignment, stop and recommend against scaling the method.

## Required deliverables

- Input provenance table (ROM/LST identity and hashes where available).
- Normalization specification with examples of preserved and masked fields.
- Candidate function-pair matrix with raw/normalized scores, uniqueness, control-flow agreement and confidence.
- Instruction-anchored evidence for any accepted pair; explicit false positives and unresolved boundaries.
- A go/no-go recommendation for reuse in later donor-to-target work.

## Stop conditions / budget

- Maximum 3 candidate EL19A reader functions plus the single CF48D donor reader.
- Maximum 2 independent comparison windows per candidate after function-boundary confirmation.
- Stop if input provenance is unavailable, boundaries cannot be established, or no unique alignment emerges after the bounded comparison.
- Do not build a general-purpose tool or scan the full ROMs.

## Acceptance criteria

A positive result requires reproducible alignment supported by several instruction windows, compatible control-flow/call structure, and manual confirmation of the actual reader path. No address, symbol, unit or calibration meaning transfers from CF48D to EL19A.
