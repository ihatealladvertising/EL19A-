## Decision question — ANSWERED

The two curves are **one selector-driven mechanism**, not two independent promotions. Exactly one `sub_22E44` call runs per invocation: `UWORD[FFFF84FE] >= 0x00C8` selects `0x10D12`; `< 0x00C8` selects `0x10D1A` via `add #8,r4` in the `jsr` delay slot. Both results are written to the same `UWORD[FFFF1054+0x430] = FFFF1484`.

`sub_6A8C0` and `sub_6A96C` are **sequential, with a gated RAM handoff through `FFFF1D64`**, not merely parallel consumers and not a GBR-inheritance trick. `sub_6A8C0` reads `FFFF1484`, establishes its own `GBR = FFFF1D12`, and writes `FFFF1D64`; the immediately following `sub_6A96C` reads `FFFF1D64` using explicit literal bases and writes `FFFF1578`.

The payload relation is **near-2:1, not exactly 2:1**: `A = 2B` at indices 1 and 3, but `A = 2B+1` at indices 0 and 2. No physical-domain label (gain %, torque, pressure, fuel, airflow, etc.) is supported by this trace.

### 3.2 Query derivation

Inputs at `0x6AA08`/`0x6AA0C`: `UWORD[FFFF156A]` and `UWORD[FFFF156C]` (i.e. `FFFF1054+0x516/+0x518`). Then:

```text

abs_diff = sub_22494(raw_diff)                  @ 0x6AA12
pre_clamped = min(0xFFFF, abs_diff)             @ 0x6AA16-0x6AA20
query = min(0xC000, pre_clamped << 6)           @ 0x6AA22-0x6AA34
```

`0x6AA32` stores `pre_clamped` to `UWORD[FFFF1054+0x122] = FFFF1176` (already-scaled offset). `sub_22494` computes a 32-bit absolute value.

`sub_22E44` contract: `r4` = 8-byte/4×UWORD BE table pointer, `r5` = UWORD query. It uses grid points `0x0000, 0x4000, 0x8000, 0xC000`; `query >= 0xC000` returns `table[3]` via the `rts` delay slot at `0x22E54`. Otherwise `loc_234E4` derives index/fraction and tail-calls `sub_231C8` for truncating interpolation. With `query = pre_clamped << 6`, the underlying breakpoint set is `pre_clamped = 0x000, 0x100, 0x200, 0x300`. Both payloads are descending, so the descending interpolation branch applies.
