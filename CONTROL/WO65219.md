## Investigation findings

### 1. FFFF84EA declaration

Listing line 475145: `FFFF84EA FF UNDEFINED .res.b 1`. FFFF84EA is an undefined 1-byte RAM cell. UWORD[`FFFF84EA`] therefore spans bytes `FFFF84EA`–`FFFF84EB`, both declared `.res.b 1`.

### 2. Verified read of FFFF84EA

At PC `0x703E8`–`0x703EA`:
```
000703E8  mov.w   word_7048E, r6 ; h'FFFF84D4    ; r6 = FFFF84D4
000703EA  mov.w   @(h'16,r6), r0                 ; r0 = UWORD[r6 + 0x16] = UWORD[FFFF84EA]
000703EC  extu.w  r0, r6                         ; r6 = zero-extended value from FFFF84EA
000703EE  jsr     @r2 ; sub_22F54                 ; call with r6 = UWORD[FFFF84EA]
```

The UWORD value at `FFFF84EA` is read and passed as the query argument to `sub_22F54` (map lookup helper), confirming WO65193's finding that `FFFF84EA` is the row-axis query for `0x0C3D6`.

### 5. Conclusion

No direct writer to UWORD `FFFF84EA` was identified after searching the effective address dictionary, RAM xref indexes, unresolved indexes, and manually verifying multiple listing locations where `FFFF84D4` is used as a base register. `FFFF84EA` is an undefined RAM cell (`.res.b 1`) that is read but has no identified static writer.

**Bounded negative:** The producer of `FFFF84EA` cannot be determined from static analysis. It may be:
- Never written after power-on (retains whatever value is in RAM at reset), or
- Written through a computed pointer or dynamic mechanism not resolvable by the static indexes.

This is a genuine unresolved producer boundary per the WO65219 stop boundary: "Stop at the first unresolved producer or hardware/scheduler boundary. A bounded negative is acceptable with method and coverage stated."
