## Objective

Close the remaining cross-domain question: do the two NTC acquisition paths on ADC2 inputs AN27/AN31 contribute to the monitor return flags that dispatch DTC slots P0101/P0102/P0103, or are these independent monitor families?

The work is a bounded input-to-monitor join. It must either establish an exact source-to-argument edge or explicitly eliminate the proposed relationship within the inspected code paths. Do not assign coolant/IAT, MAF or other physical sensor identities from P-code names.

AN31 (`ADC2 channel 0x1F`) uses the same `0xF406` curve and has output fields `FFFF84BC/FFFF84BB`. WO65182 found separate consumer paths but could not assign physical sensor wiring. At dispatcher entry, r4 is the return from `sub_7631A` (slot 134/P0103), r5 is `sub_76448 OR sub_7652C` (slot 133/P0102), and r7 is the return from `sub_76736` (slot 132/P0101). The dispatch polarity and caller chain are closed; the monitor-return producers' relationship to NTC fields remains the gap.

## Scope

1. Trace only the NTC output/normalized fields `FFFF84C1`, `FFFF84BF`, `FFFF84BA`, `FFFF84B8`, `FFFF84BC) and `FFFF84BB` into the existing monitor functions `sub_7631A`, `sub_76448`, `sub_7652C` and `sub_76736`.
2. Determine whether any of those monitor functions reads the NTC fields directly, through a verified block copy/mirror, or through an indexed/GBR-relative alias. Reconstruct only the necessary caller/producer edge and keep byte/word width, signedness, clamp and guard conditions explicit.
3. For every accepted edge, connect the value or derived flag to the appropriate return register and DTC slot:
   - `sub_76736` return → r7 → P0101 slot 132;
   - `sub_76448 OR sub_7652C` → r5 → P0102 slot 133;
   - `sub_7631A` return → r4 → P0103 slot 134.
4. If no NTC value reaches these monitors, identify the actual inputs and first meaningful condition feeding the relevant return flags, then record the exact stop boundary. Do not broaden into all other DTC slots or all NTC consumers.
5. **Targeted constant fingerprint:** record the nontrivial monitor thresholds actually used in these paths (including the known `0x20`, `0x914E`, `0x9356` values where they occur) and compare their dataflow position with the NTC accepted range/normalization from WO65182. The objective is to distinguish a true NTC-derived threshold from an unrelated monitor gate—not to infer engineering units from literal values.
6. **Call-graph motif:** summarize the verified chain from monitor producer through `sub_761C8` and `sub_762C6` to the DTC writer, distinguishing the monitor calculation from the generic DTC helper/slot-array sink.
