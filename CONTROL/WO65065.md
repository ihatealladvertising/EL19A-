## Checkpoint 1 — direct writer and source-field provenance (2026-11-20)

### Confirmed writer

- The only two exact code paths found for the A70/A72 writes are in `sub_8CF66`, called by `sub_8B98C` at `0x8BF96`.
- `sub_8CF66` establishes GBR=`FFFF95BC` at `0x8CF74`. Its local pointer `var_6C` is assigned `0xFFFF937C` at `0x8D0A8` or `0x8D0C4`; thus the source UWORD pair is `FFFF937C` and `FFFF937E` (not the destination pair).
- Destination base is literal `FFFF2150` (`off_8D2A8`). Offset constants are `0xA70` (`word_8D25A/29E`) and `0xA72` (`word_8D25C/29C`).

### A70 update

- Input UWORD: `[FFFF937C]` at `0x8D202` (via pointer in `var_6C`). It is zero-extended and compared unsigned against `0xFFFE` at `0x8D204–0x8D206`.
- If input is `0xFFFF`, `0x8D216` writes `0xFFFF` to `FFFF2150+0xA70` (saturating sentinel). Otherwise `0x8D21A` increments by one and delay-slot store `0x8D228` writes the incremented UWORD.
- If the preceding descriptor/status gate takes `loc_8D220`, `0x8D222` sets R6=0 and `0x8D228` writes zero instead.

### A72 update

- Input UWORD: `[FFFF937E]` at `0x8D244` (via pointer in `var_6C`, offset +2), zero-extended and compared unsigned against `0xFFFE` at `0x8D246–0x8D248`.
- If input is `0xFFFF`, `0x8D258` writes `0xFFFF` to `FFFF2150+0xA72`; otherwise `0x8D250` increments and delay-slot store `0x8D258` writes the incremented UWORD.
- If the preceding descriptor/status gate takes `loc_8D25E`, `0x8D260` sets R6=0 and `0x8D264` writes zero.

### Conditions and downstream use

- A70 increment-vs-zero decision is controlled by the two descriptor bytes `[R1+4]` and `[R1+6]`: the code tests both at `0x8D1F0–0x8D1FA`; a zero test routes to `loc_8D220`, while the path through `loc_8D1FC` increments/saturates.
- A72 uses the adjacent descriptor-byte pair `[R1+5]` and `[R1+7]` (`0x8D232–0x8D23C`) plus the preceding `@(4,R6)` nonzero gate (`0x8D22C–0x8D230`). The false/reset path writes zero at `0x8D264`; the update path increments/saturates.
- The function subsequently reads both destination UWORDs back at `0x8D4C6` and `0x8D4D0`, then copies them to a separate output record at `0x8D4CC` and `0x8D4D4`. These are readbacks, not additional destination writers.
- WO65064's reader at `0x8D26C/0x8D27C` compares both destination words unsigned against ROM UWORD `0x97B2=100`; this matches the pair updated here.
