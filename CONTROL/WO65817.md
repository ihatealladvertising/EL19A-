## Question

Do the donor-derived names attached to EL19A scalar candidates survive independent target-side reader and consumer tracing?

## Falsifiable hypothesis

mDSHCUT at 0x8550 is a strong independent donor-address match and existing target evidence candidate; mDDSHPTD/N at 0x848A/0x848B may be related QDSPT rate parameters; mDDPAPO is not established because donor mappings disagree (0x9258 vs 0x9290) and neither equals the current 0x924E candidate.

**Prediction:** A donor-derived scalar name is accepted only when the mapping is reproducible and the EL19A target-side reader/consumer supports the proposed identity. Donor name/address agreement alone is not functional or physical calibration proof.

**Result: SUPPORTED** — donor name/address agreement exists for 0x8550, but functional identity remains partial; 0x848A/0x848B and 0x924E lack sufficient target-side evidence for donor-name acceptance.

## Candidate classification

### 1. 0x8550 — mDSHCUT (donor dashpot cut threshold)

| Dimension | Finding |
|---|---|
| **Storage** | UBYTE at ROM 0x8550, raw value 0x0A (10) |
| **Reader** | `sub_403D8` @ `0x4043A` loads ROM byte 0x8550 (zero-extended) into R5 |
| **Query** | `r5 = (FFFF1DB4.bit5 ? UBYTE[FFFF84BA] : UBYTE[FFFF84BA] + 3)` — hysteresis-adjusted threshold compare |
| **Arithmetic** | `cmp/hs r2,r5` (unsigned R5 ≥ R2); if true → `or #0x20,r0` (set bit 5); if false → `and #0xDF,r0` (clear bit 5); stored to `FFFF1DB4` @ `0x4044A` |
| **Consumer** | `FFFF1DB4.bit5` gates the dashpot target path into `UWORD[FFFF1018]` @ `0x40548–0x4054E` (passes `UWORD[FFFF1054+0x39C]` when SET, 0 when CLEAR) |
| **Endpoint** | Internal UWORD `FFFF1018` — no named torque/throttle/actuator command |
| **Donor match** | A2L donor address match exists (mDSHCUT at donor 0x8550); target ROM byte 0x0A matches donor raw |
| **Structural confidence** | MEDIUM — threshold comparison with hysteresis is consistent with a dashpot cut/enable, but the physical meaning of `FFFF1DB4.bit5` is unproven |
| **Functional confidence** | LOW — no named dashpot command or actuator endpoint; bit 5 is an internal state flag |
| **Output/physical confidence** | UNRESOLVED — no physical unit, no actuator path, no vehicle-test evidence |

**Verdict:** GENERIC CANDIDATE (upgraded from "unresolved" to "partial structural support"). The donor name mDSHCUT has reproducible address/value correspondence, but the target-side reader/consumer does not support the proposed physical identity beyond an internal hysteresis threshold. The bit-5 state flag is consistent with a dashpot cut/enable but is not proven to be one.

**Verdict:** GENERIC CANDIDATE (donor name not supported). The donor-derived D/N labels are not established by target-side evidence. Both bytes are identical (0x43), and no target-side reader distinguishes them. The QDSPT-family context is partial but does not support the specific donor names.

### 3. 0x924E/0x9258/0x9290 — mDDPAPO (disputed donor mapping)

| Dimension | Finding |
|---|---|
| **Storage** | UWORD at ROM 0x924E = 0x00FF (binary byte factor: 0 or 255) |
| **Reader** | `sub_403D8` uses 0x924E as a binary enable factor in the QDSPT calculation (0 → disabled, 0xFF → enabled) |
| **Query** | Not a query axis; it is a constant enable factor applied to the table result |
| **Arithmetic** | `table_result × (0x924E ? 0xFF : 0)` → UWORD `FFFF1054+0x39C` |
| **Consumer** | Internal UWORD `FFFF1018` — no named endpoint |
| **Donor match** | DISPUTED — donor mappings disagree: 0x9258 vs 0x9290, neither equals the current 0x924E candidate. The donor locations are hypotheses only |
| **Structural confidence** | LOW — 0x924E is a binary enable factor, not a calibration curve; its donor-name assignment is unsupported |
| **Functional confidence** | LOW — no named endpoint |
| **Output/physical confidence** | UNRESOLVED |

**Verdict:** REJECTED for donor-name acceptance. The donor mappings (0x9258 vs 0x9290) do not agree with each other or with the 0x924E candidate. The target-side evidence shows 0x924E is a binary enable factor in a QDSPT calculation, not a PAPO (pressure/air pump output) calibration. No donor name should be attached.
