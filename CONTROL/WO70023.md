## Outcome summary

The existing `tools/sh7058_cross_rom_scanner.py` machine export is already a near-complete per-call evidence record and is the correct canonical source for the per-address calibration-candidate catalogue. The integration contract is therefore a **thin adapter over the existing scan document**, not a second scanner.

`CONTROL/SH705X_SCANNER_INTEGRATION_MATRIX.tsv` records **96 rows across 13 required columns**: 2 `constant`, 12 `direct_observation`, 3 `metadata`, 16 `heuristic`, 36 `derived`, 17 `rule` and 10 `test_case` rows. It covers every exporter record family and meaningful field, the workbench transformations that currently lose evidence, the grouping/identity rules, the trust boundaries, failure/status behaviour and the ten adversarial acceptance fixtures. **Integration recommendation:** make `build_scan_export()`'s JSON the canonical evidence input and add one adapter, `to_per_address_catalogue(scan_document)`, that groups resolved table bases into candidates while retaining every call, span, variant and limitation. Do not reuse the workbench's `summarize_tables()` aggregate as the canonical record; it is a derived view only. `WO70021` remains authoritative for the final entity schema — all concept names here are provisional.

## 3. Per-address grouping and identity rules (recommendation)

1. **Candidate identity key:** `(decoded_rom_sha256, address_space, base_address, processor_profile)`. `address_space` must be explicit (`file_offset` | `rom_ea` | `ram_ea`); this tool emits decoded-image offsets used as ROM EAs, so the adapter must not silently equate file offset with ROM EA.
2. **One candidate per resolved base; all observations nested.** Every call row (resolved and unresolved) is retained in an `observations[]` collection keyed by `call_pc`. A resolved base groups its calls; unresolved calls live in the call log with `base=null` and are never dropped.
3. **Conflict retention.** Width, element type, dimensions and axes are kept as `geometry_variants[]`/`axis_variants[]`. `geometry_conflict=true` when more than one distinct variant exists. The adapter must never pick a "winning" geometry.
4. **Axes are first-class, not tables.** Lift `axis1_variants`/`axis2_variants` into axis objects keyed by `(address, axis_type, count, end_exclusive, sha256)` and link them from each table. A shared axis is one object referenced by many tables.
5. **Overlapping candidates stay separate.** No overlap merging; keep each candidate's explicit `[start, end_exclusive)` span and payload hash.
6. **Determinism.** Sort call PCs, helper addresses/kinds and table bases numerically; sort JSON keys; emit variants in a stable order. Repeated runs over the same input must be byte-identical.
7. **Unresolved/incomplete.** Keep `resolution_status`, `argument_evidence_method` and `argument_evidence_limits` on every derived candidate so the method limitation propagates.
8. **Source/profile context.** Attach `input`, `tool`, `layout` and the ROM hash to every candidate; never merge candidates across different `decoded_rom_sha256` or profiles.

## 4. Non-lossy transformation and the adapter boundary

The smallest safe adapter consumes the existing scan document and emits provisional catalogue sections. It must **not** re-implement discovery or call extraction.

```
to_per_address_catalogue(scan_document) -> {
  manifest:   {schema, input, tool, layout, summary, xml_comparison},
  helpers:    helper_catalogue[],          # from scan["helpers"]
  candidates: table_candidate[],           # one per scan["tables"] entry
  observations: call_observation[],        # every scan["calls"] row, resolved or not
  axes:       axis_object[],               # lifted from axis variants
  leads:      cross_rom_lead[],            # from cross_rom_comparisons
}
```

Mapping matrix (full detail in `CONTROL/SH705X_SCANNER_INTEGRATION_MATRIX.tsv`):

| Source (scanner) | Provisional concept | Rule |
|---|---|---|
| `input`, `tool`, `layout`, `summary` | `scan_manifest` | carry verbatim; keep hashes and method labels |
| `helpers[]` | `helper_catalogue[]` | one per helper address; heuristic class retained |
| `calls[]` | `observations[]` | retain all; link to candidate by `table` when non-null |
| `tables[]` | `candidates[]` | one per base; nest variants and call links |
| `table_span`/`axis*_span` | `candidate_span` | exclusive end; null hash when out of bounds |
| `axis*_variants` | `axes[]` + `axis_links[]` | axis object, never a table base |
| `xml_comparison` | source reconciliation | source-by-source; never one `in_scope` boolean |
| `cross_rom_comparisons` | `leads[]` | typed hypothesis with both source hashes |

**Reuse boundary:** `discover_helpers()`, `extract_calls()`, `build_scan_export()` and `write_machine_exports()` are reused as-is. No second discovery implementation is created. The adapter is pure transformation of the scan document.

## 6. Trust boundaries and failure behaviour

**Direct observations:** call PC/opcode/delay slot, raw r4/r5/r6 window values, instruction words, span payload/hash, source/decoded hashes.

**Derived:** resolved `table`/`axis` candidates, spans/extents, summaries, XML set comparison, cross-ROM counts.

**Heuristic (must stay labelled):** nearest-`0x4F22` caller candidate within 0x800 bytes, 56-byte linear register window, delay-slot-only argument effect, inferred layout bands, helper stub classification/kind/dims/element type, "non-trivial" `>2 distinct bytes`, donor symbol/payload consensus.

**Failure/status rules:** truncated or out-of-region extent → `out_of_bounds`, null hash, candidate retained; missing address/width or zero count → specific span status, no fabricated extent; unknown element width → `unknown_element_width` and no extent (never default to width 1); inconsistent geometry → conflict flag plus all variants; unknown processor/profile → empty helpers plus default layout marked unknown; absent optional index → `unavailable`, never a false-empty truth; malformed container metadata → null container identity while decoded identity is kept; partial scan → all detected calls retained with per-row statuses.

No semantic names, units, conversions, query sources, interpolation or consumer behaviour are invented anywhere in this contract.

## 7. Adversarial synthetic acceptance matrix (specification only)

The matrix defines ten fixtures with explicit expected outcomes (rows `accept.T1`–`accept.T10`): two independent calls to one base (both PCs retained); one shared axis across multiple tables; same base with conflicting geometry/element type (conflict flag + both variants); overlapping non-identical spans (both retained); unresolved base/partial arguments (retained, null base); extent crossing the ROM boundary/truncated image (out-of-bounds, null hash); duplicate call evidence and deterministic ordering (byte-identical repeated runs); donor-only symbol hit (never target proof); file-offset vs ROM-EA mismatch (kept distinct); missing/stale optional index (unavailable state). No test code was written in this WO.

Existing coverage already exercises call extraction, delay-slot tracking, span exclusivity/hashing, unresolved-call retention, geometry conflicts, cross-ROM counting and JSON/TSV emission (`tools/test_sh7058_cross_rom_scanner.py:L42–L198`). The gaps the fixtures add are: shared-axis linkage, overlap separation, byte-level determinism, donor-only non-promotion, address-domain separation and stale-index handling.
