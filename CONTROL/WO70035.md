Build an Excel-compatible, machine-readable table set that makes the Nissan/Infiniti ROM catalogue searchable by vehicle/model year/engine/transmission and exposes exactly what the 431-record detailed DAT scan can and cannot corroborate. Keep Master ROM IDs, updated ROM IDs, ECU IDs, FIDs, source filenames, and binary hashes as separate identifier types.

## Method

- Parsed the first structured catalogue table at its explicit delimiter: `Showing 1 to 2,161 of 2,161 entries`. Required the seven expected columns and 2,161 well-formed rows.
- Expanded every comma-separated `ROMs Updated` value into a row-level ROM-ID crosswalk. Preserved source spelling, source line, master ROM ID, vehicle attributes and original list text.
- Parsed the following ECU/FID inventory separately. Its multiline structure was not flattened into the vehicle catalogue; only the source-line model/year/engine/ECUID/FID fields were normalized.
- Parsed all 431 rows of `dat_detailed_431_results.tsv`. Kept one row per unique detailed direct-DAT payload and preserved source filename, payload SHA-256, ROM size, ROM MD5, CPU, primary Nissan metadata FID, detected tokens, helper/table/call counts, geometry/type summaries and checksum status.
- Reconciled the 39 distinct primary scan FIDs against the 43 parsed ECU/FID records. Exact matches and prefix-only candidates have distinct dispositions. No prefix match was promoted to exact identity.
- Did not infer a vehicle from a part-number filename, incidental FID token, table geometry, or donor-family similarity.

### Mass DAT scan reconciliation

The standalone batch ran 16,584 source files: 11,744 direct .dat/.bin candidates, 1,318 ZIP/PDX archives, 80 7z archives and 3,442 ancillary/unsupported files. It attempted 13,698 unique candidate payloads across 14,666 source references: 11,216 scanned and 2,482 load-rejected. There were 1,399 archive/member reads, 1,395 successful and four failed.

For the direct DAT subset:
- 11,740 source references represented 11,668 unique payloads.
- 9,186 loaded as ROM candidates; 2,482 were rejected.
- 431 unique positive payloads produced detailed helper/call/table findings.
- 8,755 other successfully loaded direct DAT payloads did not produce detailed helper/table records in this run.

Across the 431 detailed snapshots, there are:
- 313 512-KiB images and 118 1-MiB images.
- CPU tags: SH705519N 241; SH705828N 118; SH705520N 72.
- 39 distinct primary FID families.
- 15,131 helper detections; 128,307 table detections; 73,401 marked non-trivial; 157,369 call-site/table associations.

These are **per-snapshot observations**. Repeated table addresses in different revisions are not unique project-wide calibrations. The batch report records 838 distinct helper addresses and 6,599 distinct table addresses across the 431 snapshots. Shape and FID recurrence are useful for grouping variants but do not assign ignition/fuel/knock semantics or physical units.

### FID crosswalk

The separate source ECU/FID inventory yielded 43 data records. Of 39 scan primary FID families:
- One exact FID match: `1CMC7QPD401`, across eight DAT snapshots, matching ECUID `EM62B`, Tiida / HR16DE (source line 2411).
- Two prefix-only candidate families: `1CMC7QPD4` (32 snapshots) as a prefix of `1CMC7QPD401`; and `5CMCE3E61` (two snapshots) as a prefix of `5CMCE3E6` (ECUID EC80A/EC82A, Note/Tiida? / HR16DE).
- 36 scan primary FID families have no match in this 43-row ECU/FID inventory.
- No match was found for target FID `8CMCKRN5` or ROM code `8W83B` in this source inventory.

The one exact match and two prefix candidates do not establish a full vehicle/model mapping for all 431 DATs. The master-ROM code catalogue and ECU/FID inventory remain separate tables.

### 431 / 433 / 434 count reconciliation

- **431** = detailed direct-DAT records in the mass-DAT result TSV.
- **433** = 431 DAT layouts plus EL19A and V6 comparison images.
- **434** = the finalized WO70034 base-table set after adding C12W as a further independent comparison image.
- Juke S19 is a code-twin inherited layout/value overlay and is not counted as another independent layout.

Therefore the mass-DAT run itself has **431 detailed DAT results**, not 433 direct DAT results. The 433/434 counts describe expanded cross-ROM comparison sets.
