## Objective

WO65736's routine-local census of `FFFF859C` references surfaced an unreported comparison at `0x42D78`–`0x42D86`:

```
00042D78  mov.w  word_42DE6, r3 ; h'FFFF859C
00042D7A  mov.l  off_42EDC, r5  ; h'8996
00042D7C  mov.b  @(8,r3), r0
00042D7E  mov.b  @r5, r2
00042D80  cmp/hs r2, r0
00042D82  bf     loc_42D88
```

A **runtime byte counter** at `FFFF859C+0x08` is compared (`cmp/hs`) against a byte stored in the ROM at `0x8996`; if the runtime value is below the ROM byte the flow falls through, otherwise it branches to `0x43044`. That makes `0x8996` a **ROM limit byte gating a runtime path** — a calibration-adjacent constant the current catalogue does not report. Determine its table membership and neighbours.

## Mandatory falsifiable hypothesis

- **Identity layer advanced:** input identity (a ROM byte used as a runtime limit).
- **Hypothesis:** `0x8996` is not a free-standing scalar but a member of an existing multi-byte calibration table already in `discovered_tables_catalog.csv`, so it inherits that table's units/geometry rather than needing a new object.
- **Evidence:** WO65736 §"What the reference-anchored census does show" (the `0x42D78` comparison and its ROM operand); the catalogue's coverage of the `0x84xx–0x90xx` region.
- **Prediction:** if the hypothesis holds, `0x8996` falls inside a catalogued table's address span and its neighbours are consumed by similar limit comparisons; if it is free-standing, the surrounding bytes will be reached by unrelated code or not at all.
- **Cheap discriminator:** look up `0x8996` in `discovered_tables_catalog.csv` (span containment, not exact match), then find at most three other references to the containing table's span and report what kind of access each is.
- **Information gain:** either attaches a runtime gate to a known calibration object — which matters for any definition build — or records a genuinely free-standing ROM constant that must stay unnamed.

## Scope

1. Report the containing catalogued table for `0x8996`: table start, end, size and the row's recorded name/description, or state that no table spans it.
2. Report the bytes `0x8990`–`0x899F` from the ROM image and mark which of them are referenced by code.
3. Decode at most three other readers of the containing span (or of `0x8996` itself): PC, routine, access width, and whether the use is a limit comparison, a table lookup or something else.
4. State the comparison semantics observed at `0x42D78`: which side is the runtime value, which is the ROM byte, and what the branch selects.
5. State whether the byte is a per-table entry (indexed) or a single global limit, with separate confidence.
6. Stop at an indirect dispatcher, a peripheral/CAN read, or after three decoded readers.
