## Objective

Extract a compact, page-cited glossary of Nissan tuning terms, signal names, units, formulas and operating conventions from the repository's existing tuning literature. Use that glossary to generate a short list of **falsifiable, evidence-graded** EL19A calibration hypotheses.

This workstream addresses the gap between verified reader mechanics and physical/domain interpretation. It must not turn a generic Nissan term or donor-side convention into an EL19A calibration name.

## Source documents

Read only the relevant sections of these repository PDFs:
- `UpRev Nissan Tuning Guide.pdf`
- `UpRev Nissan Tuning Guide(1).pdf` — tree metadata shows this is byte-identical to the unnumbered guide; verify locally and treat as one source if confirmed.
- `Nistune MAF Tech Notes.pdf`
- `Knock Listen Device.pdf`

The UpRev copies have the same Git blob SHA (`0936cac077a82fffb491774fe318bd8cef51ad58`) and are expected duplicates. Record the local verification; do not extract the duplicate twice.

## Required method

1. Verify the three source PDFs are readable and record their exact filenames, hashes and page counts. Confirm the two UpRev copies are identical before collapsing them to one source.
2. Use text extraction/search to locate relevant passages. Inspect rendered pages only where tables, charts, equations, diagrams or extraction artifacts require visual confirmation. Record PDF page numbers (and printed page numbers where they differ).
3. Extract only technically relevant vocabulary, prioritizing:
   - MAF transfer/calibration, voltage, frequency, airflow and load terminology;
   - fuel/airflow correction and scaling conventions;
   - ignition timing, knock detection/listening, knock-window or threshold terms;
   - sensor signal conditioning, filtering and units where explicitly described.
4. For each glossary entry, record: term; concise paraphrased definition; units; formula or scaling if stated; signal/input/output context; applicable Nissan/ECU context; source PDF and page; certainty or caveat.
5. Cross-reference those terms only against existing EL19A candidate evidence and prior donor-A2L comparisons where a concrete match exists. Use current reports and candidate addresses as leads; do not launch a broad ROM/A2L census.
6. Create up to five hypotheses in this exact form:
   - **Hypothesis:** the proposed target role/name.
   - **Prediction:** what must be true in the EL19A query, axis, output, unit or consumer path if the hypothesis is correct.
   - **Cheap discriminator:** the smallest static check or bounded existing-evidence comparison that would falsify it.
   - **Result:** supported lead, weakened lead, or unresolved; do not claim a test was run unless it was.
7. Prioritize information gain. A hypothesis that would separate several competing table interpretations is more useful than a broad list of plausible Nissan names.

## Evidence handling

- The PDFs provide external vocabulary/conventions, not EL19A-specific proof.
- Keep source-literature facts, donor A2L labels, EL19A static evidence and speculation in separate columns/sections.
- Cite every glossary entry to a PDF page. Paraphrase; do not reproduce long passages.
- Do not infer that a generic tuning-guide procedure applies to the EL19A ECU or a particular engine calibration unless the source explicitly identifies that context.
- A target table is not semantically verified merely because its geometry or raw range resembles a literature description.

## Stop boundary / exclusions

- This is a bounded literature extraction, not a complete book review. Stop when the relevant sections of the three distinct PDFs have been covered and the glossary/hypothesis list is complete.
- Do not open or analyze other PDFs unless a cited source explicitly points to one and the additional document is indispensable; record that dependency instead.
- No web research, vehicle tests, Mode 06 access attempts, live tuning, full firmware simulation or broad donor-ROM/A2L search.
- No PDF modification, repository index/catalogue/script/tool/workbook/XML/A2L/ROM/LST/Library edits.
- Only authorized repository output: `CONTROL/WO65240.md`; Worker 2 may update only its own lifecycle/queue entries in `CONTROL/active_work_orders.md` at closeout.

Deliver a concise glossary with exact page references, a target cross-reference matrix where evidence exists, and no more than five falsifiable hypotheses ranked by information gain. A negative or no-match result is acceptable. Close when the source coverage and limitations are explicit; semantic promotion is not an acceptance criterion.
