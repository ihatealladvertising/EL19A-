## Question

Are `0x848A` and `0x848B` consumed by the same QDSPT calculation or by different paths (Drive vs Neutral)? This is the second cheapest follow-up discriminator from WO65817.

## Falsifiable hypotheses

1. Both bytes are consumed by the same QDSPT calculation, making the D/N distinction unsupported. **Result: REJECTED** — they are not the same kind of object.
2. They are consumed by different paths (Drive vs Neutral), supporting the donor D/N labels. **Result: REJECTED** — 0x848B is a ROM constant, not a RAM cell.

**Prediction:** neither hypothesis holds; the donor mapping conflates a RAM cell with a ROM constant. **Result: CONFIRMED.**

## Trace result

### 0x848A = FFFF848A (RAM cell)

- Accessed via `mov.w word_XXXX, rX ; h'FFFF848A` in at least 4 routines:
  - `0x020E16` (sub_20E00+)
  - `0x03615A` (sub_36140+)
  - `0x036184` (same routine)
  - `0x036AB4` (sub_36A90+)
  - `0x036B06` (same routine)
- All accesses read the RAM byte FFFF848A (raw value 0x43).
- Used in QDSPT-related calculations (WO64834 established the QDSPT context).

### 0x848B = 0x0000848B (ROM constant)

- Accessed via `mov.l off_40614, r6 ; h'848B` at `0x0404D4`.
- At `0x0404DE`: `mov.b @r6, r2` — reads a byte from ROM address 0x0000848B.
- The ROM byte at 0x0000848B has raw value 0x43 (same as 0x848A's RAM value, but this is a coincidence of the ROM image).
- FFFF848B (the RAM cell) exists (`.res.b 1`) but is **never referenced** in code.

### Verdict

The donor mapping `mDDSHPTD @ 0x848A` / `mDDSHPTN @ 0x848B` conflates two different object types:
- `0x848A` = RAM cell FFFF848A (read in QDSPT routines).
- `0x848B` = ROM constant 0x0000848B (read once at 0x0404DE in a different routine).

The D/N distinction is **unsupported** because:
1. The two "candidates" are not both RAM cells.
2. They are not consumed by the same calculation or by different paths in the same routine.
3. The ROM constant 0x848B is used in a completely different code path (0x0404D4) from the RAM cell 0x848A (0x020E16, 0x03615A, etc.).

**Classification: D/N UNSUPPORTED** — 0x848A and 0x848B are different object types (RAM vs ROM). The donor D/N labels cannot be validated.
