# WO65010 — 0x8485 / FFFF36C1 Gate and Initialization Audit

- **Status:** COMPLETE — bounded reader/initialization audit
- **Date:** 2026-11-16
- **Type:** Side research; does not replace or alter the standing calibration-discovery priority or next WO65009.
- **ROM:** EL19A / f501.bin (1 MiB; MD5 46991697c502052752a2cabcb84c9e27)
- **Primary evidence:** `EL19A_Complete_Disassembly_ANNOTATED_V3_NEXT6_15_V32_MASS_UPDATE.lst` (Library file ID `file_000000000140820eb2a84e54b2c3038c`).

## Question
Determine whether ROM byte `0x8485 = 0x0A` is a coolant-temperature threshold, a scalar/configuration gate, an index/mask, or merely adjacent to the `0x848A/0x848B` candidate pair.

## Confirmed findings

### 1. ROM byte and destination
- Listing data at `0x8485`: `0A 1E 32`; the byte under investigation is UBYTE `0x0A`.
- `sub_9FA50` loads the pointer to `0x8485` at `0x9FA78`, reads the byte at `0x9FA7E`, and stores it at `0x9FA84`.
- With R10 = `FFFF363C` and R0 = `0x85`, the destination is `FFFF36C1`.
- A second conditional path in the same routine loads the same pointer at `0x9FB16`, reads at `0x9FB1E`, and stores to the same destination at `0x9FB20`.
- These are byte-copy operations; neither instruction sequence compares the ROM byte with a temperature value.

### 2. Initialization path
- `sub_A7D60` is called by `sub_29D82` at `0x29DB4`; `sub_29D82` is called by `sub_24E42` at `0x29776`.
- Within `sub_A7D60`, pointer `0x8485` is loaded at `0xA7EAA`; the byte is read at `0xA7EAE` and stored to `FFFF36C1` at `0xA7EB2`.
- In this same sequence, `0x8DC1` is read at `0xA7EB4` and stored to a different destination, `FFFF36E4`, at `0xA7EB8`. It is **not** the source for `FFFF36C1`.
- Thus the independent initialization path also copies `0x8485` into `FFFF36C1`.

### 3. Consumer and branch meaning
- In `sub_9FA50`, code loads `FFFF36C1` at `0x9FBF0`, executes `tst r2,r2` at `0x9FBF2`, and branches to `loc_9FC44` at `0x9FBF4` when the byte is nonzero.
- Given the ROM value `0x0A`, the tested value is nonzero when this copied value is present. This is a zero/nonzero gate, not a numeric comparison against coolant temperature.
- `sub_9FA50` is called at `0x9D790`. The bounded evidence establishes the local gate and its input, not the larger diagnostic/state-machine meaning of the branch.

### 4. Relationship to 0x848A/0x848B
- `0x8485` is not demonstrated to share a function with `0x848A/0x848B` merely because of proximity.
- WO64831 already tracks `0x848A/0x848B` as a paired UBYTE scalar candidate with labels/scaling unproven. Keep that pair separate.
- The adjacent bytes `0x8486/0x8487` (`1E 32`) are not shown here to be axes or a temperature sequence.

## Assessment
- **VERIFIED:** UBYTE `0x8485 = 0x0A` is copied into RAM byte `FFFF36C1` by both `sub_9FA50` and `sub_A7D60`; `sub_9FA50` subsequently tests that RAM byte for zero/nonzero.
- **VERIFIED:** the observed consumer is a boolean-style gate; no coolant-temperature operand or threshold comparison appears in the traced sequence.
- **HYPOTHESIS / unresolved:** the broader configuration, diagnostic or status meaning of `FFFF36C1` and the branch to `loc_9FC44` is not established.
- **Rejected for this evidence:** assigning `0x8485` as a coolant threshold, temperature calibration, index, or mask.
- **Separate candidate:** `0x848A/0x848B` remains independent and unproven semantically.

## Stop condition and remaining boundary
The requested two reference paths and their shared RAM destination/consumer were inspected. The local branch condition is resolved; broader diagnostic semantics are not necessary to answer whether these sites implement a coolant threshold. Stop here rather than expanding into the entire `sub_9FA50` state machine.

## Corrections / cautions
- Do not describe the `0x9FA7E` or `0x9FB1E` accesses as direct temperature comparisons.
- Do not confuse the `0x8DC1 → FFFF36E4` copy with the `0x8485 → FFFF36C1` copy in `sub_A7D60`.
- Preserve WO64831's separate `0x848A/0x848B` candidate record and its unresolved labels/scaling.
