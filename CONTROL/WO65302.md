## 7. Additive corrections to closed records (no source report edited)

1. **WO65290 — `0x85B3` value and clamp direction.** The report states `0x85B3=0x00` and describes E708 as clamped "to at least" that byte. Direct ROM read gives `0x85B3=0x01`; instruction trace `0x451FC–0x4520E` yields `min(U8[FFFF84D4+0x56], 0x01)`, an upper cap. The substantive E708 dead-store conclusion is unchanged.
2. **WO65290 — branch-dependent scale.** `FFFF99F0.bit6` selects `0x85AD` (`r12=450`) versus `0x85AE` (`r12=1584`) before both branches converge at `loc_451D8`. The constant-query result still holds because the `0x85B0/0x85B1` clamp pair is common.
3. **WO65287 — address-space labels.** The subtract source at `0x44146` is `FFFF859C+9 = FFFF85A5` (RAM), and the negated clamp at `0x46BDE` is `FFFF85C4+0x1B = FFFF85DF` (RAM). They are not EL19A ROM calibration bytes `0x85A5`/`0x85DF`. ROM `0x85DF` is a separate byte with an unrelated direct read at `0x37F82`.
4. **Donor-address direct transfer.** The required donor VALUE address blocks in EL19A are all `FF` and have no LST data label or code reference. This is a negative result, not an alignment key.
