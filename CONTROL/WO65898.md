## Question

At `0x07EB14`-`0x07EB22` the ladder tests `FFFF355D` bits 4|5, and when both are clear tests `FFFF34B5.bit5` and ORs `0x20` into `r12`. What produces `FFFF34B5.bit5`, and does the `r12` aggregate it feeds reach a named torque/throttle/actuator output?

## Answer 1 — `FFFF34B5` is addressed under three different bases

All three arithmetic identities hold, so all three notations name one byte:

| Base | Displacement | Effective address | Base source |
|---|---|---|---|
| `FFFF34B3` | `0x02` | `FFFF34B5` | `sub_A14F0` family and the `0x07E…` ladder |
| `FFFF34B0` | `0x05` | `FFFF34B5` | the `0x04BFxx`/`0x0A0Exx` families (`off_A1744`-style pools) |
| `FFFF3454` | `0x61` | `FFFF34B5` | the `0x09D3xx`/`0x09E6xx` families |

Own-base resolution over all 19,240 GBR-relative sites finds **39 accesses to this one byte**: 24 bit-5 setters, 1 bit-5 clear, 10 reads, and 4 operations on other bits of the same byte.

## Answer 2 — bit5 producer conditions

`FFFF34B5.bit5` is set by **24 sites**, all `mov #2,r0` … `or.b #h'20,@(r0,gbr)` pairs in the `0x09C00C`–`0x0A5430` band:

`0x09C00C`, `0x09C148` (base `FFFF34B3`) · `0x09D3AE`, `0x09EFF6` (base `FFFF3454`) · `0x0A04BC`, `0x0A04CE`, `0x0A04E4`, `0x0A0560`, `0x0A093C`, `0x0A0C72`, `0x0A16F0`, `0x0A1D7E`, `0x0A20AE`, `0x0A2134`, `0x0A249A`, `0x0A24F6`, `0x0A3038`, `0x0A30F0`, `0x0A32D8`, `0x0A3892`, `0x0A5430` (base `FFFF34B3`) · `0x0A0FF6`, `0x0A1030`, `0x0A146E` (base `FFFF34B0`).

The sampled setters are all "condition detected → publish a status bit" blocks that also write neighbouring status bytes in the same cluster. Representative sites:

- `0x09C006`-`0x09C016`: after a `cmp/ge`, sets bit6 of `FFFF3509` (`@(h'56,gbr)`), **sets bit5 of `FFFF34B5`** at `0x09C00C`, then clears bits at `@(h'5C,gbr)` and `@(h'52,gbr)` and returns. A pure status publication block.
- `0x0A04B2`-`0x0A04BC`: a stack-flag test (`tst #4`) selects the `or.b #h'20` delay slot at `0x0A04BC`; the block continues to test `@(h'66,gbr)` bit2 and sets further bits.
- `0x0A1D74`-`0x0A1D7E`: after `jsr sub_A0690` and clearing bit0 elsewhere, sets bit5 in the `bra` delay slot at `0x0A1D7E`, then falls into the block that copies `UBYTE[FFFF84B4]` into `UBYTE[FFFF371E+0xB9]`.

The single clear is at **`0x09D37C`** (`mov #2,r0` … `and.b #h'DF,@(r0,gbr)`), inside a routine that also clears bits at `@(h'5F,gbr)`, `@(h'5E,gbr)`, zeroes `UBYTE[FFFF2150+0x53D]` and returns at `0x09D38C` — a cluster reset, not a consumer.

Other bits of the same byte: bit6 cleared at `0x04BFB8` and `0x04C070`, set at `0x04C598`; bit4 set at `0x0A4E90`.

So bit5 is a **latched condition flag** raised by many detection paths and cleared only by one cluster-reset routine.

## Answer 3 — the `r12` aggregate sinks to `FFFF3579.bit4`, not to a command

Inside `sub_7E8B2` (`0x07E8B2`-`0x07ED1E`) `r12` is a condition accumulator:

```
0x07EA40  mov #h'10, r12                     seed bit4 (a fixed gate, not a live condition)
0x07EA62  or r0, r12                         bit0   <- UBYTE[FFFF363C+0x4B+idx] == 0
0x07EAC4  or r0, r12                         bit1
0x07EAE8  or r0, r12                         bit2
0x07EB12  or r0, r12                         bit3   <- UBYTE[r5+idx] == 0 path
0x07EB22  or r0, r12                         bit5   <- FFFF34B5.bit5 (this WO)
0x07EBAC  mov r12,r0 / and #h'3F,r0 / cmp/eq #h'3F,r0
0x07EBB0  bf loc_7EBCE                       any missing bit -> bit4 of FFFF3579 cleared
0x07EBB4  ... tst #2 on FFFF3575.bit1        additional gate before publishing
0x07EBBE  or #h'10, r0                       -> set bit4
0x07EBCE  mov r9,r0 / and #h'EF,r0           -> clear bit4
0x07EBD2  mov.b r0,@((byte_FFFF3579 - h'FFFF34B3),gbr)
0x07EBD6  mov.l off_7EC80,r12                r12 reloaded with FFFF2150 - aggregate dead
```

The aggregate is masked to six bits and compared against `0x3F`: `FFFF34B5.bit5` is one of six conjuncts. The result is written as **bit4 of `FFFF3579`** and `r12` is then overwritten, so the aggregate never reaches a call argument, an MMIO register or an actuator store. `FFFF3579.bit4` = "all six qualification conditions met", published for whatever reads that status byte.

## Verdict

`FFFF34B5.bit5` is a latched condition flag produced by 24 detection paths and cleared by one cluster reset; the `r12` aggregate in `sub_7E8B2` consumes it as one of six conjuncts and publishes the conjunction into `FFFF3579.bit4`. No torque, throttle, dashpot or actuator output is reached.

**Classification: INTERNAL STATE FLAG** (latched condition bit), with the aggregate classified as an internal status publication (`FFFF3579.bit4`). No named output.
