## 1. Executive closeout

**Independently validated.** The three sources parse cleanly and are internally consistent in the two properties that matter most for a definition: no two declared objects overlap, and no row's `(ADDR)` name suffix disagrees with its `storageaddress` (75 suffixed rows checked, 0 mismatches). All 19 `3D` tables declare exactly two axes whose point counts equal the table dimensions (0 mismatches). The 179-row catalogue has 179 distinct addresses and 0 internal extent overlaps, so it is a genuinely additive discovery set, not a re-list.

**Corrected / newly exposed.** Three defects are structural rather than technical and are invisible in any single-row review:

1. **57 of 76 merged-definition rows declare no complete extent.** 22 rows are `type="1D"` with neither `sizex`/`sizey` nor any axis, and 35 rows are `type="2D"` that declare only `sizey` plus one axis. Those 35 are single-axis curves mistyped as 2-D surfaces; the 22 are scalars with no declared size at all. In every one of the 35 the single axis's point count equals `sizey` (33 rows ×16 points, 2 rows ×8), so their true extents are 16 B and 8 B respectively.
2. **The ignition fragment declares 6 rows for 3 objects.** `0x9B2E`, `0x9C2E` and `0x9DAE` are each declared twice (once as a timing map, once as a "Knock Window" view of the same bytes/axes). Three of the six rows are aliases.
3. **Exactly one address is claimed by two sources:** `0x0E904` is both a merged-definition row (with a static 0–240 Y axis) and a catalogue row (with a proven `UWORD` axis at `0x0FA62`). Every other catalogue row is genuinely absent from the merged XML.

**Left unresolved.** 41 of 76 definition rows have no citation in any `CONTROL/WO*.md` report, and 154 of 179 catalogue rows have no consumer evidence at all. Those are missing-evidence gaps, not contradictions, and they dominate the backlog.

**Best next project-level move.** Do not trace more tables. First spend one cheap definition pass fixing the 57 extent/type defects and the 3 ignition aliases (WP4 issues I-01/I-02/I-03 below); until those are fixed, any consumer trace that lands on one of those rows cannot be reflected in the definition, so the tracing work already completed cannot be banked.

Read this table carefully, because it is the single most important risk statement in this audit: **the tier label and the row's evidence content do not coincide.** A `Reader-Verified` row means "a helper was identified and the geometry derived" — it does **not** mean the query, the output staging or any consumer is known. 154 rows, 86 % of the catalogue, are in that state. Only 25 rows carry any consumer claim, and 23 carry a destination RAM cell.

Consequences for definition work:

- 154 rows are **not** ready for a definition draft on their own evidence. They have geometry (a `start`, an `extent_hex`, a `dimensions`, a `storage` type and usually an axis pointer) but no evidence that the bytes are consumed at all, so a name for them would be pure inference.
- 75 rows name a ROM axis address in `axis1`, and 34 rows declare both axes. Those are the cheapest rows to promote, since the axis object itself can be audited independently.
- 0 rows are mis-attributed by name: the catalogue never reuses a merged-definition display name for a different address, so the "different display name" duplicate risk the WO warned about does not materialise — except at `0x0E904`, where the *address* matches.

Absence verification: of the 179 catalogue addresses, 178 do not appear in the merged definition and none appear in the ignition fragment; the one that does (`0x0E904`) is dispositioned in WP4.

## 7. Reproducibility

All derived numbers come from one read-only pass over the three pinned files with Python 3 `xml.etree.ElementTree` and `csv`, plus a regex scan of `CONTROL/WO*.md` for `0x%04X` address mentions. No repository index, resolver run, ROM read or listing read was needed, so no tool version applies; the invocation shape is:

```python
ET.parse(X)  # merge XML: top-level <table> rows under <rom>
ET.parse(I)  # ignition fragment
csv.DictReader(open(C))  # catalogue
# extent = sizex*sizey*width(storagetype); width uint8=1, uint16=2
# single-axis rows (no sizex): extent = sizey*width(storagetype), with sizey cross-checked
# against the one declared axis's point count in every row (33 x16, 2 x8, 0 mismatches)
# cited(row) = address appears as 0x%04X in any CONTROL/WO*.md
```

Grades are assigned mechanically from those fields: `VERIFIED` = non-`[S]` row with a declared axis and a citation; `PARTIAL` = reader/geometry evidence but a missing layer; `PROVISIONAL` = declared only, no citation; `DUPLICATE/ALIAS` = second view of an identical address+extent; `CONTRADICTED` = two sources disagree on the same bytes. Row counts reproduce exactly (261 accounted, 258 unique starts).
