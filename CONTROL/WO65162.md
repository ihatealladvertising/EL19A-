## Why this is being offloaded

The project has accumulated three overlapping layers of calibration knowledge: an existing XML definition, a separate ignition/knock fragment, and a large discovery catalogue of reader/helper-verified but not yet integrated tables. The main analysis stream is already occupied with targeted consumer traces and donor crosswalks. An independent worker can add substantial value by auditing these existing claims end-to-end, finding contradictions and omissions, and returning a prioritized evidence-quality report—without repeating ROM-wide discovery or changing engineering artifacts.

This assignment is deliberately an **independent evidence audit**, not a new table hunt and not an XML implementation task.

## Decision question

For every current EL19A definition entry and every row in the discovered-table catalogue, what is actually supported by ROM/listing evidence today, what remains provisional, what is contradictory or duplicated, and which missing evidence gives the next highest return on investigation?

Deliver a complete, row-level audit and an actionable ranked remediation/trace backlog.

## Work packages

### WP1 — Reproducible inventory and identity reconciliation

1. Parse the two XML sources and catalogue using read-only methods.
2. Create a normalized inventory of every row: source file, original name, start address, storage type/shape/axes/conversion fields where declared, XML confidence/status marker, and catalogue row identity.
3. Reconcile duplicate declarations, same-start aliases, overlapping extents, repeated names, and likely axis/data-object relationships. Do not call two entries duplicates solely because they share a start or similar values.
4. For every inferred extent, state whether it is declared, reader-proven, inferred, or unknown. Do not extend a table to 256 bytes simply because a 256-byte probe was previously used.
5. Record exact parse errors, missing files, and ambiguous rows rather than silently dropping them.

### WP2 — Evidence audit of the existing 82 XML rows

Audit all 76 merged-definition entries and all 6 ignition-fragment entries against existing EL19A evidence. For each entry assess:

- **Identity:** is the ROM start correct for this target, with effective address checked rather than copied from a donor?
- **Storage:** element width, byte order, signedness, exact exclusive end address, packing/stride, and dimensions.
- **Axes:** address and exact extent for each axis, width/signedness, point count, order, raw-to-engineering conversion, and producer/query units.
- **Reader:** actual helper and caller; argument mapping; coordinate producer; search/interpolation/clamp behavior; output conversion.
- **Runtime path:** selector/gate and state only where statically established.
- **Consumer:** helper return/result staging and first meaningful downstream reader/consumer.
- **Definition quality:** XML representation matches the established storage/reader mechanics; scaling and units have explicit evidence; correct confidence marker.
- **Evidence citation:** source WO plus exact LST PC(s), and the shortest supporting ROM/listing instruction range or source artifact reference.

Use the existing closed WO reports and index outputs to avoid redoing finished traces. Reopen an individual code path only when the present claim cannot be adjudicated from cited evidence or an actual contradiction is identified. No generic helper-family census.

### WP3 — Evidence audit of all 179 discovery-catalogue rows

For every catalogue row:

1. Confirm its catalogue identity and source metadata.
2. Verify that it is genuinely absent from the merged XML by address/extent/alias reconciliation (not merely a different display name).
3. Record the strongest available level of evidence: raw shape only; storage/extent; helper argument; reader mechanics; caller/query; output staging; first consumer; or complete semantic chain.
4. Identify whether the row is ready for a definition draft, needs one specific missing edge, is a duplicate/alias, or should remain discovery-only.
5. Reuse existing WO reports and index outputs; do not redo the 179-table discovery or run a broad scan. Manually inspect only disputed/high-impact rows.

### WP4 — Contradiction, overlap and risk review

Produce a separate issue register for:

- XML type/dimension/axis/scaling mismatches against code.
- Address/extent collisions, table overlays and aliasing that are not clearly represented.
- Claims marked verified that do not meet the project's current evidence standard.
- Candidate rows that appear in XML under a different name or as a component/axis of another entry.
- Unresolved query producer, conversion, selector, output or consumer edges that affect interpretation.
- Any discrepancy between two work orders or between a work-order result and the current XML/catalogue.
- All donor-derived hypotheses that are not independently supported by EL19A evidence.

For each issue give severity, affected row(s), exact source, consequence, confidence and the smallest next discriminating action. Distinguish a true contradiction from missing evidence.

### WP5 — Prioritized next-analysis backlog

Return a ranked list of up to 25 next investigations. Score each by:
- definition impact (whether it can turn a provisional item into a well-supported definition or correct an existing one),
- evidence readiness (how close the chain is to closure),
- reuse/force-multiplier value (whether one trace resolves multiple rows),
- effort and dependency cost.

For each recommendation state the exact target/edge, what is already known, what remains unknown, which existing WO/index must be reused, what not to repeat, and a crisp stopping boundary. Do not create or claim new work orders.
