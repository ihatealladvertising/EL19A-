## Objective

Reconcile the already-published EL19A target workbench catalogue and the 151-ROM donor index into a deterministic structural-readiness matrix. The required decision is whether each target object has a sufficiently supported **location, storage representation, exact extent and geometry** to be included as RAW/PROVISIONAL or retained as an established definition object.

**Do not make full EL19A reader mechanics, query reconstruction, interpolation/clamp tracing or downstream consumer tracing a prerequisite. Do not repeat those traces.** Reuse previously verified details where they already exist, and keep semantic uncertainty separate from structural inclusion.

This is an inventory/reconciliation task, not a global rediscovery scan and not an XML-edit task.

## Permanent threshold to apply

A target candidate is structurally ready for a raw/provisional definition when the target evidence supports:

1. ROM effective address and correct address-space interpretation;
2. element type, width, signedness and byte order;
3. exact byte extent and end address, verified within the target ROM;
4. dimensions/geometry, with duplicate or conflicting interpretations preserved;
5. target-byte payload/range identity sufficient to distinguish the object from an address-only lead; and
6. no unresolved material extent, geometry, overlap or mapping conflict that would make the displayed object misleading.

A helper/call record, candidate base, donor address match or payload match alone is not enough without target extent/geometry validation.

A known physical axis, query source, physical units, conversion, full reader path or downstream consumer is **not required** for RAW/PROVISIONAL inclusion. Use clearly labelled sample-index axes and raw scaling when physical axis/query semantics are unknown. Do not invent physical axis orientation where the storage geometry does not support it; record that boundary and hold only the affected presentation decision.

Keep these confidence dimensions separate: target structural confidence, cross-reference corroboration, runtime/reader evidence, semantic confidence and export eligibility. Cross-ROM evidence may corroborate a target structure but must not inflate target-side structural facts or transfer donor names, units, conversions, axes or meanings.

5. Do not delete or modify any existing XML object in this work order. An XML-only object is not automatically disproved merely because the current scanner export lacks it.

### C. Add donor corroboration as a separate dimension

1. Join the EL19A candidates to the existing 151-ROM index and exact/same-geometry outputs using exact source identities and match keys.
2. Record exact-payload support separately from same-geometry/different-payload support, and preserve unique donor ROM IDs as well as pair counts.
3. Preserve conflicting donor geometries and historical/current scanner-version differences.
4. Do not use donor names, units, conversions, axes, A2L pairings or physical interpretations as EL19A facts. The V6 A2L is provisionally paired and must remain labelled as such.
5. Do not interpret pair totals as independent-table totals or use a donor match to repair a missing target extent.

### D. Apply the raw/provisional disposition

For every target candidate address, assign one explicit structural outcome:

- `READY_RAW_PROVISIONAL` — target type, full extent and geometry are supported; semantic/query/consumer details may remain unknown.
- `READY_ESTABLISHED_INPUTS` — existing target evidence additionally supports the semantic fields actually presented.
- `HOLD_STRUCTURAL_CONFLICT` — address, extent, type, dimensions, orientation or overlap is materially conflicting.
- `XML_ONLY_NOT_TARGET_CONFIRMED` — existing definition object has no corresponding confirmed target candidate in this export; retain for later reconciliation, do not automatically delete.
- `OUT_OF_BOUNDS_OR_INVALID` — target bytes do not support the proposed location/extent.
- `NOT_A_CALIBRATION_OBJECT` — only when existing target evidence already establishes a pointer, code constant, RAM object or other non-calibration structure; do not infer this from absence of a reader trace.

Where a physical axis/query domain is unknown, recommend an index-axis/raw-scaling presentation when technically valid. Keep semantic name, units, conversion, query source, interpolation/clamp, consumer and physical role explicitly unresolved unless supported by existing evidence. Do not create new reader/consumer traces to fill these fields.
