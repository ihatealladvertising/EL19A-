## 3. Method

1. **Target normalization.** Parsed the pinned 291-address TSV, 291-candidate catalogue and 377-call export. Compared their address sets, candidate fields, observation fields and call PCs. Address keys were normalized to uppercase `0x` form without insignificant leading zeroes; original addresses and candidate IDs are preserved in the TSV.
2. **Target-byte validation.** For each declared span/geometry, recomputed byte length, end address, payload SHA-256, distinct-byte count, constant/zero state and in-bounds status from `EVIDENCE/VERSA f501.bin` using the SH7058 effective-address-to-file-offset mapping. Declared and computed values were compared; every observation was retained.
3. **Conflict preservation.** Enumerated exported geometry/axis conflict flags, duplicate geometry declarations, candidate extent overlaps, axis/table dual roles and unresolved call observations. No conflict was silently deduplicated or repaired.
4. **Definition reconciliation.** Built the union of target candidates and current XML, both scope matrices, the discovered-table catalogue and candidate register. Linked only the Findings records already indexed against reconciled addresses; each source's names, dispositions and status text remain separate.
5. **Donor corroboration.** Joined each target address to the preserved exact-payload, same-geometry and provisional crossref exports by exact source identity and match key. Pair counts, unique donor ROM IDs and unique V6 addresses were computed separately.
6. **Disposition.** Applied the six WO70031 outcomes per target address. Missing physical/query/consumer semantics were not used as blockers. Existing XML-only or definition-source-only records were retained as unconfirmed rather than deleted or declared false.

### Byte-order treatment

The pinned per-candidate export does not carry a byte-order field. For 1-byte objects the TSV records `NOT_APPLICABLE_ONE_BYTE`. Of the 104 two-byte candidates, 73 have an explicit source declaration in the reconciled target-address rows (71 with both matrix `big-endian` and catalogue `UWORD BE`, 2 with catalogue `UWORD BE` only); the remaining 31 inherit the target SH7058 profile and the ROM-level definition baseline `Endian=Big`. The TSV records the exact evidence basis per row. This is a target ROM-level storage convention, not donor-derived and not a new reader/consumer trace. No donor A2L association was used to set byte order.
