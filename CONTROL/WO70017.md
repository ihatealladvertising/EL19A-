# WO70017 — Build the V6/Juke/CF48D calibration metadata reference library

**Status:** ASSIGNED — WORKER 1 — READY  
**Priority:** P1 — definition completion  
**Workstream:** DONOR METADATA / CALIBRATION OBJECT CROSS-REFERENCE  
**Owner:** Worker 1  
**Created:** 2026-11-26  
**Branch:** `main`

## Objective

Extract the actual calibration-object metadata from the two available Nissan A2Ls and the CF48D RomRaider XML into a compact, machine-readable reference library that can be joined to EL19A target objects. The purpose is to stop rediscovering Nissan storage, axis and conversion conventions table by table.

## Pinned inputs

- EL19A target candidates: `EVIDENCE/VERSA f501.bin`
- V6 ROM/A2L pair: `EVIDENCE/side project/64810223F121200000.hex` and `EVIDENCE/side project/64811000p2_m.a2l`
- Juke ROM/A2L pair: `EVIDENCE/Nissan Juke 1.6-dig-T S19 (9APCTDEM06)/9APCTDEM06.s19` and `EVIDENCE/RFCC_2XHK19BDF1.a2l`
- CF48D reference pair: `EVIDENCE/CF48D.bin` and `EVIDENCE/CF48D.xml`
- Candidate/target context: `CALIBRATIONS/EL19A_best_guess_provisional_full_definition.xml`, `CALIBRATIONS/EL19A_release1_conservative.xml`, `CALIBRATIONS/discovered_tables_catalog.csv`, `EVIDENCE/EL19A_22_FINGERPRINT_JOIN_2026-11-26.md`, `tools/a2l_structural_matcher.md`, and the relevant current Findings records.

## Required work

1. Parse all relevant A2L `CHARACTERISTIC` and `AXIS_PTS` objects in V6 and Juke, preserving exact identifier, address, object type, record layout, dimensions, axis references, axis conversion, value conversion, limits, units, and referenced `COMPU_METHOD` formulas.
2. Resolve referenced `RECORD_LAYOUT`, `COMPU_METHOD`, `AXIS_DESCR`, `AXIS_PTS_REF`, `FUNCTION`/group membership and any calculation/formula entries needed to interpret each extracted object. Preserve raw formula text as well as a normalized readable summary; do not evaluate a formula unless its syntax and inputs are fully understood.
3. Parse the CF48D XML into the equivalent fields: table name, storage address, dimensions, storage type, axes, axis values/addresses, scaling/conversion, units, and any relevant category/description metadata.
4. Include every donor object that can plausibly join to the current EL19A helper-backed inventory by exact payload, geometry, address-independent structure, or existing fingerprint report. Also include an index of all donor calibration objects so later joins do not require reparsing the A2Ls.
5. Record source artifact paths, byte sizes and SHA-256 hashes; record parser/tool version or exact script hash and any unsupported A2L constructs.

## Output

Create `CONTROL/WO70017_DONOR_METADATA.tsv` plus a concise `CONTROL/WO70017.md` report. The TSV must have one row per donor object and preserve at minimum:

`donor_rom, donor_a2l_or_xml, source_hash, object_name, object_kind, address, storage_type, record_layout, dimensions, byte_extent, axis_1_ref, axis_1_type, axis_1_conversion, axis_1_units, axis_1_limits, axis_2_ref, axis_2_type, axis_2_conversion, axis_2_units, axis_2_limits, value_conversion, value_units, raw_formula, function_group, parse_status, unresolved_fields`.

Use explicit empty/unresolved values; do not silently omit unsupported fields. If one object expands to multiple axis/conversion records, use a documented stable row-key convention or companion TSV.

## Evidence and interpretation rules

- A2L/XML definitions establish donor metadata for their own ROMs, not EL19A semantics.
- A matching name, geometry, address, function group or conversion is a lead, not a target-side proof.
- Do not transfer donor names, units, scaling, axes or formulas into EL19A definitions in this WO.
- Keep source declarations distinct where V6 and Juke disagree; do not normalize away conflicts.
- Reuse existing fingerprint and matcher results; do not rerun broad scans or repeat completed donor investigations.

## Acceptance criteria

- All relevant source objects and their referenced metadata are represented, with a parse-status field.
- A second pass can resolve each extracted row back to exact source declarations.
- The report lists parser coverage, unsupported constructs, conflicts and exact artifact hashes.
- A concise candidate crosswalk identifies donor objects that correspond to known EL19A candidate addresses, but labels each relationship as exact payload, structural match, name-only or unresolved and cites the underlying evidence.
- Findings disposition is stated. Use PROMOTED only if a material EL19A interpretation changes; otherwise NOT REQUIRED.
