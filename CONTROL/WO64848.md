### Confirmed corrections
- At `0x42B86–0x42B8C`, the test is `FFFF1D7F.bit7). If set, control branches to `0x42F58`; if clear, the paired-map path continues. This is a path gate, **not evidence that the bit selects 9C2E versus 9DAE**.
- In the paired path, both calls execute sequentially: `0x42BB2` reads map `0x9C2E`; `0x42BC8` reads `0x9DAE`. Both use X axis `0xE4AC), Y axis `0xE4BC), UBYTE query `FFFF849A), and UWORD query `FFFF859C+0x16 = FFFF85B2). The original inputs are reloaded for call 2; call 2 does not consume call 1's result.
- Each result is ANDed with `0x7F). V55's recorded payload comparison says the two 16×16 UBYTE maps are byte-identical. Given identical axes, reader and inputs, the two masked interpolated results are therefore equal; their signed difference is zero. This rules out a nonzero 9C2E-versus-9DAE differential in the observed paired path.
- At `0x42BF2–0x42BF6`, the zero differential is shifted and added to the UWORD at `FFFF1054+0xA4 = FFFF10F8). That word is stored at `FFFF1000+0x0A = FFFF100A` (`0x42C04`), then sign-sensitive shift/extraction produces the byte stored at `FFFF1C78+1 = FFFF1C79` (`0x42C14`). Under the byte-identical-map condition, this output is the signed high-byte conversion of the base word at `FFFF10F8), not a differential correction.
- The subsequent branch tests `GBR+6.bit5` and `GBR+3.bit7` before proceeding; the store at `0x42C14` is conditional on reaching this path.
