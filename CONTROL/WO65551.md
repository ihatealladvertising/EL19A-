## Objective

Determine whether Claude's ordered dynamic-programming alignment of one-byte A2L VALUE characteristics to EL19A ROM bytes provides reproducible, non-accidental address-map evidence. Establish which individual mappings, if any, survive independently justified anchors and stronger raw-value constraints. Do **not** assume the A2L belongs to EL19A.

## Starting observation — hypothesis, not verified result

Claude reported an experiment over A2L declarations in `0x83EB–0x84C4` and EL19A ROM bytes in `0x848A–0x8550`:

- 142 exposed UBYTE/SBYTE scalar declarations; 137 aligned in one run.
- 86 mappings remained identical across four gap/mismatch penalty settings.
- Reported examples: `mDDSHPTD` → ROM `0x848E`; `mDDSHPTN` → `0x848F`; `mDSHCUT` → `0x8550`.
- The DP allowed skipped A2L entries and skipped ROM bytes; unsupported/nonlinear conversion methods were assigned the unconstrained raw range 0–255.
- A2L declaration order was assumed to be preserved in ROM order.

These counts measure parameter stability only. They are not confirmed matches. In particular, unconstrained 0–255 entries and common byte values (especially zero) can create accidental matches. The reported +4 displacement for `mDDSHPTD/N` relative to the expected EL19A candidates at `0x848A/0x848B` is an explicit discrepancy to resolve.
