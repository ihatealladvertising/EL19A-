## 2. Reproduction of the reported experiment

### 2.1 Declaration count

The A2L address window `0x83EB–0x84C4` contains 145 `REC_UBYTE_C` VALUE declarations in file order. Three are duplicate-address `mf*` flag declarations (`mfDFAPSC1C`, `mfDCATON`, `mfDRPWTSPF`) whose non-flag twins share `0x842C`, `0x8430` and `0x84BA`. Excluding the three flags, or deduplicating by A2L address while preserving first declaration order, yields **142 declarations**, reproducing Claude's first count. No SBYTE declarations occur in this window.

The ROM window `0x848A–0x8550` contains **199 bytes**. Original bytes at the named addresses are `0x848A=0x43`, `0x848B=0x43`, `0x848E=0x01`, `0x848F=0x00`, `0x8550=0x0A`.

### 2.2 Reconstruction and discrepancy

A bounded Needleman–Wunsch-style DP was reconstructed with diagonal match/mismatch, A2L-skip and ROM-skip transitions, using declaration order as the A2L sequence and ascending address as the ROM sequence. Two interval derivations were tested:

1. **Correct conversion inversion** for this generator's simple `RAT_FUNC` rows (`physical = raw × sixth_coefficient + third_coefficient`, e.g. `COMP_0008` `0 1 0 0 0 100` and `COMP_0035` `0 1 50 0 0 1`). This yields 140 invertible declarations and two unsupported nonlinear rows (`COMP_0111`, `COMP_0398_S`, `physical = 256/raw`), which were assigned the unconstrained `0–255` interval as required. 141 of 142 intervals are the full `0–255`; only `mDSHCUT` is `0–155`.
2. **A plausible reconstruction of the original scoring**, in which the A2L physical limits were treated directly as raw-byte bounds. With gap-first tie-breaking this reproduces the reported displacement: `mDDSHPTD → 0x848E`, `mDDSHPTN → 0x848F`. With correct inversion and the same tie-breaking, those first two declarations instead fall at `0x848A/0x848B`. This shows the reported +4 displacement is a scoring/tie-break artifact, not target evidence.

Neither reconstruction reproduces the reported **137 aligned** or **86 stable** mappings. Under the correct-conversion model, all 142 declarations pair with in-interval ROM bytes in every tested match/mismatch/gap combination (27 combinations; 142 pairs in all), and 142 pairs remain identical across four representative penalty settings. The limits-as-raw reconstruction likewise pairs all 142 declarations. The original 137/86 counts therefore depended on scoring details not preserved in the repository; they are **not confirmed** and are not used as evidence here.

## 3. Stricter alignment and chance control

- **Reliable conversions:** 140/142 linear `RAT_FUNC` rows are invertible; `COMP_0111` and `COMP_0398_S` are nonlinear and were excluded from positive scoring.
- **Discriminative content:** after inversion, 141 declarations accept all 256 byte values. `mDSHCUT` accepts 156 of 256 values (`0–155`), contributing only `−log2(156/256) = 0.715` bits. Total information in the declaration block is therefore **0.715 bits**, overwhelmingly below what is needed to identify 142 ordered addresses.
- **Weighted scoring:** weighting match/mismatch by this information value leaves the same 142-pair alignment; the sole constrained declaration does not change the order decision.
- **Permutation control:** 300 shuffles of the 199-byte ROM window produced the identical DP score (85) and pair count (142) as the true order for the representative `match=1, mismatch=-1, gap=-1` setting. The null distribution is degenerate because nearly all intervals are full-range; the observed alignment is indistinguishable from chance.
- **Order-preservation test:** declaration order and A2L-address-sorted order produce indistinguishable scores and pair counts. The assumption that A2L declaration order is preserved in ROM order is **not supported** by this block and was not silently retained.

No general scalar sweep, full-A2L alignment or whole-ROM address-map discovery was performed.
