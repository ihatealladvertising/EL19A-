## Question

Two independent routines read the 3-byte-entry table at `FFFF A074`: `sub_8AD7C` walks all 198 entries testing **bit3** (WO65877), and `sub_228F0` returns **byte 1 bit7** for an arbitrary index (used for entries `0xAD`/`0xAE`/`0xAF` at `0x08053C`-`0x08056C`, mirrored into `FFFF34E7` bits 6/5 by WO65892). Nothing has established where the table comes from. Is `FFFF A074` a ROM copy (and if so from which ROM address), a computed runtime structure, or a mixed buffer — and what are its three fields?

## Why it has value

The table gates the `FFFF34F5` qualification latch through one bit and mirrors three of its entry bits into a shared status byte through another. If it is a ROM configuration block, the definition build must account for it and its 198 entries; if it is runtime-built, then bit3/bit7 are computed conditions and only the inputs matter. Today neither is known, so both readings are live and any downstream use of bits 5/6 is ambiguous.
