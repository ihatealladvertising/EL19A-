## 1. Verified geometry

| Object | Start | End (excl.) | Width | Shape | Source pointer pool entry |
|---|---|---|---|---|---|
| AFR map bank 1 | `0xA08C` | `0xA10C` | UWORD | 8 rows × 8 cols, row stride 16 B | `off_470C0` = `dword_A08C` (`0x470C0`) |
| AFR map bank 2 | `0xA10C` | `0xA18C` | UWORD | 8 rows × 8 cols, row stride 16 B | `off_470D0` = `dword_A08C+h'80` (`0x470D0`) |
| X axis | `0xC7E2` | `0xC7F2` | UWORD | 8 points | `off_470BC` (`0x470BC`) |
| Y axis | `0xC7C2` | `0xC7D2` | UWORD | 8 points | `off_470C4` (`0x470C4`) |
| LTFT axis 1 | `0xBBD8` | region 16 B | UBYTE | 7 comparisons at `+1…+7` | `off_3A46C` (`0x3A46C`) |
| LTFT axis 2 | `0xBC9A` | region 16 B | UBYTE | 7 comparisons at `+1…+7` | `off_3A478` (`0x3A478`) |

Geometry proof for the maps is instruction-derived, not assumed:

- `loc_7588` (reached by tail jump from `sub_7054`, `0x707E–0x7082`) sets `mov #8, r5` in the delay slot, then `mulu r5, r0` with `shll r5` → row stride `8 × 2 = 16` bytes, and reads the four interpolation neighbours `@r4`, `@(2,r4)`, `@r5`, `@(2,r5)` as UWORD (`0x75A4–0x75BA`).
- The two axis pointers are consumed by `sub_76C0` (`0x76C0`), which is entered with `r4 = 0xE` (`sub_7054+0xA` / `+0x16`) and walks `mov.w @(r0,r4)` **downwards by 2 bytes** until `r4 < 0` (`0x76F0–0x76F4`): offsets `14,12,…,0` = exactly **8 UWORD points**. The sibling `sub_7088` uses `0x1E`/`0x10` for a 16-point/16-column family, which confirms the `0xE`→8-point convention rather than being a one-off.
- `0xA10C − 0xA08C = 0x80 = 128 B = 64 UWORD = 8×8`, matching the independent `A08C+0x80` pointer arithmetic.

Axis point values (raw, uninterpreted):

- `0xC7E2`: `0018 0020 0028 0030 0038 0040 005C 0078` (monotone ascending)
- `0xC7C2`: `0030 0060 0080 00A0 00C0 00E0 0100 0120` (monotone ascending)
- `0xBBD8`: `00 15 28 40 58 70 80 90 | 31 35 3A 40 45 5C 5C 5C` — reader compares `+1…+7` = `15 28 40 58 70 80 90`
- `0xBC9A`: `00 14 24 34 44 58 6C 80 | 78 78 78 78 78 70 6C 68` — reader compares `+1…+7` = `14 24 34 44 58 6C 80`

Both UBYTE axes begin with `0x00` and the searched window is the seven ascending bytes after it. Whether `+0` is an unreferenced first point (making these 8-point axes) or a header byte is **not resolved**; see §5.

Payloads (full 8×8 dumps in the evidence file) are **not duplicates of each other**: 63 of the 64 UWORDs differ (`0xA08C` range `0x801C–0x8056`, `0xA10C` range `0x8022–0x8058`). This is materially different from the byte-identical pair closed as a bounded negative in WO65152, so the two banks are genuinely independent data objects.

## 2. Instruction-anchored trace — AFR maps (`sub_46DC6`)

`sub_46DC6` (`0x46DC6`) is entered from one place only: `sub_3ED74+0x3F0`. It sets `gbr = FFFF902C` (`0x46DDA`) and `r9 = FFFF2630` (`off_470AC`), and takes its bank-enable pointer in `r7` → `r11` (`0x46DE6`).

| PC | Effect | Note |
|---|---|---|
| `0x46E76` | `r4 = 0xCB40` | conversion table, first of two lookups |
| `0x46E7C` | `r5 = 0xD446` | second conversion table |
| `0x46E82` | `r10 = 0xC7E2` | **X axis**, kept for the map call |
| `0x46E84` | `jsr sub_72C4` (`r4=0xCB40`, `r5=0xD446`, `r6=UWORD[*(arg_4)]`) | raw-query conversion, bank 1 |
| `0x46E8C` | `r4 = off_470C0` = `0xA08C` | **bank-1 map base** |
| `0x46E94` | `r5 = 0xC7C2` | **Y axis** |
| `0x46E96` | `r2 = r2 + r6` → `gbr+0x10` | converted X argument staged |
| `0x46EA0` | `jsr sub_7054` (`r4=0xA08C`, `r5=0xC7C2`, `r6=0xC7E2`, `r7=r14`, stack=`r13`) | **bank-1 read** |
| `0x46EB8–0x46ED2` | clamp, then `sub 0x8000` fold | result normalisation |
| `0x46EDC` | `word[0xC0 + r9] = r2` → `FFFF26F0` | **bank-1 result latched** |
| `0x46EE0` | `r0 = UWORD[*(arg_4)+2]` | bank-2 query is the *next* word of the same argument record |
| `0x46EEE` | `r4 = off_470D0` = `0xA10C` | **bank-2 map base** |
| `0x46EF4` | `r5 = 0xC7C2` | same Y axis |
| `0x46F00` | `jsr sub_7054` (same helper, bank-2 base) | **bank-2 read** |
| `0x46F3E` | `word[0xC2 + r9] = r2` → `FFFF26F2` | **bank-2 result latched** |

Both reads are straight-line: there is no conditional, table or counter between `0x46E8C` and `0x46EEE` that could skip or substitute one bank for the other. The only branch in the block (`0x46E64–0x46E72`, `0x46E56–0x46E5E`) writes unrelated feature words at `FFFF2840`/`FFFF2842` from `0x861E`.

### Where "bank" actually exists in this function

The pair is not selected at the table level but **routed at the output level**, by two runtime enable bytes reached through the caller's `r7` pointer (`r11`):

| PC | Effect |
|---|---|
| `0x46F40–0x46F5A` | optional clamp of the caller-supplied value through `sub_3784` with `dword_470D4` = `0x72D8000`; result kept in `r6` |
| `0x46F60–0x46F74` | `byte[r11] >= 1` → output = **bank-1 map result** (`word[0xC0+r9]`), else output = the clamped fallback; stored to `gbr+0x20` (`FFFF904C`) |
| `0x46F78–0x46F98` | `byte[r11+1] >= 1` → output = **bank-2 map result** (`word[0xC2+r9]`), else the same fallback; stored to `gbr+0x22` (`FFFF904E`) |
| `0x46F9A–0x47002` | both routed words are offset by `0x1CB6` and scaled through `sub_3784` into `gbr+0`, `gbr+4`, `gbr+8` (`FFFF902C/9030/9034`) |

So each bank's correction is always computed; the enable byte only decides whether that computed result or a substituted value reaches the output cell. Because both alternatives write the **same** cell, the mechanism is substitution, not masking.

## 4. Relationship test and a false-positive reader ruled out

- The AFR maps' axes are `0xC7E2`/`0xC7C2` (`off_470BC`, `off_470C4`). `0xBC9A`/`0xBBD8` are never passed to `sub_7054`/`sub_76C0`, and `0xA08C`/`0xA10C` are never touched by `sub_3A204`. The two families share no helper, no argument record and no RAM cell.
- `EVIDENCE/CF48D.xml` lines 111–112 declare the two LTFT axes as standalone tables with no parent, and lines 204–214 give the AFR banks the axes `0xC7E2`/`0xC7C2`. The definition file therefore does **not** claim the linkage either; the WO's premise of a "purported" linkage is contradicted, not merely unproven.
- The third grep hit for `0xA08C`, `off_574CC: .data.l dword_A08C+h'2A` (`0x574CC`, used at `0x5737E`), is **not a table read**. The value `0xA0B6` is loaded into `r13` and immediately consumed by `mul.l r2, r13` at `0x57384` as a 16-bit immediate multiplier; the address range merely happens to lie inside the bank-1 payload. Future reader censuses must not count it as a second consumer of the map.

## 5. Unresolved edges (explicit stop boundary)

1. **Physical domain of both maps** — no scaling, unit, output conversion or actuator boundary was traced. `sub_7054` is shared with other families, so its `0xE`/`8` constants establish geometry only.
2. **Producer of the map queries** — `UWORD[*(arg_4)]` and `UWORD[*(arg_4)+2]` are caller-supplied record words from `sub_3ED74`; their source was not traced (this is an Elan-style producer question, out of this WO's bounds).
3. **Identity of the two enable bytes** at `r11`/`r11+1` — the only demonstrated bank-selection mechanism in the pair. Untraced.
4. **`FFFF8468` and `FFFF85DC+5` producers** — both LTFT queries are RAM reads of unknown origin.
5. **7-vs-8 point reconciliation on the UBYTE axes** — the search compares 7 values (`+1…+7`) while the RAM index domain is `0..7` and the byte at `+0` and at `+8` are both present but unreferenced by this reader. No axis point count is promoted beyond "7 values compared".
6. **`FFFFA25C`/`FFFFA2DC` provenance** — the 8×8 UWORD tables read at `0x3A318`/`0x3A326` are RAM; whether they are copies of ROM objects was not established.
7. **Computed-address readers** — the reader census is literal-reference based (9 pool entries, verified in the binary). An indirect access through a computed base pointer would not appear and is not excluded.
