## Objective and result

Compare the existing UpRev EM43A tuned and back-to-stock Osiris ROM files to determine what regions and data shapes a real Nissan tune changed, and whether the file format exposes useful calibration metadata. Treated strictly as a cross-family tuning-pattern study, not EL19A semantic proof.

**Hypothesis result — MAIN CLAIM REJECTED / METADATA SUBCLAIM PARTLY SUPPORTED.** The tuned-vs-stock pair does not expose localized, structurally recognizable calibration edits at the file level. The declared 1 MiB payload region is high-entropy and differs at 99.597% of byte positions between the two files, so no data-like versus code/configuration block classification is defensible from this pair alone. The format does expose plaintext metadata key names in a trailer, but no calibration labels, addresses, table geometry or human-readable tune values were recovered.

## Outer header structure

Both files share a 0x00–0x48 prefix:

- `0x00`: ASCII `UpRev Osiris ROM File Ver 1.0000`, followed by `0D 0A 1A`.
- `0x40`: bytes `66 42 48 60 00 01 00 00` are identical in both.
- `0x48–0x4B`: little-endian field differs: tuned `0x00000003`, stock `0x00000005`. This is the first differing byte range (first difference at `0x49`).
- `0x60`: ASCII `ROMData `.
- `0x68`: little-endian `0x00100000` in both, consistent with a declared 1 MiB payload.
- `0x6C`: `0x00100018` in both; `0x70`: `0x00000001` in both. Semantics not asserted.
- `0x74–0x83`: 16-byte per-file value differs: tuned `3955667759116a2d62a07662bf855988`, stock `9d2f8e7e64776bf81f73e6e7cfd3d328`.

The 1 MiB payload consistent with the `0x68` field is `0x74–0x100073`; the trailer begins at `0x100074`.

## Byte-level differential

Whole-file start-aligned comparison:

- Common prefix: 73 bytes (`0x00–0x48`).
- Common suffix: 0 bytes.
- File length delta: tuned is 963 bytes (`0x3C3`) longer.
- Overlapping-file differing bytes: 1,044,470 of 1,048,838 (99.5835%).
- Differing-byte runs: 4,219 total; 3,026 at least 16 bytes; 2,458 at least 64 bytes; largest 12,287 bytes.

Declared payload region `0x74–0x100073` (length `0x100000`):

- Differing bytes: 1,044,351 / 1,048,576 (99.597073%).
- Equal byte positions: 4,225.
- Differing runs: 4,215; largest 12,287 bytes.
- Longest identical run: 2 bytes.
- Byte entropy: tuned 7.999866, stock 7.999812 (all 256 byte values present in each).
- Direct payload XOR: entropy 7.992326; only 4,253 zero bytes; longest zero run 20 bytes.

This is not a sparse plaintext diff. It rules out a simple same-keystream XOR exposing localized calibration edits and provides no basis for classifying changed payload bytes as calibration data, checksums, code or configuration. No block-geometry repetition was observed because no plaintext table/curve structure is exposed.
