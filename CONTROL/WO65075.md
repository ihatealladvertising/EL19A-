- The pinned listing contains no code operand spelling `FFFF9C48`; the exact string is the RAM allocation row only. The full-address `FFFF9C10` references are the literal loads at `0x96920`, `0x969D6`, `0x9734A`, plus its allocation row.

- This read occurs before the new UWORD stage at `0x972E0`. Its first local data use is `0x96D9E extu.w R0,R2`; `0x96DA8 mul.l R2,R9` then consumes the zero-extended prior-state word in local arithmetic. It is not a consumer of the value subsequently copied from `FFFF27DE`.
- At `0x972DC–0x972E0`, the function reloads offset `0x68E`, reads UWORD `FFFF2150+0x68E = FFFF27DE` at `0x972DE`, then writes that value unchanged to `GBR+0x38 = FFFF9C48` at `0x972E0`. ROM bytes at the GBR setup, prior-state read, source read, and output store match the pinned listing.
- No later `GBR+0x38` read appears in `sub_969C2` before its GBR restore at `0x97332` and return at `0x97344`. The helper/GBR-preservation evidence for the producer-to-store path is reused from WO65070, not expanded into a new call census.
