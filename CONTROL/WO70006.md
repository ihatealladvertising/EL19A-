### B. Scanner source audit (source review only; no run validation)

- Helper discovery is signature-based rather than keyed to fixed helper addresses: it scans ROM offsets `0x04000–0x7FFFF` for four structural stub patterns (2D implicit, 2D ROM-axis, 3D implicit, 3D ROM-axis), including PC-relative `mov.l` and `mov.w` helper-load variants. The helper family and geometry are inferred from instruction idioms and nearby helper bodies.
- Pattern A now recognizes the `add #imm,r4; rts; mov.w/mov.b @r4,r0` saturated return shape and derives the count from clamp bytes / element width + 1. For `0x7E` and UWORD cells, this correctly gives 64.
- Call recovery is bounded and heuristic: the source looks up to 20 instructions forward from a PC-relative helper-address load for an indirect call; it then reconstructs register state from a 56-byte window before the call and partially handles literal loads, immediates, register moves, extensions, add-immediate and delay-slot instructions.
- It is not a path-sensitive SH-2 emulator. Branch/fall-through flow, stack arguments/spills, wrapper calls, arbitrary memory-based pointers, broad arithmetic and all register clobbers are not fully modeled. A linear window can cross control-flow edges; stale-register and missed-call/false-call cases remain possible. The pre-cal layout bound is heuristic (`cal_hi=0x14000`); mid-ROM layout selection is likewise heuristic.
- The cross-ROM payload count is not a homologous-table comparison: the source matches raw byte slices against a set of EL19A slices, without requiring equal dimensions, element type, axes, orientation or semantic identity. “Non-trivial” is only defined as more than two distinct byte values. Same-address+kind is not a geometry equivalence test. The XML comparison checks dimension product and storage type, not axis pointers or orientation. The script does not compute processor IDs/FIDs or executable-code overlap.
- Therefore implementation review is PARTIAL: useful helper-pattern and clamp logic is present, but completeness and per-call argument accuracy are not validated by raw outputs.
