## Objective

Use the existing MMIO census and output/actuator inventory to select a small number of high-value actuator endpoints and trace backward from each endpoint to its command variable, calculation, lookup result and candidate calibration table. The goal is to anchor a table's output role from the sink side, not to repeat the MMIO inventory.

## Falsifiable hypothesis record

- **Identity layer advanced:** output identity and, where the chain closes, function identity.
- **Hypothesis:** at least one selected actuator endpoint has a statically provable command-dataflow chain back to a previously catalogued calibration lookup result.
- **Evidence:** exact MMIO address/register, write PC, caller/register provenance, RAM command field, calculation and table-reader report anchors; reuse WO65106 and existing table/consumer reports.
- **Prediction:** a valid chain must connect a concrete MMIO write to a command variable and then to a specific lookup result or calculation input, with no unresolved pointer/alias break.
- **Cheap discriminator:** choose one endpoint with the strongest existing writer and RAM-field provenance; inspect only its immediate backward dataflow and the already documented candidate consumer paths.
- **Falsifier:** the endpoint is not a real actuator command, its write value is unrelated to the candidate command field, or the path terminates before any candidate lookup result can be connected.
- **Information gain:** explain how the selected endpoint distinguishes competing candidate table roles and why it is more discriminating than tracing additional readers.
- **Result:** record supported, weakened, rejected or unresolved for each endpoint.

## Required method

1. Reuse `CONTROL/WO65106.md` and existing writer/consumer reports. Select no more than two endpoints, prioritizing a clear actuator interpretation and existing RAM writer evidence.
2. For each endpoint, record MMIO address/register, access width, write PC(s), branch conditions and the source register/value.
3. Resolve source register and pointer provenance backward only as far as necessary to identify the command RAM cell or calculation result. Record scaling, signedness, clamps and units only when directly supported.
4. Check whether that command cell/result is already tied to a catalogued table output by an existing reader/consumer report. If not, perform only a narrow trace of the named candidate path.
5. Build the chain explicitly: MMIO output ← command variable ← calculation ← lookup result ← table. Mark each proven and unresolved edge.
6. Include a hypothesis/discriminator/result table and state whether the evidence establishes an actuator role, a software command role only, or no relationship.

## Reuse and no-repeat boundaries

- Reuse `CONTROL/WO65106.md`, `INDEX/` MMIO census/output inventory, and only directly relevant existing reader/consumer reports.
- No repeat MMIO census, no full peripheral register sweep, no broad RAM xref, no full catalogue re-trace, and no generic actuator-driver inventory.
- Do not assume that a memory-mapped register is an actuator output without evidence. Do not infer physical units from donor names alone.
