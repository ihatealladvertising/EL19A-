## Objective

Trace the eight source bytes used by the proven MB28 transmit helper, RAM `FFFF3DD0–FFFF3DD7`, backward to their nearest producers and known diagnostic/Consult symbol identities. Determine whether any payload byte is demonstrably a copy or transform of a named OBD Mode $01 PID, Consult Mode $22 CID, or existing diagnostic state cell.

This is a static source-code crosswalk, not a claim that MB28 periodically broadcasts live engine signals. It is intentionally limited to the known `sub_B5580` source buffer and any additional source expressions independently confirmed in WO65258.

- WO65108: `sub_B5580` copies eight bytes from `FFFF3DD0–FFFF3DD7` to MB28 data `FFFFDC88–FFFFDC8F`; ID word `0x7E80), DLC 8, TXPR1 request bit `0x1000`.
- WO65108 also records a separate direct response-shaped payload writer at `0x4AF4–0x4B20`, after matching received bytes `03 31 81 01`. Treat this as a distinct path; do not assume it uses the `FFFF3DD0` buffer.
- WO65173 provides the existing OBD Mode $01 / Consult Mode $22 diagnostic source map.
- WO65239's 179-row join classifies actual query variables against OBD/Consult names: direct same-cell examples include `FFFF85DA` and `FFFF855E`; a derived PID $43 relationship exists at `FFFF84A4). Reuse exact cells and proven transforms only.
- WO65176 confirms no additional active TX mailbox or RAM payload buffer in the audited HCAN1 mailbox range.

## Mandatory falsifiable hypothesis record

- **Identity layer advanced:** RAM input identity and CAN payload output identity.
- **Hypothesis:** one or more bytes in `FFFF3DD0–FFFF3DD7` are direct or transformed copies of runtime cells already named by the diagnostic source map, giving an independent output-path corroboration for those symbols.
- **Prediction:** bounded backward traces will identify byte producers and at least one exact same-cell or fully explained transformed relationship to an OBD/Consult source; alternatively, all eight bytes will remain service-specific/unmatched.
- **Cheap discriminator:** trace only the eight source bytes' nearest reaching stores/copies and compare their exact source EAs/transforms with WO65173/WO65239's named diagnostic cells.
- **Falsifier:** no byte has a proven same-cell or fully explained derived relationship to any named diagnostic source, or the source buffer is not the actual payload on the confirmed path.
- **Information gain:** a positive match would independently connect a named ECU state variable to a transmitted CAN payload; a negative result would establish that this mailbox is not a useful general-purpose signal dictionary.
- **Result:** supported, weakened, rejected or unresolved. A numerical resemblance or correlated-looking expression is not a match.

## Scope

1. For each byte `FFFF3DD0+i`, i=0…7, identify the nearest reaching writer(s), exact PC, width, source EA/register/immediate, copy length and branch guard. Preserve multiple writers and runtime branch separation.
2. Trace each source back only far enough to classify direct RAM source, derived expression, constant/protocol byte or unresolved state. Record all arithmetic, masks, scaling and saturation.
3. Compare each exact source cell/expression against the named cells in WO65173 and WO65239. Accept only direct same-cell identity or a fully documented transform with matching width and branch context.
4. Keep the direct response payload path (`03 71 81 01 00 00 00 00`) separate unless a proven shared producer or source buffer is demonstrated.
5. If WO65258 discovers additional distinct payload source expressions, record them as pending crosswalk candidates; do not broaden into an unrelated full-RAM scan.
6. Stop at the first unresolved computed pointer, bulk-copy alias or event boundary.
