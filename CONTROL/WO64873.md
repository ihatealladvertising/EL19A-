## Confirmed

- `sub_403D8` chooses E688/0x848B only when both `FFFF85F8.bit4` and `FFFF8600.bit6` are set (`0x4048A–0x40498)); all other states proceed to E678/0x848A.

- `FFFF8600` is byte +1 of the `FFFF85FF` structure. Initialization copies three bytes from `FFFF85FF` to `FFFF8602` through `sub_2245C` (`0x20FB4–0x20FBE`); this does not establish the semantic meaning of bit6.
- The annotated listing contains no direct code comment or established producer trace that identifies the combined condition as Drive vs Neutral. A search of exact `FFFF8600` references found only the branch use plus RAM definition; aliases/indirect updates are not excluded.

## Decision

**Do not label 0x848A / 0x848B as Neutral/Drive or Drive/Neutral yet.** Their selection is confirmed as a two-bit state condition, but mode identity is not. Neither bit's producer/state semantics are sufficiently established by this bounded pass.
