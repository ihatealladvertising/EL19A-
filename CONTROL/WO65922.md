## Question

`0x078C0A` builds a four-bit mask from `FFFF3579.bit0` and `r12` bits 7/6/5 (values `1`, `2`, `4`, `8`) and stores it to `FFFF2150+0x6FE` = **`FFFF284E`**, gated by `FFFF34E2.bit4`. Does anything read `FFFF284E`, and does that read reach a named output, or does the mask terminate as internal state?

## Answer

**`INTERNAL STATE FLAG`.** The cell has exactly **one reader — `0x078C34`, inside the same routine that writes it (`sub_77608`)** — and that read is an overlap test between the stored mask and the newly built mask. It selects no value, feeds no table, and reaches no MMIO register, actuator, lamp or diagnostic publication. Its only outward product is one status bit, `FFFF357A.bit2`, in the same `FFFF34C1` block.

`FFFF284E` is therefore a **previous-mask memo**: the routine remembers the mask it last accepted so it can decide, on the next periodic pass, whether the new mask still shares a bit with it.

## Complete access census — five code sites, no others

Every reference to the offset is a pool word `h'6FE`; there are **three** such pool copies and **five** code sites, and all five resolve under `base = FFFF2150`:

| Site | Function | Base register | Form | Effect |
|---|---|---|---|---|
| `0x0775BC` | `sub_7759C` | `r5 = FFFF2150` (`off_77890`, `0x0775A4`) | `mov.b r2,@(r0,r5)`, `r2 = 0xFFFFFFFF` → byte `0xFF` | **write `0xFF`** (init / invalidate) |
| `0x0776D0` | `sub_77608` | `r11 = FFFF2150` (`off_77890`, `0x077642`) | `mov.b r2,@(r0,r11)`, `r2 = 0xFFFFFFFF` → byte `0xFF` | **write `0xFF`** (init / invalidate) |
| `0x078C34` | `sub_77608` | `r3 = FFFF2150` (`off_78E24`, `0x078C30`) | `mov.b @(r0,r3),r2` | **the only read** |
| `0x078C46` | `sub_77608` | `r3 = FFFF2150` (`off_78E24`, `0x078C42`) | `mov.b r13,@(r0,r3)` | **write the built mask** |
| `0x078C52` | `sub_77608` | `r3 = FFFF2150` (`off_78E24`, `0x078C4C`) | `mov.b r2,@(r0,r3)`, `r2 = 0x80` | **write `0x80`** |

Pool copies: `word_77600`, `word_777D4`, `word_78CF0` — all `.data.w h'6FE`.

**No absolute literal** `FF FF 28 4E` exists in ROM (0 hits), and **no base literal exists anywhere in `FFFF2000`-`FFFF284E`**, so no closer base register can reach the cell with a displacement below `0xFFF`. The `0xFE` byte-displacement route is impossible for the same reason (`FFFF284E - 0xFE = FFFF2750`, and no `h'FFFF2750` literal exists). The offset `0x6FE` is not constructible from a byte immediate — it exceeds `0xFF` and `0x6FE / 2 = 0x37F` is odd, so no `mov #imm` + `shll`/`shll2` build reaches it — and the three pool copies above are the only carriers of the value.

## What the one read does (`sub_77608`, `0x078BEE`-`0x078C58`)

`sub_77608` installs `gbr = FFFF34C1` at `0x07761C`-`0x07761E` (`off_77894`) and is called from the periodic dispatcher at `0x0707CC` (pointer-table entry `0x070A00`).

```
0x078BEE  mov.b @(h'B9,gbr),r0        r0 = UBYTE[FFFF357A]
0x078BF0  mov   r0,r6
0x078BF2  mov   r0,r12                 r12 = UBYTE[FFFF357A]  (source of mask bits 2/4/8)
0x078C00  mov   r6,r0 ; tst #4,r0      FFFF357A.bit2 ?
0x078C04  bt    loc_78C0A
0x078C06  bra   loc_78C30
0x078C08  mov   #unk_FFFFFF80,r13      DELAY SLOT: r13 = 0x80  (mask "inactive")
loc_78C0A:
0x078C0A  mov.b @(h'B8,gbr),r0        UBYTE[FFFF3579]
0x078C0C  tst   #1,r0 ; bt loc_78C12    bit0 clear -> skip
0x078C10  mov   #1,r13                 mask bit 1
0x078C12  tst   #h'80,r12 -> or 2       FFFF357A.bit7 -> mask bit 2
0x078C1C  tst   #h'40,r12 -> or 4       FFFF357A.bit6 -> mask bit 4
0x078C26  tst   #h'20,r12 -> or 8       FFFF357A.bit5 -> mask bit 8
loc_78C30:
0x078C32  mov.w word_78CF0,r0 ; h'6FE
0x078C34  mov.b @(r0,r3),r2            READ  prev = UBYTE[FFFF284E]
0x078C38  tst   r6,r13                 T set when (prev & new) == 0
0x078C3A  bt    loc_78C4C               no shared bit -> invalidate
0x078C3C  mov.b @(h'2F,gbr),r0         UBYTE[FFFF34F0]
0x078C3E  tst   #h'10,r0 ; bf loc_78C4C bit4 set -> invalidate
0x078C46  mov.b r13,@(r0,r3)           store the accepted mask
loc_78C4C:
0x078C52  mov.b r2,@(r0,r3)            store 0x80
0x078C54  mov   r12,r0 ; or #4,r0
0x078C58  mov.b r0,@(h'B9,gbr)         FFFF357A |= 4   (bit2)
```

Semantics: the field is `0xFF` after the reset/init writes, `0x80` when no mask is active or the gate failed, and otherwise the last accepted mask (`1`-`0xF`). Because the init value is `0xFF`, the first evaluation always intersects a non-zero new mask and is therefore accepted — the `0xFF` seed is an "accept the first mask" state, and `0x80` is the explicit "no bits" sentinel.

## Terminal and second hop

- **Hop 1 (the read itself):** a local branch gate. No value is selected or published.
- **Hop 2:** `FFFF357A.bit2` (set on the invalidate path at `0x078C58`). `FFFF357A` is an unnamed RAM byte (`UNDEFINED .res.b 1` in the map, no ROM literal), read at `0x078BEE` and — for a different purpose — at `0x08AF6E` in `sub_8AD7C`, where it is copied verbatim into a stack frame slot (`0x5C`) alongside `FFFF34C1+0xAB`, `+0xBF`, `+0xCF` and `+0xD4`. That is a diagnostic frame builder, and what consumes the frame is **beyond this WO's stop boundary**.
- **No MMIO/actuator/lamp/diagnostic-publication endpoint for the mask itself.** The mask never leaves `sub_77608`; nothing outside the routine reads `FFFF284E`.

## Reconciliation (additive — WO65910 unedited)

- **WO65910 said:** the mask is "gated by `FFFF34E2.bit4` (`@(h'2F,gbr)` + `tst #h'10`)".
- **Corrected:** the gate is at `0x078C3C` inside `sub_77608`, whose `gbr` is installed from `off_77894 = h'FFFF34C1` at `0x07761C`; `FFFF34C1 + 0x2F = **FFFF34F0**`, not `FFFF34E2` (`= FFFF34B3 + 0x2F`). The `FFFF34B3` base belongs to other routines and was carried in from them. The gate's function, polarity and position in the block are unchanged; only the address attribution is corrected. Recorded as `REC-000018`.
- Also recorded additively: `r13` is initialised to `0x80` in the `bra` delay slot at `0x078C08` — a further instance of the FND-000013 delay-slot rule, this time setting a *default value* rather than a bit — and `r12` (the mask's bit source) is `FFFF357A` itself, which WO65910's wording left implicit.
- **Confidence:** HIGH for the five sites, the bases, the gate address and the block semantics. **Limits:** the census is complete for offsets carried by the three `h'6FE` pool words and for every base literal within `0xFFF` below the cell; a writer reaching the byte through an unrelated base far below the cell (e.g. `FFFF1D80` + a large offset) is not excluded, and the `0x08AF6E` diagnostic frame's destination was not traced (stop boundary).
