# WO65084 — Calibration Option Byte `0x8405`: Complete Bit-Gate Inventory and Three Worked Gates

**Status:** BOUNDED COMPLETE (2026-11-21)

**Depends on:** WO65080 (`0x8405` bit 2 gate at `sub_703A8`/`loc_704D0` — reproduced here as part of the full inventory), WO65060 (flags/bitmasks listed as an unmapped category with 0 XML v3 entries).

## Objective

`0x8405` is the only calibration byte found so far that is tested by more than a handful of unrelated routines: 21 load sites, single-bit tests, each gating a different computation. WO65080 read two of those sites. This WO completes the inventory and works three gates far enough to state what the bit actually selects, without assigning a semantic name.

## Scope and stop condition

- Method: every code site whose annotation resolves to `h'8405`, plus the immediately following test, mask and branch target. The enclosing function is the nearest preceding `sub_` label.
- Stop at: mask, branch polarity, and the first branch-specific load or store. No downstream consumer trace, no unit or physical identity, no whole-ROM flag search.
- Concurrency: distinct from WO65083 (`0x7800–0x9500` scalar sweep), WO65080/81/82 (`0x11700–0x13000` bank and `0x12844` block), and the closed scalar-window censuses.

The listing symbolises the byte as `h'8405` = `dword_8404+1`, i.e. the second byte of a 4-byte ROM object at `0x8404`. Neighbouring objects are separately labelled `byte_8400` and `byte_8403`; `h'8406` has no reference at all and `h'8407` one, so the four bytes are not one uniform field set.

**Shipped value:** `VERSA f501.bin` at `0x8404–0x8407` is `07 0C 1E 03`, so `0x8405 = 0x0C` — **bit 2 and bit 3 set, bits 0/1/5/6/7 clear** in this calibration. Bit 3 being set but never tested is itself a data point: the byte carries at least one bit with no reader in this binary.

## 2. Worked gate A — bit 0 selects between 1000 and 800

`sub_685A6`, `0x686DC`–`0x686EE`:

```
0686DC mov.l off_68764,r6 ; h'8405
0686DE mov.b @r6,r0
0686E0 tst   #1,r0
0686E2 bt    loc_686EE            ; bit 0 clear
0686E4 mov.l off_68768,r6 ; h'FFFF3616
0686E6 mov.w word_6873C,r13 ; h'3E8   (1000)
0686E8 mov.b @(5,r6),r0
0686EA tst   #4,r0
0686EC bt    loc_686F0
0686EE mov.w word_6873E,r13 ; h'320   (800)
```

Bit 0 clear → `r13` = **800** (`tst #1` sets T when the tested bit is zero, so `bt` means clear). Bit 0 set → `r13` = **1000**, unless `FFFF3616+5` bit 2 is set, which forces 800 again. One calibration bit chooses the default value, a second runtime bit can override it. No unit is assigned; the two candidate values are the entire finding.

## 3. Worked gate B — bit 7 reads a trust-bank table

Two functions use bit 7 to choose between a RAM-held value and a ROM table:

- `sub_6F5E8` `06F6B4`: bit 7 **set** → `06F6BC mov.l off_6F754,r6 ; h'965C` then `06F6C0 mov.w @r6,r2`; bit 7 **clear** → `06F6C2` path reads `FFFF2150+0x312`.
- `sub_6F8EC` `06F93A`: bit 7 **set** → `06F944 mov.l off_6FAB0,r6 ; h'1171E` with the delay-slot read `06F94A mov.w @r6,r5`; bit 7 **clear** → `06F94C` path uses the `FFFF2150` stage.

`0x1171E` lies in the `0x11700–0x13000` trust-bank range. This is a **calibration bit that selects a trust-bank scalar**, which refines WO65080's bounded negative ("no ROM flag selecting normal-vs-trust for the same output cell was found"): the selector exists, it is `0x8405` bit 7, and it is used at least twice. It selects a scalar against a RAM-staged value rather than one twin against another, so it does not by itself prove a normal-vs-trust selector for the 18 pairs.

## 4. Worked gate C — bit 2 publishes a RAM flag

`sub_2BEAC` `02BF24`–`02BF30`: `tst #4`; when bit 2 is **clear** (`bf loc_2BF38` skipped only if set) the routine executes `02BF2C mov #h'FFFFFFC0,r2` / `02BF2E extu.b r2,r0` / `02BF30 or.b #h'20,@(r0,gbr)` — it sets bit 5 of a GBR-relative byte — then returns 1 in `r0`. With `0x8405 = 0x0C` in this ROM, bit 2 is **set**, so this branch does not execute in the shipped calibration.

Bit 1 (four sites, `0x6FFE4`, `0x7030E`, `0x703BA`, `0x704DC`) is the compute-vs-cached-value gate already recorded in WO65080 §3 and is not re-derived here.

## Bounded negatives

- No test of bit 3 or bit 4 of `0x8405` anywhere in the listing.
- No multi-bit mask and no `cmp`-based range test on the byte: every site is a single-bit `tst`/`and`.
- No store to `0x8405` (ROM); the byte has no RAM copy established by this method.
- No reader outside the 21 sites above was found by literal annotation; GBR-relative or pointer-derived aliases into `0x8404+1` were not tested.
- No semantic identity, unit, or "enable/disable" convention is assigned; polarity is reported per site exactly as printed (`bt` vs `bf`).

## Unresolved

1. What each selected outcome is: the 1000/800 pair (gate A), the `0x965C`/`0x1171E` scalars (gate B), and the `FFFF2150+0x312`/`FFFF2150+0x384` stages the bit-7 and bit-0 paths read.
2. Whether `0x8405` is a build/region code rather than a user calibration switch — the presence of an unread bit 3 and the 12-to-4-to-1 site distribution are consistent with either.
3. The 4-byte object `0x8404` as a whole: `0x8404` = `0x07` and `0x8405` = `0x0C` in this build; `0x8406` is never read.
4. Bit 5 (`0x5B6A8`) selects a `0x500` vs immediate path that was not worked.
