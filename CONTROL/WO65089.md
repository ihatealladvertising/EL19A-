## Helper contracts used in these traces

### sub_22C38 — 8×8 UBYTE map

Caller contract: R4 = map pointer; R5 = first UBYTE axis; R6 = second UBYTE axis; R7 = first query; stack byte argument = second query. The helper searches each eight-point axis and tailcalls the 8×8 interpolation path. Return value is in R0; callers here retain the low byte or zero-extend as required.

### sub_22AFC — 16×16 UWORD map

Caller contract: R4 = map pointer; R5/R6 = two UWORD queries. It performs the two 16-point axis searches, then tailcalls the 16×16 interpolation path. Return value is in R0. Signed centering is a caller operation, not part of this helper's UWORD return contract.

### sub_22FAC — 32-point UWORD curve

Caller contract: R4 = value-curve pointer; R5 = UWORD axis pointer; R6 = UWORD query. It searches the 32-point axis (last-point offset 0x3E) and interpolates the selected UWORD values. Return value is UWORD in R0; caller-side extension, scaling and storage are separate operations.

These contracts establish widths and argument roles only. They do not supply physical units or calibration names.

## 1. Mode-selected 8×8 UBYTE pair — 0x0A342 / 0x0A382

**Caller:** the processing block beginning at `loc_379B0`; map call at `0x37BF8` in the 0x379B0–0x37C40 range.

**Inputs and selection**

- GBR is set to `FFFF1850` at `0x379C2–0x379C4`.
- The two UBYTE axis pointers passed to the helper are ROM `0x0DFF2` and `0x0DFFA` (loaded into R5/R6 at `0x37BF2/0x37BF4`).
- First query R7 is derived from UBYTE `FFFF860D` (loaded through `FFFF8602+0x0B`). The active path masks it with `0x08` at `0x37A3A`, so this path supplies discrete query values 0 or 8. Other gate paths may bypass this lookup; do not generalise the query outside this call path.
- Second query is UBYTE `FFFF8534+0x46 = FFFF857A`, loaded at `0x37B8E` and passed as the stack byte argument at `0x37BEE`.
- The map pointer is selected from UBYTE `FFFF85FB` at `0x37BDC–0x37BEA`. The tested bit is bit 7: **set selects 0x0A382; clear selects 0x0A342**. These are distinct physical map objects with the same axes, not one merged table.
- `0x37BF8` calls sub_22C38. Its JSR delay slot at `0x37BFA` zero-extends the returned UBYTE in R0 into R7.

**Output and first direct use**

- Returned byte is staged at `GBR+2 = FFFF1852` (`0x37C00`).
- Under a local bit-5 gate, the byte is also copied to `GBR+0x0A = FFFF185A` (`0x37C0C`); the related status bit is cleared in that branch.
- The returned byte is then multiplied by ROM UBYTE `0x8F68`, combined with UWORD `FFFF85DA` and factor `0x37`, shifted/scaled and saturated to UWORD range no greater than `0x7FFF`. The resulting UWORD is stored at `GBR+0x4C = FFFF189C` (`0x37C3A`) and `GBR+0x74 = FFFF18C4` (`0x37C3E`).
- These are direct result-derived state stages. No physical meaning is assigned to the maps, axes, inputs, scale byte or RAM outputs.

**Assessment:** high-confidence mode/bit-selected 8×8 UBYTE response surface pair, with a discrete first query and a separate byte query; output feeds status/state staging and two scaled UWORD fields. Functional identity beyond that software path remains unknown. The catalogue's provisional “candidate register” wording is not confirmed as a Nissan function.

## 2. Centered 16×16 UWORD surface — 0x0D8D6

**Caller:** `sub_5C220`; lookup call at `0x5C28E`.

**Query construction**

- First query: if UWORD `FFFF97F4` is nonzero, UWORD `FFFF8494` is multiplied by 20,480 and divided by UWORD `FFFF97F4` through sub_21AC0; the result is capped to UWORD and staged at `FFFF1054+0x296 = FFFF12EA`. If `FFFF97F4` is zero, the query falls back to UWORD `0xFFFF`.
- Second query: UWORD `FFFF859C+0x10 = FFFF85AC` is multiplied by 32, then offset by `-0x1000`, capped to UWORD and replaced by `0xFFFF` if the intermediate is negative.
- R4 is loaded with map pointer `0x0D8D6` at `0x5C288`; the two UWORD query values are passed in R5/R6. The call to sub_22AFC occurs at `0x5C28E`; its delay slot at `0x5C290` zero-extends R5.

**Output and first direct consumer**

- The helper's UWORD return in R0 is shifted by `-0x8000` using `0xFFFF8000` at `0x5C292–0x5C29A`, then stored as a UWORD at `FFFF1054+0x4F6 = FFFF154A` (`0x5C29C`). The data is therefore a centered signed-style result encoded in a UWORD slot; the helper itself returned UWORD.
- The next routine, `sub_5C2A4`, reads that result at `0x5C2E8`. It adds UWORD `FFFF1D12+0x3C`, multiplies the combined term by a locally derived factor, then continues into a gated/scaled arithmetic path. The direct consumer is a calculation, not a semantic label or hardware endpoint.

**Assessment:** high-confidence 16×16 UWORD surface used as a centered signed correction term between two normalized/scaled UWORD queries and subsequent local arithmetic. Physical domain and units remain unresolved.

## 3. Inline 8×8 SWORD set — 0x0B422 / 0x0B4A2 / 0x0B522 / 0x0B5A2

**Caller:** `sub_969C2`; a scheduled entry is referenced from the function/dispatch table at ROM `0x219C0`. Incoming R12 is not assigned in the local function prologue; its producer at the dispatcher/callback boundary remains unresolved.

**Index construction**

- The function establishes GBR=`FFFF9C10` at `0x969D8`; R11 is `FFFF2150).
- A preliminary eight-point search at `0x96B30–0x96B46` uses UWORD `FFFF1D12+0x30` against axis `0xFEA0`. That index selects separate ROM fields from `0xF5D2/0xF5C2/0xF5B2/0xF5A2` and stages auxiliary state at `FFFF2150+0x17A/+0x176). This preliminary search is not the final pair of inline map indices.
- The map-row index R13 is independently searched at `0x96BF2–0x96C08` using the same UWORD query `FFFF1D12+0x30` against the second axis `0xFEB0 = 0xFEA0+0x10`.
- The map-column index R4 is searched at `0x96C12–0x96C28` against UWORD axis `0xFD9C`, using incoming R12 as the query. R12's caller provenance is unresolved; do not invent its physical source.
- Both selected indices are bounded to 0..7. The flattened byte offset is `16*R13 + 2*R4`; the same offset is used for all four maps.

**Map reads and immediate stages**

| Map | Read PC | Storage | Destination |
|---|---:|---|---|
| 0x0B5A2 | 0x96C44 | SWORD BE | UWORD FFFF2150+0x74E = FFFF289E |
| 0x0B522 | 0x96C58 | SWORD BE | UWORD FFFF2150+0x74C = FFFF289C |
| 0x0B4A2 | 0x96C6E | SWORD BE | UWORD FFFF2150+0x74A = FFFF289A |
| 0x0B422 | 0x96C7A | SWORD BE | UWORD FFFF2150+0x748 = FFFF2898 |

- All four maps use the same row/column indices but remain distinct payloads and output cells.
- After the direct stages, local flag paths choose between each map result and alternative words from the `0x9060` record; the selected values are staged into `FFFF2150+0x5EA/+0x5E8/+0x5E6/+0x5E4`. In particular the 0x0B422 result in R6 is moved into R13 at `0x96D02` when that path is selected.
- R13/R12 are sign-extended at `0x96D0A/0x96D0C` and multiplied by UWORD coefficients at GBR+0x32/+0x36. Subsequent signed difference/clamp arithmetic through sub_22448 produces additional local stages. This establishes signed correction/combination behavior, not the maps' physical domain.

**Assessment:** high-confidence set of four separately stored 8×8 SWORD lookup channels, sampled on a common 8×8 index pair and selected/combined through signed local arithmetic. Column-query provenance at the dispatcher boundary is unresolved. Do not merge the four physical maps or label them torque, spark, knock or another physical subsystem.

## 4. Bidirectional 32-point UWORD pair — 0x0F712 / 0x10F8A

### Forward direction — sub_648A6

- Query selection depends on ROM UBYTE `0x87C8.bit7`: set selects UWORD `FFFF1066`; clear selects UWORD `FFFF1064`. UWORD `FFFF10A0` is added and the query is bounded to UWORD range.
- Caller passes R4=`0x10F8A` (UWORD values), R5=`0x0F712` (UWORD axis), and R6=query to sub_22FAC at `0x648D8`. The delay slot at `0x648DA` stores the raw UWORD result at `GBR+0x8E = FFFF10E2`.
- The result is then normalized/converted through ROM UWORD `0x91B4`, sub_21AC0 and a branch on ROM UBYTE `0x8CCC.bit7`. It is conditionally staged as UWORD at `FFFF1054+0x6B8 = FFFF170C`; a derived byte is stored at `FFFF1054+0x6B6 = FFFF170A`.

### Reverse direction — sub_68A3C within the sub_689BA path

- Query is UWORD `FFFF33E6+4 = FFFF33EA). The call at `0x68A46` passes R4=`0x0F712` (values) and R5=`0x10F8A` (axis) to the same helper sub_22FAC; the delay slot zero-extends R0 into R6.
- The returned UWORD is normalized using ROM UBYTE `0x8F67` and the local UWORD range at GBR+0x10, with division/scaling and clamping. It is staged at `FFFF1054+0x52C = FFFF1580` (`0x68A7C`).
- This reverses the value/axis pointer roles compared with sub_648A6. The paths are structurally bidirectional, but no real-world “forward”/“reverse” physical meaning is assigned.

### Additional caller context

The scheduled routine beginning `loc_372CA` uses R4=`0x0F712` and R5=`0x10F8A` at `0x37398`; its query is derived from four times UWORD `FFFF9916+0x98`. The UWORD curve result is adjusted by UWORD `FFFFB374+0x118`, clamped nonnegative, then staged in `FFFF9916+0x26/+0x28`. This is a separate use with its own query path; no physical label follows from it.

**Assessment:** high-confidence bidirectional UWORD transfer/conversion pair. Each direction uses a distinct query and subsequent normalization; exact units/physical domain remain unresolved.

## 5. Two-piece 32-point UWORD curve sets — 0x10EEA/0x1100A and 0x10F2A/0x1104A

### Piecewise path in sub_68A86, called from loc_689A4

- Query R6 is the UWORD at `FFFF1054+0x52C = FFFF1580`, produced by the preceding sub_68A3C path or a branch that reuses its prior staged value.
- The routine reads the last UWORD of axis `0x10EEA` at `0x68A8E`. If R6 is within that range, it calls sub_22FAC at `0x68AA8` with values `0x1100A`, axis `0x10EEA`, query R6. Delay slot extends the query.
- If above the last point, R6 is shifted right by four bits and bounded; the routine calls sub_22FAC at `0x68ACA` with values `0x1104A`, axis `0x10F2A`. Result is UWORD-extended.
- Both branches store the result to the same UWORD cell `FFFF1054+0x5C4 = FFFF1618` (`0x68AB4` or `0x68AD4`).
- First direct consumer is `sub_68AF4`: it reads the curve output at `0x68AFA` and another UWORD `FFFF1054+0x2E4 = FFFF1338` at `0x68B00`, multiplies them, shifts right 16 and caps the result. It stores UWORD to `FFFF2150+0xA78 = FFFF2BC8` at `0x68B1A`. `sub_68B20` immediately reads that field at `0x68B24` and copies it to `FFFF2150+0xA76 = FFFF2BC6` in the RTS delay slot at `0x68B2A`.
- This is a strongly supported two-range transfer: the low segment interpolates against one axis/value pair; the high segment uses a different axis/value pair and a query scaled by 1/16; both converge to one output and a multiplicative consumer.

### Independent piecewise use in the sub_68D94 processing path

- The routine saves its registers, sets GBR/R11=`FFFF1054`, then calls `sub_690C6` at `0x68DAA` (delay slot reads UWORD `FFFF1054+0x384`). Later local gates, `sub_22E7C`/`sub_22E60` results and UWORD fields `FFFF1054+0x5BC/+0x5C0/+0x5C6` construct and clamp the first R6 query. Gate state includes ROM `0x8CD3.bit7` and runtime flags around `FFFF1E6E` / `FFFF1D99`; no physical meaning is assigned.
- The first piecewise lookup at `0x68F46` (values `0x10EEA`, axis `0x1100A`) or `0x68F54` (values `0x10F2A`, axis `0x1104A`) is selected by comparison with the last point of UWORD axis `0x1100A`. Both paths converge at `0x68F5E`; further arithmetic with UWORD `FFFF1054+0x384`, ROM UBYTE `0x8F67` and the first point of `0x0F712` scales/caps the result and stages UWORD at `GBR+0x12 = FFFF1066).
- A second query is formed from local fields at `FFFF1054+0x3B0` and `+0x5C6`, bounded at `0x69024–0x69038`. The calls at `0x6904A` (values `0x10EEA`, axis `0x1100A`) and `0x69058` (values `0x10F2A`, axis `0x1104A`) apply the same two-piece selection to that second query. The result is stored at `FFFF1054+0x464 = FFFF14B8` (`0x69066`, longword staging); subsequent multiply/scale/clamp logic uses UWORD `FFFF1054+0x384`, ROM UBYTE `0x8F67`, ROM UBYTE `0x8B51) and the first point of `0x0F712), then writes UWORD to `FFFF1054+0x474 = FFFF14C8` (`0x690B4`).
- Thus the same paired curves are used in a second multi-stage conversion/processing context, not just one isolated callsite. The two local outputs remain separate; no physical unit or identity is inferred.

**Assessment:** high-confidence two-piece, branch-selected 32-point UWORD transfer function. Each piece has a distinct axis/value placement; the high-query branch rescales its input before interpolation; both converge within a caller on a shared result slot. The output is then multiplied/scaled into UWORD stages. Physical domain and units remain unassigned.

## Corrections and guardrails retained

- A mode-selected or paired shape is not evidence of MAF, flow, torque, fuel, ignition, knock, dwell or another vehicle function.
- The 0x0B422 set uses **three** local axis searches/activities: a preliminary FEA0 search used for auxiliary ROM status staging; the map-row index uses FEB0 against UWORD FFFF1D12+0x30; the map-column index uses FD9C against incoming R12. Do not describe the final map query as two known sensor variables: R12 provenance is unresolved.
- The map values at 0x0B422 etc. are SWORD BE; the RAM staging words store their bit patterns. Sign extension is explicit at the arithmetic consumers.
- sub_22FAC argument order is values pointer in R4, axis pointer in R5, query in R6; the paired 32-point groups are not to be reversed or merged.
- The 0x0D8D6 helper returns UWORD; subtraction of 0x8000 is a caller operation.
- Reuse existing B956/C0D6/C756/C956 and normal/trust mirror evidence; none is repeated here.
