# WO65002 — A3C2 4×4 UBYTE reader and axis/query audit

**Status:** BOUNDED PASS — direct reader call and both axis pointers confirmed; second query provenance remains unresolved.  
**Target:** EL19A `f501.bin` · 1 MiB · MD5 `46991697c502052752a2cabcb84c9e27` · SH7058 · FID `8CMCKRN5`  
**Scope:** V56 candidate A3C2 only. One callsite; verify geometry, reader, axes, first query and immediate result staging. No semantic or donor-name assignment.

## Evidence

- Direct call at `0x6F37C`: R4=`A3C2`; R5=`DF35`; R6=`DF29`; R2 points to `sub_22B44`.
- Helper `sub_22B44` at `0x22B44` is the established 4×4 UBYTE two-axis reader. It calls `sub_233CC` for each axis with maximum index 3; both axes are raw UBYTE (no ×4 transformation in this wrapper).
- Argument order at the A3C2 call: first axis R5=`DF35`, first query R7; second axis R6=`DF29`, second UBYTE query stack-supplied.
- First query preparation at `0x6F35E–0x6F378`: UWORD `[FFFF3454+0x0A] = FFFF345E` is zero-extended, shifted right two, bounded to 0xFF, then zero-extended to UBYTE R7 at `0x6F378`.
- The immediate lookup result is staged as a caller stack byte at `0x6F37E`. It is then zero-extended at `0x6F380` and participates in subsequent local arithmetic; no physical endpoint is established here.
- Axis pointer literals at `0x6F420` and `0x6F424` resolve respectively to `dword_DEC8+0x6D = DF35` and `dword_DEC8+0x61 = DF29`. These are interior addresses within the larger `dword_DEC8` data block, not independent labelled axis objects.
- V56 records A3C2 as a zero-filled/generic 4×4 map candidate with DF29/DF35 axis pointers. The LST confirms the call and exact pointer use; this WO does not independently re-hash the raw 16-byte payload.

## Disposition

**Confirmed:** A3C2 is passed as the data base to a direct `sub_22B44` call; 4×4 UBYTE reader contract; raw UBYTE axes; R5=DF35 and R6=DF29; first query is `min(FFFF345E >> 2, 255)`; result staged locally.

**Unresolved:** second query's exact stack source; exact axis byte values/monotonicity; independent raw payload/hash verification; semantic purpose and downstream physical endpoint.

**Stop boundary:** no wider function or consumer trace. No semantic promotion.

**No changes:** workbook, XML, ROM, IDB, LST, scripts and Library files remain unchanged. Only this GitHub WO report and the operational register are in scope.
