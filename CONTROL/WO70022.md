## Objective

Establish the actual Python/runtime and testing constraints for the proposed modular ROM-tool suite. Recommend a sustainable minimum Python version, dependency policy, fixture layout and test/CI approach based on evidence from the current repository and available local execution environment.

This task is an audit and recommendation only. Do not install packages, change the environment or modify code.

## Required work

1. Inspect the current repository's Python scripts, imports, syntax and declared/runtime assumptions. Identify Python 2-specific legacy dependencies separately from Python 3-compatible modules.
2. Record the actual available local interpreter(s), exact versions and platform details where the worker environment permits. If local Windows/PowerShell information is unavailable, state that limitation rather than infer it.
3. Inventory external dependencies by script and capability. Distinguish standard-library-only code, optional packages, required packages and dependencies that are merely present in the current environment.
4. Inspect existing tests and GitHub Actions. Record what is tested, how it is run, test coverage gaps, runtime versions pinned by CI, and whether scripts can be tested independently.
5. Recommend a minimum Python version and explain tradeoffs for Windows use, current local workflows and future portability. Treat compatibility with `C:\Python27\python.exe` as a legacy workflow question to assess, not as an automatic requirement for all new code.
6. Propose a minimal testing strategy: pure unit tests, synthetic ROM/A2L/XML fixtures, golden outputs, regression fixtures from validated scanner cases, optional integration tests and CI matrix.
7. Recommend repository layout and CLI conventions for standalone scripts, including input validation, output paths, exit codes, logging and deterministic serialization.
8. Identify any installation, packaging or environment work needed later, but do not perform it.
