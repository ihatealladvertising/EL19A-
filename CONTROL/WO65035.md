# WO65035 — Targeted Caller Provenance of Stack-Sourced Indirect Calls

- **Status:** ACTIVE
- **Objective:** Determine whether selected stack-sourced indirect-call arguments in WO65031/WO65032 originate from fixed helper literals, ROM descriptor vectors, caller-supplied callback pointers, or unresolved dynamic values.
- **Scope:** Prioritize 12 representative sites across low/middle segments, sampling repeated call families rather than exhaustively tracing all 89+ stack-sourced sites. Start with `0x20C7E`, `0x20CA4`, `0x20CB0`, `0x462F2`, `0x47368`, `0x4B78A`, `0x5129E`, `0x52A24`, `0x5E0E8`, `0x6216C`, `0x65F98`, `0x7682E`.
- **Method:** Trace stack-slot stores back through the immediate caller, identify argument construction and fixed literal loads; check whether the same caller passes a stable pointer or a value derived from a descriptor/index. One caller boundary maximum; group equivalent wrappers.
- **Output:** Site → stack offset → producer/store PC → caller argument origin → fixed/descriptor/dynamic classification; unresolved boundaries explicit.
- **Stop:** No exhaustive interprocedural def-use, no broad RAM-writer scan, no cadence/semantic claims from call patterns.
- **Artifact boundary:** WO only plus operational register; no XML, workbook, ROM, LST, IDB, scripts or Library modifications. Minimum chat.
