# WO65034 — Targeted Provenance of RAM-Address Indirect Call Targets

- **Status:** BOUNDED COMPLETE — CLOSED
- **Correction:** The seven addresses listed in the initial draft are **not established RAM callback-pointer slots**. Their literal values are used as direct JSR/JMP destinations. The earlier “RAM callback slots” label is withdrawn.
- **Source:** annotated EL19A listing and `EL19A_Xref_Index.csv`.

Each ROM literal contains the RAM address itself; the call register is then used directly by JSR/JMP. This is not a ROM table lookup and no extra pointer dereference is visible at these sites.

## Important ambiguity

`0xFFFF1810` and `0xFFFF1820` are also referenced as UWORD data by GBR-relative accesses in `sub_36A26` / `sub_36E02` / nearby code (including a write to `0xFFFF1810` at `0x36A76`). This creates a code/data or address-space interpretation issue that this bounded trace does not resolve. Do not name these as callback slots or assert executable RAM contents without a separate RAM-image/initialization analysis.

The remaining RAM targets likewise have no proven initializer/body reconstruction in this pass. Their direct transfer destinations are confirmed; their runtime contents and origin are not.

## Conclusion

**BOUNDED COMPLETE — seven RAM-address transfer targets reconciled to their ROM literal sources and call sites.** No RAM callback table established. Further RAM code-image/initialization provenance is a separate task and must not be conflated with ROM function-pointer inventory.

No broad RAM-writer scan; no XML, workbook, ROM, LST, IDB, scripts or Library files modified.
