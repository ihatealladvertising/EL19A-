# WO65086 — `0x8405` Bit 0 Across Its Twelve Sites: Per-Site Consequences and the Shared 1000/800 Default

**Status:** BOUNDED COMPLETE — CLOSED (2026-11-21)
**Target:** `VERSA f501.bin` (1 MiB SH7058, MD5 `46991697c502052752a2cabcb84c9e27`) + `EL19A_Complete_Disassembly_ANNOTATED_V3_NEXT6_16_ALL_PENDING_ANNOTATIONS(1).lst` (MD5 `99635224d16ab7705445e27bf233e549`)
**Depends on:** WO65084 (the 21-site `0x8405` inventory; this WO takes its most-used bit), WO65085 (bit 7, claimed concurrently — not reopened here).

## Objective

Bit 0 of `0x8405` is tested twelve times, more than any other bit. WO65084 worked one of those sites (the 1000/800 selection in `sub_685A6`). This WO classifies what the other eleven do and tests whether bit 0 has one mechanical meaning.

## Scope and stop condition

- Method: each of the twelve bit-0 sites, its branch polarity as printed, and the first branch-specific effect (a load, a call, a store, or an executed block). Polarity is stated per site; `tst #1` sets T when the tested bit is **zero**, so `bt` means "bit clear".
- Stop at the first effect. No trace of the values stored, no physical identity, no unit assignment.
- Concurrency: does not reopen WO65085's bit-7 trace, WO65084's bits 1/2/5/6/7 gates, or any closed census.

## 1. The two constant-selection sites agree exactly

| Site | Function | Bit 0 clear | Bit 0 set | Secondary gate |
|---|---|---|---|---|
| `06519C` | `sub_65174` | `r13 = h'320` (800) | `r13 = h'3E8` (1000) | `FFFF35C8+0x53` bit 2 forces 800 |
| `0686E2` | `sub_685A6` | `r13 = h'320` (800) | `r13 = h'3E8` (1000) | `FFFF3616+5` bit 2 forces 800 |

Two unrelated routines select the **same pair of constants, `1000` and `800`, with the same polarity and the same "runtime bit overrides back to 800" shape**, using different secondary cells. This is the strongest cross-site evidence in the byte: bit 0 has at least one shared consequence — the choice of a default value from that pair.

## 2. The other ten sites, by consequence class

**Compute-only-when-clear (4 sites).** Bit 0 clear runs an update block; set skips it.

- `03652A` `sub_3648C`: clear → body reading `0x8DDD` and comparing `FFFF859C+0xD` against `0x89E9`; set → `loc_36576`.
- `06CF80` `sub_6CF6E`: clear → three calls `sub_6D4BC`, `sub_6D976`, `sub_6DAFC`; set → straight to `loc_6D310`.
- `06CFC6` `sub_6CF94`: clear → if `FFFF9860+8 != 1`, `or #4` **sets** bit 2 of the status byte at `FFFF34C8`; set → `and #0xFB` **clears** that bit. This is the one site where bit 0 publishes a RAM status bit rather than choosing a value.
- `06D420` `sub_6D274`: clear → body that reads `0x8B0E` bit 0 and `FFFF3628+0xC` bit `0x40`; set → `loc_6D4A0`.

**Compute-only-when-set (5 sites).** Bit 0 set runs a staged computation; clear skips it.

- `06E1DE` `sub_6DF26`: set → `FFFF1054+0x5EC = r13`; clear → `loc_6E208`.
- `06E300` `sub_6DF26`: set → store `r6` at `FFFF1054`-relative `+0x736` and skip the clamp; clear → clamp against `FFFF1054+0xA2C`.
- `06FB0A` `sub_6FADC`: set → body interpolating from `FFFF1054+0x384`; clear → `loc_6FB74`.
- `06FC08` `sub_6FADC`: set → interpolate axis `0xF912` through table `0x10954` (`sub_22F80`); clear → `loc_6FC2C`.
- `06FD9E` `sub_6FD8C`: set → body reading ROM `0x95B2` and `FFFF1860+0x10C`; clear → `loc_6FE6A`.

**Value staging, no branch (1 site).** `06EDCE` `sub_6EBF8` executes `and #1,r0` and stages the bit itself into `r13` alongside a `FFFF35CB+6` bit-`0x80` byte on the stack — bit 0 is consumed as data here, not as a gate.

## Findings

1. Bit 0 is not a single global switch. It has **twelve readers with four distinct consequence classes**: value choice (2), compute-only-when-clear (4), compute-only-when-set (5), and expression-as-data (1).
2. Seven of the twelve take the "active" outcome when bit 0 is **set** (five compute bodies plus the two `1000` choices); four take it when **clear**; one consumes the bit as a value. The majority polarity is therefore "set = enabled / higher default", but the minority is real and must not be normalised away.
3. The only cross-site identity is the **1000/800 pair** (§1). Every other site's effect is local to its own subsystem, with its own secondary gate (`FFFF35C8+0x53` bit 2, `FFFF3616+5` bit 2, `FFFF3628+0xC` bit `0x40`, `FFFF9860+8`, `FFFF1D99`-family bytes elsewhere).
4. `0x8405` bit 0 therefore reads most plausibly as a **mode-enable bit whose consequences are implemented per subsystem**, not as a single feature switch. That is a structural reading; no vehicle function, unit, or calibration name is assigned.

## Bounded negatives

- No site tests bit 0 together with another bit of the same byte in one mask; every test is a single-bit `tst`/`and`.
- No store to `0x8405` (ROM); the byte is read-only.
- No site compares the byte against a value (`cmp`), so no range/enum interpretation is supported.
- The stored results of the seven compute sites were not followed; their consumers are untraced.
- The `FFFF34C8` status-bit publication at `0x6CFC6` was not traced to its reader.

## Unresolved

1. What the two 1000/800 defaults parameterise, and why two subsystems share the pair.
2. Whether the `FFFF34C8` bit-2 publication is the same status bit read elsewhere, and by whom.
3. Which runtime cells (`FFFF35C8+0x53`, `FFFF3616+5`) the per-site overrides come from, and whether they share a producer.
4. Whether any of the twelve sites is dead code in this calibration (`0x8405 = 0x0C`, bit 0 clear — so the "set" bodies at `06E1DA`/`06E2FC`/`06FB02`/`06FC04`/`06FD9A` do **not** run on the shipped value, while the "clear" bodies at `036520`/`06CF7C`/`06CFC2`/`06D41C` and the `800` choice do).
