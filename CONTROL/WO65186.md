## Key Finding — Address Correction

The WO was scoped to RAM addresses `FFFF9866` and `FFFF9868` as the bound fields under GBR=`FFFF9862`. **This premise is incorrect.** The actual code path sets GBR to `0x00009862` (not `0xFFFF9862`), and the clamp reads access **ROM** addresses `0x00009866` (GBR+4) and `0x00009868` (GBR+6), not RAM `FFFF9866`/`FFFF9868`.

The RAM addresses `FFFF9862`, `FFFF9866`, and `FFFF9868` appear in the listing only as `UNDEFINED .res.b 1` data reservations (listing lines 480141, 480145, 480147) with **zero code references** — no reads, no writes, no GBR-relative accesses under any base.

## Clamp Arithmetic (software only)

The interpolated UWORD result from `sub_22EFC` is:

1. Multiplied by 13 (`mulu r2, r6` at `0x00065852`, `r6 = 13`)
2. Upper-clamp: if `result×13 > upper_bound×4`, clamp to `upper_bound` (`cmp/gt r2, r6` at `0x0006585E`; `bf` skip at `0x00065860`)
3. Lower-clamp: if `lower_bound×4 ≥ clamped_value`, clamp to `lower_bound` (`cmp/ge r2, r5` at `0x00065870`; `bt` at `0x00065872`)
4. Staged at `FFFF2BD8` (`mov.w r2, @(r0,r11)` at `0x00065894`, `r11 = FFFF2150`, `word_6591C = h'A88`, `FFFF2150+0xA88 = FFFF2BD8`)

The ×4 transformation is `shll2` (shift left by 2). Intermediate width is 32-bit MAC result (`mulu` → `sts macl`), truncated to UWORD via `extu.w` before comparison.

Both UWORDs are **independently addressed static ROM constants** stored adjacently at `0x00009866` and `0x00009868`. They are not initialized from RAM, not copied together at runtime, and not modified after shipment. They are a fixed pair embedded in the ROM image.
