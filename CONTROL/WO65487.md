## Falsifiable hypothesis record

- **Identity layer advanced:** input identity.
- **Hypothesis:** `FFFF1640` and `FFFF164C` are internal filtered state cells of one correction loop, so their producers are the same small function family rather than an acquisition or CAN source.
- **Evidence:** WO65322 (`0x6913C`/`0x6915A`, `0x6B24C`/`0x6B278`, `0x87C8=0x00`); WO65305 step 7 writer/reader list.
- **Prediction:** the `sub_68C28` callers are a small bounded set in the same correction/limiting region, and both writers are arithmetic (filter/clamp) rather than ADC/CAN reads.
- **Result:** **PARTLY CONFIRMED, with two corrections.** Both cells are arithmetic and neither is acquisition-derived (prediction upheld). But they are **not one loop**: `FFFF1640` is a *flag-selected* setpoint written by a limiter in `sub_6E1xx`, while `FFFF164C`'s filter is **disabled in the shipped ROM** (`U8[0x8CBE] = 0x00`) so its producer returns its argument unchanged. And the caller set is **empty** in the index — both routines are invoked indirectly.
- **Information gain:** removes the last hope of attaching a physical (airflow/boost) input to the `0x0CD56` map from this side: the query is an internal, clamped, flag-selected setpoint, and the clamp against `FFFF164C` is against a **static default**, not a computed limit.

## 2. `FFFF1640` — flag-selected, clamp-limited internal setpoint

Two word stores exist, mutually exclusive on a ROM flag:

- `0x6E1DE tst #1, r0` with `r0 = U8[0x8405]`; `bt loc_6E208`.
- **ROM `0x8405 = 0x0C` → bit0 = 0 → branch TAKEN.**

| Site | Condition | Value written | Live on this ROM? |
|---|---|---|---|
| `0x6E1E6` | flag bit0 = 1 | `r13` | **DEAD** (ROM bit clear) |
| `0x6E20C` | flag bit0 = 0 | `r5` | **LIVE** |

The live value `r5` is the output of a five-stage limiter chain (`0x6E18A`–`0x6E1D2`): a working value `r14` is clamped down by `U16[FFFF3454+0x1C]` (`0x6E1B6`), then by words at `r1+0xA1E`, `r1+0xA22`, `r1+0xA2C` and `r1+0x…` (`0x6E18E`, `0x6E19A`, `0x6E1C4`), with the intermediate result also written to `FFFF1054+0x5F2 = FFFF1646` at `0x6E18A`. `r1` is the routine's base argument and **was not resolved in this WO** — the clamp-edge identity is the exact open question.

**Classification:** internal, clamp-limited setpoint whose *source* is selected by a ROM flag; not a measurement. It is then used as the X query of the `0x0CD56` reader (`0x6913C`), i.e. the map's row input is a **setpoint**, not an airflow/boost measurement.

## 3. `FFFF164C` — producer is an identity pass-through as shipped

`sub_6B236` at `0x6B240`–`0x6B24C`: reads `r4 = U16[FFFF164C]`, calls `sub_6AF84`, writes the result back to `FFFF164C`. Inside `sub_6AF84`:

- `0x6AF8C` `r2 = 0x8CBE`; `0x6AF92` `r0 = U8[0x8CBE]`; `0x6AF96 tst #1` / `0x6AF98 bt loc_6B010`.
- **ROM `0x8CBE = 0x00` → branch TAKEN immediately**, skipping the entire limiter chain (`0x6AF9A`–`0x6AFF0`: `FFFF99F4` byte+3 bit2, `U8[0x8B51]` bit5, `FFFF1E75` bit7, `FFFF3454+0x3E`, `U8[FFFF1E09]`, `FFFF8522`, `FFFF8532`).
- Live path `0x6B010`: `and.b #0x7F, @(0x71,gbr)` with `gbr = FFFF1D98` → clears **bit7 of `FFFF1E09`**, then `0x6B014` `mov.w @r15, r0` returns the stacked argument and `rts`.

⇒ **`FFFF164C` is written back with its own value unchanged.** The whole limiter is disabled on this calibration; `FFFF164C` holds a static/default value, and the `min(FFFF164C, mapOut − 0x8000)` at `0x6B26E` clamps against that **constant**, not a computed limit. This **strengthens** WO65322's "min against `FFFF164C`" into "min against a static default", and explains why no other writer surfaced.

Cross-link worth carrying: `sub_6AF84` reads `FFFF84D4+0x4E = FFFF8522` and `FFFF84D4+0x5E = FFFF8532` — the **same block as WO65484's unresolved Y query `FFFF84FE`** (`FFFF84D4+0x2A`). Handed to WO65496.
