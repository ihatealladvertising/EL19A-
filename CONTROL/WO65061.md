## Checkpoint 1 — bounded instruction-level regression results (2026-11-20)

### PASS — effective-address controls

- **Indexed read 1:** `0x46BD8` PC-relative `mov.w` resolves pool `0x46CF2`; signed UWORD `0x85C4` loads as `R12=FFFF85C4`. `0x46BDA` sets `R0=0x1B`. `mov.b @(r0,r12),r2` at `0x46BDE` therefore reads `FFFF85DF`.
- **Indexed read 2:** `0x4700E` resolves pool `0x47036`; signed UWORD `0x85C4` loads as `R4=FFFF85C4`. `0x47012` sets `R0=0x1B`. `mov.b @(r0,r4),r2` at `0x47014` therefore reads `FFFF85DF`.
- **Third read — GBR-relative (new correction to WO65003's two-reader count):** `0x59C4A` loads signed UWORD `0x85C4` from pool `0x59CB8` into R0 (`FFFF85C4`); `0x59C4C` copies R0 to GBR. No intervening GBR write occurs before `0x59CA2`. The instruction reads `GBR+0x1B = FFFF85DF`. The branch at `0x59C56` can reach this read. Thus **three RAM read sites are currently established**: `0x46BDE`, `0x47014`, and `0x59CA2`.
- **ROM/RAM distinction:** ROM `0x85DF` contains byte `01`; literal pool `0x38084` contains pointer `000085DF`. These facts do not change the effective address of the GBR-relative access at `0x59CA2`, which is RAM `FFFF85DF`.

## Checkpoint 2 — stale-GBR and PKIOR_W boundary regressions (2026-11-20)

### PASS — exact `0x55xxx → FFFF8AF0` stale-GBR rejection

- Caller `sub_55518` saves its incoming GBR at `0x5552A`, loads word `0x8A34` at `0x5552C`, and establishes **GBR=`FFFF8A34`** at `0x5552E`.
- It calls `sub_55F66` at `0x557CC` (delay-slot instruction `0x557CE`).
- Callee `sub_55F66` saves GBR at `0x55F78`, loads `0x8A40` at `0x55F7A`, and temporarily sets **GBR=`FFFF8A40`** at `0x55F7C`. It restores the saved caller GBR at `0x56106` before returning at `0x56118`.
- Caller instruction `0x55846` is `mov.l @(h'B0,gbr),r0`. The caller's restored GBR is `FFFF8A34`; effective address is **`FFFF8AE4`**.
- The reported false alias `FFFF8AF0` is exactly the result of incorrectly retaining the callee's temporary GBR: `FFFF8A40 + 0xB0 = FFFF8AF0`. It is **not** the address read at `0x55846`.
- Intervening helper calls in the caller path were checked: `sub_564D4` and `sub_562D4` save/restore GBR; `sub_5611C` does not change GBR. No helper leaves its private GBR active in the caller.
- This is the concrete regression that rejects stale callee GBR propagation across a call/return boundary.

### PASS — PKIOR_W ISR-local pointer and RTE boundary

- `INT_ATU11_IMI1AC` entry is `0x28658`. It saves incoming `R0`, `R2`, and `R3–R7` before using these registers.
- At `0x2869A`, `mov.w word_286DA,r2` loads ROM word `F770`, sign-extending to `R2=FFFFF770`; `0x2869C` reads `@(4,R2)` = `FFFFF774`.
- Additional explicit PKIOR_W pointer loads occur at `0x286A4`, `0x286E4`, `0x2870E`, and `0x28738`; the pool `word_28808` also contains `F770`. Their accesses use the newly loaded R6 plus displacement 4.
- No pre-entry R2/R6 value is used as the PKIOR_W pointer. The `mov.w` pool loads define the base before the relevant dereferences.
- The ISR restores R2 at `0x2878C` and exits with `rte` at `0x28790`. PKIOR_W-derived pointer state must not be propagated beyond this interrupt-return boundary.
- This validates the relevant save/load/restore boundary. The original historical false-positive instruction PC / exact false-hit record was not independently recovered, so the named PKIOR_W regression is **PARTIALLY REPRODUCED**, not claimed fully closed.
