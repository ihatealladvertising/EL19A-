- **PKIOR_W / stale-register regression:** reproduce the reported stale-register alias. The current listing contains explicit literal-pool loads of `0xF770` at PCs `0x2869A`, `0x286A4`, `0x286E4`, `0x2870E`, and `0x28738`; the pools at `0x286DA` / `0x28808` contain `F7 70`. These are positive control sites, not proof that the reported false-positive site has been identified. Record the exact false-positive PC and def-use path if recoverable; otherwise mark this subtest unresolved.
- **RAM `FFFF85DF`:** verify the two indexed reads at `0x46BDE` and `0x47014`. Both require the actual base `FFFF85C4` plus `r0=0x1B`. Keep separate from ROM `byte_85DF` at `0x000085DF`, including its literal-pool pointer at `0x38084` and GBR-relative read at `0x59CA2`.
- **`0x55xxx → FFFF8AF0` regression:** recover the exact PC and expected access form from the original report/evidence before testing. Current listing evidence distinguishes ROM `byte_8AF0` at `0x00008AF0` (pointer literals at `0xA506C`, `0xA5304`, `0xA7F64`) from RAM `FFFF8AF0`; do not infer a RAM reference from the ROM object or fabricate the missing PC.
- **Register-state tests:** verify `extu.b` updates the tracked register (including `r0`), values are not carried across unrelated functions or unproven control-flow joins, and branch delay slots are modeled only for delay-slot instructions (`bt/s`, `bra`, `rts`; not plain `bt`).

### 2. Structural pilot

- Validate function bounds against the current listing; do not assume the 2026-11-01 function index is current.

- Resolve absolute literals, GBR-relative, base+displacement, base+index, PC-relative literal pools, and pointer indirection only where register provenance is supported.

### 3. Bounded output

- Include address, PC, function, R/W, width, bit operation/mask where applicable, access form, register provenance, and confidence.
- Any new test harness must be separate from existing scripts, read-only, deterministic, and kept in scratch until reviewed. Do not alter ROM, LST, IDB, XML, workbook, existing scripts, or prior evidence files.

## Acceptance criteria

1. ROM/listing byte-integrity check remains reproducible with exact counts and hashes.
2. Both `FFFF85DF` RAM readers resolve to the exact same effective address, and ROM `0x85DF` is never aliased to RAM `FFFF85DF`.
3. PKIOR_W positive controls resolve only where the `0xF770` definition is proven; stale state is not propagated across functions/unsupported joins. The original false-positive site must be identified or explicitly left unresolved.
4. The `0x55xxx → FFFF8AF0` case is tested only after its exact PC/access form is recovered; otherwise it remains NOT TESTED.
5. `extu.b`, signed loads, GBR changes, and delay-slot semantics pass focused instruction-level checks.
6. Every unresolved register/base/index site is reported with method coverage and stop reason.

## Stop condition

Stop at the first unresolved instruction semantics, data/control-flow join, or missing regression-site provenance that could create a false effective address. Do not broaden into whole-ROM RAM xref generation until acceptance criteria are met.
