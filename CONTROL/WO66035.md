## Question

Do the U16 BE vectors at `0xFC10` and `0xFC30` participate in engine-speed / idle-speed control, and what are their actual reader, query, table and first meaningful output roles?

## Identity layer advanced

**Input identity, function identity and output identity.** Physical calibration identity is conditional on a target-side consumer/output path; do not claim it from values or shape alone.

## Falsifiable hypothesis record

- **Hypothesis:** One or both vectors are axes or value curves used by an engine-speed / idle-speed control calculation.
- **Evidence:** User-supplied array values verified in pinned ROM (see below); user-supplied log summary only (contextual, unaudited). Known diagnostic references: `FFFF85DA` is the direct OBD Mode 01 PID 0x0C engine-speed source; `FFFF85B2` is a derived engine-speed mirror.
- **Prediction:** If an array is a speed axis, decoded code must load its ROM address and pass it in an axis argument to a lookup/interpolation routine. The corresponding query must resolve to `FFFF85DA`, `FFFF85B2`, or a fully traced conversion from them before it is named engine speed.
- **Cheap discriminator:** Search only exact references to `0xFC10` and `0xFC30`; follow each reference's register lineage through the first helper call; resolve the query argument and first meaningful result consumer.
- **Result:** SUPPORTED for reader-backed axis status; WEAKENED for idle-speed engine-speed identity (query source not traced to FFFF85DA or FFFF85B2).
- **Information gain:** Separates (a) a real RPM query axis (not established), (b) a speed-like axis queried by another variable (confirmed), (c) an unrelated speed-control/table use (confirmed reader-backed), (d) an unreferenced numeric sequence (rejected — both are referenced).

### Reader helper chain (from annotated disassembly EL19A_Complete_Disassembly_ANNOTATED_V3_NEXT6_16_ALL_PENDING_ANNOTATIONS(1).lst)

**sub_2340C** (lst:27328) — U16 axis search / breakpoint locator:
- r0 = axis base address, r4 = byte offset start, r5 = U16 query value
- Iterates backward through U16 axis entries (decrements r4 by 2)
- Compares each axis value with query; on bracket found, computes fraction via sub_23700
- Returns r4 = byte offset of lower bracket entry, r5 = interpolation fraction

**sub_231C8** (lst:26981) — linear interpolation helper:
- r1 = lower bracket value, r0 = upper bracket value, r3 = fraction
- Result = lower + fraction * (upper - lower) / 65536 (MUL.L high-word, no rounding)

**sub_22F54** (lst:26598) — wrapper for 0xFC30 reader:
- r0 = axis base (0xFC30), r5 = query value (zero-extended from r6)
- Calls sub_2340C for axis search
- Post-search: reads bracket values, tail-calls sub_231C8 for interpolation
- Auxiliary data: r4 = h'10B34 (off_8CDE0) or h'10B44 (off_8CDEC) depending on call site

**sub_22F80** (lst:26624) — wrapper for 0xFC10 reader:
- Identical structure to sub_22F54 but with offset h'1E (30) instead of h'E (14) for bracket-value read
- r5 = axis base (0xFC10), r5 = query value

## Judgment

**WEAKENED.** Both vectors are confirmed reader-backed U16 axes used in lookup/interpolation routines (sub_22F54/sub_22F80 → sub_2340C axis search → sub_231C8 interpolation). However, neither query source has been traced to FFFF85DA or FFFF85B2 (the established engine-speed diagnostic cells). Without query-to-engine-speed proof, the vectors cannot be named idle-speed control axes. They may be speed-domain axes used by a different calculation, or the query source may resolve to engine speed via a path outside the bounded exact-reference search.
