## Question

Do the U16 BE vectors at `0xFC10` and `0xFC30` participate in engine-speed / idle-speed control, and what are their actual reader, query, table and first meaningful output roles?

## Why it has value

The user supplied two monotonic speed-like arrays:

- `0xFC10–0xFC2F`, 16 U16 BE values: `[400, 500, 600, 700, 800, 900, 1000, 1100, 1200, 1300, 1400, 1500, 1600, 1700, 1800, 1850]`.
- `0xFC30–0xFC3F`, 8 U16 BE values: `[400, 610, 820, 1030, 1240, 1450, 1660, 1850]`.

A user-supplied log summary reports idle samples concentrated in coarse speed buckets and one transient peak at 2112 RPM. The candidate vectors' 1850 maximum could cover an idle band while not covering that reported transient. The log summary does not establish the ROM objects' identity. A reader/query trace is the lowest-cost discriminator between a genuine idle-speed object, an unrelated speed-domain object, and coincidental monotonic data.

## Identity layer advanced

**Input identity, function identity and output identity.** Physical calibration identity is conditional on a target-side consumer/output path; do not claim it from values or shape alone.

## Falsifiable hypothesis record

- **Hypothesis:** One or both vectors are axes or value curves used by an engine-speed / idle-speed control calculation.
- **Evidence:** User-supplied array values above; user-supplied log summary only (309 cleaned samples, 233 APP=0 running-engine samples, coarse A-byte buckets, one 2112-RPM peak). The raw CSV was not found in the repository during WO generation. Known diagnostic references: `FFFF85DA` is the direct OBD Mode 01 PID 0x0C engine-speed source; `FFFF85B2` is a derived engine-speed mirror; `FFFF855E` is Consult-only C22_0x121A per WO65724 and is not an established RPM source.
- **Prediction:** If an array is a speed axis, decoded code must load its ROM address and pass it in an axis argument to a lookup/interpolation routine. The corresponding query must resolve to `FFFF85DA`, `FFFF85B2`, or a fully traced conversion from them before it is named engine speed. The lookup result must reach a speed/idle-control branch or output to support the function claim.
- **Cheap discriminator:** Search only exact references to `0xFC10` and `0xFC30`; follow each reference's register lineage through the first helper call; resolve the query argument and first meaningful result consumer. No broad scan or full table census.
- **Result:** UNRUN. Worker must mark supported, weakened, rejected or unresolved from the actual trace.
- **Information gain:** Separates (a) a real RPM query axis, (b) a speed-like value curve queried by another variable, (c) an unrelated speed-control/table use, and (d) an unreferenced numeric sequence, without repeating candidate discovery.
