## 2. Falsifiable hypothesis record

- **Hypothesis:** at least one of `FFFF85A4` / `FFFF852A` has a localizable indexed writer from the `0x85AD–0x85B3` scalar family or the A452 temperature-query chain.
- **Prediction:** WO65118 would contain a `write` row naming either address, with a resolvable base and source expression.
- **Cheap discriminator:** count `write` rows per exact address; then recompute effective addresses for every non-byte-width row using the WO65263 scaling rule before accepting it as a producer.
- **Result:** **NEGATIVE** for both cells. `FFFF852A` has 81 `read` rows and **0** `write` rows. `FFFF85A4` has 60 `read` rows and 1 apparent `write` row, but that row (and its paired read) is a word-width misaddress: it resolves to `FFFF856C`, not `FFFF85A4`.
- **Information gain:** the producer gap is not a missing index query; it is partly an index address-column artifact that had to be removed before the true negative could be stated.

## 4. FFFF85A4 — producer unknown after misaddress removal

### 4.1 Correct byte-width readers

### 4.2 Misaddressed non-byte rows — additive correction

| WO65118 rows | Indexed address | Form / annotation | Base | Correct EA | Width factor |
|---|---|---|---|---|---|
| `0x3605C` (`sub_36012`, `write w`), `0x3606A` (`read w`) | `ffff85a4` | `mov.w r0, @((dword_856C − h'8534),gbr)` / `mov.w @(h'38,gbr), r0` | `FFFF8534` | **`FFFF856C`** | 2× |
| `0x3C6A4`, `0x3C7B0`, `0x3D188` (`sub_3C590`), `0x3E354` (`sub_3E30C`) | `ffff85a4` | `mov.l @(h'3C,rN), r6/r2` | `FFFF84B4` | **`FFFF84F0`** | 4× |

Derivation: the annotations `h'38` and `h'3C` are already the width-scaled byte displacements. The index address column adds the width factor a second time: `FFFF8534 + 2×0x38 = FFFF85A4` and `FFFF84B4 + 4×0x3C = FFFF85A4`. This generalizes WO65263's word finding to longword rows: **for `mov.w/mov.l` GBR/base-displacement rows, the WO65118 address column is inflated by the access-width factor; byte rows are correct.**

Additional checks:
- WO65118 already has a correct word row for `FFFF856C` at `0x6C596` (`sub_6C4DC`, `base=ffff8534`) — a read, not a writer.
- WO65118 already has correct longword rows for `FFFF84F0` at `0x4A100`/`0x4A242` (`sub_49CD0`, `base=ffff84a4`) — reads, not writers.
- No `write` row exists for `FFFF856C` or `FFFF84F0` either. Therefore removing the misaddress does not create a producer.

### 4.3 Discriminator result

- **ROM scalar family:** no indexed writer to `FFFF85A4` (correct byte rows) or to its corrected aliases.
- **A452 chain:** WO65290 records `FFFF85A4` as an unresolved second axis staged at `0xAEE3E`, with producer unresolved in WO64869. No new producer was found in the indexes.
- **E700 context:** WO65290's `r4 = max(U8[FFFF85A4], U8[0x85B0])` then `min(..., U8[0x85B1])` reduces to constant `0x08` on this ROM, so the missing producer does not change the E700 query result.

**Result: BOUNDED NEGATIVE — no indexed writer. Physical identity remains UNASSIGNED.**
