## Objective
Mine `EVIDENCE/RFCC_2XHK19BDF1.a2l` (X12C_KH3DT_DI_NAM_R/C, 2012 SH7058) as a metadata-only donor and cross-reference its COMPU_METHOD/COMPU_TAB/record-layout definitions against the pinned V6 A2L and EL19A catalogue.

## Required work
1. Pin file identity, size and SHA-256 for both A2Ls; record ECU/project metadata.
2. Extract and normalize COMPU_METHOD scaling, units, format, coefficients, limits and referenced tables; identify shared Nissan naming/scaling conventions.
3. Compare characteristic/axis/function naming across X12C and V6; classify apparent Bank1/Bank2, Normal/Trust, Drive/Neutral and other pairs only where explicit metadata supports the distinction.
4. Crosswalk candidate scaling and pair structures to the 179 EL19A catalogue entries, carrying forward existing EL19A reader/axis evidence from WO65133–WO65141. Donor metadata is a search hint, never proof of EL19A meaning.
5. Produce a compact reusable mapping and contradiction/ambiguity register, including cases where identical names have different conversion methods.

## Acceptance criteria
- Reproducible inventory of A2L conversion methods and references, with exact source locations.
- Explicitly separate exact text/name matches, structural analogies and EL19A-supported matches.
- Bank symmetry requires paired characteristic declarations and compatible axes/record layouts; do not infer bank identity from suffixes alone.
- Every proposed EL19A match links to its EL19A catalogue row and existing reader evidence; no ungrounded semantic promotion.
- Report top 20 high-value candidate matches and unresolved questions.

## Boundaries
Read-only. No edits to either A2L, ROM/LST, XML, workbook, catalogue, indexes, scripts or tools. No new broad ROM scans. Do not transfer donor addresses, labels, units or semantics into EL19A definitions. Reuse WO65133–WO65141 outputs; if a required donor artifact is missing, report the dependency rather than reconstructing it.

### 8. Contradiction / ambiguity register

1. COMPU ID reuse with different content (502 IDs) — any earlier note keyed on COMPU ID across files is invalid; use normalized content.
2. mMABFSFT2 present without mMABFSFT in X12C — the V6 pair is not a fixed Nissan template.
3. D/N dashpot objects (mTDSHPTD/N, mDDSHPTD/N) absent in X12C — D/N reading for E678/E688/848A/848B has no second-donor support.
4. Unit-label drift with equal factors (L/min vs L/min/10; 0.0391 vs 0.0390625) — donor unit strings are unreliable as physical units.
5. X12C has no FUNCTION/FUNCTION_LIST data — function-family evidence is V6-only.
6. Identical donor signatures do not prove identical EL19A payload semantics; WO65141's "no verified physical identity" verdict stands.

### 9. Unresolved questions and next discriminator

- Whether EL19A 0x0B7D6 (constant 0x8000) corresponds to an unused/disabled second instance, as X12C keeping only mMABFSFT2 might suggest — discriminator: reader-side condition that selects 0x0B756 vs 0x0B7D6.
- FFFF85FB.bit7 polarity (A vs D) for 0x0A342/0x0A382 — discriminator: producer of FFFF85FB.bit7 (throttle-delta sign).
- Whether other EL19A header fields follow the X12C ID-block layout (e.g. mECUHWNO-adjacent declarations near 0x8200) — next discriminator: list X12C CHARACTERISTICs in 0x8000–0x8300 and compare against EL19A bytes, ID/text blocks only.
