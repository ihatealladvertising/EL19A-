## Closeout — 2026-11-22

**Result:** the B956 UWORD result is the **input term of a fixed-point recursive (multiply-accumulate) update** inside `sub_969C2`. That update uses both the current-pass B956 result (held in `R7`) and the previous-pass B956 result (`FFFF9C48`), each multiplied by its own coefficient. Those coefficients come either from ROM coefficient tables indexed by two axis searches, or from fixed ROM words at `0x9060–0x9066` when `UBYTE[FFFF1C70] != 0`. The saturated output is staged as a SWORD on the stack and then (minus the FC90 result `FFFF27DC`, offset by `0x8000` and floor-clamped) at `FFFF27EA`. WO65070's `FFFF9C48` stage is the **one-pass delay element** of that update. No physical meaning is assigned.

### 2. Current-pass consumer — register `R7` (new)

`0x96A0C mov r0,r7` keeps the raw helper return in `R7`. A register-write scan of `0x96A10–0x96D94` finds no write to `R7` and no `jsr`/`bsr`, so `R7` at `0x96D94` is still the unmodified B956 result.

```text
96D94 extu.w r7,r7                  ; B956 (current pass)
96D96 mov.w @(0x38,gbr),r0          ; GBR=FFFF9C10 -> UWORD FFFF9C48 = B956 (previous pass)
96D9C mul.l r10,r7  -> r14 = macl   ; × coefficient c0 (r10, sign-extended at 96D98)
96DA8 mul.l r2,r9   -> r2  = macl   ; × coefficient c1 (r9, sign-extended at 96DA2)
96DAA/AE shar r14 / shar r2 ; 96DB0 add ; 96DB2/B4 shar×2
96DB6 shar r6 ; 96DBA add r6,r14 (jsr delay) ; 96DB8 jsr sub_22448 (r0 = r4) ; 96DBC add r0,r14
```

`acc = ((((B956·c0)>>1) + ((B956_prev·c1)>>1)) >> 2) + (T1>>1) + sub_22448(T2)`. Here:

- `T1` is the saturated term from `0x96D08–0x96D58`: `−(c3·GBR[0x36]) − (c2·GBR[0x32])`, using `r12`/`r13`.
- `T2` is the saturated term from `0x96D5A–0x96D92`: the same form with `GBR[0x30]`/`GBR[0x2C]`.
- Each of these partial sums saturates to `0x7FFFFFFF`/`0x80000000`.

**Coefficient selection** (`0x96C28–0x96D06`):

- Row index = axis search of `UWORD[FFFF1D42]` (WO65165 producer) over the ROM axis at `0xFEB0`, 7 steps. It is stored to `GBR+9`.
- Column index = axis search of `UWORD[FFFF85B2]` (B956's second query, still held in `r12` from `0x96A14`) over `0xFD9C`. It is stored to `GBR+0xA`.
- Coefficient tables have 16 bytes per row, 8 UWORD columns:
  - `c0 = B5A2[row][col]`;
  - `c1 = B522[row][col]`;
  - `r8 = B4A2[row][col]`;
  - `r6 = B422[row][col]`.
- The selected values are also staged to `FFFF2150+0x74E/0x74C/0x74A/0x748`.
- **Override gate:** stack byte `+0x40 = (UBYTE[FFFF1C6C+4] != 0)` (`0x96A1E–0x96A2C`). When it is set:
  - `c0 = ROM[0x9066]=0x2000`;
  - `c1 = ROM[0x9064]=0x0333`;
  - `c2 = ROM[0x9062]=0xFFAE`;
  - `c3 = ROM[0x9060]=0x0000`.
  
  These are also staged to `FFFF2150+0x562/0x5EA`, `+0x560/0x5E8`, `+0x55E/0x5E6` and `+0x55C/0x5E4`. When the byte is clear, the table values are used and only `+0x5EA/+0x5E8/+0x5E6/+0x5E4` are written.
