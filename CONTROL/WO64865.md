## Confirmed
- ROM `0x90EA` is loaded through a pointer and read with `MOV.W @R2,R5` at PC `0xC03D6`; it is a UWORD operand, not UBYTE.
- `0x90EA` is the last UWORD in a contiguous 16-UWORD block `0x90CC–0x90EB`; it is not an isolated one-word scalar object.
- In `0xC034C–0xC03F0`, five query bytes are paired with UWORD operands `0x90E8/0x90E6/0x90F6/0x90F4/0x90EA`. Each is passed through `sub_22A8C`; results are combined through `sub_2304C` and stored as a longword at `FFFF2150+0xAD4`.
- The state-management code at `0xC02EA–0xC02F0` copies the `+0xAD4` longword into `+0xAD8`; later code at `0xC0570–0xC0586` reads `+0xAD4` as part of another composite calculation and subtracts a separate `+0xAF0`-derived term before a further indexed calculation.
- This is a multi-input composite state path, not evidence that `0x90EA` is a standalone APO compensation change-rate scalar.
- WO64850's prior downstream audit already found the path terminates in internal state; no percentage conversion or physical throttle endpoint was established.
